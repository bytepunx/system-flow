# scripts

Purpose-named shell scripts for common tasks. The `Makefile` calls these; CI calls the same ones. Each script runs from any directory, prints what it does, and exits non-zero on failure. POSIX sh only; the operator's interactive shell is zsh.

`flai test` runs the same tests and lints by path: `system-flow.yaml`'s `tests` declare them as tiers (gofmt, vet, golangci-lint, the changed packages' Go tests without `-short`, vitest, `shellcheck.sh` on the changed scripts, the markdown lint, and, under `flai test --all` only, `template-test.sh`, `flaiover-test.sh`, `integration.sh`, and `smoke.sh`), and `flai test <path>...` runs those the paths select, cheapest first, stopping at the first that fails. Agents use it between tasks. `flai verify <story>`, which the close-out runs, runs those a story's branch selects, the `--all` ones whose paths it selects included. Those paths name the scripts each `--all` tier runs, so a change to a script runs the tests that exercise it: `template-test.sh` selects the template tier, the `flaiover-*.sh` scripts and `env.sh` the flaiover tier, `integration.sh` the integration tier, and every script the smoke tier. The scripts and `make` targets stay for people and CI.

| Script | Does |
|--------|------|
| `env.sh` | Sourced by the others: puts Go, `~/go/bin`, and `./bin` on PATH, sets `FLAI_CONFIG` to `.flai-cache/config.json` |
| `with-env.sh` | Runs the command given with `env.sh`'s environment, so a `flai test` tier reaches a tool installed in `bin/`, such as golangci-lint |
| `flai.sh` | Runs `bin/flai`, building it from `flai/` first if missing or stale |
| `flai-build.sh` | Builds `bin/flai` from source |
| `flai-reference.sh` | Regenerates `docs/users/flai-reference.md` and the flag index in `docs/operators/settings.md` from the command help (`go run`, leaves `bin/flai` alone) |
| `test.sh` | Behavior tests: `go test -race -short` in `flai/`, seconds, no external dependencies, then `flaiover-unit.sh` |
| `flaiover-unit.sh` | flaiover's vitest against a current `bin/flai`. In a story worktree it first runs `flaiover-install.sh --if-needed`; in the main checkout it does nothing while `flaiover/node_modules` is missing. Given arguments, runs vitest with them instead of the whole suite, as `flai test`'s vitest tier does for the files it selected |
| `integration.sh` | Integration tests: full `go test -race` including real git and the monorepo round-trip, but not the gateway checks (`TestGateway*`), which the smoke tier runs. In a worktree, such as a story's or the merge queue's, it first runs `flaiover-install.sh --if-needed`, so the components tests run on the tree's own lockfile (I-0178). Arguments go to `go test`: `flai test`'s `integration` tier passes `-json`, so its findings name each failing test by file and line |
| `smoke.sh` | Smoke tests: render the template and check it, check this repository, lint the markdown, `install-test.sh`, then `gateway-smoke.sh` |
| `gateway-smoke.sh` | The gateway checks: for each gateway whose key is set (OpenRouter's `OPENROUTER_API_KEY`), its `TestGateway<Name>` in `flai/internal/serve`, verbosely, a paid `claude -p` capped by `FLAI_TEST_GATEWAY_BUDGET`; for each whose key is unset, one line saying it was skipped and why. See the [contributors guide](../docs/contributors/index.md) |
| `install-test.sh` | Installs flai with `install.sh` and upgrades it with `flai self-upgrade` from releases 999.0.0 and 999.0.1 built from the tree with `flai-snapshot.sh --local` and served by `release-server.sh` as `local/flai`. Keeps every check: no `sudo` in `install.sh`, an explicit `FLAI_INSTALL_DIR`, the default `HOME/.flai/bin` with the `PATH` line printed, `self-upgrade --check`, `--dir` upgrading 999.0.0 to 999.0.1, and where `self-upgrade` installs outside and inside a project. No token, no request to GitHub. A failing step prints its output and the server's request log. `make install-test` |
| `install-published-test.sh` | Installs the latest published flai from GitHub with `install.sh` and `flai self-upgrade`, with a token from `GITHUB_TOKEN`, `GH_TOKEN`, or `gh`. No close-out runs it; `install-published.yml` runs it on push to main, daily, and by hand. A failing step prints its output; on a host (`CI` unset) it also opens or bumps the issue "The latest published flai release does not install from GitHub" through `flai issue`, uncommitted. `make install-published-test` |
| `release-server.sh` | `URL=$(scripts/release-server.sh --owner $$ [--repo local/flai] DIST_DIR...)` builds `bin/release-server` and serves the dist folders on `127.0.0.1` as GitHub's release listing, release by tag, and asset download, one release `flai/vX.Y.Z` per version, newest first. Prints the base URL; logs each request to stderr; stops within a second of the `--owner` process exiting |
| `flai-test.sh` | `shellcheck.sh`, gofmt, vet, golangci-lint v2, then `flaiover-unit.sh`, `integration.sh`, and `smoke.sh`: not `test.sh`, whose short Go tests the full run holds, so each Go test runs once |
| `flai-snapshot.sh` | GoReleaser snapshot build of every target into `flai/dist`, unsigned. `--local X.Y.Z [--dist DIR]` builds this host's target only, unsigned, with the plain version X.Y.Z, as `flai_X.Y.Z_<os>_<arch>.tar.gz` and `checksums.txt`, into DIR (relative to `flai/`) or `flai/dist`, for `release-server.sh` |
| `check.sh` | `flai check --strict` on this repository; with `CLOSE_OUT_STORY` set, as `flai verify` sets it for the tiers it runs (smoke runs this), scoped to the story with `--story` and `--record-issues`, so findings outside it are notes recorded in issues; else with `MERGE_QUEUE_STORIES` set, as the merge queue's batch and bisection set it to the stories they verify, comma-separated, scoped to them with `--story` alone, so a finding outside every one is a note and none is recorded (I-0174) |
| `close-out.sh` | Before a story goes to review, in its worktree, on its branch: `flai verify <story> --record-issues` through `flai.sh`, which runs every check (no rebase left unfinished, the branch contains the main branch, the narrative's `## Current state` and `## Next steps`, `flai check --strict` scoped to the story, then the tiers the branch's changes select), so the close-out and `flai verify` never disagree; then the commit with the `git commit` options given, which also commits the issues `--record-issues` recorded, the check with `flai verify <story> --sync-only` that the branch still contains the main branch, which passes over commits on it that change only `wip/` paths the branch does not change, and the clean worktree check. It stops at the first step that fails, and every run ends with one line naming the story, the outcome, and the step it stopped at, so nobody runs it again to learn why it stopped |
| `lint-md.sh` | markdownlint-cli2 over every markdown file, with the CI globs and `.markdownlint.yaml`; given files relative to the root, over just those, as `flai test`'s markdown tier does. With no files and `CLOSE_OUT_STORY` set, as `flai verify` sets it for the tiers it runs (smoke runs this), it leaves out `wip/`, which the branch holds as the main branch last committed it, and lints instead the markdown under `wip/` that the story changes against the main branch, so a line another agent commits to main's `wip/` fails no story (S-0345, I-0117); with `MERGE_QUEUE_STORIES` set instead, as the merge queue's batch sets it, the same for what the batch changes, so such a line fails no batch either (I-0174) |
| `shellcheck.sh` | ShellCheck, the pinned one `install-tools.sh` puts in `bin/`, over every `scripts/*.sh`; given files relative to the root, over just those, as `flai test`'s shellcheck tier names them. It follows what each script sources from beside it (`-x -P SCRIPTDIR`), such as `env.sh`, and prints findings by file and line. A finding the code is right to have is disabled on its line by a `# shellcheck disable=` directive with the reason beside it, never file-wide. `make shellcheck` |
| `mdlint-fixtures.sh` | Regenerates `flai/internal/mdlint/testdata/cases/expected.txt` with markdownlint-cli2, the reference flai's own markdown lint is tested against |
| `template-test.sh` | Renders `template/` into a temp dir and checks the result |
| `install-tools.sh` | Installs golangci-lint v2, GoReleaser, and ShellCheck (a pinned release, checked against its pinned sha256) into `bin/`, pnpm into `.flai-cache/pnpm` |
| `flaiover-install.sh` | `pnpm install --frozen-lockfile` in `flaiover/`. With `--if-needed`, only when `flaiover/node_modules` is missing or older than `pnpm-lock.yaml`, as in a story worktree, which `git worktree add` makes without it; it says so, and pnpm's output goes, on stderr. An install linked from another store, such as a bare `pnpm add` makes from the default store, is removed and made again from `env.sh`'s store rather than aborting with `ERR_PNPM_ABORTED_REMOVE_MODULES_DIR_NO_TTY` (I-0177) |
| `flaiover-pnpm.sh` | The pinned pnpm in `flaiover/` with `env.sh`'s store and caches: add a dependency with `scripts/flaiover-pnpm.sh add <package>`, never a bare `pnpm add`, which uses the default store and may be the host's other pnpm |
| `flaiover-install-test.sh` | Reproduces I-0177 in a scratch copy, with local packages and no network: an install from another store, then `flaiover-install.sh --if-needed` with no TTY, which must pass and leave the install on `env.sh`'s store |
| `flaiover-dev.sh` | Dev server against this repository (`PROJECT_DIR` defaults to the root) |
| `flaiover-digests.sh` | `<image> <version> <index-digest>`: prints the flaiover release's digest list (`design/system/release-signing.md`, "The digest list") from the index in the registry, with `docker buildx imagetools` and `jq`; `release-flaiover.yml` signs and publishes it on a `flaiover/v*` tag |
| `flaiover-build.sh` | Production build (adapter-node) |
| `flaiover-test.sh` | `flaiover-install-test.sh`, `flaiover-install.sh --if-needed`, then prettier, eslint, svelte-check, vitest |
| `flaiover-e2e.sh` | flaiover's end-to-end tests (`make flaiover-e2e`): `flaiover-install.sh --if-needed`, Playwright's Chromium when missing, the build, then `playwright test` against `node server.js` on 127.0.0.1:4173 (`FLAIOVER_E2E_PORT` picks another), with arguments passed on |
| `flaiover-image.sh` | Builds the flaiover image locally as `flaiover:local` from the repo root |
| `litellm.sh` | `up`, `down [--purge]`, `status`, `key [--rotate]`, `logs`: a local LiteLLM proxy in Docker with Postgres behind it, for the gateway tests and a `litellm` provider entry (E-0019). `up` needs `ANTHROPIC_API_KEY` the first time, binds the proxy to `127.0.0.1:4000` (`LITELLM_PORT`), issues a virtual key with a budget (`LITELLM_MAX_BUDGET`, 5 USD per 30 days), and writes the key file `.flai-cache/litellm/litellm.env` (`LITELLM_BASE_URL`, `LITELLM_API_KEY`, `FLAI_TEST_LITELLM_HAIKU`: `LITELLM_HAIKU_MODEL` when set, else the script's free default, recorded in `admin.env` only when set and dropped from it when it is a retired default), which `env.sh` sources, so every script, `flai.sh serve`, and the agents it starts have them; the master key stays in `admin.env` beside it, read by the script alone. `make litellm`, `make litellm-stop`, `make litellm-status` |
