# S-0118 When viewing a story's page with an agent pane, if the agent has failed, a retry button should appear

## Context

The story page's agent pane (`flaiover/src/lib/components/StoryAgent.svelte`) already has a Restart agent button, added in S-0116. It shows when the agent has failed and the story is in ready or in progress. It posts `{action:'restart'}` to `/api/items/<id>/agent`, which calls `agent.restart` on the host flai and then `serve.Restart` in `flai/internal/serve/restart.go`. For a ready story, `serve.Restart` refuses when the in-progress limit is full. This story renames the button to Retry, moves it to the top right of the pane, and hides it once clicked. TH-0011 asks whether a retry on a ready story with the limit full should be queued.

## Decisions
- A retry on a ready story with the in-progress limit full is queued, not refused, and a queued agent shows a yellow dot. The operator decided this on TH-0011, and it is recorded in ADR-0044, which refines ADR-0043.
- A queued mark counts only while its story is in ready. For a story in progress, a retry starts at once. A second retry while one is queued is refused. Reason: once the story leaves ready, the launcher would never start the queued agent.
- Retry keeps the testid pattern `story-agent-retry` and posts the existing `restart` action. Reason: flai's `agent.restart` already does what the button needs, so no new host method is needed.
- Retry stays hidden from the moment it is pressed until the state shows a newer run. Reason: this meets criterion 4. The button comes back only when flai refuses, so the operator can try again once the reason is fixed.
- Each task is committed when it is done, not only at review. Reason: the operator's start prompt asks for it, and it overrides `git.md`, which commits when a story lands.
