## Decisions

- The planner's plan stands: T-1402 (the test) alone in layer 1; T-1403 (smoke step, contributor guide) and T-1404 (live run, design and operator docs) in layer 2, both after T-1402 because one runs its test and the other records its run; they share no path.
- `/spend/logs` answers 401 to a virtual key: only the proxy's master key reads it. The test reads the key's own spend from `/key/info` with the virtual key before and after each run, and reads `/spend/logs` (filtered to the key's SHA-256) only when `LITELLM_MASTER_KEY` is set, logging why it did not otherwise. The agent's environment never gets the master key; the recorded run sets it for that one command from `.flai-cache/litellm/admin.env`.
- TH-0429 (operator, 2026-10-13): no spend on Anthropic. The check runs free through the unified route to an OpenRouter free model, and the `/anthropic` pass-through is opt-in (`FLAI_TEST_LITELLM_PASSTHROUGH=1`). Criteria 1 and 4 were reworded to match, and T-1526 was added before T-1404 for the proxy and test changes.
- Through LiteLLM's `openrouter/` provider (translated to chat completions), Claude Code stalled in 4 of 4 runs on its ~50k-token requests, while the same model passed through OpenRouter's Anthropic API directly. So the script's default deployment is `openrouter-messages/*`: `anthropic/*` with `api_base` OpenRouter's Anthropic API. `openrouter/*` is kept, documented as the route that stalls.
- The check's prompt asks for the sub-agent in the foreground (`run_in_background false`), after one free model launched it in the background and `claude -p` waited out its 5 minutes. This also changes the OpenRouter check's prompt; it makes no difference to a model that already ran it in the foreground.
- MS-0092: S-0238 shared `docs/operators/index.md`; S-0356 adds only the LiteLLM provider entry and leaves § The connection from flai on the host and § The image flai dials alone.
