## Decisions

- Plan: layer 1 T-2876 (request files, Ask/Await, record asked_by, kluster event in inbox), T-2879 (kluster.agent_namespaces), T-2882 (guard), which share no path and wait for nothing; layer 2 T-2884 (serve takes requests) after T-2876 and T-2879, whose files and limit it reads, and T-2887 (CLI --job, MCP tools, wait_for_events end) after T-2876, whose Ask it calls; they share no path so run together; layer 3 T-2889 docs after all, describing what they built.
- Followed ADR-0292 over the planner's wording, as the story's Notes ask: the request is flai kluster deploy|teardown S-nnnn --job and the MCP tools kluster_deploy and kluster_teardown, not a new subcommand; the key is kluster.agent_namespaces, default 2, 0 allowed (turns deploys before review off).
- Criterion 2 says the request waits for the job and answers its outcome; ADR-0292 §5 says it answers the job id at once and the agent waits for a kluster event. Both are met: the request answers at once, and --wait (CLI) or wait_seconds (MCP, at most 45) waits for the outcome, saying a job still queued or running and how to read it later when it outlasts the wait.
- The kluster event (ADR-0292 §5) and wait_for_events not ending while a kluster job runs are built here, as the way the agent waits; they were missing from the planner's tasks and go in T-2876 and T-2887.
- TH-1138, operator confirmed the orchestrator's recommendation: S-0660 keeps to its nine criteria; S-0763 (backlog, E-0035, after S-0660) builds the namespace's kubeconfig, flai kluster exec, and log; flai kluster env stays S-0661's, and S-0661 gained S-0763 in after.
- T-2882: --wait added to the guard's flaiValues so flai --wait 5m kluster deploy is read as the deploy flai runs; the general gap for other value flags is I-0358.
- T-2884: a deploy request for a story in review with no job and no passing record at its head is refused, since flai serve's review pass deploys it; an asked job that meets the lock held by a shell or the dashboard ends refused; the limit counts a story in progress whose asked deploy is queued without a record yet, so it cannot be passed between a request and its deploy.
- T-2887: the CLI and the tools wait (--wait, wait_seconds) only on a job whose state file is kept (kluster.HasAskedJob), since a review deploy flai serve queued itself keeps none; wait_seconds over 45 is refused, not capped.
