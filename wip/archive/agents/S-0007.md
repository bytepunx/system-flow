# S-0007 Work item and narrative commands

## Context
Every work item and narrative in this repo has been hand-written so far. This story makes flai the writer: epic/story/task creation from the template's item bodies, validated transitions, blocking, the board, narratives, index maintenance, and archiving. Rules come from design/system/work-hierarchy.md and workflow.md; the existing items in wip/ and wip/archive are the fixture the parser must round-trip. S-0005 left internal/template (cache, render), internal/manifest, and internal/execx. S-0005 itself sits in review, so this story must not disturb it.

## Current state
All seven tasks done and the story is in review; every transition from T-0017 onwards was made with flai itself. flai/internal/workitem holds the parser, purpose-built front matter writer, repo scan and ID allocation, transition rules, board.md handling, item creation from embedded or template item bodies, narratives with index regeneration, and archive planning. Commands: epic/story/task new, show, move, block, unblock, board, stream open/log, archive. ## Decisions
- Front matter is parsed with goccy/go-yaml but written by a hand-rolled emitter for the fixed schema, so hand-written files round-trip byte for byte and flai never churns unrelated lines. goccy would quote every timestamp.
- Tasks may go from in-progress straight to done; review is story-level human acceptance. Living design updated in work-hierarchy.md and workflow.md; ADR-0004 is refined, not reversed.
- Titles containing ": " are double-quoted in YAML. Item templates now use `{{ .title | quote }}`; the round-trip test caught T-0017 violating this.
- Item bodies come from the project's template items/ when that template is already in the cache, else from copies embedded in the binary. No fetching during item creation.
- wip/agents/index.md is regenerated from the narrative files on every change rather than edited in place.
- Moving a story to ready appends it to the board's pull order; leaving ready removes it.
- `--reason` text is appended under the item's ## Notes so the history is readable without the transitions list.
