It takes `flai/cmd/plan.go` too, added to its touches: S-0218 put the orchestrator's plan gate (`orchestratorPlans`, `mcpPlan`) there, and it must allow exactly the epics `flai plan --candidates` lists, not only backlog ones.
- **Hand placements (T-0884, ADR-0088).** The record is a `placed` map in `board.md`'s front matter; the placer flag is `--placed-by`, since `--by` is the policy; the orchestrator is recognised by its name `orchestrator`, and with `FLAI_ROLE=orchestrate` its placements are always recorded as its own. `--apply` records nothing. Any column change drops the record, ready to backlog included. The dashboard's drag records `flaiover`, not the operator's name: still by hand, which is all the window needs; passing the operator's name from `hostapi/writes.go` is outside this story's touches.
- **T-0896's shared promote check lives in `workitem/promotable.go`.** `flai move` and the MCP `item_move` both call `(*Repo).Promotable`, rather than one copy each; added to the task's and story's touches with `mcpserver/folder.go` (the tool descriptions name the orchestrator's exceptions) and `cmd/plan_test.go` (S-0218's test of planning any backlog epic gave way to `plan_orchestrate_test.go`, since an epic with a backlog story is no longer a candidate). - **T-0904 started before T-0899 is done.** T-0899 waits only on the operator's paste of the two `.claude/agents/orchestrator.md` files (TH-0161); its prompt and convention, which T-0904 describes, are committed, and the paste changes no path T-0904 touches.
