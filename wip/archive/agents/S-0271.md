## Decisions

- The planner's tasks are kept as drafted. Layers: (1) T-1054, the shared writer every other task calls; (2) T-1055 command, T-1056 MCP tool, T-1059 check rule, each waiting on T-1054's function and parser, no path in common; (3) T-1058 host method, which runs the command and so waits on T-1055, and T-1061 conventions and harness prompt, which name the command and the tool and so wait on T-1055 and T-1056; (4) T-1063 design and docs, which describe all of them and regenerate the reference from the built command.
- Layer 2 and 3 tasks are short, so they run one at a time rather than at once.
- `narrative.state` (T-1059) is advisory, a warning `--strict` passes over: every story's narrative is unwritten between `flai stream open` and its first state write, and failing `--strict` would stop `flai task done` and main's check in that window; the close-out's narrative step (`flai/internal/verify/story.go`) still gates review. It uses the same written test as verify's `Unwritten`; making verify call `workitem.Section.Written` is left out, as `verify` is not in this story's touches.
- T-1056 needed `stream_state` added to the expected tool lists in `flai/internal/mcpserver/server_test.go` and `folder_test.go`; made by the story's agent, touches widened.
- Layer 3 (T-1058, T-1061) runs at once: neither builds the other's package, and no path is shared.
- No guard change: `flai guard` allows sub-agents an allowlist of reads (`cliReads`, `MCPReads` in `flai/internal/guard/guard.go`), so `flai stream state` and `stream_state` are refused to them as writes already.
