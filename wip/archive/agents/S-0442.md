## Decisions

- Started on a share (MS-0132, ADR-0134): on the Components page S-0442 adds only the source picker, the frame URL per source, and the story's dev server; S-0441 keeps the tried-tokens flow, its notice, and its tests. In `docs/users/flaiover.md`, `design/system/flaiover-dashboard.md`, and `design/system/component-library.md` S-0442 writes one subsection of its own on sources. Replied settled.
- Plan reviewed and changed: the helper that finds the components a branch changes, `flaiover/src/lib/explorer/changed.ts` with its test, moved from T-1882 to T-1881, since the picker marks and lists them first and the review link reuses it. T-1882 now waits for T-1881 and also touches `flaiover/src/lib/components/Review.svelte`, which the review route only wraps.
- Layers: 1 is T-1879 (flai/internal/components) and T-1881 (dashboard picker), with no path in common and talking only over the host methods' JSON; 2 is T-1880 (after T-1879: it calls the worktree start) and T-1882 (after T-1881: it reuses `changed.ts`); 3 is T-1883 (docs, after all four, to describe what they built).
- The contract fixed between the layers: `components.list`, `components.status`, `components.start`, and `components.stop` take an optional `story`; with one, the catalogue is read from its worktree and the dev servers are that story's, each answered with `story` set. The dashboard passes it as `?story=S-nnnn` on `GET /api/components` and as `story` in the bodies of `POST /api/components/start` and `/stop`, and keeps the source in the page's URL as `?story=`.
- T-1879: the install is a separate `components.ServeWorktree`, since `serve.go` was outside its touches. The main checkout is never installed into. The install timeout is ten minutes.
- T-1880: all four methods refuse a story that is not in progress or in review, which is stricter than `design.get`, since the review rule would stop its server anyway. The stop on leaving review polls the story's transitions every five seconds from the supervisor, rather than hooking `serve.go`'s watcher. Touches widened to `flai/internal/config/config.go` (the `MaxServers` field) and `flai/cmd/serve_actions_test.go`.
- T-1881: the picker's stories come from `GET /api/board`, since the Design page lists only proposals. The changed components are a branch's committed changes, from `stream.diff`. Touches widened to `ComponentList.svelte`, so the catalogue list marks them as well as the picker.
- T-1882: the review page reads the worktree's catalogue, so a component the branch adds counts, and names the changed components beside the link. Touches widened to `Review.svelte` and its test.
- T-1883: touches widened to `design/system/dashboard-host-channel.md` (the methods' `story` param) and `docs/users/flai.md` (`flai components serve --story`), per documentation.md's rule for a changed command.
- Sync after S-0441's acceptance stopped on the Components page, its test, and `docs/users/flaiover.md`. Resolved by keeping both stories' lines, as MS-0132 agreed.
- The MCP `task_done` refused every close (host flai 1.52.0, project at 1.55.1; I-0157 bumped), so each task was closed with the worktree's `scripts/flai.sh task done`.
