# S-0096 Flai serve should start a flai mcp in the background as a child process

## Context

`flai mcp http` (S-0076, ADR-0030) already served MCP over HTTP, one process per project, with its token, address, state, and log in the project's `.flai-cache`, but only when started by hand with `flai mcp start`, and ADR-0030 said it "is not part of `flai serve`". The operator asked that it run whenever `flai serve` runs and stop when it stops.

## Current state

Done; all three tasks and both criteria.

- T-0344: `internal/serve/mcp.go`'s `superviseMCP` runs per served project. It starts `flai mcp http --exit-with <serve pid>` through `cmd`'s `serveMCP` unless one already runs for the project (then it is used and never stopped), looks again every 15 s, starts its own again if it stopped, and stops its own when the project is dropped or `flai serve` stops. `--exit-with` makes the child go by itself when `flai serve` is killed. A project with no remembered address takes the first free port from 4243, one start at a time.
- T-0345: [ADR-0034](../../design/adrs/0034-flai-serve-keeps-each-served-project-s-http-mcp-server-running.md) refines ADR-0030. `flai serve status` names each project's running server. The design, operator, and user docs are updated.
- T-0346: tried with a real `flai serve` built from this branch, under a scratch configuration, serving three scratch projects with no dashboard running.
  - It started three servers on 4243, 4244, and 4245, each its child with `--exit-with`.
  - Beta's server answered an MCP `initialize` (headers `X-Flai-Project-Key: beta`) and an `inbox` call listing Beta's ready story; without the token it answered 401.
  - `flai mcp stop` on Gamma's server was undone 7 s later, on the same port.
  - `flai serve stop` stopped all three, and their ports were free.
  - A `flai serve` killed with SIGKILL left its three children to exit by themselves, 2 s later.

## Next steps
None: in review. When this ships, the operator's own `flai serve` will start an HTTP MCP server for every project registered with it on its next start (this repository included), on 4243 and up, unless one already runs there.

## Decisions
- ADR-0034 `--refines` ADR-0030 rather than `--supersedes` it: only one clause is reversed ("not part of `flai serve`"), and `--supersedes` would mark all of ADR-0030 superseded, though its transport, token, per-project process, and stdio decisions all stand. The new ADR says in its first line which clause it reverses.
- A child process per project, reusing `flai mcp http` whole, rather than one listener inside `flai serve` for every project: the story asks for a child process, and the per-project server, its token, state, and `flai mcp status` already exist and work.
- `--exit-with <pid>`, looked at every 2 s, rather than Linux's parent-death signal: it works on every platform flai builds for, and needs no change to how children are detached (`Setsid`).
- A server someone started by hand is used and never stopped by `flai serve`; `flai mcp stop` on one `flai serve` keeps lasts only until the next look. Both are said in the operator docs.
