## Decisions

- Kept the planner's four layers: (1) T-1067 and T-1068, no `after`, no shared path; (2) T-1069 and T-1070, after both of layer 1, which they join; (3) T-1073, after T-1069, whose `flai test --json` it runs; (4) T-1079, after all, which it describes, and sharing `template/CHANGELOG.md` with T-1067.

- Tier contract, shared by the manifest key and the verify package: `name`, `command` (argv with placeholders `{packages}` and `{files}`), `dir` (where it runs, relative to the checkout root; the placeholders are made relative to it), `paths` (`**` globs relative to the root, `!`-prefixed ones excluding), `format` (`go-test-json`, `vitest-json`, `golangci-json`, `gofmt-list`, `plain`), `all_only`, and `all_command` (argv used under `--all`; without it `{packages}` becomes `./...` and `{files}` `.`). `dir` and `all_command` were not in the planner's draft: Go tiers run in `flai/` and vitest in `flaiover/`, and vitest needs `related` for a path but `run` for everything.
- Findings are parsed only from a failing tier; a parse that finds nothing falls back to the `plain` tail. So a tier that skips itself (vitest without `node_modules`) passes.
- This repository's tier commands go through a new `scripts/with-env.sh`, which sources `env.sh` and runs its arguments, so `golangci-lint` and the npm cache resolve as the scripts resolve them; `scripts/flaiover-unit.sh` passes its arguments through to vitest. Both added to the story's and T-1069's touches.
- The manifest-to-verify mapping and one `verify` entry point that the CLI and MCP share are written by me between layers, so T-1069 and T-1070 never duplicate them.
- T-1067's sub-agent left `flai check` unwired (outside its touches); I added `manifest.tests` to `check.go` with a test, bumped `template/template.yaml` to 1.0.65 for its changelog entry, and regenerated `flai-reference.md`; touches widened to match.
- `flai guard` allows `flai test` and the MCP tool `test` for sub-agents (`guard.go`, outside the planner's touches, added to T-1069's): running tiers writes nothing flai owns, and a task sub-agent or verifier would otherwise be refused the command this story makes for test runs.
- The markdown tier calls `scripts/lint-md.sh` with the files, so the pinned markdownlint version stays in one place; `lint-md.sh` added to the touches.
- T-1069 (sub-agent): `flai test` exits 0 pass, 1 a failing tier, 2 when it cannot answer (usage, manifest, git, a stopped run). The golangci-lint tier passes `--allow-parallel-runners`, since parallel story agents otherwise fail it at once, and `--show-stats=false`. Its CLI tests need real git and go, so they skip under `-short`.
- T-1070 (sub-agent): the MCP tool also takes a task ID whose own worktree exists; `max` 0 is the default, a negative one refused.
- T-1073 (sub-agent): `test.run` answers `Written{data: flai test's result}` like every write, exit 1 with JSON is an answer, exit 2 an error. The dashboard's `REQUIRED_METHODS` in `flaiover/src/lib/server/agent.ts` lists it, which the contract test needs (touches widened).
- TH-0230 (flai): S-0228 and this story conflicted in `writes_test.go`, where S-0228 realigns the `refused` table; I moved `test.run`'s refusals beside `item.criteria`, away from it, and the trial merge is now clean.
