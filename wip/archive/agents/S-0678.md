## Decisions

- Plan kept as the planner drafted it. Layer 1 is T-3004 (phases in serve.Activity and Host.Agent) and T-3008 (the trial judge keeps verdicts across calls). They share no path and wait for no task, so they run together. Layer 2 is T-3013, which waits for both: it measures the fix T-3008 makes, using the phases T-3004 adds.
- T-3008 runs in its own worktree from story/S-0678 (task/T-3008). flai/internal/serve imports storygit, so T-3004's tests build the package T-3008 is editing (delegation.md, Tasks worked by sub-agents). Its two files are copied back into the story worktree before its close.
- T-3004 also records activity.conversations, around readConversations. Without it, part of agent.activity fell outside every phase.
- T-3008 reads the branch heads once per judge call, not once per judge. The MCP server keeps one judge for its whole session, so heads read once per judge would go stale, and an existing test expects the same judge to see a new commit. Kept merges are bounded by count, 256 per root, least recently asked dropped, rather than by the judges made since a merge was asked for. Git's version is remembered per comparable runner, so tests with fake gits stay independent of each other.
- T-3013 closed I-0313. At loads of 4 to 13, every call answered under 200 ms after the fix, and the slowest took 87 to 125 ms. What is left is about 90 ms of CPU and 8 to 10 for-each-ref calls per agent.status. Reading the heads once per Activity call would save about 20 to 30 ms more; this is noted, not required. The run could not be repeated at I-0313's load of about 100.
