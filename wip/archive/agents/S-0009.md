# S-0009 flai dashboard

## Context
flai dashboard runs the flaiover image against the current project (brief item 5). The image does not exist yet (E-0003, S-0015), so this story builds the runner and proves it with a stand-in image; the real image plugs in through config. Design: design/system/flai-cli.md, flaiover-dashboard.md runtime section, design/tech/docker.md. Docker is invoked through execx.Runner (ADR-0010) so tests use a recording fake. The container binds to localhost only; the repository is mounted read-write at /project with the host UID so written files keep sane ownership.

## Current state
All three tasks done, story in review. cmd/dashboard.go runs the image detached as flaiover-<project> on 127.0.0.1:<port>, mounts the repo read-write at /project, passes --user uid:gid, pulls when missing or --pull, and offers status, logs, stop, --attach, --open; precedence is flags, manifest dashboard section, config. Tests use a recording fake runner (missing docker, pull, run arguments, precedence, already running, status from inspect, logs, stop). A real smoke with a python http.server stand-in image proved the plumbing against this repository, including that files written from the container keep the host user's ownership. Docs for users and operators, design, tech, and S-0015 updated. Lint and all tiers green. Committed at review and pushed.

## Next steps
1. Operator approves; `flai accept S-0009 --by alex --trailer ...` is expected to tag flai/v0.9.0 and close E-0002's last story; the operator may then accept E-0002, a major release (flai 1.0.0).
2. E-0003 begins with S-0011 (SvelteKit scaffold and repo reader API). The image built in S-0015 must run as an arbitrary UID on port 3000.

## Decisions
- Detached by default with the URL printed; --attach streams logs; there is no foreground mode because agents drive the command.
- Status and the already-running message read the container's real image and port with docker inspect, never the configuration.
- Bound to 127.0.0.1 only; exposing further is the operator's explicit action and the operator docs say not to.
- The image must run as the host user; this is a hard requirement on S-0015, not a nice-to-have.
