- Overlap rule narrowed from TH-1217's package import closure, counted both ways, to direct imports read per file, counted both ways. Criterion 2 says only what main brings in that 'undoubtedly' impacts the story, and the operator's criterion takes precedence over the orchestrator's recommendation. Data from the six stories in review: each changes a package that imports flai/internal/workitem, and flai/cmd imports nearly every internal package. So a package-level closure, even one step deep, would still send almost every flai story back on any flai acceptance. Per-file imports still block the I-0229 case: S-0416 changed flai/internal/guard/roles.go, which imports flai/internal/roles. They also block the orchestrator's caller case: a main file that calls a function the story renames must import the story's package. A main path overlaps the story's change set (its last verify's Paths) when: it is one of those paths; it is in the same Go package directory as one of them; a Go file main changed imports the package of one of them; or a Go file the story changed imports the package main's path is in. A non-Go file under a Go package, such as an embedded or testdata file, belongs to the nearest enclosing directory holding Go files. Other languages overlap by file only.
- Shared paths: T-3378 and T-3379 change flai/internal/preview/accept.go and flai/cmd/accept.go. S-0744 (in review) changes flai/internal/preview and flai/cmd too; the trial merge decides whether that conflicts.
