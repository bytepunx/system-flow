# S-0126 Threads don’t correctly render markdown

## Context

Thread entries showed as raw markdown on every page with threads: `flaiover/src/lib/components/Threads.svelte`, the one component that lists entries (item, review, document, and editor pages), printed `e.text` in a pre-wrapped paragraph.

## Current state

T-0459 done and committed on `story/S-0126` (ce3017e): entries render through `render` from `$lib/markdown` in a `prose prose-sm` block. `Threads.svelte.test.ts` mounts the component with a list, bold, inline code, and a link, and fails against the old paragraph. `scripts/flaiover-test.sh` passes: lint, svelte-check (0 errors, the existing `NewItemForm.svelte` warning), 69 files and 491 unit tests. `design/system/flaiover-dashboard.md` and `docs/users/flaiover.md` say entries render as markdown. Not viewed in a running dashboard; the test renders the real markdown module in jsdom. The story is in review.

## Next steps

1. Operator reviews and accepts S-0126.

## Decisions

- Entries use the explorer's renderer (`$lib/markdown` `render`, `html: true`), as the item body and documents do, so an entry reads as it does in its thread file. Thread text is repository markdown written by agents and the designer, the same trust as the documents already rendered this way.
- Relative links in an entry resolve from the repository root, not from `wip/threads/`: authors write repository paths.
- No line-break conversion: single newlines join as in any markdown document, matching how the thread file renders in the explorer.
