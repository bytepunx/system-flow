# S-021 flai template push publishes template changes to a remote

## Context
S-003 published the template once by hand with a subtree split. This story makes publishing a command and ties it to acceptance: flai template push clones the template's remote branch, replaces its contents with the local template, commits with the version, pushes, and tags; flai accept calls it for a template component after bumping the version, so a template release is one acceptance step. The convention: assume permission, surface git errors verbatim, never retry, never force without --force.

## Current state
All three tasks done, story in review. flai/internal/publish runs the clone-replace-commit-tag-push cycle in a working clone under the cache; flai template push exposes it with --dry-run, --tag, --force, --remote, --ref, --json and defaults from template.yaml publish; flai accept calls it with --tag for template components (opt out with --no-publish or --no-push) and reports a publish failure without undoing the acceptance. Tests on a bare remote cover the lifecycle including refused tags, branch creation, an external commit, and a missing remote. A dry run against the real remote shows only template.yaml changed (the publish section). Docs: user push section, contributors sync procedure now the command, template.md, flai-cli.md. Lint and all tiers green. Committed at review and pushed.

## Decisions
- Clone-and-replace rather than subtree for ongoing pushes: works for any local template directory, not only a subdirectory of a git repository; the remote's history was seeded once by subtree in S-003 and continues linearly.
- Commits in the working clone use a fixed flai identity so the push works on hosts without a global git identity; the message names the version and the source path.
- An existing tag is refused rather than moved; bumping the version in template.yaml is the fix, --force the escape hatch.
- Accept treats a publish failure as reportable, not reversible: the local acceptance stands and the operator reruns flai template push.

- Lint must gate the commit on its own exit code; piping the test script through grep and tail hid a failure once. Run it plainly or with pipefail.
