# S-0198 Give the operator the option to have all issues turned into stories

## Context

## Decisions

- The plan is a chain, one task per layer: T-0730 → T-0731 → T-0732 → T-0733 → T-0734 → T-0735. T-0731 calls T-0730's functions. T-0731 to T-0734 each change `design/system/flai-cli.md` or `docs/users/flai.md` with their own docs, as the documentation convention asks, so each waits for the one before. T-0735 describes everything built before it. No layer has two tasks, so none runs in parallel.
- An instance records its story as a `Story: S-nnnn.` line under its heading. It is readable and parses back without changing the heading, which the same-second join depends on.
- A story links an issue when its body names the issue's ID or its document's file name. Today's remediation stories already name issues that way.
- The nature comes from the class: `defect` and `blocker` give `remediation`; `efficiency` and `impression` give `improvement`. The recommended solution is the issue's `## Remediation` text, since flai cannot write one. Both choices were put to the designer on TH-0074.
- Designer, TH-0074, 2026-10-03T01:46:03Z: the review page lists every open issue the story recorded or bumped first, checked, then every other open issue with no story, unchecked. With any checked, Accept reads `Accept and Create Stories` and does both: the stories are made only once the accept succeeds, and not at all when it fails. The check takes the recommendation: `issues.story_after`, default `168h`, `0` turns it off, rule `issues.no-story`, a warning. A backlog story is made for I-0007 so that `flai check` passes here.
- `flai issue story` writes nothing to the issue; the new story's body is the link. Issues live under the checkout's root, so a story's own issues are committed on its branch, while wip lives in the main checkout. Writing the issue file would leave an uncommitted change outside wip, which acceptance refuses. `issues.SetRemediation` was dropped for this reason. The design's "the story ID once one exists" is answered by `flai issue list --json`'s `story`.
- `--story` on `issue list` and `issue story` reads the issues from the story's worktree when it has one, so a story in review can show and remediate the issues it recorded before they reach main.
- T-0735 says the story's agent makes no story for its issues, so the review page's checked rows can appear: the operator chooses at acceptance. The agent runs `flai issue story` only when asked, or for an issue `flai check` warns about. The designer confirmed it on TH-0075 at 2026-10-03T02:12:01Z: take the recommended approach. T-0735 was done without a sub-agent, being shorter to do than to brief.
- `design/system/conventions.md` and `docs/users/conventions.md` still said the summary is reported at epic completion, so T-0735 corrected them and gained them as touches.
- The story's touches now include the dashboard, the manifest, hostapi, and the docs, which the criteria need. They overlap S-0242's T-0729 on `design/system/flai-cli.md`, `docs/users/flai.md`, and `docs/users/flai-reference.md`. Conflicts there are resolved at sync.
