## Decisions

- One commit per task, as the operator's start instruction asks, instead of `git.md`'s one commit when the story lands. The operator's instruction takes precedence.
- The platform comes from the Docker daemon (`docker version`), not flai's GOOS/GOARCH: an amd64 flai under Rosetta drives an arm64 daemon.
- The build stage runs on `$BUILDPLATFORM` instead of emulating the whole build. Production dependencies are plain JavaScript, and running the amd64 image confirmed it.
- QEMU on the amd64 runner, not a native arm64 runner matrix: one job, one `build-push-action` call, and only `apk add tini` runs emulated.
- The PR check workflow (`flaiover.yml`) builds no image today and still does not. The arm64 build runs where the image is built, in `release-flaiover.yml` on every push to main and on tags.
