# S-012 Documentation explorer and search

## Context
S-011 gave flaiover the repository reader and the API. This story adds the documentation explorer (every markdown file rendered from a tree, Mermaid diagrams, code highlighting, a front matter panel), the ADR list with its supersession chain, and search across design and wip with snippets. Design: flaiover-dashboard.md views and search sections, design/tech/markdown.md and search.md (markdown-it, shiki, mermaid, MiniSearch). Rendering happens in the browser from raw markdown served by /api/docs/file; the search index lives in the server process and is rebuilt on watcher events.

## Decisions
- Rendering stays in the browser (design decision kept): the server serves raw markdown and the SPA renders, so the API is a file reader and the bundle carries markdown-it; mermaid and shiki load only when a document needs them.
- The index is one MiniSearch instance per server process, rebuilt debounced 300 ms after any change; a query before the first build triggers it.
- Narratives are documents, not items (they carry stream, not id), so they route to the explorer; the item itself routes to /items/<id>.
- Links use SvelteKit's resolve() with the catch-all route so the svelte lint rule holds; relative links inside rendered markdown are rewritten to /docs/<path> by the renderer, not by resolve.
