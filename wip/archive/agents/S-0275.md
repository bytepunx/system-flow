Layer 2: T-1077 (CLI `--commit`) and T-1083 (MCP tools), both after layer 1 because they call its helper and its paths; they share no path. Layer 4: T-1105 (design and user guide) after T-1077, T-1083, and T-1093.
- T-1072 extracts the touch-widening `flai task done` already has (S-0269, `taskdone.run.widen`) into `itemedit` and has `taskdone` call it, rather than writing a second copy; its touches gain `flai/internal/taskdone/taskdone.go` and its test.
- `--commit` commits as `docs: [S-nnnn] record|bump|close I-nnnn <title>` or `docs: [S-nnnn] ADR-nnnn <title>`: issue and ADR files are design records, and `git.md` gives docs-only changes no release bump.
- `--commit` checks the branch before writing, so a refused call writes nothing; it commits only the paths written (`git commit -- <paths>`), leaving other work in the worktree as it was.
- `Issue.Changed` reports the file the last write wrote, recorded in `Save`, rather than new return values: about 60 call sites keep compiling, and `summary.md` stays the caller's (`SummaryPath`).
- The MCP tools `issue_close` and `adr_new` write in the recording story's worktree when it has one, as `issue_new` and `issue_bump` do, with or without `commit`.
- The host channel's `issue.new`, `issue.bump`, and `issue.close` commit in the main checkout with `--autocommit` and widen no story's touches, as the planner assumed: the dashboard has no worktree. The dashboard's `REQUIRED_METHODS` lists them (outside T-1093's touches; added by the story's agent). No dashboard page calls them yet, so the routes list in `design/system/flaiover-dashboard.md` is left as it is.
- The template's `design/adrs/README.md` names `--commit`; this project's own ADR index is left alone, since it is not a baseline copy and other stories edit it.
