# S-0206 Planner, orchestrator, and analyzer runs are logged in an activity document, with cost, seconds, and work completed in its front matter

## Context

The planner, orchestrator, and analyzer (E-0016) have no story and so no narrative. This story gives each an activity document in `wip/agents/<kind>.md`: front matter totals (`kind`, `accrued_cost`, `accrued_seconds`, `tasks_completed`, `last_run`) and a `## Log` flai writes per activity, measured from the run's stream-json log as story runs are (ADR-0051). Nothing starts a strategic run yet (S-0208 does the planner), so serve gets the functions S-0208 and S-0218 call when an activity or a run ends, and the MCP tool `activity_log` lets a long-running agent report each activity. S-0205 builds the per-day strategic metrics on what `flai stats` reads here.

## Decisions
- Plan layers: 1) T-0772, the document model everything writes and reads through. 2) T-0773 (serve measurement), T-0774 (check), T-0775 (stats), each waiting for T-0772 only, with no path in common, so they run together. 3) T-0776 (MCP tool), waiting for T-0773 whose serve function it calls.
- `tasks_completed` counts the activities logged: an activity is the strategic agent's unit of work, as a task is a story agent's.
- `last_run` is the timestamp of the newest entry, when the latest activity ended.
- A strategic run's logs are `<serve dir>/agents/<key>-<kind>-*.log`, so `AgentLogs`' naming carries over; S-0208 starts the runs that write them.
- An activity's span runs from the later of the newest run's start and the last entry to its end; its cost is the run's usage apportioned to that span as a task's is (ADR-0051).
- `activity_log` takes `kind` explicitly rather than inferring it from the agent's name, since S-0208 has not fixed how strategic agents are named.
- T-0772's review: `WriteIndex` lists an activity document that does not parse as unreadable instead of failing, since every move rewrites the index; `flai check` names the fault.
- `AppendActivity` rewrites the document without a lock, as `LogStream` does; flai has no file locks anywhere, so a concurrent serve and MCP write could lose one entry. Left as is, consistent with the narratives.
- T-0773's review: an activity's span ends no later than the second after its run's last event, so a run that died without its end logged does not charge the hours since to the next entry.
- At a strategic run's end, a final reply after the agent's last `activity_log` is logged as its own entry when it spent anything: the cost is real, and dropping it would understate the totals.
- A strategic run's log is named `<key>-<kind>-<start>.log` with the start time required after the kind, so a project keyed like `t-planner` cannot lend another project its logs. S-0208 names the planner's logs so.
- T-0775's review: the dashboard's `stats.get` builds the report too, so it reads the activity documents as `flai stats` does, and the parity test now has one. An unreadable document fails stats, as an unreadable item does.
- The issue first numbered I-0066 is I-0067: S-0204 had recorded another I-0066 on its branch (I-0065, bumped).
- `strategic-agents.md` (template 1.0.40 and here) now says `activity_log` takes the kind, the summary, and the items, and that a run's end logs the time since its last activity with its final reply; it had said only the summary.
- Went to review with `flai check --strict` failing only on S-0173's `story.unaccepted` and E-0015's `epic.lags-stories`, both outside the story and reported on main too, following the designer on TH-0056 (findings outside a story are notes); I-0057 bumped.
- TH-0095 (S-0204 and S-0206 blocking each other's close-out) resolved itself: S-0204 moved to review two seconds before the thread opened.
- T-0775 runs in its own worktree: its `cmd` tests build the packages T-0773 and T-0774 are editing.
- `flai stats` gains a `strategic` section of each kind's totals and its log entries in the window; the per-day series and the comparison with delivery are S-0205's. The addition goes in metrics.md under this story's ADR.
