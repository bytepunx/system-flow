# S-0295 One in-progress story holds every ready story by overlap, through folder-wide touches and docs/users/flai.md, so the board runs one story at a time under a limit of three

## Context

I-0087: one open story held every ready story by overlap, through folder-wide touches, a story in review, and `docs/users/flai.md`. On TH-0180 the operator took all three remedies as one ADR refining ADR-0046, and asked for the shared list to be editable through the CLI, HTTP, MCP, and the dashboard, with globs.

## Current state

All twelve tasks are done, committed on story/S-0295, and synced with main. Both criteria are ticked: `hold_i0087_test.go` reproduces I-0087 and fails when any one of ADR-0096's rules is reverted, and I-0087 is closed on the branch. The story's touches are now the files the branch changed, with `flai/internal/guard` as a folder.

The close-out passed every step on the second verifier's run, and S-0295 is in review.

## Next steps

1. The operator reviews and accepts S-0295 (`flai accept S-0295 --by alex`), or sends it back.
2. After acceptance, the installed flai that `flai serve` and `flai mcp` run needs upgrading before the new hold rules and `claims.shared` take effect on the board.

## Decisions

- Kept the planner's twelve tasks and their seven layers as drafted: they match the story and TH-0180. Layers: 1 T-1023 (the ADR every other task builds); 2 T-1024, T-1025, T-1026 (no shared paths: hold.go, manifest, conventions); 3 T-1027 (after T-1024, both change hold.go), T-1028 and T-1029 (after T-1025, they call its matcher and edit function); 4 T-1030 (after T-1025 and T-1027, it changes hold.go and the claim), T-1031 (after T-1028, it runs the command); 5 T-1032 (after T-1031, it calls its methods); 6 T-1033 (documents everything, writes CHANGELOG after T-1026); 7 T-1034 (closes the issue on the finished story).
- The template's default shared list is `design/adrs` and `design/issues`, under the project's design layout, not this project's six paths. The planner's assumption on TH-0180 reasoned that the paths come from the template's layout; only those two do. `docs/users/flai.md`, `docs/users/flai-reference.md`, `design/system/flai-cli.md`, and `template/CHANGELOG.md` are this repository's own files, and a pattern naming a file a project lacks would only mislead its operator.
- Changing the shared list is refused by `flai guard` to every session flai serve starts: a story's agent and its sub-agents, the planner, the orchestrator, and the analyzer, through both the MCP edit tool and `flai shared add|remove`. The ADR grants the orchestrator nothing: the list decides what holds, and the orchestrator's permissions do not include holds.
- T-1024's new reason text says a hold by a story in progress ends when it "moves to review, is cancelled, or is sent back". Four tests outside its touches asserted the old text and two `held_seconds` cases in `metrics/claims_test.go` counted time held by a story in review; I updated them and widened T-1024's touches. `held_seconds` is defined in `metrics.md` as replaying the hold rules, so its definition stands and its values follow ADR-0096.
- T-1025 matches globs with `path.Match` a segment at a time, not `bmatcuk/doublestar`: the hand-written `**` is short and the folder-inside rule is flai's own anyway. `Covers` treats a touches entry whose last segment has an inner dot as a file and anything else as a folder, erring towards holding. Removing the last pattern leaves `shared: []`. T-1025 ran in its own worktree (`task/T-1025`) because every package builds against the manifest; it was cherry-picked onto the story branch.
- T-1026's changelog entry opened template 1.0.59, so `template/template.yaml` moved to 1.0.59 with it (T-1026's touches widened).
- `flai guard` refused `flai adr new` to T-1023's sub-agent; I ran it with the body the sub-agent wrote.
- T-1027's narrowing made the grown-claim notice report a narrowed folder's files as gained; `itemedit/claim.go` now counts a path as gained only when neither it nor a folder around it was claimed before (T-1027's touches widened).
- T-1028, T-1029, and T-1031 each ran in their own task worktree and were cherry-picked onto the story branch. T-1029's tools are registered in `addProjectTools`, so a folder of projects serves them too, and `flai guard` reads `FLAI_STARTED_BY` as well as the role and story.
- The agent definitions under `.claude/agents/` do not list `mcp__flai__shared_paths`, so the planner, explorer, and verifier cannot call it yet. Left as is: they can read `claims.shared` from `system-flow.yaml`, and a `.claude/` change needs the operator to paste it.
- T-1030 gave `Holds` the shared list through `WithShared`, and `NewBoardView` now takes the `Holds`, so the board and `wait_for_work` apply the exception (four callers changed, T-1030's touches widened). `Repo.SharedClaims` reads `system-flow.yaml` again on every call (about 0.25 ms), so an edit takes effect in a running `flai mcp`.
- `flai check`'s `wip.overlap` still compares the raw touches of stories in progress, with the shared exception added. ADR-0096 says a story in review keeps its claim for `wip.overlap`, as ADR-0046 framed it, but the code never compared review stories, and making it do so would warn on every overlap rule 1 now allows. Left as it was.
- `settings.shared` runs `flai shared add|remove --autocommit`: the planner's design left the manifest edit uncommitted, which would leave `system-flow.yaml` dirty in the main checkout after a dashboard edit, while `settings.default_agent` commits. `flai shared` gained `--autocommit` and `--trailer` like `flai agent set`.
- Narrowing applies to this story too: once T-1034 named two files in `design/issues`, the story's `design/issues` touch claimed only those, and sync reported the other issue files the close-out bumped. The story's touches are now the files it changed, listed one by one. A story that means to claim a whole folder can no longer do so while one of its tasks names a file in it: that is ADR-0096's rule as decided, and the out-of-claim report at sync is what catches it.
- First close-out (verifier): every step passed but flaiover, which stopped on `notify.test.ts` (I-0085, bumped); it passed alone and `scripts/flaiover-test.sh` passed whole. The verifier also named a missing doc comment on `PatternError.Error`, now added.
- `docs/operators/settings.md` and the generated reference were updated as soon as the CLI changed (T-1028, T-1031), rather than waiting for T-1033, so the reference and settings index tests stayed green between tasks.
