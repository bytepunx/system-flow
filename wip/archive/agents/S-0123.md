# S-0123 A project served from below an import folder can be removed from the dashboard and served again

## Context

Since S-0120 flai serve serves every git repository with a keyed `system-flow.yaml` below a folder named for import, and since S-0102 every project below the folder it was started in. Neither is in the registry, so `flai serve project remove` (S-0121) refused them and the settings page (S-0122) offered no Remove. TH-0014 and TH-0016 (answer A) left a list of removed roots for this story. Code: `flai/internal/serve/below.go` (FindBelow, Place), `candidates.go` (offers.folderProjects), `flai/cmd/serve_project.go`, `flai/cmd/serve_actions.go` (servedView), `flaiover/src/lib/components/SettingsPanel.svelte`.

## Decisions

- The list keeps roots, not keys: a key can change in the manifest, and the registry is by root too.
- `flai serve project add` on a removed project below a folder flai serve serves from takes it off the list and does not register it, so it is served from below again as before it was removed; a removed root no longer below such a folder is registered as `add` always did.
- Serve stays offered on every unserved project, as S-0122 left it; a removed one says so and Serve is what brings it back.
