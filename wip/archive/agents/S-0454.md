## Decisions

- Kept the planner's seven tasks and four layers as the orchestrator approved them on TH-0538. Layer 1 is T-1931, the ADR every other task builds to. Layer 2 is T-1934 (server), T-1936 (client), and T-1937 (harness): no path in common, so they run together, each by its own task sub-agent. Layer 3 is T-1938 (docs), which waits for the three it describes, and T-1939 (Playwright), which waits for the server and client it drives. Layer 4 is T-1940, the removal of the server-sent events, which waits for T-1939's run against them.
- The ADR took number 0182, not the predicted 0179, which S-0450 took. T-1931's and the story's touches name 0182.
- ADR-0182 keeps the path `/api/events` and removes the server-sent events route and `sse.ts`, so a plain `GET /api/events` answers 404. It refines ADR-0029 and ADR-0172.
- T-1934 keeps the global `__flaioverAgentUpgrade` and `exposeAgentUpgrade`, now a router by path that takes its routes from `hooks.server.ts`, since the design names both and `agent.ts` importing `events-socket.ts` would make an import cycle. Its `Origin` check compares with `Host` only, so a proxy that rewrites `Host` would be refused 403.
- T-1936 tells listeners to refetch with a manifest `change` of kind `project` and an `agent('')`, which every one of the 15 importers of `$lib/events` already treats as "ask again". No callback was added and no component changed, so no question was needed.
- T-1937 lets through a socket that asks for any `vite-` subprotocol, since Vite's client opens `vite-hmr` and `vite-ping` on the base path, which the path rule alone would take for the app's.
- T-1939 runs `node server.js` over the build with a fake flai on `/agent` inside the test, the handshake `project-events.test.ts` uses, rather than a real `flai serve`: it needs no flai binary, repository copy, or `~/.flai`. It signs in with a login token made for the run as the session cookie. Page: `/license?project=e2e`, whose layout's inbox follows events.
- Run against the server-sent events (main's `events.ts` swapped in, by T-1939's sub-agent): pages 1 to 5 fetched `/_health` in 4 to 5 ms; page 6's fetch timed out after 5001 ms, "a fetch from page 6 of 7, with 6 event streams open over server-sent events". Page 6, not 7, because the sixth stream fills the six connections. Over the WebSocket every page's fetch answered in 4 to 5 ms, in five runs and again after T-1940.
- Done outside the planned touches: `docs/users/flai.md`'s harness line names the `WebSocket` (T-1938); `scripts/README.md`'s row for `flaiover-e2e.sh` and `flaiover/package.json`'s `test:e2e`, which now builds first since the config serves `build/` (T-1939). The proxy note went into `flaiover-dashboard.md`'s endpoint bullet.
- The first close-out passed every tier but smoke, where the LiteLLM gateway check failed on the retired default model (I-0171, bumped; S-0455 fixes it). I ran it again with `FLAI_TEST_LITELLM_HAIKU=openrouter-messages/nvidia/nemotron-3-ultra-550b-a55b:free` for that run only, as the operator confirmed for S-0445 on TH-0534. Nothing on the host changed.
