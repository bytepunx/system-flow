## Decisions

- The story had no touches, so `story_start` held it on S-0431 and S-0486. Declared the taskdone package, the command, the MCP description, and the shared docs; none overlaps an open story outside `claims.shared`.
- Fix, proposed from I-0202's instance: the check step of `flai task done` keeps at most ten notes outside the story and counts the rest in `check.notes_omitted` ([ADR-0198](../../design/adrs/0198-task-done-s-answer-lists-at-most-ten-of-the-check-s-notes-outside-the-story-and.md), proposed). Findings inside the story stay whole; `flai verify` keeps every note for `--record-issues`. Cutting notes in the fit instead was rejected: it still answers about 35,000 bytes of notes the agent cannot act on.
- Plan, two layers: T-2102 (the ADR) first; T-2103 (code, test, help, docs) after it, because its docs link the ADR.
- Worked both tasks here rather than through task sub-agents: there is no fork agent type in this harness, the code change is about thirty lines in files already read, and a fresh sub-agent's briefing would cost more than the edit.
