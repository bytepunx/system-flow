# S-0394 A story's pull request checks and reviews show in flai show and on its dashboard page, and a failing check or a requested change reaches its agent as a thread that sends the story back

## Context

S-0393 pushes a story in review and opens its pull request (`flai/internal/serve/forge.go`, ADR-0166). This story reads that pull request's required checks and reviews back, keeps them, shows them, and sends the story back on a failure.

## Decisions

- **Plan kept, touches corrected.** The planner's eight tasks and four layers stand. Touches changed to match the code:
  - T-1617 adds `serve/forge.go` and `serve/forge_test.go`: the read runs in the forge pass S-0393 wrote, and the fake forge there answers no checks or reviews yet. `serve.go` is dropped, since the pass is wired already.
  - T-1619 adds `flaiover/src/lib/server/agent.ts`: `hostapi/contract_test.go` fails unless a new host method is in `REQUIRED_METHODS` in the same commit. T-1621 drops it.
  - T-1620 adds `harness/harness.go`, its test, and `adapters.go`: the prompt for a resumed agent says the designer answered, which does not fit a thread by `flai serve`.
  - T-1621 swaps `review/[id]/+page.svelte` for `Review.svelte` and its test, where the review page renders, and adds an examples file for `ForgeStatus.svelte`.
- **Layers.**
  - First: T-1615 (kept state) and T-1616 (ADR). Each waits for nothing.
  - Second: T-1617, T-1618, and T-1619, each after T-1615, since each writes or reads the kept state. They share no path.
  - Third: T-1620 after T-1617, since it starts the agent for the thread T-1617 opens; T-1621 after T-1619, since it calls that host method.
  - Fourth: T-1622, after the tasks whose work it describes.
- **Kept state per story, in the forge package.** `.flai-cache/forge/status/S-nnnn.json`, one file per story, as ADR-0166 keeps the push state per story, so two stories never write one file. It sits in a folder of its own because `leftReview` globs `forge/*.json` as push state. It lives in `flai/internal/forge`, which `hostapi` can import, not `serve`, which `hostapi` cannot.
- **One send back per failure.** A failing required check is keyed by its name and the head commit. A changes-requested review is keyed by the review's URL, since the review stands across a fix's new commit until the reviewer reviews again.
- **Task worktrees for layers 2 and 3.** T-1617, T-1618, and T-1620 each ran in a task worktree, `task/T-nnnn` from the story branch: `cmd` builds `serve` and `hostapi`, and `serve` builds `hostapi`, so a half-done edit in one would fail another's tests. T-1619 and T-1621 ran in the story worktree, where flaiover's tiers run. I copied each task's files back and closed it there.
- **A reviewer's latest deciding review counts** (T-1617). Only each author's latest approving, changes-requested, or dismissed review can send the story back, as GitHub counts a reviewer's decision.
- **Archived stories' send-back threads are resolved** (T-1617, my fix in review). Accepting a story archives it at once, so the resolve looks a story up with `repo.Get` when the board list does not hold it.
- **No headless agent beside a hand-run session** (T-1620, my change in review). The sub-agent started an agent for a sent-back story that flai serve had never run. I changed that: such a story is worked from a session of its own, whose inbox lists the thread. A run without a session still gets a new one.
- **`flai forge status --json` names the read `pull_request_read`** (T-1618). Its `pull_request` already holds the number. `flai show --json`, `item_get`, and `forge.status` use `pull_request`.
- **`item_get` reports `pull_request_error`** (T-1618) for a kept file it cannot read, rather than failing the read of the item.
