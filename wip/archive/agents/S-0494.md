# S-0494 flaiover's events socket removes its Repo listeners only when the close handshake completes, so the server-stop test races and fails in CI

## Context

I-0205: `EventsSocket.close()` sent 1001 but left each socket's Repo listeners to its own `close` event, which fires after the close handshake; neither the client's close nor `server.close` waits for that, so the server-stop test raced on CI.

## Current state

Close-out passed at 872bb6560 (`flai verify S-0494 --last`). The diff meets criteria 1 and 2: `EventsSocket.close()` tears each socket down before its 1001, the server-stop test reproduces I-0205 against main, and I-0205 is closed. S-0494 is in review.

## Next steps

1. The operator reviews and accepts S-0494.

## Decisions

- Fix as I-0205's instance proposes: each open socket keeps one idempotent teardown (clear its ping, take its Repo listeners off, forget it); `close()` runs it before it sends 1001, and the socket's `close` event runs it for a socket that closes on its own. The test's `vi.waitFor` fallback was not taken, since it would hide the race rather than remove it.
- Plan: one task, T-2107, one layer, touching only `events-socket.ts` and its test. Worked by the story's agent itself rather than a task sub-agent: a 20-line change whose priming would cost more than the edit (`delegation.md`: do not delegate what is slower).
- The server-stop test now asserts no listener right after `close()`, before the client sees 1001; it fails against main's `events-socket.ts` (`expected 1 to be +0`) and passes with the fix.
- `design/system/flaiover-dashboard.md` says the sockets come off the Repo before their 1001 is sent; ADR-0182 already says close with 1001 and needs no change.
