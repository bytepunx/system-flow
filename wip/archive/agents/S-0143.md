# S-0143 Stories and Tasks track tokens and cost

## Context

Epics, stories, and tasks gain a `usage` block in their front matter: tokens and cost per model, measured from the Claude Code stream-json logs flai serve keeps for the agents it starts (`<serve dir>/agents/<key>-<story>-<time>.log`), summed up the hierarchy when an item moves into done, and charted by model. Worktree `.flai-cache/worktrees/S-0143`, branch `story/S-0143`.

What the logs hold (read from `~/.flai/serve/agents` on 2026-09-29):

- A `result` event per run, with `modelUsage` per model: `inputTokens`, `outputTokens`, `cacheReadInputTokens`, `cacheCreationInputTokens`, `costUSD`. It includes subagents. A resumed session (after an answer) reports totals cumulative over the session: S-0122's second run reports 20402200 cache reads, its first 16935243, and the second run's own messages 3466957.
- `assistant` events carry `timestamp`, `session_id`, `message.id`, `message.model`, and `message.usage`. The same message repeats once per content block. Input and cache tokens match `modelUsage` exactly when deduplicated by id; output tokens do not (the streamed value is the first chunk's), so time slices apportion the reported totals rather than summing streamed output.
- Cost per token is stable enough for an estimate: 0.33 to 0.59 dollars per million tokens for claude-opus-5-5 across 47 of 50 sessions.

## Decisions

- Usage is measured only from agents flai serve starts with the claude-code harness: their logs are the only record of tokens and cost flai can read. Other harnesses and hand-run sessions record nothing unless summed from children.
- A task's usage is its story's session totals apportioned by the share of input and cache tokens its in-progress window holds; its cost is marked estimated.
- Estimated cost uses the model's blended rate from the reported sessions read, not a price table: no price is hard-coded that could go stale.
- `flai serve` writes the measured usage, since it alone knows its log directory and project key; every move into done sums usage up the hierarchy from front matter alone, so it works on any path (CLI, MCP, accept) without the logs.
- A model keeps a fixed colour slot by family on every chart (opus 0, sonnet 2, haiku 5, fable 6). An index into the report's model list repainted opus between the story and task charts.
- The completion charts use flai's per-model series, so the epic filter does not apply to them, as with cumulative flow and throughput.
- Each task was committed on its own because the operator's start instruction said to commit each task. The git convention says to commit when the story lands. The operator's word takes precedence.
- ADR-0051 is written as accepted. It is the designer's to reject at review.
- The backfill was not run in this repository: the host's flai (1.23.0) would refuse items that carry `usage`. It was checked on a scratch clone instead.
