# S-0073 The dashboard reads work items through the channel: project, board, items, threads, and file changes

## Context
Second story of ADR-0029's build order: the dashboard's reads of work items leave the mount. flai answers the project, board, items, one item, and threads as structured data over the channel S-0072 built, and a watcher in flai tells the dashboard which files changed. S-0072 was in review when this was pulled, so `story/S-0073` was fast-forwarded onto `story/S-0072`; the operator was told to accept in order. inbox.ts, activity.ts, and search.ts keep working because `Repo.items()` and `Repo.threads()` keep their shapes and change their source; their own file reads (narratives, documents, the search crawl) are S-0074's.

After this story the board, items, and threads need a connected `flai serve`; `flai dashboard` starts it.

Numbers are in `design/system/flaiover-dashboard.md`: warm requests 2 to 5 ms against about 40 ms; the first after a change 60 to 80 ms against 40 to 55 ms. A `flai move` on the host reached an open `/api/events` stream in 544 ms and the board answer followed. With `flai serve` stopped the routes answered 503 with the command that starts it and `/_ready` was not ready; the first run of this showed the board and manifest still answering 200 from kept answers, which is the flaw fixed in the last commit and confirmed fixed on a rebuilt image. In a browser: the banner on every page, no cards, and when `flai serve start` ran the banner went and fifteen cards appeared without a reload; an item page with its children; the overview with the template version.

Not tried: macOS and Windows; a project with thousands of items (the first request after a change reads every item file).

## Decisions
- 2026-09-20: flaiover's tests read their fixtures through `flai hostapi` from this tree (`flaiAsk` in `$lib/server/testing.ts`) instead of a TypeScript parser kept for tests: the criterion says the parsers are deleted, the test scripts and CI already build flai for the write tests, and the tests then exercise the answers the dashboard really gets. It found a real gap at once (three-digit thread anchors).
- 2026-09-20: `flai hostapi` is a visible command, not a hidden test hook: it is the terminal's view of what a dashboard can ask, which ADR-0029's auditability wants.
- 2026-09-20: the watcher polls (300 ms, one tick of debounce) instead of using fsnotify; reasons in `design/tech/go-libraries.md`.
- 2026-09-20: answers are kept until a change and forgotten when flai goes. Keeping them made warm requests twenty times faster than the mount; not forgetting them showed a stale board with flai stopped, found end to end.
- 2026-09-20: chokidar left now, not in S-0074 as that story's text says: nothing imports it once the hub carries the changes.
- 2026-09-20: `project.info` leaves out the template's repository address, which can be a folder on the host.
- 2026-09-20: based on `story/S-0072` (in review) by fast-forward, because every line of this story builds on it; if S-0072 is sent back, this branch is rebased after the fix.
