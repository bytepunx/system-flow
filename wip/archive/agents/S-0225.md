# S-0225 The planner's cost is recorded on the epic or story it planned

## Context

ADR-0051 puts what story agents spend on items; ADR-0079 logs what the planner spends in `wip/agents/planner.md`, on no item. This story puts a planner activity's apportioned usage on the epic or story it planned, under `usage.strategic`, apart from the agents' figures, and shows it and an expected cost in `flai stats`, `flai show`, and the dashboard. ## Decisions

- `usage.strategic` is a list, one entry per strategic agent kind, each with `kind`, `seconds`, `estimated: true`, and `models`. It is kept apart from the agents' `models` and `seconds`, so every per-model figure stays the agents' alone (criterion 2).
- A charge is summed up the hierarchy when it is made: the planned item and every item above it get it at once. `RollUp` and `Measure` keep `strategic` as it is. Recomputing it from the children at roll-up would lose a parent's own planning, which cannot be told apart from its children's once summed. Consequence: a story moved to another epic after it was planned leaves its planning on the old epic; recorded in the ADR.
- The planned item is the one `serve/agents.json` records under `plans` for the run whose log is the newest, for both `LogRunEnd` and `LogActivity`: the planner plans one item per run (ADR-0082), so no item list or agent name is trusted.
- Only the planner charges items. The orchestrator and the analyzer have no item of their own yet (S-0226, S-0227).
- Mean cost per agent hour: the agents' cost over their hours, over stories measured from their logs (`source: log`, seconds above zero), archived included, all time. Stories only, since a task is a share of its story and an epic a sum. Expected cost: `forecast.duration`, else `estimate`, times that rate, marked estimated, shown whenever the item has one, not only before an agent works it, so it can be compared with the actual.
- A new ADR rather than ADR-0081: ADR-0081 does not cover item usage, and `metrics.md` changes only with an ADR.
- Plan, in layers:
  - Layer 1: T-0803, the usage types, their front matter, and charging up the hierarchy. Everything else builds on it.
  - Layer 2: T-0805 (serve: charge on planner activity, `Measure` keeps it) and T-0806 (metrics and `flai stats`). No path in common, so they run together; T-0805 in a task worktree of its own, since `flai/cmd` builds both packages.
  - Layer 3: T-0807, `flai show` and the item page; waits for T-0806, whose figures it shows and whose `docs/users/flai.md` it also edits.
  - Layer 4: T-0808, the cost charts; waits for T-0806's JSON and for T-0807, which edits the same dashboard documents.

- T-0805: the planned item is found by the log's file name in any project's `plans`; the charge carries the entry's seconds, so the item and `planner.md` agree exactly. The entry is appended before the charge, and a failed charge is an error that still returns the entry; `activity_log` then warns instead of refusing.
- T-0806: an item with only strategic usage starts the spend series; strategic totals follow the agents' rule (entered done in the window, cancelled left out); the rate is rounded to four decimals before it prices.
- T-0807: `expected_cost` sits beside `item` in `flai show --json` and in hostapi `item.get`, not inside the item. The dashboard reads `item.get`, so it got the field there and in `itemById`. MCP `item_get` does not carry it: three stories in progress touch `flai/internal/mcpserver`, and `flai show` and the item page meet the criterion.
