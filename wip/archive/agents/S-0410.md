## Decisions

- **Plan.** Kept the planner's six tasks, with two changes. Layer 1: T-1706 (usage reader) and T-1707 (provider entry), apart in package and path. Layer 2: T-1708 waits for both, since the adapter returns T-1706's reader and starts with T-1707's entry; it now also touches `flai/internal/harness/harness.go`, for the interface that hands the reader the run's model. Layer 3: T-1709 waits for T-1708, since serve reads through the adapter. Layer 4: T-1710 and T-1711 together, both waiting for T-1709: the gateway test drives serve's pricing, and the docs describe what T-1706 to T-1709 built; T-1711's after moved from T-1710 to T-1709, as they share no path.
- **The model of a call.** `--format json` names no model on a root step (agent-adapters.md § The `--format json` events). The reader takes the model the run started with, which serve records per run and the story's agent names, through an optional adapter interface in `harness.go`.
- **Cost.** OpenCode prices each step, not the run. The reader keeps each session's totals across the logs one `usage.Read` gives it, in order, and reports them as an End after each priced step, so that a resumed session is cumulative as Claude Code's `result` is and `RunTotals` and the gateway pricing work unchanged. A step OpenCode priced at 0 (a model with no price) is no reported cost.
- **Reasoning tokens** are counted in output, at whose rate OpenCode prices them; `usage` gains no field, so `metrics.md`'s contract keeps its shape (ADR-0130 already names metrics.md as changing where the events are named, so no new ADR).
- **Sub-agents.** The stream holds the root session's steps only. The reader reports the `task` call that starts a sub-agent and its result, but a sub-agent's own calls are not in the stream; reading them (`opencode export`) is left out of this story and recorded as an issue.
- **Strategic activity.** A strategic run is read with its recorded harness's reader only when that harness reports cost. Otherwise claude-code's reader stands, as before S-0410. Existing strategic runs record the `command` harness but log Claude Code's stream-json, and 21 tests showed it (T-1709).
- **Rates** are read with every harness that reports cost and merged. So each such harness reads every log once, and with two harnesses that is twice the reading (noted in flai-cli.md).
- **A provider the agent names but the start did not resolve** is refused on opencode, not ignored: ignoring it would send a bare model to OpenCode's own providers (T-1708).
- **Gateway check budget.** OpenCode takes no budget flag, so `TestGatewayOpenCode` fails after the run when the run spent more than `FLAI_TEST_GATEWAY_BUDGET` (T-1710).
- **S-0407 overlap** (MS-0348). The trial merge conflicts in `harness/opencode.go`, its tests, `harness_test.go`, and three docs. Agreed: whichever story is accepted second keeps both sides, `Capabilities{Resume, Guard, Cost}`.
- **Fixtures.** No `opencode` binary is on this host, so the fixtures are written in the shapes read from v1.19.5's source (agent-adapters.md), not recorded from a run.
