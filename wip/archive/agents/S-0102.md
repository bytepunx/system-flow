# S-0102 No project selector is visible

## Context

On the operator's host, `flai serve` (installed flai, no `--config`) runs with `/home/alex/git/bytepunx` as its working directory, a folder of a dozen repositories. Only `sf` (this repository) is registered, and no folder is named for import (`import_roots` is empty). The board therefore knows one project, and the switcher, a plain label while there is one (S-0095), shows no control to switch or import with.

## Current state

Done; all three tasks and both criteria.

- T-0359: a `flai serve` started in a folder that is not a project (`Options.Folder`, its working directory) serves the system-flow projects below it for the dashboard the registered projects reach, without writing them to the registry, and counts the folder as an import root. `flai serve status` names the folder and its projects.
- T-0360: the switcher is always a `<select>`, even with one project. The projects come first, then an optgroup "Not imported yet" with the repositories offered for import. With nothing connected it is disabled and says so.
- T-0361: tried as the operator's setup is.
  - A folder held `flow` (registered, as `sf` is), `other` (a project, not registered), and two plain repositories.
  - A scratch `flai serve` was started in the folder, with this branch's dashboard on 5199, in a browser.
  - `flai serve status` showed `flow`, `other` served from the folder, and `kickr` and `loci` offered.
  - The switcher, visible with Flow selected, held Flow and Other, then "Not imported yet": kickr and loci. Switching to Other showed its overview. Picking loci prompted, and Import committed it and switched to loci as a project, leaving only kickr offered.

  The design, user, and operator docs are updated. flai-test (lint 0 issues), the flaiover suite (414), lint-md, and `flai check --strict` are clean.

## Next steps
None: in review. For the operator's own board: once a flai with this is installed, restarting `flai serve` in ~/git/bytepunx offers the repositories there, and the dashboard image with the switcher change is the next flaiover release.

## Decisions
- A `flai serve` started in a folder that is not a project treats that folder as `flai dashboard` there does (S-0101, ADR-0036): the system-flow projects below it are served, and its other git repositories are offered for import, as the story's "subdirectory of the current flai serve working directory" asks. It is an added case of ADR-0036's decision, not a reversal, so it is recorded in the living design and here, not in an ADR. Started inside a project (as `flai dashboard` there starts it), `flai serve` does nothing of the kind.
- The folder's projects are served for as long as that `flai serve` runs, not written to the registry, so stopping it leaves nothing registered behind. They use the dashboard the registered projects, or one recorded by `flai dashboard`, reach.
