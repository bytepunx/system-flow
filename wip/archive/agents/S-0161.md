# S-0161 The dashboard forgets only the answers a changed file affects, and gathers changes that arrive together

## Context

Cause 6 of `design/system/server-performance.md`: `Repo.changed` in `flaiover/src/lib/server/repo.ts` forgot every answer at any change, and `routes/board/+page.svelte` asked for its board, `/api/publish`, and the agents at every `change` event. Worked in `.flai-cache/worktrees/S-0161` on `story/S-0161`.

## Current state

Both tasks done and committed on `story/S-0161` (748019c, 42fa6ea after the rebase onto S-0160); S-0161 is going to review with every criterion checked.

- T-0571: `$lib/changes.ts` gives a changed path its kind from the layout; `Repo.changed` forgets only the answers read from that kind (table `READS` in `repo.ts`); `/api/events` sends `{ path, kind }`.
- T-0572: `follow(kinds, f)` in `$lib/events.ts` gathers changes over 500 ms (at most 2 s in a burst) and calls a page only for the kinds it shows; the board asks for board, publish, and unpushed only on item or manifest changes, agents on item and thread changes and `agent` events; activity, charts, ADRs, item page, threads, agent panel, and inbox follow their kinds.
- Docs: `design/system/flaiover-dashboard.md`, `design/system/server-performance.md` (cause 6), `docs/users/flaiover.md`.
- Checks: 604 flaiover unit tests, prettier, eslint, svelte-check, and `pnpm build` pass in the worktree. The request rate in the running dashboard was not measured again: it needs an image from this story in place of the operator's container.

## Next steps

1. The operator reviews and accepts S-0161.
2. After acceptance, measure `/api/publish` and `/api/unpushed` request counts in the new dashboard's log over seven minutes with agents working, against S-0152's 56 and 58.

## Decisions

- Each task is committed when it is done, as the spawn instruction from flai serve says, rather than only at review as `git.md` says; the operator's instruction takes precedence.
- The dashboard, not flai, tells a path's kind: flai's `change` notice stays a path, and `$lib/changes.ts` reads it against the manifest's layout, so no flai change or ADR is needed. Unknown paths and changes before the layout is known forget everything, so a wrong reading can only cost a request, never show a stale answer.
- `threads.list` is forgotten on item changes too, because a thread's view names its story, which flai reads from the items (`threads.StoryOf`).
- `project.info` is forgotten only by `system-flow.yaml` and unknown paths; a host action enabled in a shell changes no file of the project, and before S-0161 it reached the dashboard only by the chance of another file changing. A write through the dashboard still forgets everything.
