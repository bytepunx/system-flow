# S-0112 A restarted flai serve never starts an agent for a story that was already ready: the stale rule predates flai host

## Context

`flai/internal/serve/agents.go`'s launcher retires every story ready at its first look (`stale`), so each `flai host` restart of serve leaves ready stories with no agent and no stated reason. `serve/agents.json` (`startedBefore`, `settleOrphans`) already stops a restart starting a story twice. ADR-0038 records "a restart of flai serve still starts nothing that was already ready"; this story supersedes that clause.

## Current state

## Next steps

2. After acceptance, `flai push --pending`. Once serve runs the new flai, S-0109 still waits: it names no harness and the host has no command set. Its `waiting` now says so. Give it one with `flai edit S-0109 --harness ...`.

## Decisions

- A live run (an agent started and still running for a story in ready) is not a skip, so it gives no `waiting` reason: the story has its agent.
- The `agent not started` line is logged when a story's reason changes, not at every look, so the minute tick does not repeat it (the idiom of `mcp.go`'s `warned`).
- The `agent` action being off is stated as a skip reason for each ready story too, so that no ready story waits without one. That costs one log line per story per serve start in projects that leave the action off.
- ADR-0041 is recorded as accepted, not proposed. The story's notes give the fix as the operator's decision.
- T-0391 (the installer smoke test) was added to this story rather than a new story. It is a small fix, and the story cannot reach review until all three tiers pass (work-management.md: a five-minute fix is a task on the current story).
- Commit trailers name the model that did the work, Claude Opus 5.5, as the session's attribution instructions say. `git.md`'s project addition names Claude Fable 5.1. Raised as TH-0009 on `design/conventions/git.md`; S-0112 does not wait on it.
