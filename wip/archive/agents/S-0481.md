## Decisions

- The fix is two parts. `scripts/flaiover-install.sh` installs with `--config.confirm-modules-purge=false`, so an install linked from another store is purged and rebuilt from the lockfile instead of aborting with no TTY: this recovers from any store change, not only a bare `pnpm add`. `scripts/flaiover-pnpm.sh` runs the pinned pnpm in `flaiover/` with `env.sh`'s store, so a dependency is added without the default store or the host's other pnpm (nvm's pnpm 12.6.0 here). Reproduced both ways in a scratch copy first: a bare add before the first install aborts the next install; the purge flag recovers it.
- Rejected a `storeDir` in `flaiover/pnpm-workspace.yaml`: a relative path resolves per worktree, so each worktree would get a store of its own that differs from `env.sh`'s, and the mismatch would remain.
- The reproduction test, `scripts/flaiover-install-test.sh`, runs from `scripts/flaiover-test.sh`, the `flaiover` tier, since no tier selects `scripts/` and the manifest's tiers are not this story's to change.
- Plan: two layers. T-2070 (the fix, its test, and its docs) first; T-2071 (close I-0177) after T-2070, since its reason names the fix. Both are short, so I work them myself rather than through task sub-agents.
