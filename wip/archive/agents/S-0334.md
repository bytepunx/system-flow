## Decisions

- A share lifts a hold on its own, without the operator's confirmation: the operator took the planner's recommendation on TH-0318 and resolved TH-0319. Recorded in ADR-0134.
- Plan re-layered from the planner's draft. `messages` imports `workitem`, so the `workitem.Share` type and the holds that read it must exist before the messages package can write shares: T-1204 now comes before T-1203, not after it.
  1. T-1202, the ADR (done by the story's agent).
  2. T-1204, `workitem.Share`, `Repo.Shares`, `Holds.WithShares`, `Holds.OverlapsBy`; waits for the ADR.
  3. T-1203, `messages.AskHold`, `messages.Share`, `flai message share`, `message_share`, guard; waits for T-1204's type.
  4. T-1205 (serve asks, prompt names the share) and T-1206 (docs) run together: both wait for T-1203's commands, and share no path.
- Shares live in the conversation's front matter under `shares`, and `workitem` reads them itself, so every caller of `Repo.Holds` (board, inbox, wait_for_work, story start, launcher) agrees without a new parameter.
- The operator who may share is the holding story's owner, as ADR-0097 takes the story's owner for permission_prompt.
- `message_share` takes no `story` argument, like the other message tools (S-0331): an agent shares only as its own story; the operator shares when the author is the holding story's owner. The CLI's writer flag is `--from`, as `reply` and `escalate` have it.
- flai serve asks at every look, whether or not the agent action is on or the limits have room: a held story matters most on a busy board, and agents outside flai serve pull through `wait_for_work`, which honours shares too.
- `Holds.InForce` is exported so flai serve judges a share in force by the same rule as the holds, rather than a copy (T-1205's sub-agent had copied it).
- T-1206's docs landed in T-1205's commit f067076: the installed flai 1.39.13 that serves MCP commits every changed file at task done, which S-0322 fixed in 1.39.14. T-1205's touches were narrowed back to its own files.
- `docs/operators/settings.md` changes only in its generated flag index (`make flai-reference`). Agreed with S-0232 (MS-0037) that both merge cleanly, and told S-0341 (MS-0038) that whichever is accepted second regenerates it.
