# S-0267 The close-out's flai tier runs each Go test once: the short behaviour run is dropped where the full run follows it

## Context

`scripts/flai-test.sh` ran `scripts/test.sh` (short Go tests and vitest) and then `scripts/integration.sh` (full Go tests), so every close-out of a story that changes `flai/` ran the short Go tests twice.

## Current state

T-0846 and T-0848 are done and committed on `story/S-0267`, synced with main. `scripts/flai-test.sh` runs the lint, `scripts/flaiover-unit.sh` (vitest), `scripts/integration.sh` (the full Go tests), and `scripts/smoke.sh`; `scripts/test.sh` runs the short Go tests, then `scripts/flaiover-unit.sh`. ## Decisions

- Two tasks in two layers: T-0846 (scripts, Makefile) first; T-0848 (devex.md, scripts/README.md, docs/operators/index.md) after it, because it describes what T-0846 makes. No path in common.
- Both tasks are a few lines each, so I work them myself rather than through task sub-agents: handing them over would cost more than the edit.
- The vitest block moves to `scripts/flaiover-unit.sh` (the planner's touch) so that `test.sh` and `flai-test.sh` share it rather than copy it; `make test` still runs it after the short Go tests.
- `.github/workflows/flai.yml` runs the short and the full Go tests as two steps too; it is outside the story's touches and criteria, so I leave it and note it for the operator.
- The planner wrote T-0842 and T-0843 with the same split while I wrote T-0846 and T-0848. I cancelled the planner's and added its one extra path, the `scripts/close-out.sh` header comment, to T-0848. I did not reply on TH-0114: a reply from me would mark the cost-of-delay question answered, and that question is the operator's.
- `code-quality.md` says each tier runs only once the prior one passes. `flai-test.sh` leaving out the short Go run does not break that: the full run holds every `-short` test, so the behaviour tier still runs, inside the integration run.
- The branch changes no file under `flai/`, so its own close-out runs the markdown lint and the check, not `flai-test.sh`. The verifier runs `scripts/flai-test.sh` as well, so that the changed sequence itself is tested.
- The duplicate vitest run that `flaiover-test.sh` adds when a branch changes `flaiover/` is the same kind of duplicate. It is outside this story; it could be a story of its own.
