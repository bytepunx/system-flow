# S-0144 Automatic publish/push should be a setting

## Context

Since S-0094, `flai push --pending` computes, applies, and tags the pending release before it pushes. Agents run it whenever `inbox` reports an unpushed acceptance, and the board's Push now runs it, so every acceptance is published at once and the operator cannot batch releases (ADR-0032). This story makes that release-at-push opt-in: a new host action, `publish`, off by default.

## Current state

Done, in review. story/S-0144 holds b13d564 (push releases only with the setting), ae635bc (ADR-0048 and docs), 385b443 (renamed to `auto-publish`; release tags on already-pushed commits are pushed on their own), 91795bc (I-0050). Both criteria ticked and verified by tests. `make flai-test`: gofmt, vet, golangci-lint, behavior, integration, and template smoke pass; the repository's strict check fails only on `wip.overlap` warnings with S-0138 and TH-0029's `threads.archived`. ## Decisions

- Worked while the board showed S-0144 held by overlap with S-0138: the operator's flai serve started this agent for S-0144 with the instruction to work it to review. Narrowed the claim from `flai/cmd` to the files this story changes; the remaining overlap is `design/system/flai-cli.md` and `docs/users`, documentation where a conflict is resolved at sync.
- Did not run `flai push --pending` for the unpushed S-0137 acceptance, as the convention would have it: under S-0094 that command releases, which is exactly what this story's operator does not want done unasked.
- The setting is a host action, `publish`, not a manifest key: pushing and releasing act with the operator's credentials on the host, which host actions govern (ADR-0029). Recorded as ADR-0048.
- Did not change the acceptance preview's text in `flaiover/src/lib/components/Review.svelte`, which still says an acceptance pushes when pushing is enabled (stale since S-0087): it is the dashboard component, outside this story's claim. Proposed as a follow-up.
- TH-0031, operator: A, named `auto-publish`. Agents keep pushing merged commits after an acceptance; that cuts no release. ADR-0048 accepted.
- Fixed within this story: a release published after its acceptances were pushed tagged a commit the remote already had, and neither `flai release --pending` nor `flai push --pending` pushed that tag. Both now push tags they just made on their own (`pending.TagsOnly`, `Unpushed.Pushes`). It is this story's normal flow, so it could not wait.
