## Decisions

- **Plan.** The planner's four tasks are kept as drafted. Layer 1 is T-1890, since its exclusions decide which components the examples and the test cover. Layer 2 is T-1891 and T-1892, which share no path and run apart. Layer 3 is T-1893, whose pass needs every example and the test in place. Each task is small beside priming and review, so they are worked one at a time, by this agent.
- **What renders.** A headless pass over all 69 components, light and dark, in the harness of `flai components serve` with the setup, found no component that fails to import or compile. Every harness `error` was a missing required prop. Components that fetch `/api/*` reach flaiover's own server inside the dev server, which answers 500 without a dashboard token, so they show their own failure state.
- **Exclusions.** A component is excluded when everything it shows comes from the app's server or its app-wide stores, so that in the harness it shows only an empty frame or the server's error, whatever its props. A component with UI of its own beside a failed fetch, such as AcceptConfirm or Threads, stays listed. The fourteen, each written with `flai components config`:
  - EditorDialog, HostFlai, HostFlaiBanner, InboxBadge, UnsignedBanner: no props; each shows only what an app-wide store holds (`editorState`, `hostFlai`, `projectState`, `inboxState`), which the app's layout fills from the host channel and the harness never does, so each renders nothing.
  - DocEditor, ItemEditor, Review: each loads the document or item its one prop names from `/api` before it shows anything, so the harness shows only the server's error.
  - SettingsPanel, HostPanel, HostProcesses: each shows only the host or project settings it loads from `/api`, so the harness shows only "Loading…" or the server's error.
  - HostAgentNotice, PlanAction, StoryAgent: each shows only what `/api/host-agent` or `/api/items/<id>/plan` answers, so the harness renders nothing.
  - OpenQuestions, AgentStream, added at T-1891 once their examples showed it: OpenQuestions lists only the questions in the app-wide `inboxState`, and AgentStream only the entries `/api` streams, so each shows an empty box whatever its props. The panels that embed AgentStream stay listed.
- **Examples (T-1891).** Four task sub-agents wrote the 47 files, one disjoint set of components each, since the files share no path; the story's agent reviewed them. Every example leaves `theme` out, so the page shows both themes, but for Chart's second, whose `theme` prop fixes the chart's palette. ComponentFrame's `server` is Vite's default `http://127.0.0.1:5173/__flai/components/`, since flai picks the dev server's port at each start: the frame loads only where a dev server answers there. StrategicAgentPanel's runs have each ended, since a running one calls its `stream` prop, which the harness's logger answers with `undefined`; PlannerPanel, OrchestratorPanel, and AnalyzerPanel show the running state. The design examples carry every token the design system has, as the page passes them, so ProposalCompare's file is 148 KB as the page indents it.
- **The test (T-1892).** `flaiover_test.go` serves a copy of flaiover, with its `node_modules` linked to the installed one as the harness's integration test links its fixture's, so that Vite's caches and SvelteKit's generated files stay out of the repository and a dev server the operator runs on flaiover shares nothing with it. It reads the components key from this repository's `system-flow.yaml`, asks for the setup and each listed component, and ends with a control, a broken component, so that its check is shown to fail. Breaking `AgentDot.svelte` in the worktree made it fail naming the file; it was restored. It was run alone through `scripts/integration.sh -run`, its one test, rather than the whole `flai test --all`, which the close-out runs.
