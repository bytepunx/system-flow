## Decisions

- Plan is offered on the card by the item page's rule: writable board, an epic or a story, not archived, not done or cancelled, and the `plan` host action on. flai judges the rest (a planner already running is refused with its reason in the notice), as on the item page.
- The board learns whether the `plan` host action is on from `GET /api/host-agent`, which gains `plan_enabled`: the board already asks it on load and after agent actions, and it already carries the planner runs (`plans`). Asking `/api/items/:id/plan` when the menu opens would add entries after it renders and move its focus.
- Refusals of Plan on the board read as the board's other card-menu errors (flai's error alone), not the item page's `refused: ...`, so every card-menu write reads the same.
- S-0263's occurrence of I-0057 is reverted from its branch and kept in this narrative: S-0248's branch bumps the same issue, and TH-0111 asks one of the two to narrow its change.
- Plan: layer 1 is T-0834 (all of `flaiover/src`); layer 2 is T-0835 (the design and the user guide), after T-0834 so that the documents describe what it built. No two tasks share a layer, so they run one at a time.
