## Decisions

- The rule is ADR-0248: every acceptance commits the main checkout's uncommitted files under `wip/`, `design/`, and `claims.shared` (the shared set), in a commit of their own before the merge when the story's change would overwrite one, leaves the rest as they are (refused only as `dirty_main` when the story would overwrite one; `--yes` includes them from the shell), and sends a story whose rebase it cannot settle back to its agent whoever accepts, as ADR-0189 had the orchestrator's acceptance alone do. ADR-0189 had rejected "abort and send back on every acceptance" so the operator could settle a stop in place; the operator's S-0566 reverses that, so the ADR records the reversal rather than editing ADR-0189.
- `docs/` is not in the shared set: flai writes nothing there in the main checkout; a project names a docs path in `claims.shared` when it wants it committed. `design/` is, since the digest, the analysis reports, the issue files, their summary, and the ADR index are written there on main by flai and its strategic agents.
- The merge queue's landing (`--batch`) keeps its own send back (ADR-0176) but takes the shared-set rule too, so its eligibility, preflight, and landing count a dirty shared file as clean.
- Plan: layer 1 is T-2436 (send back for every acceptance: `flai/cmd/accept.go`, serve, preview), T-2439 (the five design and user documents), and T-2438 (the dashboard), which share no path; layer 2 is T-2437 (the shared set of uncommitted files), after T-2436 because both change `flai/cmd/accept.go` and `flai/internal/preview/accept.go`. The docs and dashboard tasks ran in layer 1 on the ADR's names (`shared_uncommitted`, `uncommitted`, `dirty_main`, the pre-commit subject) rather than wait for the Go.
- T-2436 overlaps S-0509 and S-0510 on `flai/internal/serve/agents.go` (comments and one prompt string); the trial merge at sync decides, and a conflict is settled in the stories' conversation.
- The verifier's review of the diff found one gap: a rebase the acceptance's sync found already in progress in the worktree (`syncStopped.Found`, reachable only past the preview's uncommitted-worktree blocker) was still answered with the sync's own words to the operator. Fixed: it is sent back too, without an abort, the thread saying flai left the rebase as it found it. `design/system/flaiover-dashboard.md` still described the checkbox and `include_uncommitted`; fixed. The merge queue's preflight now errors on a main checkout git cannot read, where `DirtyOutsideWip` answered nothing; the preflight runs only on the main checkout of a served project, which is always a git repository, so nothing changes in practice.
- The baseline role file `flai/internal/roles/baseline/orchestrator.md` (and its copies under `design/workflows/roles/` and `template/root/`) still says, in the orchestrator's acceptance step, that flai "leaves them out of the acceptance" of the main checkout's uncommitted files; true for the rest, not the shared set. Left alone: S-0554 and S-0425 touched those files, the sentence instructs no operator, and the harness prompt in Go was updated. Open for a follow-up.
- `accept_remote.go`'s message under pull-request acceptance ("bring main onto origin's main yourself … git rebase origin/main and resolve the conflicts") concerns the operator's own main checkout against the remote, not a story's worktree, and is left as it is.
