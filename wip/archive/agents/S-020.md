# S-020 flai upgrade re-integrates the latest template

## Context
flai new renders a template once; nothing brings a project forward when the template changes. S-020 adds flai upgrade. The hard part is knowing which rendered files the project has since edited: the story notes propose a lock file with a hash per rendered path, written by new and upgrade, so upgrade can replace untouched files, add new ones, merge marker files (CLAUDE.md, conventions) above the marker, and report the rest as conflicts. Local template sources have no history, so the lock is the only reliable way. This repository was hand-assembled and has no lock; its first upgrade will be a relock at the current version.

## Current state
All four tasks done, story in review. system-flow.lock.yaml (ADR-0015) is written by flai new and flai upgrade and read by upgrade to tell project edits from baseline; check warns when a project records a template version without a lock. flai upgrade classifies every template path (add, merge above the marker, replace when unchanged since applied, same, conflict), offers keep, replace, or a git diff per conflict in a terminal, requires --keep-all or --replace-all otherwise and changes nothing without one, refuses a dirty tree unless --force, and updates the lock and manifest only when no conflict is unresolved. --relock records a hand-assembled project; this repository is relocked at 1.0.0 with 45 files and upgrade reports it up to date. Tests cover every class, both policies, no-lock behaviour, relock, the dirty-tree guard, and the same-version no-op. Docs and design updated. Lint and all tiers green. Committed at review and pushed.

## Decisions
- The lock records the template's rendered hash for every path, including kept conflicts, so a kept divergence is a conflict again next upgrade rather than silently adopted.
- system-flow.yaml is rendered by the template but owned by the project afterwards; upgrade never classifies it and only touches template.version and template.applied, plus repo and ref when a different source was passed on the command line.
- Marker files merge regardless of hash: template above the marker, project below.
- No lock means every difference is a conflict; --relock is the migration for projects that predate the lock.
- Conflict diffs use git diff --no-index against a temporary render of the template's version.
