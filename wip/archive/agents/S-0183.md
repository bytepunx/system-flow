# S-0183 Agents and dev servers get only the environment they need: no host token, the project's own tools first

## Context
Three issues with one cause, the environment flai and the scripts hand on: I-0044 (agents inherit the host's address, token, and config), I-0001 (a story worktree lints with the host's golangci-lint v1), I-0039 (the dev server and compose point at a token file flai no longer writes).

## Decisions
- The launcher removes `FLAI_HOST_URL`, `FLAI_HOST_TOKEN`, and `FLAI_CONFIG`, the three the criterion names, and keeps `FLAI_HOST_ADDR`: it only moves the host's address, and a flai the agent runs that talks to the operator's host by intent (`flai serve status`, `flai push`) needs it.
- A `flai serve` under a host keeps MCP servers only when the `host/token` beside its own config is `FLAI_HOST_TOKEN` (`host.Dir.Holds`). The token is already written before the host starts its children, so no new state is needed. Its dashboard connections need no change: its registry is in the `serve` folder beside its config, so another `--config` has its own.
- `scripts/env.sh` keeps honouring a `FLAI_CONFIG` already set: agents no longer inherit the operator's, and tests and operators set it on purpose.
- `scripts/install-tools.sh` installs into the main checkout's `bin/` (and pnpm into its `.flai-cache`) from any tree, so the tools a worktree finds are the ones it installs. Refinement, not an ADR.
- `flaiover/compose.yaml` mounts `~/.flai/serve/dashboard.token` by default, `DASHBOARD_TOKEN_FILE` otherwise; compose cannot run `flai dashboard token --json`. `scripts/flaiover-dev.sh` keeps `PROJECT_DIR`: the dev server still uses it to name the project it asks flai about (`docs/operators/settings.md`); only the container never did.
- The operator's instruction says to commit each task; `git.md` says to commit when a story lands. Followed the operator.
