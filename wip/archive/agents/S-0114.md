# S-0114 Flai serve should set up a timeout to check board status

## Context

The operator filed S-0114 at 08:16Z on 2026-09-24 after watching ready stories sit while agents for others ran. The launcher in `flai/internal/serve/agents.go` already looks every minute, on every change under `kanban/` and `threads/`, and when an agent it started ends (S-0104, S-0112). The serve log shows the true cause of the waits: every agent flai serve started connected to MCP as `system-flow`, because the project's `.claude/settings.local.json` sets `FLAI_AGENT=system-flow` in its `env` and Claude Code applies that to the MCP server it spawns. The shared cursor `.flai-cache/mcp/system-flow.json` is then nobody's own sign, so each of flai's own agents ending counted as someone attending for six minutes (08:05 to 08:11, and 08:21 to 08:27). And the attended rule has no bound at all: an agent at work on its own story keeps its sign fresh for hours and no ready story is started while the limit has room. The reason logged at 08:16 also said "attending" while the in-progress limit was what was full.

Tasks: T-0408 bounds the hold (a story only someone attending holds back is started after the attended window, the limit is reported ahead of attendance, the log repeats only when the reason changes in kind); T-0409 has the claude-code adapter name its agent with `flai mcp --agent`, the I-0037 root cause; T-0410 records it in an ADR refining ADR-0038 and ADR-0041 and in the docs.

## Decisions

- The "timer" the story asks for is a bound on the attended hold, not another periodic look: the launcher already looks every minute (S-0104), and the log proves it fired. What kept stories in ready was the attended rule, which nothing bounded. Reason: a periodic check that changes nothing would not meet the criterion.
- The hold lasts the attended window (`attended_minutes`), counted from when attendance became the only thing holding the story, not from when it entered ready. Reason: one knob, and an idle agent holding `wait_for_work` still gets the window to pull first, so flai does not race it for a story that was held by the limit.
- The MCP agent name is passed as an argument (`flai mcp --agent`), not fixed by the environment. Reason: Claude Code's settings `env` overrides the process environment for MCP servers, which is what merged every started agent into one name (I-0037); an argument cannot be overridden that way.
