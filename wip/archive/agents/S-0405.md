# S-0405 With the merge queue on, a story's close-out and flai verify leave the test tiers the manifest marks for the queue to the batch, so a close-out main outruns no longer runs integration and smoke twice

## Decisions

- Plan, four layers. Layer 1: T-1653 (the ADR) and T-1654 (the `queue` tier key) share no path and wait for nothing. Layer 2: T-1665 (verify leaves queue tiers out) waits for T-1654's field. Layer 3: T-1666 (the batch runs them) and T-1674 (close-out scripts, convention, manifest) share no path; T-1666 waits for T-1665 rather than running beside it, as the planner had it, because T-1665 may change the selection that `batch.go` calls, and a half-done signature would fail T-1666's build; T-1674 waits for the ADR and for verify's behaviour it describes. Layer 4: T-1681 (design and docs) waits for both.
- T-1665's touches widened to `select_test.go`, `verify.go`, the MCP `verify` tool and `cmd/mcp.go`, and `mergequeue/eligible.go`: the MCP tool must make the same decision as the CLI, and the rule for whether the queue batches belongs beside the queue's eligibility.
- The queue counts as on for `flai verify` only when it can batch: the `merge-queue` host action is on for the project, `orchestration.permissions.accept_reviews` is on, and acceptance is local, the conditions under which `flai serve` builds a batch (ADR-0173). With the action on but either of the others off, no batch would run the tiers, so verify runs them. A hold does not count: a held queue resumes and batches later.
- `flai verify --all` (and the MCP `verify` tool's `all`) is the criterion's `--all`: it leaves no tier to the queue. `flai verify` had no `--all`; `flai test --all` keeps its meaning.
- A tier left to the queue is a step of its own state, `queued`, not `skipped`, which keeps meaning covered by another selected tier.
- Review additions beyond the sub-agents' work. T-1654: `flai manifest set` (`settings.go`) writes `queue` back and tells tiers apart by it, or a rewrite of `tests` would drop it. T-1665: the dashboard's review page knows `queued`. T-1681: `flai mcp start`'s HTTP server passes the queue decision to `verify`, as stdio `flai mcp` does; `workflow.md`'s stale "it only reads" sentence and the operators' guide's merge-queue section are brought up to date.
- A queue tier is validated as a boolean only. `queue` with `fix_command` is allowed: a tier's fix runs at task done, sync, and accept without verify's selection (ADR-0139).
- In this repository the close-out runs the tree's flai with `.flai-cache/config.json`, so it leaves tiers to the queue only when that configuration turns `merge-queue` on, beside the host's `~/.flai/config.json`. Recorded in ADR-0174's consequences and the operators' docs.
