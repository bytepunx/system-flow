## Decisions

- Plan: the planner's four tasks stand, one per layer, as drafted: T-2634 (the key), then T-2644 (`verify.Run` at once, reads the key), then T-2653 (smoke's skips, shares `run.go` and its tests with T-2644 and reads its ordering), then T-2661 (marks this repository's tiers and times the runs that the code tasks build). No two can run together, since each reads what the one before writes.
- The key is a flag, `parallel: true` on a tier, not `after: [<tier>]`. A tier marked `parallel` starts once every tier before it in the list that is not marked has ended, without waiting for the marked tiers before it; an unmarked tier waits for every tier before it, as now. With no tier marked the run is serial as before. The flag keeps "cheapest first, stop at the first failure" for free: the cheap per-path tiers stay unmarked, so the expensive ones start only when they pass. `after` would let a tier name exactly what it waits for, but needs a cycle check, a meaning for an `after` naming an unselected tier, and a way to tell an empty list from none; no tier here needs that precision. Recorded in the ADR T-2634 writes.
- A tier's `FLAI_VERIFY_PASSED` names the tiers it waited for that passed (and, in a close-out, the reused tiers and the check step), not whatever happened to end before it started, so what smoke skips does not depend on timing.
- T-2644 kept `verify.Tiers`, the merge queue's batch, serial (one tier per `Run`), so its `Started` and `Ended` callbacks stay true; the batch still passes the earlier tiers' words to each later tier (T-2653).
- Smoke's check skip is narrower than the task asked: it also needs the branch to change nothing under `flai/`, since the close-out's check step runs the running flai's check in process and `check.sh` runs the tree's, which may check what the running one does not (ADR-0232). Its lint skip is wider: `markdown` passed for the paths counts when the branch leaves the markdownlint configuration and `lint-md.sh` alone, the rule `TestRepositoryLintsClean` follows.
- T-2661 marked `flaiover`, `integration`, and `smoke` parallel, and made `scripts/flai-build.sh` build to a temporary file and rename it, since `flaiover` and `smoke` may each build `bin/flai` at once. The timing missed criterion 3 on this loaded host (see the story's Notes). I kept the marks: they are neutral to positive here and cost nothing on a host with idle cores. Criterion 3 stays unticked for the operator to judge. I-0319 records the vitest load flake the runs met.
- The first timing run found that T-2653 had not added `FLAI_VERIFY_PASSED` to `docs/operators/settings.md`, which only the integration tier's `TestSettingsIndexIsComplete` checks; fixed in 2d0bff408.
- In a close-out the `markdown` tier runs for the changed files, not whole. The plan was to skip smoke's `lint-md.sh` only when `markdown` ran whole; T-2653 widened it, as the bullet on smoke's skips above says, since otherwise a close-out would never skip it.
