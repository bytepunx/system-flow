# S-0058 An agent learns through MCP that the designer moved work to ready

## Context
The operator moves work to ready on the board and an agent connected through `flai mcp` does not find out: `inbox` lists threads only, `wait_for_events` compares against a snapshot taken when the call starts and returns file paths, and there is no board tool (`flai/internal/mcpserver/server.go`). On 2026-09-19 that cost twelve minutes before S-0040 was pulled. Everything needed to report a change is already in the files: `transitions` carry `to`, `at`, and `by`; `blocked` intervals carry `from`, `until`, and `reason`; `board.md` carries `order`. One thing is wrong underneath: `flai move`, `block`, and `unblock` default `--by` to the config author and ignore `FLAI_AGENT`, so an agent's moves from the command line are recorded as the operator's. Work is in `.flai-cache/worktrees/S-0058` on `story/S-0058`.
