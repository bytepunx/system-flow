## Decisions

- One host per machine is enforced by binding its control address, 127.0.0.1:4241 by default (`FLAI_HOST_ADDR` overrides, so tests and a second machine user can choose): the operating system allows one listener, and a crash frees it. A lock file would need clean-up after a crash, and a flock does not work the same on Windows.
- flai serve talks to the host over that address with a bearer token the host hands its children in the environment (`FLAI_HOST_URL`, `FLAI_HOST_TOKEN`) and writes 0600 beside its state for the CLI. HTTP on loopback, as `flai mcp http` already does; requests with an `Origin` are refused.
- Children leave with the host: the host stops them (SIGTERM, grace, SIGKILL) whenever it returns, and each child gets `--exit-with <host pid>` (the mechanism `flai mcp http` already has), so a host that is killed outright leaves nothing running within seconds. No Linux-only Pdeathsig: Go forks from any OS thread, and that thread's exit would kill the child.
- MCP servers stay one per project. flai serve still decides which projects are served, then asks the host to keep or release each one's server. It starts no process of MCP itself. Without a host (bare `flai serve` in a terminal) it keeps none and says so.
- "Dashboard processes" in AC3 is read as the `flai serve` and `flai mcp` processes that `flai dashboard` used to start. The flaiover container is Docker's, not a flai sub-process, and `dashboard.restart|upgrade|stop` keep running the Docker commands as they do.
- ADR-0040, recorded as accepted, supersedes ADR-0034, since flai serve no longer starts MCP servers, and refines ADR-0029. The operator's story asked for the design, so it was not left as proposed.
- The write for processes is `host.process {process, action}`, not three methods: one command line (`flai host <action> <process>`) and one gate. It was agreed with the S-0107 agent in TH-0004 and TH-0005.
- When flai serve stops, it tells the host nothing, so a restart of serve does not bounce any agent's MCP server. The host keeps the last set until serve names another one, or the host stops.
- The `wip.overlap` warnings with S-0107 are reported to the operator in the story's Notes and the review report, not asked as a question: nothing here can clear them while S-0107 is in progress. Accepting S-0106 first lets S-0107 rebase onto it.
- Each task is committed when it is done, as the operator's start prompt asks. This differs from `git.md`, which commits when the story lands.
- The dashboard's way to the host is four `hostapi` methods that run `flai host … --json`, as every other method runs a flai command: `host.status` and `host.check` read; `host.process` (start, stop, or restart serve, mcp, or all) and `host.upgrade` gate on a new host action, `host`, because an upgrade installs a binary with the operator's GitHub token and a restart stops the process answering. S-0107 only has to draw them.
