# S-0080 One dashboard serves every project the host flai serves

## Context
Follows S-0079/S-0085. One `flai serve` per user (ADR-0029) already holds every project's connection; the dashboard still ran one container per project, each with its own login token and agent credential. This story makes one dashboard, one login, one agent credential serve every project the host's `flai serve` knows about, with a project switcher once more than one is connected.

## Current state
Branch `story/S-0080`, worktree `.flai-cache/worktrees/S-0080`. Tasks T-0306–T-0312.

- **T-0306 done** (`1ba8e28`): the login token and agent credential move from each project's `.flai-cache` to `flai serve`'s own state directory (`a.serveDir()`), shared by every project it serves. `flai dashboard` starts the one container (`sharedContainerName = "flaiover"`) only when it is not already running; otherwise it just registers the project with it. `flai dashboard stop` unregisters and only stops the container when no project is left registered. `flai dashboard status` lists what it serves.
- **T-0307 done** (`61c71b6`): flaiover's `AgentHub` (per-project connection) split from a new `AgentRegistry`, which does the one shared-key handshake once and then routes by the project key the flai names in `hello`. `AgentRegistry.solo()` returns the sole known hub when exactly one project has ever connected, so a single-project dashboard needs no configuration or query parameter — this is what makes the change backward compatible.
- **T-0308 done** (`607f0ed`): `repo()`/`agent()` resolve per request through `AsyncLocalStorage`, keyed by a `?project=` query parameter `hooks.server.ts` sets from the URL. Client-side: a `projectState` store (`$lib/project.svelte.ts`), not a path-based route restructure — `api()` and `EventSource` URLs are tagged via `projectState.tag()`. Choice remembered in `localStorage` and reflected in the URL. `ProjectSwitcher.svelte` is hidden while at most one project is known; picking reloads the page, since most pages load their data once in `onMount`. Found and fixed I-0032 along the way (the switcher never appeared after following the login link — `+layout.svelte`'s signed-in check ran once in `onMount` and never re-evaluated after the client-side redirect off `/login`; now a reactive `$effect`).

The root `/` page shows a project list with each row's glance in place of the single-project table while more than one project is known and none is chosen.

## Decisions
- 2026-09-20: shared secrets live beside `flai serve`'s state (`a.serveDir()`), not under any one project's `.flai-cache` — a project is not special just because it asked first.
- 2026-09-20: the shared container keeps a fixed name (`"flaiover"`), not one derived from a project's name, since it no longer belongs to one project.
- 2026-09-20: `AgentRegistry.solo()` is a placeholder, not a hard requirement that exactly one project be configured — a dashboard with zero or one connected project behaves exactly as before, with no query parameter or setup needed.
- 2026-09-20: project choice is a query parameter (`?project=`) plus a client store, not a path segment (`/p/<key>/...`). Matches the existing client-state pattern (`themeState`, `hostFlai`) and avoids restructuring every route.
- 2026-09-20: picking a project reloads the page rather than wiring every page to react to the choice, since each page already loads its data once in `onMount`.
- 2026-09-20: the glance route bounds each project's answer to 3s and gathers them with `Promise.allSettled`, not flai's usual ~15s default timeout, because one slow project must never delay the page for every other project on it.

## Open questions
- 2026-09-20: what should happen, on upgrade, to a project's old per-project `dashboard.token`/`dashboard.agent-key` files under its own `.flai-cache`? They become dead weight once the shared credential in `serveDir()` takes over. T-0310's ADR should say whether `flai dashboard` cleans them up or just stops reading them.
