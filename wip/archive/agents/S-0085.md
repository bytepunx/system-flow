# S-0085 Stories and epics are editable from the dashboard: title, nature, tags, touches, parent, and body, each change made by flai on the host

## Context
Asked for by the operator on 2026-09-20: stories and epics editable from the dashboard. The operator moved it to in-progress by accident and then said to continue working on stories; it was first in the ready order, so I took it as mine rather than move it back, which would have put it last.

## Current state
In review. Branch `story/S-0085`, four commits on main at 348e638.

- **`flai edit <id>`** (`internal/itemedit`): title, nature, tags, touches, parent, and the body below the heading, any together, in one checked step. A retitle is kept in step in the front matter, the heading, the file's name, the parent's list, the narrative, links to the old file name, and the index. A new parent must be open and of the right type. `--hash` makes a change made meanwhile a conflict (exit 3); the check with the change in place refuses what it introduces and every file is put back (exit 4); what is not allowed is said as `rule:`. One commit holds every file. `--show` loads an item for an editor. Works for tasks too on the command line.
- **Agents are told.** Each edit is noted in `.flai-cache/edits.jsonl`; `inbox` and `wait_for_events` report edits by others as `edited` changes naming what changed, a waiting agent wakes for them, and the MCP instructions say to read the story again.
- **Channel:** `item.show` (read) and `item.edit` (write; hash required; values only as flag values or on stdin). Both in `REQUIRED_METHODS`, so this dashboard needs this flai.
- **Dashboard:** `GET`/`PUT /api/items/:id/edit`; `ItemEditor.svelte`; the item page's `edit…` for open stories and epics, tickable acceptance criteria, and a note on tasks.
- **Documents:** users' pages (and the false claim that items can be retitled from the board is gone), the CLI, dashboard, narrative, and work-hierarchy design pages.
- Gates clean after the last edit: `make flai-test` (with flaiover's 307 unit tests), `make flaiover-test`, `make flaiover-build`, `make check`, `make lint-md` in the worktree and in the main checkout.

Tried in a scratch project (`editlab`, own `FLAI_CONFIG`, its own single `flai serve`, container `flaiover-editlab` on 4396, an MCP server on 4397, all removed since by name and recorded PID) with a browser:

- The form loads the item's values; Save is disabled until something differs.
- One save of a new title, another parent, tags, and touches: the file renamed, both epics' lists right, the narrative's title and heading, the link in a design document, the index, one commit of six files as the lab's git user with the dashboard's trailer, nothing left uncommitted.
- An agent holding `wait_for_events` over MCP was woken and told `edited ... by lab: title, tags, touches, parent`.
- A criterion ticked in place on the page, committed as `edit criteria`.
- A body without criteria on a story in progress: refused with flai's four findings, the text kept, still editing.
- A conflict: with the form open, `flai edit --nature improvement` on the host; the save showed the conflict, "save mine over it" wrote only the body, and the nature the agent had set survived.
- A task's page: no edit button, the note, the body link. An epic through the API: no parents offered, a retitle renames its file.
- Console errors were the 422 and 409 I provoked and the known `favicon.ico` 404.

Not tried: a project with thousands of Markdown files (a retitle walks wip, design, and docs once); a retitle whose new slug collides with another file beyond the refusal in code; the Review page with tickable criteria (only the item page has them); Firefox and Safari; an agent on the real MCP server, which is the installed flai 1.7.0 and will not report `edited` until it is upgraded.

## Decisions
- 2026-09-20: took S-0085 as started, since the operator's accidental move put it where my next pull would have.
- 2026-09-20: one command for fields and body together, so that one save is one check and one commit, and a refusal puts everything back.
- 2026-09-20: a retitle renames the file. The ID is the identity and the slug is cosmetic, so keeping the old name would have been simpler and no link could break; but a file named for a title the item no longer has misleads whoever browses the folder, and the story asked for it. Links are rewritten to pay for it.
- 2026-09-20: edits reach agents through a log under `.flai-cache`, not a front matter key. `ParseItem` is strict: an item with a key an older flai does not know is refused whole, and two flai of different versions do read this repository (the installed one for MCP and now for the dashboard). The same strictness in the host configuration is what made enabling push early impossible on 2026-09-20.
- 2026-09-20: "save mine over it" after a conflict sends only the fields the designer changed, with the new hash, so an agent's change to another field survives. Tried.
- 2026-09-20: the command accepts tasks; the dashboard does not offer it for them. The story puts tasks out of scope for the page, and the command is the agent's tool as much as the designer's.
- 2026-09-20: did the end-to-end check before the documentation, so that what it found (the 500, the leaked path) was written up once.

## Open questions
- 2026-09-20: should the designer edit tasks from the dashboard too? The story says to ask. The command already can; the page only needs to offer the button for tasks.
- 2026-09-20: strict parsing of items and of the host configuration makes every new key a break for an older flai on the same machine. With an installed flai and a tree's flai both in use, that will bite again. Worth deciding: tolerate unknown keys on read (and warn in `flai check`), or keep strict and never add keys without a compatibility story.
- 2026-09-20: the work-management convention could say in a line that an `edited` change means read the story again; today only the MCP server's instructions say it. It is a baseline change (template first), so it is proposed here and not made.
