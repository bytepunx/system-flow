## Decisions

- The function that works out a story's topics lives in `flai/internal/topics`, which already imports `workitem`; `workitem` validates the word itself so the import does not cycle.
- A claim reaches a sub-project by the overlap rule of ADR-0046 (`workitem.PathsOverlap`), both ways, or when the entry is the sub-project's name or a tag.
- `code` is added once per reached sub-project that is not the template, as its own source; a sub-project whose name, tag, and kind share a word gives that topic one source, not three.
- `flai show` text condenses the sources per sub-project (`StoryTopic.Summary`: "flai by tag cli and 7 touches (S-0135, T-0496)"); `--json` keeps every source. Listing each touch made one line of hundreds of characters on this story.
- `flai check` counts topics declared by every story and epic, archived ones included, as vocabulary.
- The host API refuses a topic that is not one word before calling flai (`topicWords`), so the dashboard gets a 400 with the reason.
- The "say so in the release notes" note is met by the subject of the commit that adds the key, since flai's release notes are GoReleaser's commit subjects; the commit was reworded on the unpushed story branch to say it.
