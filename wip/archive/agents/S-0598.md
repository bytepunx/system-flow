## Decisions

- I kept the planner's plan (TH-0894) as drafted: five tasks in three layers.
  - Layer 1, T-2620: `check` gets the item-write run. It waits for nothing, and the other tasks call what it adds.
  - Layer 2, T-2622 and T-2625: `itemnew.Create` and `itemedit.Apply` call the new run. They wait for T-2620 and share no path, so they run at once, one fork each.
  - Layer 3, T-2635 and T-2640: the timing and the ADR with its documents. They wait for T-2622 and T-2625 because they measure and describe the writes as built. They share no path, so they run at once.
- I refined T-2620's scope: `oneItem` runs on the written items, their parents, and their children. A child's rules write findings on the parent's path, such as `item.parent-list` and `item.done-children`, so the parent alone is not enough. The duplicate-ID pass covers every item, since it costs only a map lookup per item.
- T-2620's fork built `check.RunItemWrite(repo, now, check.Write{Items, Paths})`. Relative paths resolve under both the root and the main checkout. The narrative index is checked only when the write wrote `wip/agents/index.md`.
- In T-2622, a creation's run before the write covers the parent and its file, and its run after covers the new item and its parent.
- In T-2625, an edit's two runs cover one set: the item, its parents, its story's own files, the narrative, the index, and the files a retitle relinks. `linking` now finds those files before the write. The story's own files are in the set so that ADR-0197's refusal of a new finding on the story's own task still holds (`TestATickIsRefusedOnANewFindingInsideItsStory`).
- I changed `itemedit/criteria_test.go` myself, outside T-2625's touches, because `runCheck`'s signature changed. Two tests that expected a warning on a file the write neither writes nor reads now expect none, and their names say "stands". That is a behaviour change: refusals are the same, and those warnings are gone. ADR-0264 records it, together with `layout.gitignore` no longer being a warning on a creation, which reverses part of ADR-0213's Consequences.
- MS-0353 with S-0600: both stories change `checker.markdown()`. We agreed that whichever is accepted second keeps both, my write branch and S-0600's `LintFolder` for the whole run.
- S-0599 adds `check.Items` in `check/items.go` for its forecast batch. It is a separate file with a narrower rule set, so there is no conflict. The two could be merged later.
- The layer 2 test run's only failures were two load-timing flakes outside the change: `TestAnOperatorsReplyBecomesADigestEntry` logged a slow request, and `TestImportWithAHostRegistersTheProject` hit its host-running check. Load was 100 to 150 on 24 cores.
- The item lists inside one process are not the cost. `workitem`'s store keeps parsed items by file (S-0156), so a second `List(true)` in the same `flai` process only stats the files. The cost is in the rules that walk files: the markdown lint of `wip`, `node`, the digest, and the documentation.
