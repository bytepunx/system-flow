## Decisions

- The store is process-wide in `workitem`, always on, not opt-in for serve and mcp: `hostapi` opens a `Repo` per request, so a store on the `Repo` would not outlive a request, and one code path means every existing test exercises it. A short-lived command pays one stat per file, which it paid already in `ReadDir`.
- The story's touches were narrowed from `flai/internal/hostapi` to the two design files it records in: the dashboard's methods gain the store through `Repo.List` and `Repo.Get` with no change to `hostapi`, and the claim was holding S-0158, S-0159, and S-0162 for nothing.
- Each task is committed on its own, as the launch instruction from flai serve says; `git.md` says to commit when a story lands. The instruction takes precedence.
- A file whose modification time is within two seconds of when it was read is read again on the next list (the racy-git rule), so that a same-size write in the same timestamp tick is never missed.
