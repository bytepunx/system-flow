# S-011 SvelteKit scaffold and repo reader API

## Context
First story of E-003. flaiover is a SvelteKit app (design/system/flaiover-dashboard.md, ADR-0007): SPA on the client, adapter-node server with /api routes reading the mounted repository, Tailwind 4, MiniSearch later, ECharts later. This story scaffolds the project and builds the repository reader and the base API, the foundation for the explorer, board, and charts stories. Node 24 LTS is the design target; the host has Node 25, so the toolchain must be pinned by the project (.nvmrc, packageManager) and caches kept out of the operator's home per the safety convention.

## Current state
All four tasks done, story in review. flaiover/ exists: SvelteKit 2.63 with Svelte 5.56 runes, Vite 8, TypeScript 6 strict, Tailwind 4.3 plus typography, adapter-node configured in vite.config.ts, ssr off at the root layout, .nvmrc 24, packageManager pnpm@10.34.5, engines node >= 24. src/lib/server/repo.ts reads the mounted repository (manifest, items across kanban and archive with string timestamps, docs trees with front matter, one file raw) through an mtime cache with a chokidar watcher; six API routes under src/routes/api; an overview page shows the project and a type-by-status table. Verified by building and serving against this repository. Scripts flaiover-install/dev/build/test, Makefile targets, .github/workflows/flaiover.yml (lint, check, unit, build), design/tech pins from the lockfile, API table in flaiover-dashboard.md. Lint, svelte-check, vitest, and every repo tier green. Committed at review and pushed; the flaiover workflow runs for the first time on this push.

## Next steps

## Decisions
- Timestamps are kept as strings on the server (yaml core schema does not coerce dates), matching flai's front matter format exactly; the client parses when it charts.
- The repo reader refuses any path outside the root and serves only markdown from /api/docs/file; the manifest is a separate route.
- The nav lists only routes that exist; each view story adds its link, because the svelte lint rule requires resolve() on typed routes.
- pnpm is installed by npm into .flai-cache/pnpm with the store, npm cache, and PNPM_HOME under .flai-cache; CI uses pnpm/action-setup at the pinned version.
- The scaffold's demo route and vitest examples were removed; the e2e test checks the overview heading.
