# S-0151 Temporary banner notifications should be dismissible

## Context

## Decisions

- A temporary banner is one an action leaves on the page until the next action: the board's action notice, the item page's notice, the `/adrs` notice, the document editor's saved notice, and the Publish result. Banners that show state stay without an X, because hiding them would hide something still true: host flai not connected, `UnpushedNotice`, `HostAgentNotice` (collapsible since S-0150), and the pending publish plan with its refusal. Form validation errors next to their form (new item, item editor, thread reply, login) are not banners. Neither are the plain result lines in the Host page's panels (`HostPanel`, `HostProcesses`). If the operator wants an X there too, it is a small follow-up with the same component.
- The X clears the page's own state rather than hiding the banner, so the next action's notice shows again. The component holds no state.
- The test ID sits on the notice's text, not on the banner, so existing `textContent` assertions do not include the X.
- The operator's start message says to commit each task. `git.md` says to commit when a story lands. I followed the operator and committed once per task.
