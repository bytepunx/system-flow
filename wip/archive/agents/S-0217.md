# S-0217 flai exposes the orchestrator's deterministic operations as commands: ordering by policy, promotion candidates, and release evaluation

## Context

The designer chose (2026-10-02) that the orchestrator's arithmetic lives in flai. This story adds it as commands an operator can run without an agent: `flai order --by`, `flai promote --candidates`, `flai release --evaluate`, each with a hostapi read and an MCP tool, and the manifest settings `orchestration.policy` and `orchestration.release`. Worktree `.flai-cache/worktrees/S-0217`.

## Current state

All six tasks are done and committed on story/S-0217, synced onto main, and the five acceptance criteria are ticked. The close-out passed every step (after installing flaiover's dependencies in the worktree, recorded as I-0080), and S-0217 goes to review.

## Decisions

- Layers, as planned: (1) T-0809 manifest settings and T-0810 the ordering function and `flai order --by`, which share no path; (2) T-0811 promotion candidates, waiting for T-0809's policy setting and T-0810's ordering function, and T-0812 release evaluation, waiting for T-0809's `orchestration.release`; (3) T-0813 hostapi reads, MCP tools, and guard, waiting for the three functions it exposes; (4) T-0814 docs and the regenerated reference, waiting for the final flags, reads, and tools.
- `workitem`'s policy names are `manifest`'s constants (`manifest.OrderPolicies`), so the manifest and `flai order --by` cannot drift; `workitem` already imports `manifest`.
- A release threshold of zero is accepted (only negatives are refused), and keys that do not belong to the chosen release policy are ignored rather than reported.
- A promotion candidate meets `design/system/workflow.md`'s definition of ready (a goal, checkbox criteria, an epic not cancelled), which is stricter than `flai move`, which checks only the criteria and the draft flag. The criteria check reuses `rules.go`'s `hasCriteria`.
- A backlog story without touches is refused only when `Holds.Of` would hold it, that is while some story is in progress or review: the candidate check asks exactly what the story would meet in ready, so `hold.go` is unchanged.
- `release.Batch.IDs()` collects the pending IDs for both `PendingIDs` and `EvaluateRepo`; `EvaluateRepo` returns a history error rather than reading it as nothing pending.
- T-0813's touches widened with `workitem/policy.go` and `cmd/order.go`, so that `flai order --by` and the `order.by` read share one repo-level function.
- The guard reads `order`, `promote`, and `release` by flag (`flagReads`): `--by` without `--apply`, `--candidates`, `--evaluate`. Any `--apply`, even `--apply=false`, makes `order` a write, to stay conservative.
- The three reads are added to the dashboard's `REQUIRED_METHODS`, as every read is: the contract test requires it. A dashboard connected to an older flai reports them missing, as it does for any new read.
- The agent definitions' `tools:` lists (explorer, verifier, planner) are left as they are: the guard passes the tools, and which agents list them is S-0218's, which defines the orchestrator agent.
