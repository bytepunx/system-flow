## Decisions

- The planner's three tasks stand, in three layers, one task each: T-1199 moves the coverage test into `flai/internal/itemedit/covers.go` with no change of behaviour; T-1200 waits for it because it calls that function; T-1201 waits for T-1200 so the documents describe what is sent. No two tasks run together.
- T-1200 also touches `flai/internal/messages/messages.go` and its test: one helper there replies on the pair's open conversation, adding the new paths to its `about`, or starts one. `messages.Send` checks that each `about` path exists, which a path the commit deleted, or one only the worktree has, fails; the helper takes git's paths as they are. S-0332, held behind this story, touches `messages.go` too and can reuse the helper.
- The notice is sent right after the commit step, before the sync, so a sync that stops on conflicts loses no notice: the run that continues it has nothing to commit. It names the commit as made; after a rebase the subject still identifies it, and the old hash still resolves.
- T-1199 is worked by the story's agent, not a sub-agent: it is a move of some 30 lines, quicker done than briefed.
- The notice does not tell the agent to sync, though T-1201's Work says "sync before relying on it": the change is on the other story's branch, so a sync brings it only once that story is accepted. The notice names `git show <hash>` instead.
- The convention says to reply to a task's change notice either way, not only when the change breaks the work: the conversation awaits the told story until it replies, and since S-0335 an unanswered message keeps `wait_for_events` from ending an agent and marks a run as asked.
- The help of `flai task done` gains the tell step in T-1200, with `docs/users/flai-reference.md` regenerated there, since the reference test pins the help text.
- `itemedit.Covering` leaves out no wip path: a story with an empty claim is told of every changed path, as the notice at acceptance does.
