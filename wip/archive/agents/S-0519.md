- Operator decision (TH-0726, alex, 2026-10-29T01:59:12Z, confirming the orchestrator's recommendation): over HTTP `permission_prompt` holds a write at most 45 s; over stdio it keeps four minutes. I-0228 stays out of this story.
- T-2229 (sub-agent): `Options.PermissionHold`, where zero means four minutes, so stdio's `flai mcp` and every existing test are unchanged; a negative value refuses at once. `ask.Hold` with a bound of zero or less reads the thread once. I made the `folder.go` registration change myself, since it was outside the task's touches and is shared with S-0532 on MS-0219. I also added a tools/list check that the HTTP description says 45 seconds.
- Left as they are: the start prompt in `flai/internal/harness/harness.go` ("at most four minutes" is still true at 45 seconds, as the planner noted); `design/system/agent-narrative.md` and the `timing.go` comment, which still say "5 over HTTP", belong to I-0228's fix.
