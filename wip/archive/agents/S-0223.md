The board watcher copied the two settings files, which change only a hook. The analyzer definition gives an agent tools, so alex copies it.
- T-0968 started while T-0957 was still in progress, because the only part of T-0957 left was the definition file, which T-0968's tests do not read.
- A report's status follows the documentation standard: `draft` while the analyzer writes it, `active` once the run has ended, and `deprecated` when a later report replaces it. T-0960's sub-agent had proposed `final`, which needed an exception to the standard.
- An analyzer run that exits 0 without writing a report is recorded as `failed`, since it did no work.
- `docs/operators/settings.md` gets the `analysis.*` rows and `FLAI_FOCUS` now rather than in T-0975, because `TestSettingsIndexIsComplete` fails without them.
- `flai analyze` starts the run itself through `serve.Analyze`, as `flai plan` does. With no `flai serve` running it warns rather than refusing, though T-0971's text said it should refuse. This way the CLI and `analyze.run`, which runs it, start runs in one place.
- The analyzer's prompt and definition tell it which status to write: `draft` while it writes the report, `active` once it is done. T-0975's sub-agent found that nothing said so. Help text no longer mentions an Analyze button, since the dashboard has none until S-0228.
- T-0975 started while T-0957 was still in progress, for the same reason T-0968 did.
- Left as they are, the same as for the planner: `flai analyze` in a shell isn't refused to a story's agent; the guard doesn't see shell redirections; the analyzer's log can't be streamed (S-0228's page); and a second run with the same focus on the same day overwrites the first run's report.
- TH-0152's assumptions are taken as decided: a run with no focus is `all` and writes `<date>-all.md`; the window is front matter `from` and `to`; the guard allows writes only under `design/analysis/` (issues are S-0224's).
