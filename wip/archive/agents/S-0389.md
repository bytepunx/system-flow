# S-0389 TestTheGateIsAskedOnEveryAttempt fails now and then: the state reads refused before the second refusal is logged

## Context

Remediates I-0146: `Client.Run` in `flai/internal/channel/channel.go` published an attempt's end with `setState` before it logged it, so `TestTheGateIsAskedOnEveryAttempt` could see the state refused before the second refusal was written.

## Current state

The close-out passed every step at `adddb8fc`, integration and smoke included. T-1587, T-1588, and T-1589 are done. Both criteria are ticked: `Run` and `serveOnce` each log before they publish the state, a slow-writer test covers each, and I-0146 is closed. S-0389 goes to review.

## Next steps

## Decisions

- The planner's plan stands as approved on TH-0452: layer 1 is T-1587 (the reorder and the test), layer 2 is T-1588 (close I-0146), after T-1587 because the close names the fix.
- T-1587 was worked here, not by a task sub-agent: it is one function and one test in files already read, so a sub-agent would have been slower (`delegation.md`).
- `Run` reads whether the connection was proven from `State()` before logging, since only the attempt sets `Since`; it logs nothing once ctx ends or the client drains, as before, then publishes the state and returns.
- The new test, `TestTheStateIsPublishedAfterTheAttemptIsLogged`, logs through a writer that sleeps 200ms before each write: it failed on the old order (0 refusals logged when the state read refused) and passes on the new one. `TestTheGateIsAskedOnEveryAttempt` is left as it was.
- The first close-out failed `TestAConnectionRecordsAndWarnsOfTheUnsignedSides` in the integration tier: `serveOnce` published the connected state before it logged the connection, the same cause as I-0146 in another place. T-1589 was added after T-1587, since it uses T-1587's slow writer and changes the same two files. It moves the two log lines before the `setState`, and `TestTheStateIsPublishedAfterTheConnectionIsLogged` failed on the old order. No other `setState` in `channel.go` publishes something a log line describes.
