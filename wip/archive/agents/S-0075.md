# S-0075 Every write the dashboard makes goes through the channel, and the image no longer carries flai, git, or ssh

## Context
Fourth story of ADR-0029's build order: the dashboard's writes leave the container. The twenty flai commands it runs inside the container become named methods served by `flai serve` on the host; acceptance streams its progress over the channel; the image drops `flai`, `git`, and `ssh`. Stacked on `story/S-0074` (in review, itself on S-0073 in review); the operator was told and asked to accept in order. After this story the clone is still mounted but unused; S-0077 removes it. `/mcp` in the container stops working with the binary gone (it answers 503); S-0076 moves MCP to the host.

## Current state
All three tasks done; three commits on `story/S-0075` (198cc44 flai's write methods, b12b4e1 the dashboard and the image, and the documentation), stacked on `story/S-0074` and `story/S-0073`, both in review. `make flai-test`, `make flaiover-test` (290), and `make flaiover-build` pass. In review; accept S-0073, S-0074, then this.

Tried end to end (WSL2, Docker Engine) with a scratch project, `flai serve` from this tree, and the new image run by hand with **no project mount** (only the two secrets): every kind of write from the API (listed in `design/system/flaiover-dashboard.md`), commits authored by the host user with the dashboard's trailer, a refused story leaving nothing, a document conflict as 409, an acceptance of a story on its own branch and worktree streamed in 230 ms (merged, archived, worktree and branch removed: ADR-0022's problem is gone because git runs where the paths are), and the same from the review page in a browser. With `flai serve` frozen by PID the acceptance ended after 11 s with "may have completed on the host", and had not run; resumed, flai reconnected and the acceptance went through. No `flai`, `git`, or `ssh` in the container. Image 692 MB against 740 MB. Everything scratch removed; the operator's dashboard untouched.

Not tried: macOS and Windows; the one retry of a write after a reconnect end to end (unit tested on both sides: the journal in Go, the retry in TypeScript).

## Decisions
- 2026-09-20: flai names the methods it offers in `hello` and the dashboard reports what is missing. The image used to bring a flai of its own commit; now the host's flai can be older than the dashboard, and that should be said once, not found page by page. A Go test keeps the dashboard's list and flai's table the same.
- 2026-09-20: the journal of request IDs is in memory, per `flai serve` process, for ten minutes. It covers a lost connection; it does not cover `flai serve` restarting between the two attempts, and the dashboard retries only within five seconds.
- 2026-09-20: `/mcp` is left in place answering 503 instead of being removed here: S-0076 owns its removal and the ADR that goes with it.
- 2026-09-20: `--flag=value` map iteration made one command line's order random and a test flaky; found by the suite, fixed before the commit that carries the routes.
- 2026-09-20: a write method validates its arguments, builds the command line itself, and runs flai (its own executable) in the project's folder, reading the JSON and the log events as the dashboard did. The rules stay in one place, the commands' own tests keep covering them, and nothing the dashboard sends is ever a flag: values go in as `--flag=value` or after `--`.
- 2026-09-20: who made a change is the manifest's owner, decided by flai; the dashboard no longer names them. A holder of the dashboard token cannot sign a move with someone else's name.
- 2026-09-20: the subprocess inherits `flai serve`'s own configuration (the operator's), not a config inside the clone as the container's flai used; git identity is the host's by itself.
