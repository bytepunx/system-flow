# S-0076 flai serves MCP itself on the host, over HTTP as well as stdio, and the dashboard's /mcp endpoint goes

## Context
From S-0071's finding and ADR-0029: the operator decided on 2026-09-20 that MCP moves down to flai as a process on the host and agents do not work through the dashboard. `/mcp` had answered 503 since S-0075 took flai out of the image. Pulled after S-0073 to S-0075 were accepted; while releasing those I found that release flai never ran for 1.5.1 to 1.5.3 (I-0026) and fixed the cause here.

## Current state
In review. Branch `story/S-0076`, six commits on main at 6a51623.

- `flai mcp` is stdio as before; `.mcp.json` unchanged and checked (11 tools over stdio).
- `flai mcp http` serves the same server over Streamable HTTP at `/mcp`; `start`, `stop`, `status`, `token [--rotate]` manage it as a process of its own, one per project. Token, state, log, and remembered address under the main checkout's `.flai-cache`.
- `internal/mcphttp`: bearer in constant time, an `Origin` refused, the agent from `X-Flai-Agent` or the client's name, sessions capped and idled out, 64 requests in flight, project identity headers on every answer. Sessions for revisions up to 2025-11-25 and stateless for 2026-07-28 behind one address.
- flaiover: `/mcp` answers 410 with where MCP lives; `mcpbridge.ts`, `flai.ts`, `FLAIOVER_MCP_*`, and the bearer-only rule are gone; a test keeps the server from starting any process.
- ADR-0030 supersedes ADR-0024 and carries project identity forward. `design/tech/go-libraries.md` records the revisions and what changed. Work-management baseline says how an agent connects, template first.
- `flai push --pending` and `flai accept` push tags three at a time, the branch last.
- Gates: `make flai-test`, `make flaiover-test` (286 tests), `make flaiover-build`, `make check`, `make lint-md`, `make template-test` all clean.

Tried end to end in a scratch project (own `FLAI_CONFIG`, image `flaiover:s76`, container `flaiover-mcplab` on 4392, MCP on 4391, all removed since): a session over HTTP as a 2025-06-18 client, `inbox` under the header's name, `wait_for_events` woken 0.26 s after a move made through the scratch dashboard's API, the old `/mcp` answering 410, `start` twice, the address kept across a restart, `token --rotate` restarting the server, and `stop` with a wait held (0.33 s, the wait answered `timed_out`). Both revisions were tried with the SDK's own client in tests.

Not tried: a real agent client (Claude Code) against the HTTP server, because adding a server to the operator's client configuration is theirs to do; an address beyond loopback; Windows and macOS; many sessions at once beyond the cap test.

## Decisions
- 2026-09-20: HTTP mode is a process of its own per project (`flai mcp start`), not part of `flai serve`. The operator's words were "flai MCP can start a server process"; an agent's server must work with no dashboard, and `flai serve` exists to dial dashboards. One listener for all projects inside `flai serve` is recorded in ADR-0030 as the alternative to revisit with S-0080.
- 2026-09-20: both transport generations at one address. SDK 1.8.0 serves 2026-07-28 over HTTP only without sessions and refuses it with them; today's clients need sessions to name themselves at `initialize`. The criterion says "sessions capped": sessions are capped where they exist, and requests in flight are capped everywhere.
- 2026-09-20: its own token, not the dashboard's, so the dashboard's login cannot act as an agent and each rotates alone.
- 2026-09-20: an `Origin` header is refused outright, stricter than ADR-0024's same-host rule: no browser has business here.
- 2026-09-20: `/mcp` on the dashboard answers 410 without a token, because the message says nothing about the project and a client with a stale token should still be told.
- 2026-09-20: the session cap is loose (two opening in the same instant may both pass) rather than holding a lock across a request.
- 2026-09-20: the HTTP server serves the main checkout, where stdio in a worktree serves that worktree. An HTTP agent has no working directory on the host to mean anything else.
- 2026-09-20: fixed I-0026 inside this story though it is not in its criteria: it is small, and S-0077 to S-0080 accepted together would have hit it again. Tags go first and the branch last, because `pending.Detect` finds unpushed tags through the branch.
- 2026-09-20: a stop ends held `wait_for_events` calls as timed out (`Options.Closing`), found in the end-to-end check, where stop took 5 s with any idle agent connected.
