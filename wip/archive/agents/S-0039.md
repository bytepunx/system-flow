## Current state
Complete. `flai mcp` serves the repository over MCP on stdio using the official Go SDK (v1.8.0): `inbox`, `thread_get`, `thread_open`, `thread_reply`, `thread_resolve`, `item_get`, `item_move`, `doc_get`, `who_touches`, `wait_for_events`, plus `flai://design/` and `flai://docs/` resources. Writes go through `threads` and a new `workitem.Transition` that `flai move` now shares. Tests drive the server through in-memory transports: tool listing, inbox and replies with the narrative mirror, rule refusals reaching the agent verbatim, the acceptance refusal, path confinement for documents and resources, and the round trip where a designer's reply wakes a waiting agent in under a second. The built binary was driven over real stdio from the main checkout: handshake, tool list, inbox, item read, acceptance refusal, resource read, clean stdout. Template `.mcp.json`, this repository's `.mcp.json`, CLAUDE.md checkpoints, user docs, CLI design, and the tech pin are in. Story in review.

## Decisions
- The official Go SDK rather than hand-rolled JSON-RPC: typed tools with inferred schemas and in-memory transports for tests.
- `wait_for_events` polls file fingerprints every 250 ms instead of using inotify, which is unreliable across bind mounts and WSL; the tree is small and the latency target is a second.
- The inbox is about who spoke last, not status alone: a thread awaits the agent when its last entry is not the agent's, which handles both new questions and follow-ups.
- `doc_get` and the resources serve markdown under the layout folders only; the server is a view of the documentation and work, not a file server.
- `workitem.Transition` was extracted so the CLI and the server cannot drift: rules, save, board order, and index in one place.
- Agents cannot accept: `item_move` refuses stories and epics to done, consistent with S-0046.
