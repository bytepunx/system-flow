# S-0045 Charts do not update when switching chart type

## Context

## Current state
Complete. The chart instance in `Chart.svelte` is now reactive state and the redraw effect reads `option` before touching the instance, so every new option reaches ECharts; a second effect resizes on height changes. A jsdom component test (new `client` vitest project) mounts the component with ECharts mocked, changes option and theme, and failed on the old code. Verifying in the browser exposed a second defect the first had hidden: `flai stats --json` emitted `null` for empty lists and the aging chart threw, freezing the page; the dashboard now normalises reports and flai emits `[]`, each with a test. Checked on the served build: all seven chart types redraw in light and dark, for story and task selections, with type-filter and theme changes, and no page errors, including against the older binary that still emits `null`. Story in review.

## Next steps
1. Operator review and `flai accept S-0045` (remediation: flaiover patch, flai patch).

## Decisions
- `chart` is `$state.raw`: the effect must rerun when the asynchronously created instance appears, but the ECharts instance itself must not be proxied.
- The mount path no longer calls `setOption` itself; the effect is the single place that draws, so the first draw and every later one take the same path.
- Reports are normalised in the chart builder and on load rather than guarded field by field, so a future list cannot reintroduce the crash; flai is fixed at the source as well, since other consumers (the MCP server to come) read the same JSON.
- Component tests run in jsdom with Svelte's browser build; `jsdom` is recorded in design/tech.
