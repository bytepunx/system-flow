# S-0091 The flai CLI should install itself to a user's home directory or a configurable path

## Context
The operator reported that installing flai requires `sudo` because `install.sh` defaulted to `/usr/local/bin`, which keeps an agent from upgrading itself and keeps flai from detecting and fixing an out-of-date host on its own.

## Current state
Done, one task (`T-0321`, `afe022e`), in review.

- `install.sh` defaults `FLAI_INSTALL_DIR` to `$HOME/.flai/bin`, beside flai's own config and cache under `~/.flai` (ADR-0008): a directory the user already owns. The `sudo` fallback is removed entirely; a directory that cannot be created or written to is a plain failure naming `FLAI_INSTALL_DIR`, not a retry with elevated privileges.
- The script always prints where it installed and a `PATH` line to add, whether or not `flai` already resolves there (previously the line only appeared when nothing shadowed the new install).
- `flai self-upgrade` needed no code change: it already replaces whatever `os.Executable()` returns, so once installed under `~/.flai/bin` a bare `flai self-upgrade` (no `--dir`) needs no `sudo`. Checked this is actually true rather than assuming it, both by hand (a scratch `$HOME`, real release download, `self-upgrade --check` afterward) and in `scripts/install-test.sh`, which now also covers the default path under a scratch `HOME` and asserts no `sudo` invocation remains in `install.sh` outside a comment, alongside the existing explicit-`FLAI_INSTALL_DIR` and `--dir` cases.
- `README.md`, `docs/users/flai.md`, and `design/system/flai-cli.md` updated to describe the new default and drop the `sudo` language.
- All three acceptance criteria met. `scripts/flai-test.sh` (lint, all three test tiers including the extended smoke/install-test) and `scripts/lint-md.sh` clean on the main checkout.

## Decisions
- 2026-09-22: no ADR. This changes a default path and a script's behavior, not a structure, technology, or contract between parts (`design/conventions/decisions.md`). Recorded here and in living design (`design/system/flai-cli.md`, `docs/users/flai.md`, `README.md`) instead.
- 2026-09-22: default install directory is `$HOME/.flai/bin`, not e.g. `$HOME/.local/bin` or `$HOME/bin` — it sits beside the config and cache flai already keeps under `~/.flai` (ADR-0008), so there is exactly one place a user needs to know about, and one line to add to `PATH`.
- 2026-09-22: `FLAI_INSTALL_DIR` pointed somewhere unwritable (e.g. `/usr/local/bin` without prior `sudo` setup) is now a plain fatal error, not a `sudo` fallback. A script that silently escalates privileges when its default target isn't writable is worse than one that names the problem and lets the caller choose a writable path or arrange access themselves.
- 2026-09-22: no change to `flai self-upgrade` itself — its existing "replace whatever `os.Executable()` returns" behavior already does the right thing once the default install path is fixed. Verified this rather than assumed it (see Current state), since it's exactly the kind of thing that looks obviously true and isn't always.
