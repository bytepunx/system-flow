# S-0573 Stories in new projects ignore default agent/harness settings

## Context

The cause was found on the host. In `/home/alex/git/bytepunx/marketeer`, the 32 seeded stories were made (2026-11-03T08:04Z) before `agent:` was set in its `system-flow.yaml` (by hand, uncommitted, 17:26Z). ADR-0037 copies the default into a story only when it is made. `flai serve` reads the agent from the story alone, so the dashboard's Start agent for S-0001 was refused at 17:17:34Z: `S-0001 names no harness, and no command is set on the host` (`~/.flai/serve/journal.jsonl`). The strategic agents already resolve the default at their start (`Manifest.Agent.With`).

## Decisions

- ADR-0251, refining ADR-0037: a story whose agent names no harness starts with the project's default as it is at the start, with the story's own fields over it. A story that names a harness keeps its agent whole, so ADR-0037's "no model change under a working agent" holds. Nothing is written to the story. Recorded as accepted because it carries out the operator's goal for S-0573. Copying the default into open stories when it is set was rejected: it misses a default set by a hand edit, as marketeer's was.
- Plan, in two layers. Layer 1: T-2454 (`Repo.AgentOf` in workitem) and T-2456 (docs, help, dashboard heading) have no path in common and run together. Layer 2: T-2455 (serve reads the agent through `AgentOf`, with the regression test) waits for T-2454 because it calls `AgentOf`.
- T-2455 records the resolved agent as a run's `StoryAgent`. Setting a default therefore counts as an agent change for an agent-less ready story that last ran on the host's command, and the launcher starts it once more. That is what ADR-0251 intends.
- No `CHANGELOG.md` line: this repository has none at its root, and `flai release` writes the release notes. `CHANGELOG.md` was dropped from T-2456's touches.
