## Decisions

- Cause of I-0175: `itemedit.Apply` reads the item, runs a whole-repository `flai check` before writing, then saves its copy whole. The replanner's forecast write (by flai, 07:33:45Z) read S-0463 before `flai story start` moved it and wrote it back after, undoing the move. Every writer is read, change, `Repo.Save` with no lock, so any slow one can do the same.
- Fix in `Repo.Save` rather than at its 48 call sites: an item keeps the canonical form it was read in; Save takes one lock for item writes, reads the file again, and merges a stale copy by top-level front-matter key and body, refusing a key both changed. No call site changes, and a lost write becomes a merge or a loud refusal.
- One lock file for all item writes, not one per item: a write holds it for milliseconds, and one file leaves no lock per item in `.flai-cache`.
- Plan, one task per layer: T-2007 (the merge in Save) first; T-2008 (the edit's undo puts back only its own change) waits for it because it uses the merge; T-2009 (ADR, design, close I-0175) waits for T-2008 so the documents describe what was built.
- Cancelled the planner's T-1999, T-2001, T-2002, T-2005 (drafted 12:10 to 12:11Z, while this agent planned; TH-0577). They put a lock and a fresh read into every writer; T-2007's merge inside `Repo.Save` covers every writer at once, and two concurrent starts of one story now conflict instead of both passing.
- T-2007 merges the body by level-two section, not as one part, as its sub-agent found: as one part, 21 existing tests held an old copy across a child's creation (a line under `## Tasks`) and a move's note (under `## Notes`) and conflicted; before this story those saves silently dropped the child line.
- T-2007 also gives three `flai/cmd` test fixtures the `.gitignore` for `.flai-cache/` that real projects have, since the lock file lives there.
