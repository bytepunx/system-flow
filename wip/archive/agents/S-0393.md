## Decisions

- I kept the planner's six tasks and their layers, because each task covers one part of the criteria and the touches do not overlap within a layer.
  - Layer 1: T-1609 (the PR body), T-1610 (host action, env, guard), and T-1611 (the ADR) run together. None waits on another and their touches are disjoint.
  - Layer 2: T-1612 (the serve loop). It waits on T-1609 for the title and body, and on T-1610 for the `forge` action.
  - Layer 3: T-1613 (the `flai forge push` and `status` commands). It waits on T-1612, whose exposed function both commands call.
  - Layer 4: T-1614 (the docs). It waits on T-1611 for the ADR it links and on T-1613 for the commands' final flags.
- T-1612 keeps a state file per story under `.flai-cache`: the last pushed head, which the lease names, plus the last outcome and its reason. `flai forge status` reads that file to say why nothing was pushed (criterion 2), so the status command needs nothing more from serve.
- The guard refuses `flai forge push` only. `flai forge merge` does not exist yet, and whichever story adds it adds its refusal, so no speculative rule goes in now.
- Tasks were closed with the tree's flai (`scripts/flai.sh task done`), because the installed flai 1.57.0 is behind 1.58.0 and its `task_done` refuses (I-0157 bumped).
- T-1610 found that agents' environments are built in `serve/agents.go` (`launcher.spawn`), not `start.go`, and filtered there. The token's variable is dropped for every forge flai knows, whatever the acceptance mode. `cmd/serve_actions.go` passes the names the host gives, and `guard/call.go` wires the new rule in. All three files were committed with T-1610.
- T-1609 marks the template's places with `<!-- flai:name -->` pairs: story, criteria, definition-of-done, and verify. The project's own definition-of-done checklist is kept as it wrote it, and flai's default fills in only where there is no mark.
- T-1612 moved `forge.New` out of cmd so that serve can build the adapter. Origin commits flai never pushed are refused, not forced. A failure thread gets a new entry only when its reason changes.
- `flai forge push` runs on the operator's word without the host action, but it still needs pull-request mode and the story in review. It exits 1 when skipped. `flai forge status` never calls the forge's API.
- Criterion 4 follows the planner's recommendation on TH-0463 question 4: a force-with-lease push of story branches only. The operator finalized the story with that criterion. TH-0496 asks them to confirm, and work goes on meanwhile.
