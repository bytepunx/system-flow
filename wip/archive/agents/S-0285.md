## Decisions

- The catch is the guard's refusal, not a `SubagentStop` wake-up of a held `wait_for_events`: `flai mcp` does not know the Claude Code session it serves, so a wake-up would have to map session to agent name across processes, while the guard sees `session_id` on every hook input already. The guard learns which sub-agents run from `SubagentStart` and `SubagentStop`, whose inputs carry `session_id`, `agent_id`, and `agent_type` (seen on 2.1.290, 10:33Z runs).
- The refusal applies to a story agent flai serve started (`FLAI_STORY` set, no `FLAI_ROLE`): the planner and the orchestrator wait on `wait_for_events` between decisions by design, and an interactive session has an operator watching.
- "A thread awaits the designer" is read as "an unresolved thread on the story or one of its tasks": the guard cannot tell the agent's thread name reliably (`FLAI_AGENT` in a hook can differ from the name `flai mcp --agent` writes threads under), and an open thread is what the designer answers.
- A stale record (a session that died with a sub-agent out) costs nothing in the legitimate case: a wait with a thread open passes whatever the record says.
- The sub-agent hooks run only with `FLAI_STORY` set and always exit 0, printing nothing: a `SubagentStop` hook that exited 2 would keep the sub-agent going, and the record is read only in a story agent's session.
- The template is released as 1.0.56 (patch: the convention and the settings change, no breaking change).
- This story's own agent ran on the installed flai, whose prompt is the old one. It waited for layers 1 and 2 with foreground launches (two sub-agents in one message each time), which returned as each finished.
- Plan, by `--after` and `--touches`:
  - Layer 1: T-1004 (guard), T-1005 (`wait_for_events` description), T-1006 (start prompt). Disjoint paths, no after; T-1004 is long, the other two short.
  - Layer 2: T-1007 (delegation.md, template hooks, template release) waits for T-1004 (the hooks call its guard) and T-1006 (it repeats the prompt's wording); T-1008 (design, ADR, docs) waits for T-1004 to T-1006, whose behaviour it describes.
  - Layer 3: T-1009 (this repository's `.claude/settings.json`) waits for T-1004 and T-1007, whose file it copies, and needs the operator to paste it.
  - Layer 4: T-1010 (record, close I-0083) waits for every other task.
