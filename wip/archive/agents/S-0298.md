# S-0298 The Host Updates Tab Allows an Operator to Rollback to A Previous Version

## Context

Rollback from the Updates page: list the published flai and dashboard releases over the CLI, the host API, and MCP, and deploy a chosen one over the CLI and the host API. The operator answered TH-0202: MCP lists only, and a dashboard version chosen on the page applies once, with no pinning.

## Decisions

- The planner's tasks are kept as drafted: each names its files, its waits, and its done-when, and together they cover the three criteria.
- Layer 1: T-1038 (ADR and design, which fixes the names) and T-1039 (`selfupgrade.List`), run together: no path in common, and neither needs the other.
- Layer 2: T-1040 (CLI listings, after T-1038 for the names and T-1039 for `List`), T-1041 (MCP `versions`, same waits), T-1042 (dashboard routes, after T-1038 for the method names only, since its tests stand the channel in). Run together: Go cmd, mcpserver, and flaiover share no path.
- Layer 3: T-1043 (host `--version` and `versions`, after T-1040, whose `--list` and published refusal the launcher runs) and T-1044 (Updates page, after T-1042's routes). Run together.
- Layer 4: T-1045 (host API reads and upgrade parameters, after T-1043's commands).
- Layer 5: T-1046 (docs and the generated reference, after every user-facing change).
- Replanned after layer 1: T-1041 now also waits for T-1040, since `flai/cmd` imports `flai/internal/mcpserver` and T-1040's cmd tests would build T-1041's half-done edits in the shared worktree. Layer 2 is T-1040 with T-1042; T-1041 runs with T-1044 (Go and Svelte), then T-1043, T-1045, T-1046.
- ADR-0117: dashboard releases are listed from the `flaiover/vX.Y.Z` tags (git matching-refs), not GitHub releases, because the dashboard's release workflow pushes an image per tag and makes no GitHub release (0 flaiover releases, 97 tags on 2026-10-07).
- Layer 1's two tasks were closed apart by hand-committing T-1039's files first, but `task_done T-1039` then swept T-1038's design files into its commit c211addb (I-0104, bumped). From layer 2 on, each task's files are hand-committed before either `task_done`.
- ADR-0118 refines ADR-0117 §5. A dashboard release chosen on the page keeps running through restarts (`flai dashboard restart`, flai host's watch) until an upgrade without a tag or a start after a stop. That is how `flai dashboard upgrade --tag` already behaved, and the operator's TH-0202 answer was "apply once, like `flai dashboard upgrade --tag`". Making a restart go back to `latest` would undo a rollback on its own.
- The new methods `host.versions` and `dashboard.versions` join flaiover's `REQUIRED_METHODS`, as every host method has. An older flai still connects and gets the "upgrade flai" banner. The hostapi contract test requires it.
- Shared helpers move to the packages both sides use, once their second use arrived: `selfupgrade.Token`, `DashboardTagPrefix`, and `VersionList`; `buildinfo.Bare` for a bare X.Y.Z; and one release table, `writeFlaiReleases`, for `self-upgrade --list` and `host versions`. The test-only `hostLauncher.upgrade` wrapper is gone.
