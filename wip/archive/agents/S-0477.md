## Decisions

- Fix: `components list` joins the guard's reads (`cliReads`), open to every agent, since it only reads the manifest and props. `components serve` is a story's task sub-agent's, not a read-only sub-agent's (ADR-0141: it writes under `.flai-cache` and may install a worktree's dependencies) and not the strategic agents' own; it changes no work item, thread, or history (ADR-0060). `components config` writes the manifest and stays refused. Recorded as an ADR in T-2043.
- Plan: two layers. T-2043 (guard, tests, ADR, docs) first; T-2044 (close I-0165) waits for it, since the issue closes only once the fix is in.
- S-0472 (I-0156) asks for the same change; this fix covers it. Its cancellation is the operator's, raised on a thread on S-0472.
- The planner's T-2032, T-2034, T-2036 (TH-0593) were written while the story started. T-2043 already did most of T-2032 and T-2034, so they carry only what T-2043 left: T-2032 the end-to-end case in `flai/cmd/guard_test.go` with flai's real command names, T-2034 the sentence in `design/system/agent-adapters.md`. T-2036 closes I-0165 after both; T-2044 duplicated it and was cancelled. Unlike the planner's assumption, serve is refused to read-only sub-agents and needs an ADR (ADR-0186), since it writes files ADR-0141 forbids them.
- T-2043's sub-agent needed `flai/internal/guard/call.go`, outside its touches, to pass read-only-ness to the sub-agent rules; the story's agent made that two-line edit and widened the touches.
