# S-0369 A thread entry's author is whatever --by says, so an agent with a shell could answer a permission thread as the owner

## Context

Remediates I-0091: a served agent with a shell could write a thread entry as the owner with `--by alex` or `FLAI_AGENT=alex`. The operator confirmed on TH-0418 the orchestrator's narrowing: refuse a served agent's `--by`, `--placed-by`, `FLAI_AGENT`, or `FLAI_SESSION` only when it names anyone but the agent's own name.

## Decisions

- Plan kept as the planner drafted it, in four layers: T-1465 (ADR and design) and T-1466 (`threadAuthor`) share no path and run together; T-1467 (the guard rule) waits for T-1465, whose ADR settles what it refuses; T-1468 (`docs/users/flai.md`) waits for T-1466 and T-1467, so it describes what they built; T-1469 (close I-0091) waits for T-1468, the last of the work its reason names.
- T-1465 and T-1467 rewritten to the narrowing confirmed on TH-0418: refuse only a name that is not the agent's own, never the flags or variables as such.
- The agent's own name is the hook's `FLAI_AGENT` or the name flai serve gives the run (`agent-S-nnnn`, `planner-<FLAI_ITEM>`, `analyzer`): in this project `.claude/settings.local.json` overrides `FLAI_AGENT` to `system-flow`, so both must pass.
- An emptied or unset `FLAI_AGENT` is refused: once T-1466 makes the config's author the fallback, it would write as the operator.
- The rule goes in a new `flai/internal/guard/authors.go`, with tests in `authors_test.go`, not `thread_test.go`: S-0368, in review, rewrites the guard's command parsing in `guard.go`, so a file of its own keeps the two stories' changes apart. Touches changed to match.
- Shared `design/system/agent-adapters.md` with S-0351 on MS-0082: S-0369 changes only `### Permissions` and `### Asking the owner before a protected write`.
- Left for the operator, raised in the review report rather than as open questions: `design/conventions/session-start.md`'s project addition says to set `FLAI_AGENT` to the model name, which a served agent is now refused on the command line (flai serve has set it already; setting it to its own name passes, so the baseline `tooling.md` rule holds); and the orchestrator is not held to its `FLAI_AGENT` (an ADR-0143 residual, per TH-0418's confirmed scope).
