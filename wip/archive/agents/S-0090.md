# S-0090 Operators should be able to answer open questions in via the dashboard

## Context

Threads already have full reply/resolve support from the dashboard (`Threads.svelte`, `/api/threads/[id]/reply`). A hand-written bullet under a narrative's `## Open questions` — the OTHER shape of "open question", one with no thread of its own — had none: the documented convention (`design/system/agent-narrative.md`: "Answered questions move to Decisions") was entirely manual, with no code path for the operator to act on it at all, let alone from the dashboard.

## Current state

Done. `flai stream answer <story-id> "<question>" "<answer>"` removes the matching bullet and records it under `## Decisions`; `stream.answer` exposes it over the channel; the inbox's question entries now carry their story's id; `InboxView.svelte` offers an inline answer form on each one when writable, posting to `/api/streams/:id/answer` and refreshing the inbox on success.

All three criteria hold. Criterion 2 ("open questions block a story's move to review") came with S-0089; since its acceptance this branch is rebased onto main and joins the two: the refusal names how to answer, `TestAnsweringAnOpenQuestionUnblocksReview` covers refuse-then-answer-then-through, and `design/system/agent-narrative.md` records the rule.

## Next steps
None: in review, awaiting acceptance.

## Decisions
- `flai stream answer`/`stream.answer` named to match the existing `stream log`/`stream.log` pair, not `narrative.answer` (considered, dropped for consistency with the CLI's own `stream` noun for everything narrative-shaped).
- Criterion 2 was first left to S-0089, whose branch this one did not contain. Once S-0089 was accepted, the rebase onto main conflicted in `narrative_test.go` (both added tests) and silently duplicated `OpenQuestions` and its regexes in `narrative.go` (both added them, in different places); kept one copy and every test from both sides.
