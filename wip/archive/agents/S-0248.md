# S-0248 flai check splits an item's front-matter errors on "; ", so a message that holds one becomes two findings, the second on line 1

## Context

Remediates I-0061: `check.oneItem` split `Item.Validate`'s joined error on "; ", so a message holding "; " (an agent role that sets nothing) became two `item.front-matter` findings, the second on line 1.

## Current state

T-0830 is done, committed on `story/S-0248`, and synced onto main; I-0061 is closed and both criteria are checked. In it: `Item.Validate` returns `workitem.Problems`, `check.oneItem` ranges over it, and `manifest.Agent.Problems` feeds the agent block's problems in one by one. `TestAFrontMatterProblemHoldingASemicolonIsOneFinding` in `flai/internal/check/planning_test.go` failed without the fix (two findings, one on line 1) and passes with it. `design/system/flai-cli.md` says check reports one finding per problem.

## Decisions

- Proposed remedy, from I-0061's instance: `Validate` returns a list type (`workitem.Problems`, an error whose `Error` still joins with "; " for every other caller) and check ranges over it. Splitting on another separator would break again on the next message that holds it.
- `manifest.Agent.Validate` keeps its joined error for its other callers (`hostapi`, `cmd/agent.go`, the manifest check, which reports it as one finding); `Agent.Problems` is exported so `Item.Validate` adds each agent problem on its own.
- Close-out stopped at `flai check --strict` on main's S-0173 `story.unaccepted` and TH-0094 `threads.archived`, outside the story. Per the operator's answer on TH-0056, recorded as an I-0057 occurrence rather than fixed here; a second verifier runs the steps the script did not reach.
- Plan: one task, T-0830, in one layer, waiting for nothing. Worked myself rather than by a task sub-agent: three short edits and a test, quicker than briefing one.
