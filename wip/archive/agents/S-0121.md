The registry is `serve/projects.json` beside flai's config (`internal/serve/serve.go`); only `flai dashboard` (`cmd/dashboard_agent.go`) and the board's import (`internal/serve/candidates.go`) write it. ## Decisions

- `flai serve project add` requires `system-flow.yaml` in the folder itself, the current one by default, rather than walking up to the project above: the criterion asks it to refuse a folder with no manifest. `remove` does walk up, so `.` works anywhere in the project.
- After S-0120, `remove` of a registered project below an import folder unregisters it and says it stays served from that folder, rather than refusing. Removing it is still what the operator asked, and the answer says what else is needed.
- S-0120's acceptance is reported unpushed, and the convention says to push it first. I did not push it and did not fetch origin: agent-S-0119 found (TH-0013, TH-0012) that origin/main reuses S-0120 to S-0122, T-0437 to T-0444, and TH-0015 for other items, and asked for a hold until the designer decides the renumbering. A push would need that merge.
- An unreadable agent credential counts as a reason a project cannot be served, logged once, as a missing folder is: it was the other message `flai serve` repeated every second.
- A key another root already has is refused in `serve.Dir.Register` itself, so `flai dashboard` and the board's import refuse it too, not only `flai serve project add`. Two roots with one key would take turns replacing each other's connection in the dashboard.
- flai serve tells the dashboard a project was removed with a notification, `removed`, sent before the connection is dropped, rather than the dashboard forgetting every project that disconnects: a project whose flai is only restarting must stay in the switcher.
- `flai serve project remove` does not stop the dashboard container, unlike `flai dashboard stop`: it manages what is served, not the container.
- 2026-09-26: A project below a folder named for import is served by `flai serve` whether registered or not (S-0120). So `flai serve project remove` unregisters it but cannot take it off the dashboard; it says so and names `flai serve import remove <folder>`, which also stops offering that folder's other repositories. Proposal: a list of roots the operator removed, which folder and import-folder serving skip until `flai serve project add` there again. It could land with S-0122, whose settings page removes projects too. — A (alex, TH-0014, 2026-09-26T05:58:17Z): S-0121 is accepted with this behaviour; the removed list is later work.
