## Decisions

- Kept the planner's four layers: T-1405, T-1406, and T-1408 together, with no path in common; T-1407 after T-1406, whose contract it implements in `spend.go`; T-1409 after T-1405, T-1407, and T-1408, since it joins `priced_by`, both readers, and the spend key; T-1410 after T-1409, to describe what was built.
- Revised the tasks against S-0351's and S-0356's findings: Claude Code's message IDs are not OpenRouter's generation IDs, so a Claude Code run through OpenRouter joins by the key's usage read before and after the run; LiteLLM's rows join by `session_id`, read with the master key, so `spend_key_env` names it.
- The reader is chosen by the provider's base URL: `openrouter.ai` is OpenRouter's, `api.anthropic.com` has none, any other is read as a LiteLLM proxy. A provider's `api` names the protocol, not the gateway, so it cannot choose.
- A run's gateway cost is apportioned over its models by the harness's cost share, or tokens where that is nothing: the gateway's and the harness's model names need not match.
- Each run keeps a spend record beside its log (`<log>.spend.json`): its provider, the key's usage at start, and its price once read. flai serve keeps only a story's newest run in its state, so the record is what keeps an earlier run's gateway price and start reading. T-1409 therefore touches `serve/agents.go`, for the reading at start, and `usage/log.go`, for each run's session IDs.
- T-1405 also updates `design/system/work-hierarchy.md`, which documents an item's `usage` fields, and `front-matter-fields.txt`, whose test lists every front matter key; the release that carries `priced_by` raises `flai.minimum`.
- An empty `priced_by` reads as `harness`, or `estimate` when `estimated`, and `Same` compares it so read: items written before S-0357 are not rewritten only to add the key.
- T-1407: LiteLLM's session join also keeps to the run's window, since a resumed run keeps its session ID; the reader asks for rows (`summarize=false`), not daily totals, and refuses a truncated log.
- T-1409: each run is priced from what it added to the story's total (`Record.RunTotals`), since a resumed session's result reports its totals so far. The live run is never asked. A priced record is never asked again. `flai serve` keeps every `spend_key_env` variable out of the agents it starts. Measure takes the host's providers.
- Review of T-1409: an agent's end now prices its runs with the providers its start read (`measureWith`); reading the configuration from the end's goroutine raced with the tests that change it. A provider with no spend log flai reads (`api.anthropic.com`) is priced by the harness without a warning at every measurement.
- Known limit, documented in `flai-cli.md` and `docs/operators/index.md`: OpenRouter's join by the key's usage counts every run on that key between the run's start and the measurement; a key per story or agent makes it exact.
- `flai/internal/hostapi/settings.go` and the dashboard's Settings page do not set `spend_key_env` yet; it is set with `flai serve agent provider --spend-key-env`. What a user sees changes in S-0358.
