## Decisions

- Kept the planner's five tasks, but dropped T-1854's and T-1855's `after` on T-1853: the story's criteria already fix the key's shape and the prop kinds, and the three touch no path in common. Layers: 1 = T-1853, T-1854, T-1855 together; 2 = T-1856, which needs T-1854's accessor and writer and T-1855's reader; 3 = T-1857, which documents the commands as built.
- MS-0128: S-0437 adds only its own `root.AddCommand(newComponentsCmd(a))` line to `flai/cmd/root.go`, as S-0436's split says; replied settled.
- Tests that need `svelte` find it by walking up from the package to an installed `flaiover/node_modules/svelte`, since a story worktree has no `node_modules`, and skip when there is none. The fixture test also skips under `-short`, as tests reading the monorepo do, so it runs in the integration tier.
- T-1854 widened to `flai/internal/check/check.go` and a new `components_test.go` there: the manifest's `ComponentErrors` reaches `flai check` as `manifest.components` only through that file.
- `flai/internal/components` keeps its own `**` matcher and `CheckGlob`, with claims.shared's rules, so that it does not import the manifest; the manifest validates the same globs with `patternProblem`.
- `flai components config` merges the flags given over the existing key; `--setup ""` clears setup; `--unset` takes no other flag.
- `flai components list` fails as a whole when `node` or `svelte` is missing in a listed sub-project, rather than listing the others.
- Props are read with `node --input-type=module -e`, with the file list on stdin; the package's own `Runner` keeps stderr apart from stdout and takes a context for the one-minute timeout, which `execx.Runner` does not.
