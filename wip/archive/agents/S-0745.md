## Decisions

- The plan is the planner's four layers, one task each, run one after another: T-3173 (the key) → T-3174 (the build, which reads the arguments) → T-3175 (ensure and --layer, which call the build) → T-3176 (the documents, which describe all three). Each reads what the one before it writes, so none run together.
- ADR-0295 §4 is the shape: `agent.image.args`, a map of literal values beside `layer`. flai always passes `BASE` itself. The Dockerfile's ARG defaults stay its own, and they enter the recipe through the Dockerfile's bytes. The recipe label (§2) is `Recipe(dockerfile, "", args)`, which already leaves out `BASE` and `FLAI_VERSION`.
- T-3173 also touches `flai/internal/manifest/agent.go` and `agent_test.go`: `AgentImage` and its `problems` live there, not in `manifest.go`.
- T-3173 also changed `flai/internal/workitem/store_test.go`, whose clone test must fill every field of Item, and added the `agent.image.args.<name>` row to `docs/operators/settings.md`, which TestSettingsIndex needs.
- T-3175 adds `ModeLayer`: `flai image build --layer` leaves the harness images as they are and builds only the layer. Under `ensure`, a layer is rebuilt when it is missing or stale, or when its harness image was pulled or built in the same run. A layer whose harness image is not on the host stops the run, naming that image. T-3175 regenerated `docs/users/flai-reference.md` and the flag index, so they moved from T-3176 to T-3175.
- T-3176 also pointed `flai check`'s advice for a missing or stale agent image, and `docs/operators/runbooks/install.md`'s paragraph on a project of your own, at `flai image ensure` in place of `make agent-images`. The refusal in `flai/internal/serve/container.go` still names `make agent-images`; it is left for S-0751, which replaces that refusal with a host job.
- This repository's `system-flow.yaml` names no `agent.image.args`, and `scripts/agent-image.sh` stays its own build of the layer. S-0760 moves both.
