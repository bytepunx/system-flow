## Decisions

- Kept the planner's five tasks and its layers: T-2232 (the ADR) first, since its mount list is what the others build and test; T-2233, T-2234, and T-2235 together, sharing no path; T-2236 last, since it documents and checks the whole. Checked against main on 2026-11-06: S-0517 (ADR-0246, `storygit.GitMounts`), S-0518 (`scripts/flai.sh` falls back to `bin/flai` or the installed flai without `go`), S-0521 (`RequireMain`, the refusal), and S-0510 (the layer `flai-agent-sf-claude-code:local`) are all done. The cause that is left is the one the plan names: the container mounts no main checkout's `system-flow.yaml`, `wip/`, or `.flai-cache/verify`.
- T-2232 and T-2235 are mine, not a sub-agent's: the ADR's context is already in this session, and `scripts/agent-container.sh` is a path the guard protects from a sub-agent (D-0468). T-2233 and T-2234 go to two task sub-agents at once, in this worktree. `cmd`'s tests import `harness`, so a compile failure in the other's package is waited out, not fixed.
- S-0517's ADR, which T-2232 refines, is ADR-0246. The new ADR is ADR-0253.
- T-2233's premise is corrected. On main, a main checkout's root with no markdownlint configuration makes `mdlint.Load` answer nil, so `wip/` goes unlinted with no warning, not with `markdown.config` as the task says. The test that fails without the fallback is a `wip/` finding that a stripped root misses.
- `MainMounts` reads the wip folder's name from the main checkout's manifest (`layout.wip`, ADR-0011) rather than T-2234's sub-agent's fixed `wip`. The script reads it the same way.
- T-2235's check inside the container found a cause ADR-0253 does not name. Docker makes the main checkout's own folder as root, as the parent of its mounts, so git refused `flai verify`'s `rev-parse` there for dubious ownership. Fixed in T-2235: the adapter (`safeMain`) and the script pass git `safe.directory` for the main checkout as command-line configuration (`GIT_CONFIG_COUNT`, `GIT_CONFIG_KEY_0`, `GIT_CONFIG_VALUE_0`), which git honours for it. That is a refinement of ADR-0253, an added case, so it is recorded in `flai-cli.md`, `docker.md`, `agent-adapters.md`, and the user guide, not in a new ADR.
- The documents' passage for T-2236 went to `docs/users/flai.md`'s container harness section, beside ADR-0246's paragraph, rather than § Verify a story before review: that is where the mounts are listed. The worktree paragraph that S-0521 wrote now says the refusal is for a container without ADR-0253's mounts.
- Kept I-0264, which the hand close-out's `--record-issues` opened. Inside a container `docker` is never on `PATH`, so every close-out there records the `agent.image` note as an issue, and its commit step then stops on that file. It is S-0565's to meet, so it stays for the operator to choose at acceptance.
- The close-out was checked inside `flai-agent-claude-code:local`, as T-2236 says, not inside the layer image, which `scripts/agent-container.sh` does not run. A whole close-out inside the layer is S-0565's criterion 3.
- The hand check in T-2236 builds `bin/flai` in the worktree, with `CGO_ENABLED=0` (S-0510), rather than rebuilding the images. `scripts/flai.sh` inside the image, which has no `go`, runs that binary, so the check runs this branch's flai.
