# S-0498 A pending recommendation waits a day or more for the operator's confirmation while its story idles in progress

## Context

Remediates I-0151. The planner's plan on TH-0650, approved by the orchestrator, gives two remedies: `flai serve` reminds the operator, off the dashboard, of a thread awaiting them past `threads.remind_after`; and `flai serve` blocks a story whose agent ended asking until the answer starts it again.

## Current state

S-0498 is in review. The close-out passed at a759ff182: every tier passed, and integration and smoke are left to the merge queue. Both criteria are ticked. TH-0660 stays open for the operator to set the host's reminder channel.

## Next steps

1. The operator accepts S-0498, or resolves TH-0660 so the orchestrator can accept it.
2. After the release is installed, the operator runs the flai serve notify set command TH-0660 gives.

## Decisions

- Kept the planner's seven tasks as drafted: each matches a point of the approved plan on TH-0650, and every touch names a file.
- Layers: 1 T-2127 (the ADR, so the code builds on a recorded decision); 2 T-2128 and T-2129 (both wait for the ADR, no shared path); 3 T-2130 (waits for T-2128: both add rows to `docs/operators/settings.md`); 4 T-2131 (waits for T-2128's settings and T-2130's channel) and T-2132 (waits for T-2129 and T-2130, whose behaviour it documents; no path shared with T-2131); 5 T-2133 (waits for T-2131 and T-2132, so the issue closes on what is built and documented).
- T-2127 written by the story's agent itself: one `flai adr new` call is quicker than a sub-agent. Layer 2's tasks run at once, each in a task sub-agent; the rest one at a time.
- The ADR is ADR-0205, not the predicted 0204: S-0504 took 0204 first. The predicted touch was replaced with the real path.
- T-2129 ran in its own worktree (`task/T-2129`): its serve tests build the manifest package that T-2128 was changing at the same time. Its two files were copied into the story worktree, and the task branch was deleted.
- T-2128 also regenerated `docs/users/flai-reference.md` and bumped `template/template.yaml` to 1.0.118: the reference lists the settings catalog, and stories bump the template version with its changelog. Both were added to its touches.
- T-2129 added `releaseAsked`, a sweep at each look. It closes the interval of a story whose agent no longer waits on that thread, such as one sent back to ready or restarted by hand. Without it, an existing test showed a story sent back to ready while blocked would never start again.
- T-2130 needed `newServeNotifyCmd` registered in `flai/cmd/serve.go`, and T-2131 needed `Notify: a.serveNotify` in serve's options there. Both lines were added by the story's agent and the touches widened. The channel is read from the host configuration at each look, so `flai serve notify set` holds without a restart.
- A failed send counts as sent and is not retried until `remind_every`, keeping ADR-0205's "one attempt".
- MS-0195 with S-0504: both stories add a 1.0.118 template changelog heading. Agreed that the story accepted second renumbers its heading and `template/template.yaml` to 1.0.119 at its sync.
- Recorded I-0210: `flai guard` does not refuse a served agent the `flai serve` sub-commands that write `~/.flai/config.json`. Left to the operator's choice of a story at acceptance.
- TH-0660 gives the operator the `flai serve notify set` command for this host. It does not hold the story's work. Under ADR-0093, though, the orchestrator does not accept a story with an open thread: the operator accepts S-0498, or resolves TH-0660 first.
