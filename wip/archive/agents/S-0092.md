# S-0092 New stories should not require an epic

## Context

`--epic` was required for `flai story new` at three separate layers (the CLI, `workitem.Create`, `Item.Validate`), and the dashboard's new-item form blocked the create button until an epic was chosen, forcing an epic-as-container anti-pattern for work that does not fit an active one.

## Current state

Done. A story's `--epic`/`parent` is now optional throughout: the CLI, `workitem.Create`, `Item.Validate`, and `item.new`'s write spec (which leaves `--epic` out of the command line entirely rather than refusing). A task's `--story` is unchanged and still required. The dashboard's new-item form offers "No epic" as a real, selectable first option and no longer waits on a parent for the create button to enable. Verified live with the real CLI: a story created with no `--epic` gets no `parent:` key in its front matter at all.

## Next steps
1. Move S-0092 to review; `flai check --strict` and `scripts/lint-md.sh` clean in the main checkout first.

## Decisions
- Left `Task`'s `--story` requirement untouched: every existing task-parent code path (narratives, streams, `activity.get`) assumes a task has one, and the story only asked about stories and epics.
