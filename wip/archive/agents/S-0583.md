# S-0583 Claude Code drops any call to flai's HTTP MCP server that answers after 60 seconds, so wait_for_events, wait_for_work, verify, and a slow task_done fail for an agent in a container

## Context

Remediates I-0228. ADR-0244 left open a per-server `timeout` in the MCP file the container adapter writes, for a slow `task_done`, `story_start`, or `test` over HTTP.

## Current state

All four tasks are done and both criteria are ticked. ADR-0258 sets a 1800000 ms per-server `timeout` in flai's HTTP MCP file, measured to 660 s in the container. `mcphttp.ClientTimeout` writes it, with tests. The docs and design say what it lifts. A 126.6 s MCP `test` call over HTTP in the container returned its result, and I-0228 is closed. The worktree is clean and synced; the close-out is next.

## Decisions

- Kept the planner's four tasks and layers, approved on TH-0850: T-2541 alone (it measures the figure and writes the ADR the others cite); then T-2542 and T-2543 together (both wait for the figure and the ADR, and share no path); then T-2544 (it runs T-2542's MCP file and closes I-0228 once T-2543's docs say what fixed it).
- T-2541 measures with a scratch MCP server in JSON response mode, as S-0519's T-2227 did, not flai's own tools: `wait_for_events` returns on any board event and `permission_prompt` opens real threads. The scratch server and its logs live in the worktree's git-ignored `.flai-cache/s0583-probe/`, because the Write tool refuses paths outside the worktree.
- The container runs use the login folder `/home/alex/.claude-me`, the operator's container login setting (D-0494), mounted read-only at `/run/claude-login`, and `--model haiku` to keep the probe sessions cheap.
- T-2541 measured in `flai-agent-claude-code:local`, Claude Code 2.1.312: with no `timeout`, a 90 s call failed after 60.0 s (`The operation timed out.`); with `"timeout": 1800000`, a 660 s call returned its answer after 660.0 s, past the 300 s idle limit. The figure stays at 1800000 ms, the HTTP server's own `--idle` default, since nothing gave a reason to lower it. ADR-0258 records it, refining ADR-0244.
- T-2542 and T-2543 ran together as forked task sub-agents; neither touched the other's paths, and neither reported interference. T-2543 also changed the `flai mcp` row of `flai-cli.md` and the HTTP client sample in `docs/users/flai.md`, both inside its five files, because they still said a slow `task_done` is cut short.
- T-2544 repeated I-0228's third instance on 2026-11-07: one headless `claude -p` in `flai-agent-claude-code:local`, as `probe-S-0583`, with the MCP file `httpMCPConfig` now writes (`"timeout": 1800000`, URL, token, and Host by variable), called the MCP tool `test` on `flai/internal/guard` for S-0583 over the host's HTTP server. The server answered after 126.6 s (`mcp-http.log`, 07:34:47.761Z), and Claude Code received it: passed, go-test 2m2.8s. Without the `timeout` it would have been dropped at 60 s. `task_done` and `story_start` were not repeated; they meet the same per-server limit, measured to 660 s.
