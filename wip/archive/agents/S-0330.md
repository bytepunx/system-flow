## Decisions

- I kept the planner's plan unchanged, in four layers. T-1185, the ADR, runs first because it sets the file format. T-1186, the package, waits for it. T-1187 (the command) and T-1188 (accept, archive, and check) both wait for T-1186, and share no path, so they run together. T-1189, the docs, waits for both because it describes what they built.
- ADR-0120 gives conversations the ID prefix `MS-` beside threads' `TH-`. The title is the first line of the first message. Each entry is headed `### <time> <author> <story>`, so the side a conversation awaits is the story that did not write the last entry.
- A cancelled story's conversations read as closed but get no entry, because the criteria ask for an entry only at acceptance and archive.
- T-1187 ran in its own worktree, `task/T-1187`, because it and T-1188 both build package `cmd`. I copied its three files back and removed the worktree.
- The sender's story comes from the existing `issueStory` helper: `--from`, then `FLAI_STORY`, then an `agent-S-nnnn` `FLAI_AGENT`, then the checked-out story branch. The branch fallback is one step beyond ADR-0120's list, and the help text and docs say so. `flai message list --story` has no default, as `flai thread list --on` has none.
- At acceptance, the accepted story's conversations close as `was accepted`. Those of an epic's cancelled stories, archived with it, close as `was archived`.
- I widened T-1188 to `flai/internal/check/scope.go`, so that a story's close-out counts its own conversations as inside the story, as it does for threads anchored on it.
- I widened T-1189 to `docs/users/conventions.md` and `template/root/wip/messages/README.md`, so that the folder is listed where `wip/threads/` is and a project made from the template has its README.
- Not done here: the dashboard's accept preview (`hostapi` calls `preview.Accept`) does not list `closed_messages`. Only `flai accept` adds them. The dashboard's messages belong to S-0336.
