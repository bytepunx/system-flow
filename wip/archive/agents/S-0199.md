# S-0199 Work items carry planning data: draft, cost of delay inputs and value, and a forecast with who set it

## Context

E-0016's planner, orchestrator, and analyzer need work items to carry `draft`, `cost_of_delay`, and `forecast`, each saying who set it. Sibling stories build on this one: S-0201 and S-0202 (Finalize in the dashboard), S-0203 (draft stories from issues), S-0204 (forms), S-0205 (metrics), S-0210 (the planner fills them).

## Decisions

- Plan: layer 1 T-0739 (workitem and manifest types and the move rule: every other task builds on them). Layer 2 T-0740 (check) and T-0741 (itemedit, itemnew, cmd), each after T-0739, sharing no path. Layer 3 T-0742 (mcpserver, hostapi), after T-0741, because hostapi builds `flai edit` flags and MCP calls `itemedit.Change`. Layer 4 T-0743 (flaiover) and T-0744 (ADR and docs), each after T-0742, sharing no path. Tasks run one at a time: each is short beside priming and review.
- Schema: `cost_of_delay` has one `by` and `at` for the block, as the criterion lists them. They record who last changed any part of it. Inputs are the operator's and `value` is the planner's by definition, so the fields themselves say whose figure is whose.
- Amounts are plain non-negative numbers in the project's currency, `planning.currency` in the manifest (ISO 4217, default USD, as `usage` cost is). Durations are Go durations, like `estimate`. `planning.cycle` defaults to 168h. `planning.hour_rate` has no default: unset means the planner cannot price time lost.
- A story may carry `cost_of_delay.value` with no `inputs`: that is the share of its epic's value the planner apportions it (S-0210 computes it).
- `--yes` on `flai move` to ready (the existing global flag) finalizes a draft: it clears `draft` in the same save as the transition, and the transition's `by` records who did it. MCP `item_move` refuses always, because no agent has the orchestrator's permission until S-0218. `workitem.MoveOptions.Finalize` is the hook S-0218 will set.
- The metrics comparing estimate and forecast with the actual are S-0205's (metrics.md changes need an ADR, and S-0205 owns them). This story's ADR states that `estimate` stays the human's figure and `forecast` the planner's.
- The baseline's "Definition of ready, story" line in `work-management.md` gains "not a draft", here and in the template (a patch, with a CHANGELOG entry). The story's own criterion asks for the template's conventions to describe the fields, and that is the designer's consent. S-0243 asked on a thread first; this story's criterion makes that unnecessary.
- T-0739's sub-agent wrote the fields after `usage`, where an older flai writes back keys it does not know, so an old and a new flai write the same bytes. It added `finalize` to `TransitionAll` only: `Transition` keeps its signature, which saved about 40 test call sites.
- T-0740's sub-agent found that `flai check` splits `Validate`'s errors on "; ", so a message holding "; " became two findings. The planning messages now use ": " instead. The older `agent` role messages have the same flaw and are left as they are (not this story's).
- T-0741's sub-agent: `--draft` is refused on a story past backlog, since a draft is finalized before ready. An edit that changes no value does not re-stamp `by` and `at`. With no `--by` and no FLAI_AGENT, `by` is `agent`, as `Create` does. It regenerated `docs/users/flai-reference.md` and the flag index, outside its paths, because their tests demand it. I fixed the articles in its refusal messages ("is a epic").
- Layers 2 ran together, T-0740 and T-0741 in two sub-agents, with no interference reported.
- T-0742's sub-agent made MCP `item_edit` refuse `draft: false` as well, since clearing the flag finalizes, and `item_get` return the planning data, so that an agent can read back what it set. hostapi takes the cost of delay amounts as strings, so that an empty one removes the key.
- T-0743 and T-0744 ran together. T-0743 shows amounts without a currency, because `item.get` does not carry it. I wrote ADR-0074 myself (`flai adr new`) and added the item page's line to `flaiover-dashboard.md`. I also added the older-flai read test the criterion asks for (`TestAnOlderFlaiReadsPastThePlanningFields`).
- TH-0080, answered by the designer on 2026-10-03T06:20:12Z: "use recommendation". The metrics comparing estimate and forecast with the actual are S-0205's. The third criterion is checked with a note naming S-0205.
- The first verifier passed the lint, every test tier, the markdown lint, and the dashboard's suite. Close-out stopped on `flai check --strict`, which warns `story.unaccepted` on the archived S-0173. That is not this story's: I-0057, bumped. Meanwhile main filed its own I-0060, so this story's issue is renumbered I-0061.
- Dashboard: this story adds the fields to the item types and shows them read-only. The draft marker and Finalize are S-0201's, and the forms S-0204's.
