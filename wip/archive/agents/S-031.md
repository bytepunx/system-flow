# S-031 flai structured logging and --verbose

## Context
Applies design/conventions/logging.md to flai. Today flai writes plain lines to stderr with fmt (created config, fetching template, warnings) and prints "flai: <err>" on failure. The convention wants structured events with ts, level, component, msg, and fields; five levels including fatal; text on a terminal, JSON otherwise; --verbose selecting debug; LOG_LEVEL and LOG_FORMAT honoured; errors logged once at the boundary; stdout untouched. Library: log/slog (design/tech/observability.md).

## Current state
All three tasks done, story in review. flai/internal/logx builds the slog logger; cmd/root.go builds it once per run (PersistentPreRun) and exposes --verbose; every stderr message is a structured event with component and fields; run() logs one fatal event at the boundary with err and exits 1; stdout is untouched so --json consumers are unaffected. cmd/logging_test.go pins ts, level, msg, component, path, err for the documented events and checks the single-error rule, --verbose over LOG_LEVEL, and LOG_FORMAT=text. Docs: docs/users/flai.md Logging section, flai-cli.md, observability.md. Lint and all tiers green. Committed at review and pushed.

## Decisions
- Fatal is a custom slog level (12) rendered FATAL by both handlers; the boundary emits it once and exits 1. A sub-step the command recovers from is warn, never error, so an error or fatal event always means the command failed.
- Keys renamed via ReplaceAttr to the convention's ts, level, msg; component is a plain attribute every event carries.
- Terminal detection is on stderr, not stdin: JSON when stderr is redirected even if the user is typing.
- The final error is printed only as the fatal event; the previous "flai: <err>" line is gone. Scripts that grepped it should read the err field.
- Warnings keep a static msg ("workflow policy warning", "wip limit exceeded") with the variable text in a detail field, per the static-message rule.
