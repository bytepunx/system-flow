## Decisions

- The pager is in `Threads.svelte`, not per page, so every page that shows threads gets it; the story names stories, and the item, review, document, and editor pages all use this component.
- A single thread shows no indicator and no arrows: the story asks for them where there are several threads.
- The thread being read is held by ID, so a reload (a reply, a change event) does not move the reader; when that thread leaves the list (resolved with "show resolved" off), the one now at its position is shown. A thread just opened from the composer becomes the one shown, from the `id` that `POST /api/threads` returns.
- The "n of m" count is announced (`aria-live`) only above, so a screen reader does not hear it twice.
- I did not check the pager in a browser. The behaviour tests render the component in jsdom and use its buttons; the operator's dashboard serves `main`.
