- Guard (T-3232): the planner moves only to the workflow's initial state, the orchestrator's promote_to_ready is a move into a state a commit transition enters, its acceptance is a move a role may make only as an acceptance, and the protected-write hold asks in any active state. The Backlog and Ready constants stay because guard/roles.go, S-0748's, still reads them. Refusal texts are fixed strings, word for word with the baseline.
- Messages (T-3233): a conversation is closed once either story is in an accepted or cancelled state; a story talks from an active or waiting state; a held story is in a state a pull transition leaves, and a holder is in an active state. The state words in refusals come from the workflow.
- Forecast (T-3234): the lanes are the sum of the limits the board sets on the active states with limit, and a story in any active state holds one; the pull order is the queue states, nearest the pull first. flai forecast now passes repo.Flow() (flai/cmd/forecast.go added to T-3234's touches).
- T-3235: usage/turns.go named no state (its match is the shell's done keyword), so it is unchanged and left out of the touches. statsread's WIP limit is the limit of the state a pull moves a story into.
- Left outside the touches and recorded as I-0379: cmd/guard.go sets no Guard.Workflow, serve/replan.go calls Replay, metrics/costorder.go (S-0750's) uses NewPuller, and workitem/hold.go names InProgress for a share's holder. repo.Flow() is the baseline until S-0755 reads a project's file, so none behaves differently today.
