## Decisions

- Plan, kept from the planner: layer 1 T-1071; layer 2 T-1075 and T-1076 (both call `Verify`, no path in common); layer 3 T-1082 and T-1096 (after T-1075, the command they call and name) and T-1089 (after T-1076, whose `verify.status` it reads); layer 4 T-1108 (describes what the others built). Layers 2 and 3 run their tasks at once: each is long and they share no path.
- `Verify`'s steps, cheapest first: the unfinished rebase, the branch contains the main branch, the narrative's `## Current state` and `## Next steps`, `flai check --strict` scoped to the story in process (outside findings are notes), then each selected tier as a step of its own. The planner put contains-main and the narrative last; both take milliseconds and the close-out checks contains-main first when clean, so they go before the minutes of tiers. Contains-main does not depend on the commit the close-out makes afterwards.
- Tier selection for `Verify`: the tiers the diff selects as `flai test` selects them, plus every `all_only` tier whose `paths` the diff selects, plus every `all_only` tier with no `paths`. This reproduces both close-outs: the template's runs its test, integration, and smoke on every story; this repository's gets `paths` on integration (`flai/**`) and smoke (`flai/**`), and new `all_only` tiers for `scripts/template-test.sh` (`template/**`) and `scripts/flaiover-test.sh` (`flaiover/**`), set with `flai manifest set tests=` in T-1082. `flai test` is unchanged: `all_only` still means `--all` there.
- The tiers run with `CLOSE_OUT_STORY` set to the story, so that `scripts/check.sh` in smoke and `TestMonorepoIsClean` in integration scope themselves as ADR-0085 says.
- Known duplication kept: the short Go tests of the changed packages run before the full integration run, and smoke's `check.sh` repeats the in-process check. Cheapest first makes a failure cheap; the repeats cost seconds.
- T-1108 started while T-1096 was still in progress: T-1096 waits only on the operator's `.claude` copies, which no document describes differently.
- `flai guard` lets a sub-agent and the orchestrator run `flai verify` without `--record-issues`, and call the MCP tool `verify` (MCPReads): the run writes only flai's cache. The verifier's tools stay as they were; it reads the result with `flai verify --last` in the shell.
- `Proc.Run` gained an env parameter rather than a new interface: nothing outside `flai/internal/verify` implements it.
- T-1076 was worked in its own worktree (`task/T-1076`) because `flai/cmd`, which T-1075 changed, imports the packages T-1076 changed; it was cherry-picked onto the story branch.
- A flai-only change no longer runs flaiover's full vitest (today `flai-test.sh` runs it): a flai change selects the vitest tier only through flaiover files.
