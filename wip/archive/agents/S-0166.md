# S-0166 Charts ignore the window drop-down

## Context

The charts page sends the window to flai (`/api/stats?since=`), and flai receives it, but most of what it answers does not depend on it: `items` holds every item of the type, burn-up and cumulative flow ran from the first item ever created, and throughput had only the weeks something was done. The page then draws each time axis from the first point to the last, so a window of a day and one of a year looked the same. Measured on this repository before the fix: `flai stats --since 1d` and `--since 365d` both gave 166 items, 15 CFD days from 2026-09-15, and the same burn-up.

## Decisions

- Burn-up, cumulative flow, and throughput are windowed in flai, the reference implementation, since the window is a metric definition. The items list stays whole (aging and open items need it), and the dashboard picks the ones completed in the window. The spend series keep their start at the first bucket with spend, so the running mean keeps its meaning; the dashboard's axis spans the window instead.
- Burn-up and cumulative flow start at the later of the window's start and the first item's creation: earlier days would add only zeros, and the dashboard's axis shows the window regardless. Throughput includes empty weeks, since its category axis is only as wide as its data.
- Retitled S-0166 to drop its trailing period (MD026), keeping the operator's words; recorded against I-0027.
