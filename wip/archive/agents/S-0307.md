## Decisions

- The planner's tasks stand as written: they cover all three of the issue's directions (retry, resume, a failure that names how to finish), and their touches avoid S-0275's `storygit/commit.go` and the `hostapi/writes.go` that S-0269 to S-0275 change.
- Layers: (1) T-1137, which waits for nothing; (2) T-1138, which waits for T-1137 because the commit step calls its helper; (3) T-1139 and T-1140 together, both waiting for T-1138 because they describe what it delivered and share no path. Each layer holds one long task at most, so tasks run one at a time; T-1140 is a `flai issue close`, which only the story's agent may run, so it is mine rather than a sub-agent's.

- T-1137: the helper is `storygit.RunPastIndexLock(r, dir, args...)`. It waits 100ms, 200ms, 400ms, 800ms, 1.6s, then 2s three times, about 9.1s in all, and matches git's English text `index.lock': File exists`. code-quality.md says not to hide errors with retries; the issue and the task specify this one, and a lock held for a moment is a passing condition rather than a defect, so it stands.
- T-1138: an acceptance whose commit is missing is detected from the item's own archived file being uncommitted, not from anything under wip. The main checkout routinely holds other uncommitted wip changes, and the looser rule would let `flai accept <old story>` commit them under that story's subject. A test pins this.
- T-1138: the "commit fails even so" test makes the commit fail with a `pre-commit` hook rather than a lock held throughout, so it needs no 9s wait and no exported test knob in storygit. The storygit unit test covers giving up on a held lock.
- T-1138: a resumed commit's overlap paths come from `storygit.Committed`, which leaves out wip paths; the merge's diff included them. The journal was checked rather than changed: `hostapi` turns a non-zero `accept.run` into a channel error, so a failed commit is not recorded as done; `writes.go` stays untouched.
