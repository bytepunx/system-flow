# S-0534 A usage-limit refusal sets a budget state on the host that holds every start on that provider until the reset or a backoff, probes once, and reaches every inbox, the journal, the dashboard, and the ADR-0205 channel

## Context

ADR-0209 §5: a usage-limit refusal sets a budget state per provider on the host, in `budget.json` in the serve folder, that holds every start on that provider across every served project, probes once at the reset or after a backoff of 5m doubling to 1h, and reaches the journal, `inbox`, the dashboard, and the ADR-0205 channel. The usage-limit reader is S-0514's (`runLimit`, `limit.go`; D-0418: only a 429 or a rejecting `rate_limit_event` counts).

## Current state

S-0534 is built and closed out: every task done, every criterion ticked, and `scripts/close-out.sh S-0534` passed at the branch head (integration and smoke left to the merge queue). It moves to review.

## Next steps

1. The operator reviews and accepts S-0534.
2. Known gaps, outside the criteria: the WSL toast recipe in `docs/users/flai.md` shows an empty title for a budget notice (no top-level `title`); a budget change made by a hand start in another process is logged, not sent as a notice.

## Decisions

- The planner's nine tasks stand as drafted (TH-0711, approved by the orchestrator under `plan_backlog_stories`). Its two proposals, a hand clear command and holding the permission check, stay out, as the orchestrator's pending recommendation says; the criteria ask for neither.
- Layers, as planned: 1 is T-2282 (the state itself, which every other task reads). 2 is T-2283, T-2286, T-2287, T-2288, which wait for T-2282's API and share no path. 3 is T-2284 and T-2285, which wait for T-2283 because they change the same run files (`agents.go`, `plan.go`, `orchestrate.go`, `analyze.go`, `curate.go`), and T-2289, which waits for T-2287's `agent.status` field. 4 is T-2290, the docs, after all of them.
- The layers run one task sub-agent at a time in the shared worktree, except layer 2, whose four tasks run at once: they share no path and none builds what another changes.
- The state's key is the run's provider, or its harness when it names none (`claude-code` on its own login), as TH-0711's assumption 2 says. The probe is the first start that waits on the provider once `until` has passed (assumption 3); a probe that ends on anything but the limit clears the state (assumption 4).
- `mcpserver` does not import `serve`: the inbox's `budget` reaches the MCP server through an `Options` function `cmd` wires to the serve folder, as `AutoApprove` does (assumption 5).
- MS-0229: the hold on S-0536 stands, since both stories change the orchestrator's start path.
- Layers 2 and 3 ran their Go tasks in task worktrees (`task/T-nnnn`), since T-2283 and T-2288, and T-2284 and T-2285, build one package; I copied each back into the story worktree, their files being disjoint, and removed the worktrees.
- T-2282: a probe still running after 10m clears the state (the API served it), and a probe claim with no process after 2m, or whose process is gone, is claimed over, so a lost probe never holds forever. A refusal within the hold does not double the backoff, so runs refused together do not compound it.
- T-2283: a run on the limit is marked `usage_limited` on `AgentRun`. The curator's S-0514 retry at `resets_at` is kept: it is now just the curator's next start, which the gate holds.
- T-2286: the inboxes inside `task_done` and `story_start` answers carry `budget` too, through a `HostBudget` option on `taskdone` and `storystart`; and the HTTP MCP server is wired as the stdio one is. These widened T-2286's touches.
- T-2288: the notice's sender is kept per serve folder in `budget.go` and set by `serve.Run`, since launchers are rebuilt per action. The send is synchronous, keeping notices in order; changes are rare.
- T-2284: a story whose agent ended on the limit is started again on its own once the provider clears, spending no restart; `harness.Request.AfterLimit` tells its prompt so (widened T-2284 to `harness.go`). A held hand restart is refused rather than queued.
- T-2285: hand-start refusals sit in the exported start functions, not the `*Check` functions, since the replanner and schedules call those too and a refusal there would drop their item. `roleEnded` (S-0417's project roles, on main after T-2283) feeds the state and `RunRole` is gated.
- `budgetKeyFor`, `budgetHolds`, and `budgetHeldWhy` were added to `budget.go` by me before layer 3, so the two hold tasks shared them.
