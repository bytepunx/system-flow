# S-0061 An agent's first inbox is bounded, not the last 24 hours in full

## Context
The first `inbox` an agent calls under a new name reports every change of the last 24 hours. On 2026-09-19 that was 209 changes and 68 KB, more than a tool result may hold, 155 of them task transitions. The unbounded first look is a defect in S-0058; `catchUp` in `flai/internal/mcpserver/cursor.go` is where the bound belongs. Work is in `.flai-cache/worktrees/S-0061` on `story/S-0061`.

## Current state
Done on `story/S-0061` in one commit (866c980), ready for review.

`catchUp` in `flai/internal/mcpserver/cursor.go` now returns the newest `maxEvents` (50) changes and how many older ones it left out; the constant carries its reason. With no cursor it skips task transitions. The cursor's same-second keys are recorded for every change before filtering and capping, so nothing filtered or omitted comes back. `inbox` has `changes_omitted` and `wait_for_events` has `events_omitted`; the pull-order event is added after the cap and is not counted against it; ready work and threads are untouched. Tests: `TestAFirstLookIsBoundedAndLeavesTasksOut` (57 story changes and a task transition before the first call: 50 reported, the newest, the rest counted, no task, ready work not capped, a second look empty) and `TestALaterLookReportsTasksAndIsStillCapped` (a task transition is news once there is a cursor; `wait_for_events` is capped and counts; the omitted do not come back). Both fail with the cap and the filter disabled. `make flai-test` passes, 0 lint issues. The server instructions, both tool descriptions, `docs/users/flai.md`, and `design/system/flai-cli.md` say what a first look returns. The defect is recorded on the branch as I-0023, left open until the fixed flai is the one installed for MCP, which needs sudo.
