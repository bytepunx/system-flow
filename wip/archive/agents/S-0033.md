## Decisions
- Four digits, not five or unpadded; the parser still accepts three or more so fixtures and older repositories keep working. Recorded in ADR-0017.
- Lookups canonicalise the typed ID (any zero padding or none) and try the canonical and legacy three-digit file names, so commands work before and after migration.
- The migration derives the old ID from the file name, not the front matter, so a run interrupted after rewriting contents completes on rerun. Documentation must not spell out short IDs as examples, or a rerun widens them; the examples describe the padding in words instead. The first run here stopped at an untracked narrative; `git mv` is now used only for tracked files.
- References are rewritten only in the layout folders, the repository root's markdown and yaml, and each project's root markdown files. Go and TypeScript sources and `testdata/` are left alone; the fixture-based tests keep exercising three-digit IDs.
- Accepted ADRs were touched by the mechanical rename only; ADR-0017 records that as the one permitted edit.
- Issue IDs widen too (operator's call on 2026-09-17, folded into this story), so ADRs, items, and issues share one four-digit width.
