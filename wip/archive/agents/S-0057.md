# S-0057 Cards can be dragged within a column to change the pull order

## Context
The operator wants to reprioritise by dragging a card up or down within its column. The pull order is `order` in `wip/kanban/board.md`; today only `flai move` touches it (append on ready, remove otherwise), nothing can reorder it but a hand edit, and the dashboard ignores it when laying out a column. So the story is a flai command with the ordering rules, the columns sorted by the order in flai and in the dashboard, and then the drag with a keyboard and button alternative. Work is in `.flai-cache/worktrees/S-0057` on `story/S-0057`.

## Current state
Done on `story/S-0057` in six commits (04b08af to 98173b0), ready for review.

flai: `internal/workitem/order.go` has `PullSequence` (named stories first, the rest by ID), `Board.Place` with its refusals as rule errors, and `PlaceReadyLast`, which `Move` now uses so a story that becomes ready joins the end of the ready section. `flai order <story> --before|--after|--top|--bottom` (`cmd/order.go`). `NewBoardView` lays out backlog and ready in the sequence, so `flai board` and the MCP `board` and `inbox` tools agree. `make flai-test` passes, 0 lint issues.

## Decisions
- 2026-09-19, operator: "pull S-0057 next", after accepting S-0055.
- 2026-09-19, agent: backlog stories that were never placed stay out of `order` and sort after the placed ones by ID; a placement lists only as far down the backlog as it has to. Listing the whole backlog on the first drag would make `board.md` name every story for no gain. Ready stories are always listed, as `flai move` already does.
- 2026-09-19, agent: the alternative to dragging is a pair of buttons beside the card's link plus Alt+Arrow on the focused card, not controls inside the card: the card is one link (S-0048) and a button inside a link is invalid.
- 2026-09-19, agent: placement refusals are rule errors (`rule:` prefix), like `Move`'s, because the dashboard's flai wrapper turns those into 400 with the reason and everything else into 500.
- 2026-09-19, agent: a drop that would leave the card where it is writes nothing and shows nothing, and a drag within in-progress, review, done, or cancelled is not a drop target, so the pointer itself says no. Starting any drag clears the last notice so an old success cannot be read as the new drag's result.
- 2026-09-19, agent: the rule for a column's sequence is written twice, in Go for flai and in TypeScript for the dashboard's reader, which does not shell out to flai to read. Their tests use the same cases, and `flai.test.ts` checks them against each other through the real binary.
