## Decisions

- **The stop test's darwin failure (T-0630).** The cause is a race in the test, not in `Stop`. The test signalled the stub as soon as `run.live()` was true, which is as soon as the process exists. On macOS `/bin/sh` is bash, which takes long enough to start that SIGTERM arrived before the script had run its `trap` line. So the stub died of the default action: the launcher saw a signal death (exit -1) and not 143, and the stub that should ignore TERM was gone inside the grace period, so the journal said "ended" and not "killed". Process groups and exit handling are correct on darwin. A standalone Go program that waited 300 ms before signalling got exit 143 from the trapping script and had to SIGKILL the stubborn one. Fix: the lab waits until the stub has written its output file, which it does after its trap (`agentLab.trapped`), and the stubborn stub writes one too.
- **The identity test (T-0629).** `flai/internal/preview/accept.go` is left as it is. On macOS git works out a committer identity from the account and the hostname, so the commit the preflight protects would succeed, and the preflight is right not to refuse it. The test was wrong to rely on the host having no identity. It now sets `user.useConfigOnly` in a global config of its own (`gittest.NoIdentity`).
- **Verifying "in CI" (TH-0043).** The designer chose option b. This Mac and `go test -race ./...` in `golang:1.26` in Docker count; CI confirms on the push to main. No pull request was opened.
- **Unpushed acceptances left alone.** `inbox` reported S-0173 and S-0174 accepted and not pushed. I was started to work S-0180 and no other, so `flai push --pending` is left to the operator.
- **The shared helper.** `flai/internal/gittest` (`Isolate`, `Identity`, `NoIdentity`) is used by the tests that set git's identity process-wide, because flai's own git commands read it: `accept_resume_test.go` and `doc_test.go`. Tests that pass an identity only to their own git commands (`gitIn` and the labs in `migrate`, `pending`, `mcpserver`) are unchanged, because they already control what they need.
