# S-0257 A story agent started by flai serve cannot edit .claude/settings.json, so a story that changes the guard hook's matcher cannot ship it

## Context

I-0069: Claude Code refuses a headless flai-serve agent's writes under any `.claude/` folder as sensitive files. Only a person or a configured permission handler (`--permission-prompt-tool`) may approve them, and flai configures none.

## Current state

The story is complete on story/S-0257 and synced onto main, which now includes the accepted S-0262. The close-out passed every step on a verifier's run, after two fixes: the `nilerr` lint in `permission.go`, and a test of the escape through a symbolic link.

The rebase onto S-0262 stopped on the generated issue files: `summary.md` and the I-0073 and I-0076 instances. They were resolved by keeping both stories' instances and regenerating `summary.md`. The touched packages' tests and the markdown lint pass after it. I-0074 is bumped for this conflict.

## Next steps
1. The operator reviews and accepts S-0257. To try the feature, start an agent that edits a `.claude/` file and answer `allow` on its thread, or run `flai serve enable auto-approve`.

## Decisions

- 2026-10-05, TH-0128:
  - The fix is a flai MCP tool, `permission_prompt`, that flai serve passes to claude-code as `--permission-prompt-tool`. It asks the operator on a thread before a write under a `.claude/` folder in the story's worktree, and denies anything else.
  - The operator extended it with an opt-in auto-approve, which I made a shell-only host action, `auto-approve`, like `auto-publish` (ADR-0067). A dashboard token holder therefore cannot let agents rewrite their own hooks and permissions.
- The plan has three layers:
  - **Layer 1:** T-0874 (`flai/internal/mcpserver`) and T-0875 (`flai/internal/harness`). They share no path and wait for nothing.
  - **Layer 2:** T-0876 (`flai/internal/hostapi`, `flai/cmd`) waits for T-0874, because it wires the `Options` func that T-0874 adds.
  - **Layer 3:** T-0877, the docs, waits for all three, because it describes them.
- T-0874's review: only the story's owner can answer the thread, not anyone but the agent, so that another agent's reply cannot approve a write.
- `docs/users/flai-reference.md` is generated from the commands' help, and that help is unchanged, so T-0877 left it as it is.
- Only the project addition in `delegation.md` mentions `.claude/`, so the template needs no change. The story is tagged `flai`.
