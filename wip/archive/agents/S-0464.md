## Decisions

- The planner's four tasks are kept as drafted (TH-0556): the batch names its stories in `MERGE_QUEUE_STORIES`, comma-separated; the checks inside the tiers scope to them and record no issue; `CLOSE_OUT_STORY` stays the close-out's alone.
- Layer 1: T-1973 (`flai check --story` takes several stories) and T-1974 (the batch and bisection set `MERGE_QUEUE_STORIES`) share no path and run together.
- Layer 2: T-1975 (the scripts and integration checks read the variable) waits for T-1973, since `scripts/check.sh` passes several stories to `--story`; the variable's name is fixed, so it need not wait for T-1974.
- Layer 3: T-1976 (ADR, design, docs, close I-0174) waits for T-1974 and T-1975, since it records what they built and closes the issue once the fix is in.
- `mergequeue.Verifier` takes `logDir` (from S-0457, accepted while T-1974 ran) and then `stories`: the sync's conflicts were resolved by keeping both parameters, in that order.
- `ScopeToStory` stays a one-story wrapper of the new `ScopeToStories`, and `RunScoped` takes its stories variadic, so `verify` and `taskdone` compile unchanged.
- The template's changelog entry is 1.0.107: template 1.0.106 was published with S-0453 while the story ran.
