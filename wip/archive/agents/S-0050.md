# S-0050 Accepting a story from the dashboard works when the story has a worktree

## Context
Accepting a story from the dashboard fails for any story with a worktree (I-0017): git records absolute host paths for a worktree, and `flai dashboard` mounts the repository at `/project`, so git in the container cannot open the worktree. The operator decided the fix: mount the repository at its host path unconditionally, and add relative-path worktrees as an explicit opt-in, never chosen by detecting a git version. The story's notes hold the evidence and the reasoning. Code lives in `flai/cmd/dashboard.go` (the `docker run` arguments), `flai/cmd/branch.go` (`openStoryBranch`), `flai/cmd/accept.go` (`planRoot`, the merge), `flai/internal/config`, and `flai/internal/check`; flaiover reads `PROJECT_DIR` in `src/lib/server/repo.ts` and derives flai's config path from it in `src/lib/server/flai.ts`. Work is in `.flai-cache/worktrees/S-0050` on `story/S-0050`; `wip/` is written in the main checkout.

## Decisions
- 2026-09-18, operator: the host-path mount is unconditional; relative-path worktrees are in this story as an explicit opt-in. A switch on the detected git version was set aside because creating a relative worktree sets `extensions.relativeWorktrees` on the whole clone and git older than 2.48 then refuses it (observed with 2.47.3).
- 2026-09-18, agent: with the setting on and an older git, `flai stream open` warns and creates an ordinary worktree, which the mount covers. The operator was told and may prefer a refusal.
- 2026-09-18, agent: the setting is a per-user flai config key, proposed `worktrees.relative_paths`, not a manifest field, because the repository format is local to a clone.
- 2026-09-18, agent: verification uses a second container on another port and name against a scratch project, so the operator's running dashboard is untouched.

- 2026-09-18, agent: `/project` is not kept as a second mount; one project path in the container, and nothing in flai or flaiover needs the old one.
- 2026-09-18, agent: `flai dashboard` mounts the main checkout even when started from a story worktree, because `wip/` and the repository live there. Resolves the open question raised at the start.
- 2026-09-18, agent: the image no longer declares `VOLUME /project`, so a host-path mount does not leave an empty anonymous volume; `PROJECT_DIR=/project` stays the image default.
- 2026-09-18, agent: `flaiover/compose.yaml` now requires `PROJECT` and mounts it at its own path. Its documented usage already set `PROJECT=$PWD`.
- 2026-09-18, agent: the check package runs no commands; `flai check` reads the git version and passes it to `check.GitCompat`.
- 2026-09-18, agent: an unreadable worktree is an acceptance blocker found in preflight, reusing the mechanism the dashboard already renders, in place of wrapping git errors where they occur.

## Open questions
- Carried from S-0049: `flai issue bump` and `flai issue new` write `design/issues` in whichever tree they run in, while `wip/` is always written in the main checkout, so issue records made in both trees collide at acceptance. Proposed: decide in S-0047, which touches `flai/internal/issues`.
