## Decisions

- The planner's four tasks stand, in its three layers. Layer 1: T-1190 (the tools, `mcpserver`) and T-1191 (the guard) share no path and run together. Layer 2: T-1192 (inbox and wait) waits for T-1190, as both change `server.go` and it reports what those tools write. Layer 3: T-1193 (convention, template, design, docs) waits for T-1191 and T-1192, so its words match what they built.
- T-1190 may also change `flai/internal/mcpserver/server_test.go` where a test lists the tools; T-1192, which touches it too, runs only after T-1190 is done.
- The tools take no `from` or `story` argument: the sender is the calling session's story, resolved as the issue tools resolve theirs (`FLAI_STORY`, else the `agent-S-nnnn` name, else the story branch checked out), so an agent cannot write as another story.
- `message_get` needs no story of its own: it only reads. The tools answer the conversation as `flai message show --json` prints it.
- `message_get` is in the guard's new `MCPStoryReads`, apart from `MCPReads`, so the planner's, orchestrator's, and analyzer's allowlists, built on `MCPReads`, leave all three message tools out.
- The inboxes `task_done` and `story_start` answer list the story's `messages` too (`inbox.Options.Own`), since an agent reads those at every task transition. The inbox's `changes` carry no `message` events; `wait_for_events` does.
- Beyond the planned touches: `flai touches`' overlap line and the `items_write.go` schema text now say to message the other agent; both `delegation.md` copies say a sub-agent sends no messages; `design/system/workflow.md`'s grown-claim paragraph says to message, not open a thread.
- The close-out's integration tier found that `flai check`'s messages and experiments checks look a story up by its four-digit ID only, so a conversation naming a legacy three-digit ID (`S-004`) was reported as naming a missing story. Fixed with a `checker.named` lookup, as `after:` already did. To read the findings, `TestRunAnswersTheStorysMessages` was run once by hand with `go test -run`, since `flai test` runs the short tier only and prints no finding detail for an integration test; noted here as a deviation from `delegation.md`.
