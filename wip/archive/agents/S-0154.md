# S-0154 Story pages receive live updates

## Context

Story pages went stale once opened: the item page loaded once, Threads loaded once, and StoryAgent polled `agent.status` every 15 s while an agent ran. An agent starting or ending changes no file of the project, so nothing told the dashboard. Design: `design/system/dashboard-host-channel.md` (the channel's notifications), `design/system/flaiover-dashboard.md` (`/api/events`).

## Decisions

- The agent's run is announced by a notification of its own, `agent`, not as a `change` with an invented path: a `change` names a file, and every listener of it would treat the path as one.
- One shared EventSource per project per tab (`listen()`), because a story page would otherwise hold four connections (inbox, item, threads, agent panel) of the few a browser allows one origin. The board, ADRs, charts, and activity pages keep their own for now; they hold one besides the inbox's.
- The `agent` notification is a refinement of the channel on S-0121's precedent (`removed`): recorded in `design/system/dashboard-host-channel.md` item 14, no ADR, since either side ignores what the other does not know.
- A live reload of the item page redraws the body only when it changed, so an unrelated change does not re-run Mermaid or move the reader; explicit loads (a tick, a save, a cancelled edit) always redraw.
