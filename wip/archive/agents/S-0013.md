# S-0013 Kanban board view with transitions

## Context
The board is the operator's view of wip/kanban and the first place the dashboard writes. ADR-0007 said the server would port the validation rules from Go and keep them aligned by a fixture test. Porting the rules, the byte-stable front matter writer, board order maintenance, and index regeneration would duplicate a thousand lines that already exist in flai and drift from them. The cleaner path is to make the dashboard call the flai binary for every mutation (and, in S-0014, for metrics): one reference implementation, and the Docker image (S-0015) bundles flai. That is a design change and gets ADR-0016 here.

## Current state
All four tasks done, story in review. ADR-0016 (supersedes ADR-0007 in part): flaiover invokes the flai binary with --json for every write and, in S-0014, for metrics. src/lib/server/flai.ts finds the binary (FLAI_BIN, PATH), runs it in the project with config and cache under .flai-cache and FLAI_AGENT=flaiover, and turns the fatal stderr event into a RepoError whose message is the rule; src/lib/server/board.ts builds columns with ages and limits; routes GET /api/board, POST /api/items/[id]/move|block|unblock, POST /api/streams/[id]/log. /board drags cards between columns (reason prompted where the rules need one), shows WIP counts against limits, refreshes on SSE, and says read-only when no binary. /items/[id] shows history, blocked intervals, children, files and narrative, and action buttons for allowed moves, block, unblock, and a log entry. Tests: 22, including the wrapper against the built flai on a temp fixture copy. Scripts and CI build flai for the tests. Lint, check, vitest, and all repo tiers green. Committed at review and pushed.

## Next steps

2. Next E-0003 pull: S-0014 charts, using flai stats --json through the same wrapper; then S-0015 image bundling flai; then S-0032 observability.

## Decisions
- Delegate, do not port: every mutation and every metric goes through flai (ADR-0016). The dashboard reader still parses front matter for display and is fixture-tested; the writer, rules, and numbers have one implementation.
- The wrapper runs flai with LOG_FORMAT=json so the fatal event's err field is machine-readable; rule text is returned with status 400, everything else 500, a missing binary 503 with the board showing read-only.
- flai runs with FLAI_CONFIG and FLAI_CACHE_DIR under the project's .flai-cache so the dashboard never touches the operator's home, consistent with the safety convention.
- The board prompts for a reason only where the rules require one (cancelled, review back to in-progress); other moves are one drag.
- Cards are anchors that are also draggable; role attributes were dropped after svelte's a11y check objected.
