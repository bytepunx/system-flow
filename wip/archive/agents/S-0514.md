## Decisions

- The planner's six tasks are kept as drafted (TH-0681). Layers: 1 T-2198 (the usage reader's limit mark) and T-2199 (the ADR), which share no path and run together; 2 T-2200, after both, since `curateEnded` reads the mark T-2198 adds and follows the ADR; 3 T-2201, after T-2200, whose reset time and retry mark it reads; 4 T-2202, after T-2201, whose retry mark decides the thread; 5 T-2203, after T-2202, so the docs describe what was built. T-2200 to T-2202 share `curate.go`, so they run one after another.
- The ADR names this as the curator's part of ADR-0209 §5, ahead of S-0534's host-wide budget state, which builds on this story's reader and `limit.go` (TH-0711 assumption 1) and may fold the curator's retry into its hold.
- MS-0216: S-0519 shares `docs/operators/index.md`; S-0514 changes only what it says about the curator and the usage limit, and leaves § MCP over HTTP alone.
- T-2198: a Limit needs a 429 or a rejecting `rate_limit_event`, so another API error, such as a 529, is not taken for a usage limit. The reset time travels on the End, from the rejecting event before it.
- T-2200: the curator's log is read as Claude Code's, as its activity is (`activity.go`), not by `run.Harness`. A limit outranks the exit code.
- T-2201: a retried `asked` with held acceptances becomes `asked; accepted S-nnnn`. A retry the checks refuse is not tried at every look (in-memory `retried`). After a retry on the limit again, the scheduler still holds until that run's reset. `launcher.curate` gained a `resetAt` parameter; its one-line call-site change in `curate_test.go` was committed with T-2202, which owns that file.
- T-2202: `runLimit` also returns the harness's final text, quoted in the thread. A thread that cannot be opened is not tried again.
- T-2203: `docs/users/flai-reference.md` is generated, so `flai/cmd/curate.go`'s help text gained the limit and the reference was regenerated; `flai/cmd/curate.go` was added to T-2203's and the story's touches.
- Sub-agents worked each task; I reviewed each diff, fixed ADR-0214's example `why` to match the code, and ran `flai test` on `flai/internal/serve` and `flai/internal/usage` after T-2200 and T-2202 (both passed).
