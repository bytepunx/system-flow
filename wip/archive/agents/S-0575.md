## Decisions

- The planner's three tasks stand as drafted: three layers of one task each, T-2466, then T-2467, then T-2468, since all three write the one results document and each works on the cluster the one before leaves.
- I work the tasks myself rather than through task sub-agents. The explorer started for the story was refused every read outside the worktree, and the experiment reads and runs `~/git/bytepunx/authstar`, `signet`, and `kluster`, so a task sub-agent could do none of it.
- No GitHub push and no deploy key. authstar's `integration/scripts/provision.sh` adds a deploy key to `bytepunx/authstar-integration` with `gh` and commits and pushes there. kluster 1.3.1's `authstar` profile seeds signet through the admin API itself (`kluster-lib/profile/authstar_services.go`), so the experiment seeds each story namespace the same way and never runs `provision.sh`.
- Scratch is `/tmp/S-0575`. The two builds are `git archive` exports of authstar `e02e430` (build A, main today) and `af55c04` (build B, before S-0009 changed chronicle), so nothing touches the authstar checkout.
- Files the experiment writes go under the worktree's git-ignored `bin/s-0575/`, not `/tmp`: the Write tool is refused outside the worktree. Logs, the kubeconfig, and the exported trees stay in `/tmp/S-0575`.
- A story namespace deploys its build from its own commit's `integration/manifests` and seeds signet from that commit's `integration/config/authstar` and `lib-secrets.sh`, renamed for the namespace, rather than copying kluster's Deployments. That is the project's own deploy, which S-0578 means flai to run, and the two commits differ in chronicle's manifest and config. The seeding uses kluster-lib's own `SeedSignetBundle` and `EnsureSignetPolicy` through a scratch command (`bin/s-0575/kluster-lib/cmd/storens`), built with Go 1.26.3 in scratch caches since the host has 1.26.0.
- Each namespace gets its own RabbitMQ user on its own vhost, made with `rabbitmqctl`: the RabbitMQ passwords in `lib-secrets.sh` belong to an older cluster.
