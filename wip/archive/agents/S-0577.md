## Decisions

- Reviewed the planner's five tasks against `design/system/kluster.md` and ADR-0254, and kept them, widened:
  - T-2472 also checks the timeout, empty command lists, the story-namespace form `s-` and digits, and the kluster config's own `name` and `provider` (k3d only), as the design's § The project's cluster and § The namespaces say.
  - T-2474 runs kluster in the main checkout and writes `.flai-cache/kluster/kubeconfig` after `up`, as § The project's cluster says; S-0578's deploy reads it.
  - T-2475 also refuses `flai serve enable kluster` for a project with no block, in `flai/cmd/serve_actions.go`. The planner left that file out, but the design refuses the action without a block, and the dashboard's Features toggle runs `flai serve enable`, so the one refusal covers both.
  - New T-2497: `flai guard` refuses every served agent and sub-agent the `flai kluster` subcommands that write and lets `status` through (§ The `kluster` host action, ADR-0254 §7). No planned task covered it.
- The plan's layers:
  - Layer 1: T-2472 (manifest, check), T-2473 (host action in hostapi), T-2497 (guard). They share no path and none reads another's output.
  - Layer 2: T-2474 (kluster package) waits for T-2472's manifest type.
  - Layer 3: T-2475 (commands, enable refusal) waits for T-2474's package.
  - Layer 4: T-2476 (documents) waits for T-2473, T-2475, and T-2497, whose behaviour it describes.
- Layer 1 shares the story's worktree: the three packages do not build one another's changes.
- T-2473 is a one-entry change, so the story's agent works it itself; T-2472 and T-2497 go to task sub-agents at once.
- T-2473's new action changed the action list `TestHostActionPush` pins in `flai/cmd/serve_actions_test.go`, so T-2473 took that path too.
- Review of T-2497: the sub-agent put the kluster check inside `forgePush`, since `call.go` was outside its touches. The story's agent made it a step of its own in `Decide`, `klusterWrite`, beside `forgePush`, and widened T-2497's touches to `call.go`.
- The manifest reads the block leniently, so a misspelt key is the finding `manifest.kluster`, not a manifest that fails to load (T-2472).
- `flai/internal/kluster` streams through an `Exec` interface of its own, because `execx.Runner` returns output only at the end and a bring-up takes minutes (T-2474).
- `flai kluster down` refuses a non-terminal without `--yes`, unlike commands that proceed silently there, because it deletes the cluster and its data. `status` exits 0 for a stopped or absent cluster: it reports, not fails (T-2475).
- The no-block refusal was made one line: flai prints a refusal as one log line, which showed the block example's newlines as `\n`.
- Verified on this host: `scripts/flai.sh kluster status` in this repository, which has no block, prints the no-block sentence and exits 1. No real `kluster up` or `down` was run: it changes the operator's clusters.
