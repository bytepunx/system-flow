## Decisions

- The reads call internal packages, as the rest of the table does, rather than running the cobra command tree in flai serve's process: that would carry the CLI's process-wide state (the `apps` map, config creation, the logger from the environment) into a long-running server.
- The in-process answer is turned into the method's answer by the same `outcome` that reads a flai process's output, from its JSON and its log events, so warnings and error codes stay what they were.
- The contract test lives in `cmd`, running each command through cobra in the test's process with a fixed clock, rather than starting a built flai: a separate process cannot share the clock, and `stats` answers from it.
- `accept.preview` makes its probe transitions as the manifest's owner, where `flai accept --dry-run` uses the configured author: the name is recorded only on the probe, which is thrown away, so the answer is the same.
- `flai move` and `flai accept` start their real runs from `preview.Cancel` and `preview.Accept`, so the dry run and the real run share one preflight; the acceptance's refusal of uncommitted files outside wip is now checked after the preflight, with the same message and the same precedence.
- Not pushed: the inbox reports S-0156, S-0157, S-0158, S-0160, and S-0161 accepted and not pushed. This session was started to work S-0159 alone, so the push is left to the operator.
