# S-0197 Agents commit each task after flai stream sync, and stream sync makes conflicts easy to resolve

## Context

ADR-0069 (refines ADR-0019): agents use `flai stream sync` for the story branch's git operations and commit each task on `story/S-nnnn`. `flai stream sync` today rebases with `--autostash` and reports conflicts on one line; the story makes it refuse uncommitted changes and list each conflict with how to continue or abort, and brings the harness prompt, the conventions, close-out.sh, the design, and the user guide into line.

Every criterion is checked. The first verifier found two golangci-lint `unparam` findings in test helpers, and fixing one exposed a third; all were fixed in a4443c4 and 93b388f.

## Next steps

## Decisions

- TH-0072, designer's answer (a), 2026-10-03: because sync refuses uncommitted changes, the per-task cycle is commit the task, `flai stream sync`, resolve what it reports (`git add`, `git rebase --continue`, or `git rebase --abort`), run the tests for what the task changed, and commit any fix; before review, commit everything, sync again, resolve, and close out. `git.md`'s "Commit each task" and "Before moving a story to review" bullets change in both copies to say so. ADR-0069 is accepted and stays as written: its decision lists sync before commit, and the order changed here with the designer's consent.
- `delegation.md` (both copies) also gets the sync before the verifier's run, so every convention says the same cycle; T-0725 and the story touch it.
- The harness prompt tells the agent to sync once more before moving to review, after the verifier's run; that sync normally does nothing, and acceptance rebases again in any case.
- Touches widened to `flai/cmd/branch.go` (where `syncStoryBranch` lives), its test, the conventions, design, and user guide files the criteria name.
- The plan, two layers. Layer 1: T-0723 (sync code: storygit, branch.go, stream.go, stream_sync_test.go), T-0724 (harness prompt), T-0725 (conventions, close-out.sh, template); they share no path and wait for nothing, so they can run together. Layer 2: T-0726 (flai-cli.md, workflow.md, user guide) waits for T-0723, whose refusal and conflict report it describes. T-0724, T-0725, and T-0726 also wait in practice on TH-0072 for the order of the cycle they describe.
