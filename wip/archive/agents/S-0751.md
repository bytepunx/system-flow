## Decisions

- Kept the planner's plan: four layers, one task each. T-3177 writes the job (no after). T-3178 waits for T-3177, since it calls the job's runner. T-3179 waits for T-3177 and T-3178, since it builds on T-3178's new containerImage. T-3180 waits for T-3178 and T-3179, since it describes their behaviour. No two tasks run together: each layer reads the one before.
- The stall limit and network retries ADR-0295 §5 gives S-0751 already exist in agentimage's Runner (DefaultStall, RetryDelays, from S-0740); the job reuses them rather than adding its own.
- Strategic agents run on the harness image alone and wait only for it (ADR-0295 §6, S-0733's ADR), so criterion 5 is built in T-3178.
- T-3178's touches widened to the wiring (serve.go, agents_launch.go, cmd/serve.go, cmd/image.go), the five strategic start paths, and the run readers (agents_activity.go, stop.go, restart.go). Without a hold of their own, strategic starts would ask for the job and still record a refusal, which falls short of criteria 1 and 5.
- A run held for its image counts against the in-progress limit as a started one, and a hold left by a stopped flai serve fails at the next look and waits for a retry. It is not put back to be started again on its own (D-0609's intent: no make agent-images advice remains).
- Starts made outside flai serve (by hand through the CLI or MCP) have no image job: a missing image refuses, naming flai image ensure. A held run whose flai serve stopped fails at the next look rather than being put back. The checks' wait runs outside the checks' timeout, so a long build does not time them out.
- D-0609 cited: the make agent-images refusal in container.go was left for this story, and it is gone.
