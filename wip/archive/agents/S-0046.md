# S-0046 Moving a story to done is acceptance

## Context

## Current state
Complete and verified on the served build: the item page's move to done opened the dialog with the branch and the release plan for this story, and Cancel left it in review. One acceptance function serves `flai accept` and `flai move <story> done` from review, with the same flags; `flai accept` completes stories that are done but unarchived; `flai accept --dry-run --json` previews the plan (computed from the story worktree, where the branch commits already are), the branch, and blockers. A preflight refuses before any change when git has no committer identity or cannot run; a failed push after the acceptance commit is reported as `push_error`, not as a failure. `flai check` warns `story.unaccepted` for done stories that are unarchived or whose branch still exists. Outside git, acceptance is the transition plus the archive. `flai dashboard` passes the host's git identity into the container. The dashboard has `GET /api/items/:id/acceptance` and an `AcceptConfirm` dialog used by the board drop and the item page; notices report tags or an unpushed acceptance. Tests: move-to-done with a branch, dry run, the repair path with an unpushable remote, the identity preflight, the check rule, the dashboard identity env, and the dialog component (plan, blockers, refusal).

## Next steps
1. Operator review. Accepting it from the rebuilt dashboard is the natural first use: drop S-0046 on done, confirm, then push from a shell.

## Decisions
- The operator's instruction (done means accepted) changes the workflow text: recorded in workflow.md and the work-management project addition. Agents still never move a story to done.
- Push failure is not acceptance failure: by the time of the push everything is committed and tagged, pushing is idempotent, and the dashboard container cannot push at all. Treating it as fatal would report a failure for a story that is, in fact, accepted.
- Blockers are computed in the dry run so the dialog can refuse before the operator confirms, and enforced again in the real run.
- The container gets the host identity through the standard `GIT_AUTHOR_*` and `GIT_COMMITTER_*` variables rather than by writing git config into the mounted repository.
- The dirty-tree check parsed `git status --porcelain` by column, but the runner trims output, so a first line starting with a space lost a character and a `wip/` path looked like a foreign change. It would have refused every acceptance from the dashboard. Replaced by a shape-based parser with a test.
- Epics keep their own move semantics; only stories are accepted by a move, since an epic's acceptance is a major release the operator should ask for by name.
