# S-0195 Publishing is the one way accepted work reaches the remote, and agents no longer push unpushed acceptances

## Context

ADR-0067 (accepted 2026-10-02): publishing (`git fetch`, then `flai release --pending`, or Publish) is the one way accepted work reaches the remote, and agents publish only when the operator asks. Today the MCP instructions and `inbox`/`flai board` (`unpushed`) tell agents to run `flai push --pending`, and the board carries a push banner (`UnpushedNotice.svelte`) with Push now. `flai release --pending` checks the remote's tags (S-0174) but not whether the remote branch moved.

All seven criteria checked; S-0195 moved to review.

## Decisions

- Plan, in layers. Layer 1: T-0717 (ADR), which every other task waits for, because the first criterion says nothing is built before the designer answers. Layer 2: T-0718 (MCP instructions, inbox, `flai board`), T-0719 (`release --pending` refuses a clone behind its remote branch), T-0720 (host API drops `push.run`, `push.pending`, and auto-publish from the dashboard); their touches share no path. Layer 3: T-0721 (dashboard) waits for T-0719, whose publish-preview JSON it shows, and T-0720, whose removed host methods it stops calling. Layer 4: T-0722 (design and guides) waits for all four, whose behaviour it describes.
- Layer 2's tasks run one at a time in the story worktree, not at once: all three build and test Go package `flai/cmd`, so a half-done edit in one would fail another's tests, and each is short beside priming and review.
- "Fetch first, or refuse": flai refuses rather than fetching, as S-0174 does for tags, so flai still never fetches on its own; the refusal names `git fetch <remote>`, then a merge or a rebase onto `<remote>/<branch>`, which ADR-0067 as accepted allows.
- ADR-0067 as accepted keeps for a later agent the ability to see what is pending a publish: `inbox` and `flai board` replace `unpushed` (with its `flai push --pending` command) by `unpublished`, the accepted items `release.PendingIDs` finds unreleased, given as information, not a duty.
- TH-0070: the designer wants a publish refused because the remote moved to drop its tags, rebase or merge, verify, and re-tag, and merge conflicts worked through tasks on the stories in question, in threads with the operator. That changes the work-management baseline, which S-0196 is editing now, so it is S-0242 (backlog), not S-0195.
- S-0196 now touches `flai/internal/mcpserver/folder.go` too; T-0718 keeps its edit there to the one instruction sentence, and conflicts are resolved at `flai stream sync`.
- The story's criteria settle ADR-0067's open consequence: `flai push --pending` and `auto-publish` stay for the operator's shell, and leave the dashboard (no Push now, no push banner, no auto-publish toggle). The `push` host action stays as the gate for Publish.
