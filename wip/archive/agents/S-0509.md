## Decisions

- Plan: the planner's four tasks stand, in four layers of one task each: T-2158 (ADR) → T-2163 (adapter, pilot) → T-2170 (serve's start paths) → T-2175 (proof, issues, docs). Each waits for the one before because it builds on its output: the ADR names the mounts, the adapter builds them, the start paths call the adapter, and the proof runs the whole.
- T-2170 also touches `flai/internal/serve/container.go` and its test, S-0508's readiness and stop code, which the planner did not know of; widened before the work.
- Already in place, read before planning: the four start paths call `harness.For` and `startOf`; `pilotRequest` keeps `Role`, `Item`, `Focus`, `Since`, and `AskedOn` in the JSON; pilot hands its whole request to the inner adapter, whose `Start` adds `--agent <role>` and `FLAI_ROLE`. What is missing: the adapter refuses a request with no story; the mounts; `Builtin`, the role file's prompt, is `json:"-"` and so lost; S-0508's readiness and stop name a story.
- The ADR chooses the main checkout read-write at its host path, as T-2158 recommends: the analyzer's report, the curator's `flai digest`, and the orchestrator's `--autocommit` commands write the checkout through the CLI, with no MCP route, and the guard already bounds those writes on the host. Read-only with writes over MCP would need new MCP tools first.
- TH-0815 asked how to make criterion 4's live run, since the host's flai 1.80.2 lacks this code and has no container harness set. The operator confirmed the orchestrator's recommendation (as D-0466 for S-0508). Criterion 4 now covers a planner's container run with docker faked, logged with duration and cost. The live flai-serve run moved to draft S-0567, after S-0509. S-0509's Notes record the change.
- T-2163 (sub-agent): `containerSubject` and `roleStart` in the adapter; `ContainerName` and `ContainerCache` take a story or a role; pilot's `builtin` reads the role file from the mounted checkout.
- T-2170 (sub-agent): container readiness moved into `startOf` for every start. The four strategic paths never passed pilot's stdin (`spawnGated`); now `spawnGatedWith` does. `containerSubject()` derives the role from the run's fields, as `orchestrates()` and `analyzes()` do. I added the container stop to `OrchestratorStop` (`orchestrate_hold.go`) and its test myself.
- Rebased onto S-0517's accepted git mounts (ADR-0246). The story branch of `Start` keeps S-0517's mounts, and the worktree opens in `startOf` before the adapter.
- T-2175 limitations: I-0256 (no host configuration in the container), I-0257 (`.git/config` writable), and I-0258 (a defined role is refused); I-0216 bumped (the guard hook needs `go`). `agent-adapters.md` § What is built gained S-0509's sentence.
