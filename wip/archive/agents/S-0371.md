## Decisions

- **The planner's eight tasks are kept as drafted.** They follow the shape the operator confirmed on TH-0420, every touch is a file, and no layer's tasks share a path.
- **Layers.** 1: T-1476, the ADR, which the code builds. 2: T-1477, the check and the record, which everything else reads. 3: T-1479 (preview, refusal, keep) and T-1574 (`flai stream restore`) run together: both read T-1477's record and share no path. 4: T-1478 (the sync's warning) waits for T-1574, as both change `flai/cmd/stream.go` and the warning names the restore; T-1575 (host writes) waits for T-1574 and T-1479, whose command and flags it calls; the two run together. 5: T-1480, the docs, waits for the last code so the reference is generated once. 6: T-1481 closes I-0124 with what was built.
- **T-1476 and T-1481 are worked by this agent, the rest by task sub-agents.** The ADR and the issue close are short; the code tasks are long enough to pay for a sub-agent each.
- **The work goes on to the planner's plan while TH-0448's criteria await the operator.** The plan covers all three proposed criteria, so either answer leaves the work as it is.
- **The check leaves out generated files and the files the rebase merged.** T-1479's sub-agent found three existing acceptance tests refused on `design/issues/summary.md` and a merged issue file, which flai writes itself from both sides. ADR-0155 does not name the exclusion; the design docs do.
- **`storygit.Sync` adds the recorded paths to `undoes_main`; `storygit.Rebase` alone does not.** T-1478's sub-agent first merged them in the `flai stream sync` command only, which left `flai task done` warning on this rebase's findings alone. Moving the merge into `Sync` covers both; accept's `Rebase` keeps its own findings for its refusal.
- **Two small departures from ADR-0155, left as they are.** `flai stream restore` never removes a file: a path main deleted has no line main added, so it is never recorded. A path only the acceptance's own rebase finds cannot be kept in that same call, since keeps are checked against the record before the rebase; the rebase records it, so a second `flai accept --keep-removal` takes it.
- **`flai move`'s `--reason` help names its use as the keep reason for `done`** (T-1479, outside its first touches, as was the one field `AcceptOptions.Keep` in `preview/orchestrator.go`).
- **A conflict on a branch resolved by hand is not checked.** A rebase that stops on conflicts returns before the check, and the next sync starts from main's head. The conflicting paths are listed to the agent then, so the silent case of I-0124 stays covered.
