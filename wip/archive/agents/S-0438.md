## Decisions

- Plan, in layers: T-1858 (the ADR, which fixes the protocol); T-1859 and T-1860 together (the harness files and the process runner share no file); T-1861 alone; T-1862 and T-1863 together; T-1864 last, so the docs describe what was built.
- T-1863 now waits for T-1861 as well as T-1860: both change files of the `flai/cmd` package, and a half-done edit of one would fail the other's `flai test flai/cmd`. T-1862 and T-1863 share no file or package, so they run together.
- T-1858 written by the story's agent, not a sub-agent: the protocol it fixes is the contract every later task builds on. Recorded as ADR-0163, refining ADR-0029 and ADR-0031.
- The installed flai and the MCP server are 1.52.0, behind 1.53.0 in the history, so MCP `task_done` refuses (ADR-0142, TH-0485). Tasks are closed with this tree's `scripts/flai.sh task done`, which is 1.53.0 or newer.
- T-1859 (sub-agent): SvelteKit lets the harness page through when the plugin adds its middleware directly in `configureServer`, ahead of SvelteKit's router; no other route was needed. The harness script, an error-boundary `Frame.svelte`, and the catalogue are virtual modules, so `svelte` resolves from the sub-project and `server.fs.allow` is untouched. Vite is resolved from the sub-project with `createRequire`, and its own config loaded with `loadConfigFromFile`, so a TypeScript config works. Props change through `Frame`'s `update` without a remount.
- T-1859: the harness uses its own optimizer cache, `node_modules/.vite-flai-components` in the sub-project, so that it and the app's own dev server do not invalidate each other's. `select` also takes `functions`, as `props` does, for a component that calls a function prop as it mounts; component-library.md's table says so (T-1864), ADR-0163 stays as accepted.
- T-1860 (sub-agent): ready means the harness page answers 200; the context bounds only the wait, and once Vite answers only `Stop` or its own exit ends it. `Stop` sends TERM to the group, then KILL after 5s. Process-group helpers are split by build tag (`proc_unix.go`, `proc_windows.go`), added to T-1860's touches.
- T-1863 (sub-agent) changed three paths beyond its planned touches, added to them: `flai/internal/config/config.go` (`components.idle` lives in the host's config beside `checks`), `flai/cmd/serve.go` (the supervisor is built once and stopped when `flai serve` stops), and `flaiover/src/lib/server/agent.ts`, where the four methods join `REQUIRED_METHODS` because hostapi's contract test requires every method flai offers to be listed. The task's note had left that to S-0439; the test made it this story's. Component writes answer inside flai serve through a new `do` on a spec, still gated, journalled, and remembered by request ID.
- T-1864 started while T-1862 finished its hand run: the docs describe the methods, the command, and the action, which T-1861 and T-1863 built and tested, and T-1862 adds only a test and the story's notes.
- T-1862's hand run: the guard refuses `flai components serve` to a sub-agent (I-0156), so the sub-agent rebuilt what `Serve` writes by hand, and the story's agent then ran `flai components serve --project flaiover` itself; both rendered Gallery.svelte.
