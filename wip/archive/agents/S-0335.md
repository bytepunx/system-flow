## Decisions

- The planner's tasks stand. Layers: (1) T-1207 and T-1208 together, no path in common; (2) T-1209, after T-1208, which adds the activity field it shows; (3) T-1210, after T-1207 and T-1209, so the words describe what was built.
- Both T-1207 and T-1208 need which conversations of a story await the other story's reply. I wrote `messages.AwaitingOther`, `messages.ToSince`, and `Conversation.Other` in `flai/internal/messages/messages.go` before the layer, so each task uses one rule rather than a copy, and added the file and its test to T-1207's touches, which commits them.
- flai serve watches the whole `wip` folder (`watchedPaths` in `flai/internal/serve/serve.go`), so a reply in `wip/messages` already wakes its look: T-1208 needs no wider touch.
- An agent ends on a conversation only when no conversation of its story awaits its own reply: a message it owes is work left to do.
- T-1207: `endWhy` checks conversations in one pass of its own (`awaitingReplies`), since the check for a reply owed needs the same loop; the rule is `messages.AwaitingOther`'s.
- T-1208: a run keeps lists, `conversations` and `waits_on`, since a story can wait on several stories at once. A reply that came after the run started and before its end was judged makes it `asked` and answered at once, so the next look starts it again; the thread race of S-0317 is left to that story. `messaged` looks from a second before the end, since times are kept to the second, and never before the run's start.
- T-1208 follow-ups, made by me: the restart prompt (`harness.go`) tells an agent started on a conversation to read it with inbox or `message_get`; the start, restart, commit, and stop refusals name what the agent waits on (`run.awaits()`); the `judge` wrapper went, with `commit_test.go` calling `judgeRun`.
- Accepted risk: a conversation the story wrote last reads as awaiting the other story, even when it only answered. An agent that ends with such a conversation open is judged `asked` rather than failed, so ADR-0108's auto restart does not apply; a new message, the conversation closing, or the operator's Retry starts it again.
