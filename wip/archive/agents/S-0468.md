- `touches.folder` and `wip.after-hub` are advisory warnings, which `--strict` passes over (ADR-0188 § Consequences), not warnings that fail it as T-2058's text first said: a story keeps its folder touch from the start until its tasks name files, a planner may keep one with its note, and a hub's own agent cannot drop the `after` entries of the stories naming it, so failing `--strict` would stop task closes and close-outs over a hold nobody can clear then. T-2055's sub-agent raised the hub case; the refusals do the enforcing.
- ADR-0188's topics are `planning`, `board`, `touches`: `workflow` is not a topic flai knows.
- T-2056 and T-2057 refuse only the entries a write adds, so an item written before the rule can still be edited. `FolderTouch` reads the checkout flai runs in, and does not count `.git`, `.flai-cache`, or `node_modules`.
- T-2058 ran in its own task worktree (`task/T-2058`) beside T-2057, because `flai/cmd` builds the check package. I copied its four files back and removed the worktree.
- Review found that `itemedit.Apply` and `itemnew.Create` refused a write that brought a new advisory `touches.folder` or `wip.after-hub` as a new check finding. They now keep the write with a warning, as they do a `wip.overlap` (f266ed6). My review also limited the planner's `flai touches` rule to stories.
- `flai story new --touches` (cmd/items.go) does not hold the planner to the Planning note. ADR-0188 names `flai edit --touches`, `flai touches`, `item_new`, and `item_edit`, and the planner drafts stories through `item_new`, so I left this gap as it is.
- TH-0602 was allowed, and both `planner.md` files were written with the same two sentences (d51c774). TH-0603's write went through on the retry.
- The first close-out stopped on `TestServeSettingsAreShownToTheDashboard` (flai/cmd), which this story does not touch. The second run on the same commit passed every step, with integration and smoke left to the merge queue.
