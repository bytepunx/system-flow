# S-0286 A story that changes a path Claude Code protects is flagged at review and accepted only by the operator, flai checks permission_prompt against each new Claude Code, and the prompt covers every protected path in a worktree but .git

## Context

S-0286 makes auto-approve safe to leave on: a story that changes a path Claude Code protects is accepted by the operator only, flai serve checks `permission_prompt` against each new Claude Code version, and the prompt covers every protected path in a worktree but `.git`. ADR-0106 records it, refining ADR-0086.

## Current state

S-0286 is in review. Every task is done, all six criteria are ticked, and story/S-0286 is synced with main. The verifier's close-out passed every step: lint, the Go and vitest suites, smoke, and flai check --strict, with two warnings outside the story recorded in I-0078 and I-0073.

## Decisions

- Kept the planner's plan as drafted. Layers: (1) T-1106, the ADR every other task builds on; (2) T-1110, the protected list and the prompt, and T-1114, the Claude Code check, which share no path; (3) T-1120, the acceptance gate, which reads T-1110's `protected` package; (4) T-1121, the review page, which shows T-1120's preview field, and T-1122, the docs, which describe T-1114 and T-1120.
- Tested before ADR-0106 relied on it (Claude Code 2.1.290, Haiku, a scratch repo in /tmp): a PreToolUse hook in a nested `wt/.claude/settings.json` did not fire for a `claude -p` started at the root; the same hook in the root's `.claude/settings.json` did.
- ADR-0106 is recorded accepted: the three parts are the operator's decisions of 2026-10-06 in the story's Notes.
- The operator, for the acceptance gate, is the story's owner or the project's owner, as ADR-0097 names who answers a permission thread; with neither named, anyone but the orchestrator.
- The check's failure thread goes on `system-flow.yaml` of each served project with claude-code agents; flai still starts the agents. Its record lives in flai's host state beside its configuration.
- ADR-0106's check runs beside an agent's start, never before it, as T-1114 planned. The ADR was amended on the branch before it reached main.
- The ADR was renumbered from 0105 to 0106 because S-0272's branch also took 0105 (I-0063, bumped).
- flai guard's sub-agent refusal (ADR-0102) widened from `.claude/` to every protected path but `.git` (`guard.ProtectedWrite`), along with the agent's start prompt. Without it, a sub-agent's `.mcp.json` write would wait on a thread while auto-approve is off, where before the story it was refused at once. The conventions' project additions in delegation.md still say `.claude/`. That is a subset, and true, so they were left unchanged.
- Known limit: in a project whose manifest names no `owner`, the dashboard accepts as `designer`. That acceptance is refused for a protected story whose own owner is named. The same holds for permission-thread answers under ADR-0097. The guides tell the operator to set `owner`.
- The verifier noted that `guard.ProtectedWrite` reads the absolute path, so a checkout below a folder named like a protected one, such as `~/.idea/`, would have every sub-agent write refused while auto-approve is off. The old `.claude` check had the same shape. Left as it is.
- The Claude Code check is tested with a stand-in for `claude` only, as criterion 4 asks. No run against the real Claude Code was made from this story.
