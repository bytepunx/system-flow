## Decisions

- Plan in four layers. L1 T-3428 alone: it owns every change to flai/internal/closeout, the contract (KindResolve, Job outcome fields, the resolve: and verify: progress lines, closeout.Status) the rest builds on. L2 T-3429 after T-3428: the serve job reads that contract. L3 T-3430 after T-3429: it asks for the job, and both change flai/cmd/accept.go. L4 T-3431 and T-3432 together after T-3430: the dashboard reads accept.resolve's new answer and resolve.status; the docs describe what is built; no path in common.
- The resolve job reuses the close-out job's slot (S-nnnn.job.json, S-nnnn.log, the verify pass's running map), so a second request answers the job under way and the restart sweep records it interrupted, sending nothing back (criterion 8).
- Progress of steps and tiers reaches the log through FLAI_VERIFY_PROGRESS=1, which the job sets and flai verify reads, writing lines to stderr: an older flai ignores the variable, and neither close-out script nor the template's needs a change, and the script's read of verify's last stdout line is untouched.
- The send-back's thread and target move to a new package flai/internal/sendback so flai serve can send a story back without importing flai/cmd; the thread keeps its flai author and 'Acceptance sent back:' prefix, so agents_restart.go starts the agent with no change.
- flai accept --resolve keeps ADR-0302's refusals, the story nothing holds included, and refuses (exit 4) when flai serve takes no request: only flai serve runs the job.
- T-3428 widened to flai/internal/verify/run.go and verify.go: tiers run in one verify.Run whose scheduler runs some in parallel, so the tier hooks (RunOptions.TierStarted, TierEnded) belong in the scheduler; parallel tiers stay parallel.
- closeout.Progress keeps no Steps slice, so it stays comparable with == where three tests outside the story compare it; Running reports kind, step, and tier, and closeout.Status (type JobStatus) alone gives the steps, which the dashboard reads.
- Narrowed S-0804's folder touches: template and scripts/close-out.sh dropped, since the progress variable needs no script change; docs and design/adrs named by file.
- T-3429: the resolve job journals as action close-out with method resolve.job, so flai stats, which counts verify.job, does not count it as a close-out and metrics.md stays as it is. A rebase that does not end clean is verdict stopped at step rebase; a sync that fails with no conflict sends the story back as a failed rebase naming the log; a rebase found already waiting is left as found, as sendBackUnsettled does.
- T-3430 widened to the method lists a new host read must join: guard_tables.go's HostAPIReads, hostapi writes_test.go's good and refused tables, guardreads_test.go's comment, and flaiover's REQUIRED_METHODS in agent.ts, which the contract test checks; made by the story's agent after the sub-agent named them.
- T-3431: the review page copies LogViewer's six-line log read rather than editing LogViewer.svelte outside the touches; it follows a resolve job on load, and a close-out running alone stays in the Verification section.
- Criteria 6 and 7 are verified by the Go and vitest tests, not on a live flai serve. flai serve here runs the installed flai, which predates S-0804, so this story's own close-out log holds no progress lines; a live check waits for a release.
- Criterion 5's preview half rests on the verify record: the job's passing close-out at the rebased head is the record verify_behind_main and the sync blocker read, so no separate test of the preview was written.
