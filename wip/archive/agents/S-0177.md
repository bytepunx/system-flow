## Decisions

- ADR-0064 refines ADR-0043. Restart covers a story with no run here, and `agent start` stays for ready stories. Reason: restart is already for "an in-progress story whose agent is gone".
- The narrative records `host` (the Notes asked whether to decide this here). Reason: without it a story begun on this host outside flai serve cannot be told from one begun elsewhere.
- A story in review gets no begun-elsewhere entry or Start agent. Reason: restart takes only ready or in-progress stories (ADR-0043), and the criteria name a story in progress. The explorer noted that the review page has no agent block.
- The MCP tools need no guard change. Reason: `flai guard` refuses every MCP tool not in `guard.MCPReads` to a sub-agent.
- The operator's prompt says to commit each task, while `git.md` says commit when a story lands. Following the operator.
- A ready story that has no run here and cannot start (limit full or held) is queued as a stand-in run with no `started`. `restartWhy` of such a run is empty, so the launcher's start says the story entered ready. Reason: the queue reads as waiting on the dashboard, and a second press is refused as already queued, as for any retry.
- The command adapter (`harness.Command`) gets no env var for Begun. Reason: it gets none for Restart either, and adding one means an operator-settings row; the claude-code prompt carries it.
- `anyRunning` in flaiover leaves elsewhere entries out, so a page does not re-ask every 15 s for a story nothing here runs for.
- agent_start and agent_restart refuse an agent that flai serve started (`FLAI_STARTED_BY=flai-serve` in its `flai mcp`). Reason: the verifier pointed out that such an agent shares the operator's flai config, so it could start any story past holds and the limit. The criterion says "so an operator's own agent can do it". This is a refinement of ADR-0064, recorded in flai-cli.md.
- `flai stream open`'s reopen runs `git worktree prune` first. Reason: a worktree removed without git leaves a registration that refuses the branch a new worktree (the verifier's edge case 5).
- The inbox reports unpushed acceptances (S-0182, S-0187). I did not push them. Reason: the operator's prompt limits me to S-0177, and a push is outward-facing.
