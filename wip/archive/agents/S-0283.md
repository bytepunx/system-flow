# S-0283 flai's permission_prompt returns a result Claude Code calls invalid, so a .claude/ write and a /tmp write are refused at once with no thread

## Context
I-0082: Claude Code calls every `permission_prompt` answer invalid ("Expected a single text block param"), so an allow never lets a `.claude/` write through and a deny never tells the agent why.

## Current state
Every task is done and committed on story/S-0283, synced with main; both criteria ticked. `permission_prompt` is a raw handler answering one text block (T-1001), the users' guide says what a refused write tells the agent (T-1002), and I-0082 is closed (T-1003).

The close-out passed every step on a fresh verifier's run; the first run stopped once at `scripts/install-test.sh` with no cause shown, which passed alone and on the rerun (recorded as I-0086). S-0283 is in review.

## Decisions
- Proposal, before building (the goal asks for one): register `permission_prompt` with the server's raw `srv.AddTool` and a `mcp.ToolHandler`, which unmarshals `PermissionIn` from `req.Params.Arguments` itself and answers a `CallToolResult` of exactly one `TextContent` holding the JSON decision. The typed `mcp.AddTool` infers an output schema from `PermissionOut` and sends `structuredContent` beside the text block, which Claude Code 2.1.290 rejects (confirmed outside this story, in the story's notes). Arguments that do not unmarshal are a deny in the same shape, not a tool error, so Claude Code always reads a decision. ADR-0086's decision stands; only the wire shape changes, so no new ADR.
- Plan, kept as the planner drafted it: layer 1 T-1001 (`permission.go`, `permission_test.go`, `folder.go`); layer 2 T-1002 (`docs/users/flai.md`) and T-1003 (I-0082 and `design/issues/summary.md`), which share no path and run together. Both wait for T-1001: T-1002 describes the refusals T-1001 delivers, in its words, and T-1003's reason names T-1001's fix and test.
- T-1001 went to a task sub-agent. It made `permissionRoute` an `mcp.ToolHandler` with a `permissionResult` helper, narrowed `(*server).permissionPrompt` to return a `PermissionOut`, and added `TestPermissionPromptAnswersOneTextBlockAsClaudeCodeRequires`; `askPermission` now checks the shape for every permission test. The new checks failed on main's code (output schema listed, structured content answered, unreadable arguments a tool error) and pass after. I reviewed the diff and reran the tests.
- S-0219's no-thread `.claude/agents/orchestrator.md` refusal, traced by the sub-agent from `~/.flai/serve/agents/sf-S-0219-20261006T025719Z.log` lines 1582-1583 and 1622: the write was in S-0219's worktree while the story was still ready (it moved to in progress 14 s later), so it was the at-once "not in progress" refusal ADR-0086 intends, hidden behind the invalid-result message. No new issue: the fix now shows the agent that reason.
- T-1002 and T-1003 I did myself rather than through sub-agents: T-1002 was one paragraph in a section I had already read, and T-1003 is a `flai issue close`, a flai write the guard refuses a sub-agent. The guide names no release number for the fix, since the next release's number depends on what else is published with it.
