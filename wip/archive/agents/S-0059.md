# S-0059 Operators create epics and stories from the board

## Context
The operator wants to create epics and stories from the board by writing markdown and nothing else, with the ID, file name, front matter, parent link, and commit supplied behind the scenes, as a step toward driving the project from the dashboard. `flai epic new` and `flai story new` create the file from the project's template with empty sections; the dashboard has no create endpoint. S-0040's document save (`flai doc save`: check before and after, restore on refusal, path-limited commit with a trailer) is the pattern to reuse. Work is in `.flai-cache/worktrees/S-0059` on `story/S-0059`.

## Current state

## Decisions
- 2026-09-19, operator: continue through the ready stories; S-0059 was next.
- 2026-09-19, agent: of the two ways in the story's notes, creation takes the body on standard input and is one step in flai, because the fourth criterion needs a creation that either happens or does not; calling `story new` and then `doc save` would leave an empty item behind when the save is refused.
- 2026-09-19, agent: the body the operator writes is everything below the item's heading. flai keeps the heading it renders (`# ID Title`), so the ID and the title cannot disagree with the front matter.
- 2026-09-19, agent: a refusal is anything new the check reports with the item in place, at any level, the same rule a document save uses. The first real case was the agent's own test: an epic body without `## Notes` is an `item.heading` warning, and it was refused.
- 2026-09-19, agent: the form's tags hint says that a component's name decides which release a story cuts, because a story created without one could not be accepted when it touched two components (I-0024, found on S-0062).

## Open questions
- The form does not require a tag, as the story's first criterion says (offered, not demanded), so I-0024 can still happen to a story created here that touches two components under an epic with no component tag. The acceptance preview says what to do when it does. Requiring a component tag, or letting the operator pick the delivered component at acceptance, would close it; not in this story's scope.
- Links inside work items are not checked by `flai check` (a link to a file that does not exist in a story body was not reported while testing). Not this story's concern; noted for whoever next touches the link rule.
- Issue counters are edited per branch, so two stories in review that both record an occurrence of the same issue collide in `design/issues/summary.md` and the issue's file (seen three times today). Recording occurrences as appended lines that a command totals, rather than a counter both sides rewrite, would end it. Worth a remediation story under E-0001.
