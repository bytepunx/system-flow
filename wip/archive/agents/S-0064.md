# S-0064 A dashboard container cannot leave git hooks or configuration that run on the host

## Context
S-0052 found that the dashboard container, which has the clone mounted read-write with `.git` included, can leave a git hook that runs on the host as the operator at their next git command (I-0022, tried in a scratch project). It needs a compromised container, not just the dashboard token. With S-0062 the container may also hold a push key, which makes it a better target. This story closes the routes that can be closed by how `flai dashboard` mounts the clone, warns about what is already there, and writes down what stays open. Work is in `.flai-cache/worktrees/S-0064` on `story/S-0064`.

## Current state
Done on `story/S-0064` in two commits (53316cb, 66331fd), ready for review.

The lab first (T-0238), in the scratchpad with the published image run as `flai dashboard` runs it: an acceptance writes `ORIG_HEAD`, `COMMIT_EDITMSG`, `index`, logs, refs, `worktrees/`, objects, and rewrites `.git/config` with identical content (`git branch -d`); nothing the container does needs `.git/hooks`, `.git/info`, or a changed config. With those three read-only, every planting route tried failed and the legitimate work succeeded; `git branch -d` tolerates the read-only config. A hook written into `.git/worktrees/<name>/hooks` can be written and git does not run it.

flai: `cmd/dashboard_guard.go`. Every `flai dashboard` start mounts `.git/hooks`, `.git/info`, `.git/config`, `.flai-cache/dashboard.token`, and the host's flai config when it lies inside the clone, read-only over the read-write clone, creating the two directories when missing; with no `.git` directory it mounts nothing extra and says so. The start message, `--json` (`read_only`, `already_in_clone`), and `status` (`git_read_only`) say what is read-only and list what the clone already holds that git runs: an enabled hook, and settings such as `core.sshCommand`, `core.hooksPath`, a shell alias, a filter, `url.*.insteadOf`, a `pushurl`. `status` says when the running container was started by an older flai without the mounts. Tests with the fake runner for the mounts and their order, the in-clone config, the audit (what is and is not reported), the no-git fallback, and status. `flai adr new` now cuts a long slug at a word. `make flai-test` passes, 0 lint issues.

End to end with the branch's `flai dashboard` starting the published 0.19.0 image (the change is in how the container is started; the image is unchanged) against a scratch project with a scratch SSH remote and a throwaway push key, all removed afterwards: the start message named the read-only paths and found a hook and a shell alias planted beforehand; from inside the running container, writing a hook, `git config` for `core.sshCommand` and an alias, appending to `info/exclude`, and overwriting the token all failed; through the API a document save committed, a story was created and moved to ready, and S-0001 was accepted with merge, branch and worktree removal, tag, and `pushed: true`, the commit and `cli/v1.1.0` on the remote; on the host afterwards nothing planted had run and the config held no `core.sshCommand`. ## Decisions
- 2026-09-19, operator: "pull S-0064 next". It was in backlog; moved to ready and pulled on that instruction.
- 2026-09-19, agent: the warning about hooks and executing config lives in `flai dashboard`, not in `flai check`. The check is the repository's gate and runs in CI, where a clone has no hooks; a developer's own pre-commit hook is legitimate and would fail `--strict`. The risk is taken when the dashboard is started, so that is where it is said.
- 2026-09-19, agent: `.git/info` is guarded as well as the hooks and the config, which the story did not list: `exclude` can hide a planted file from `git status`, which would turn the visible route (a changed or added file) into an invisible one. So is the token's file and an in-clone flai config, which names the image and the push key the next start uses; this repository keeps its flai config in `.flai-cache/config.json`, so it applies here.
- 2026-09-19, agent: the ADR was recorded twice. The first title was long and the slug was cut in the middle of a word; the uncommitted file and index row were removed, the slug rule fixed, and the ADR recorded again with a shorter title.

## Open questions
- What stays open is written in ADR-0027 and the dashboard design: tracked files and refs, which show in git and are caught by review, and files git ignores that the host executes, which are project specific. This repository has such files (`bin/flai`, which `scripts/flai.sh` rebuilds only when sources changed, and the tool caches under `.flai-cache`). A separate clone for the dashboard would be the stronger boundary, at the cost of the live board; the ADR lists it as an alternative to revisit if the dashboard is offered to people the operator does not trust.
- The operator's own hooks run inside the container too, whenever the container's git commits (an acceptance, a save). That was already so and is unchanged.
