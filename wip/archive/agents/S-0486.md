## Decisions

- Kept the planner's four tasks and their layers: T-2074 (ADR) alone, then T-2075 (`itemedit.Apply` and tests) after it, since the code follows the decision; T-2076 (design and docs) after T-2075, since the docs describe what the code does; T-2077 (close I-0182) last, after both. One task per layer, so nothing runs together.
- ADR-0197 records the fix: the second check run of a checked edit is scoped to the item's story with `check.ScopeToStories` and the paths the edit wrote; what the scope leaves out refuses nothing, what it marks outside is a warning, and an epic refuses only on a path the edit wrote.
- T-2074 written by the story's agent rather than a sub-agent: the decision needed the code read here first, and the ADR is one file.
- T-2075 (task sub-agent): `runCheck` seam in itemedit, as docedit has, so tests bring another writer's finding between the two runs; a task whose parent story does not read falls back to the epic rule rather than failing the edit. The MCP test only pins that an already-started story does not refuse a tick; the race itself is tested in itemedit.
- Known residue, not fixed: `wip/agents/index.md` is a file the edit writes, so a `narrative.index` finding another writer brings on it between the edit's index write and its second check would still refuse. No instance shows it; the window is a few milliseconds.
- T-2076 (task sub-agent), with two fixes of mine: `docs/users/flaiover.md`'s item save paragraph said every introduced finding refuses, so it was changed too (outside the task's touches; `flai task done` widened them); ADR-0197 (still proposed) said the warning is shown by the caller, but text-mode `flai edit` and the MCP tools do not return warnings, so it now names `--json`.
