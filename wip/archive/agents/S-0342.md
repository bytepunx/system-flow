- The planner's six tasks stand, in its three layers. Layer 1: T-1345, the `covers` key and its validation, which everything else reads. Layer 2: T-1349 (selection and run skip the covered tier) and T-1353 (the manifests), both after T-1345 for the field; they share no path and run together. Layer 3: T-1355 (text and verify steps), T-1358 (review page), T-1359 (docs), all after T-1349 for the `skipped` state and `covered_by` shape; no path in common.
- T-1353 also marks this repository's `flaiover` tier as covering `flaiover-lint` and `vitest`: `scripts/flaiover-test.sh` runs `pnpm lint` and the whole vitest suite, a superset of both.
- The manifest is decoded without strict mode, so the installed flai the MCP server runs ignores `covers:` until it is upgraded; adding the key to `system-flow.yaml` breaks no older flai.
- T-1353 wrote `system-flow.yaml`'s `tests` through the tree's `flai manifest set tests=`, as CLAUDE.md leaves the manifest to flai; the result is byte for byte the hand edit.
- The covering tier named in `covered_by` is the nearest selected tier that covers the skipped one and is not covered itself, so it always names a tier that runs (T-1349). A covered tier stays `skipped`, not `not-reached`, after an earlier failure, since it would not have run either way.
- `flai verify`'s text keeps its `tier` prefix on a skipped step (`skipped tier go-test: covered by integration`); `flai test` prints `skipped go-test: covered by integration`.
- T-1355 also took `flai test`'s and `flai verify`'s help, the MCP `test` and `verify` tool descriptions, which listed only three states, and the regenerated `docs/users/flai-reference.md`; their paths were added to its touches before the first close of layer 3.
- The trial merge with S-0341 (in review) conflicts in the verify code, review page, and docs, where both add a state (`reused`, `skipped`). Agreed on MS-0044: whichever is accepted second keeps both; S-0342 resolves it if second.
