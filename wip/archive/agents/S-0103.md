# S-0103 Extend existing data structures, APIs, and UI to track agent configuration

## Context

First of E-0008's two stories: the data S-0104 will use to start an agent for a story. Nothing in the repository has a notion of harness or model yet. S-0079's `flai serve agent set` holds one host-wide command, with only `{story}` and `{root}` substituted. Work item front matter is parsed strictly (`yaml.Strict()`), so any new key makes an older flai's `Repo.List` fail on the whole repository (`work-hierarchy.md`). The manifest is parsed leniently, and flai owns every manifest key but name, description, and dashboard. MCP has no tool that creates or edits an item.

## Current state

All five tasks are done and every criterion is met, so the story goes to review. On `story/S-0103`: a project's default agent is set with `flai agent set/clear` in `system-flow.yaml`, and new stories get a copy with the given overrides on top. `flai story new`, `flai edit`, `flai show`, hostapi `item.new`/`item.edit`/`project.info`, MCP `item_get`/`item_new`/`item_edit`, and the dashboard's new-story form, editor, and story page all carry it. Decision in [ADR-0037](../../design/adrs/0037-a-story-carries-its-agent-copied-from-the-project-s-default-when-it-is-made.md); design and user docs updated. `scripts/flai-test.sh` (lint, unit, integration, smoke) and `scripts/flaiover-test.sh` (419 tests) pass on Node 24, as do `flai check --strict` and `lint-md`.

Trial on a throwaway project with this tree's flai and a scratch `flai serve` and dashboard (port 5203), the operator's untouched. On the CLI: no default gives no key; `flai agent set` writes the block alone; a story gets the default, and another gets its override laid over it; `flai edit --model --agent-config effort=` merges and removes a key; `--clear-agent` removes the agent; a task given `--model` and a harness "Bad Name" are refused; `check --strict` is clean. In the browser: the new-story form showed the default as placeholders and created S-0004 with `claude-sonnet-5` and `max_turns=30` over it, committed; the editor replaced the agent, then removed it when all three fields were emptied; a bad harness was refused with flai's message and nothing written.

## Decisions
- One shape everywhere: an `agent:` block with `harness` (an identifier such as `claude-code`), `model` (the model's ID, such as `claude-opus-5-5`), and `config` (a map of string keys to string values, options the harness understands). It sits in `system-flow.yaml` as the project's defaults and in a story's front matter for that story. Harness and model are identifiers validated for shape only; which harnesses flai can start, and what `config` keys each takes, is S-0104's adapters' business.
- A new story gets the project's defaults copied into its front matter, criterion 2, but only when the project has defaults. A project that never sets any keeps writing front matter an older flai can parse, since items are parsed strictly and a new key breaks an older flai's whole `Repo.List`. Overrides given when a story is created or edited win over the copied defaults.
- The defaults are set with `flai agent show|set|clear`, because flai owns every manifest key but name, description, and dashboard. It is a new top-level group, distinct from `flai serve agent`, which is the host's command for starting an agent (S-0079), and which S-0104's adapters will take over.
- `flai story new` and `flai edit` take `--harness`, `--model`, and `--agent-config key=value` (repeatable), and `flai edit` also takes `--clear-agent`. Only stories carry an agent, not epics or tasks.
- MCP gets `item_new` and `item_edit`, since criterion 4 names MCP and it has no create or edit tool yet. They go through the same code as `flai story new` and `flai edit` (in-process `Repo.Create` and `itemedit.Apply`).

- An edit from the dashboard or from MCP's `item_edit` replaces a story's whole agent, since those clients send the whole thing. `flai edit` merges its flags into the agent the story already has (`key=` removes a key), because a command line gives one field at a time. `--clear-agent` together with other flags starts from nothing.
- A story made in the dashboard sends only the agent fields that were typed, and flai fills the rest from the default. The editor's empty fields mean "none" rather than "the default", because the default applies only when a story is created (ADR-0037). The note under the fields says so.
- The template's `system-flow.yaml.tmpl` gets no `agent` key: a new project has no default until the operator sets one, so it stays readable by an older flai.
