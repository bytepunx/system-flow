# S-0115 flai serve agent start <story> starts the story's agent on demand, and the story page has a button for it

## Context

The operator asked on 2026-09-24 for a direct way to have flai start a ready story's agent now: `flai serve agent start <story>` and a **Start agent** button on the story page. S-0116, in progress beside it, answers TH-0010 by dropping the attendance hold (ADR-0043) and adding `flai serve agent restart <story>` and a **Restart agent** button (its T-0417, T-0418). ## Decisions

- story/S-0115 is based on story/S-0116 rather than main. Reason: both stories change the same functions in the launcher, hostapi, and the story page; TH-0010 says S-0115 builds on S-0116's start path. S-0116 is accepted first as a result.
- Superseded (next entry): start refused while the in-progress limit is full.
- Start goes past a full in-progress limit, logging the warning `agent started past the in-progress limit`, and does not refuse. Reason: criterion 2 lists start's refusals and the limit is not one; `flai move` warns on a breach rather than refusing; and with the refusal, start and its button could do almost nothing the launcher does not already do. Restart keeps its limit refusal, as S-0116 decided.
- `StartNow` hands the agent over to the serving flai (`launcher.handOver`) instead of waiting for it in the short-lived command. Reason: the waiting goroutine outlived the call and wrote to the caller's logger, a race under `-race`. The serving flai settles the run with `settleOrphans`, as S-0116's design says.
- The Start agent button shows only for a ready story with no run. Reason: a ready story whose run failed already has S-0116's Restart agent, which does the same.
