## Decisions

- Planner's four tasks kept, in three layers: T-2917, then T-2919 (it checks the image T-2917 builds), then T-2922 and T-2924 together (both describe what T-2919 proved). I worked every task myself, with no task sub-agents. `flai/images/` and `scripts/agent-image.sh` are protected, so a sub-agent may not write them. The docs and the issue close were a few edits each.
- GoReleaser is built in the Go stage with `GOTOOLCHAIN=auto`, not taken from its release archive. Its go.mod names Go 1.27.1, and the go command fetches that toolchain and checks it against Go's checksum database. That matches `scripts/install-tools.sh`'s `go install` on the host and needs no per-architecture sha256 pins. Only the binary reaches the image, and its Go stays at 1.26.0.
- Running the check found a third gap behind I-0281. BusyBox `ps` refuses `-p`, which `scripts/release-server.sh` uses, so the release server always read as exited. The fix is procps-ng in the layer, plus a `ps -p` probe in `--check`. It is fixed in the layer, not in release-server.sh, because the host and CI have procps.
- `--check` scopes the smoke tier with `MERGE_QUEUE_STORIES=<story>`, not `CLOSE_OUT_STORY`. Both scope the check and the lint to the story, but `CLOSE_OUT_STORY` adds `--record-issues`, which would write issues into the worktree. A check should write nothing.
- `CHECK_IMAGE` lets the check run on another image. That is how it was shown to fail on the layer built before this story, kept as `flai-agent-sf-claude-code:pre-s0672`. The live `:local` tag was never retagged, since flai serve starts agents from it.
- MS-0468: S-0682, in review, edits the same `design/tech/docker.md` table row. S-0672 takes the rebase after S-0682's acceptance and keeps both texts.
