## Decisions

- Board cards carry `held: {code, reason}` rather than two flat fields, so the `after` hold (next E-0009 story) adds a code, not a field.
- A hold names every open story that holds the ready one, not only the first, so "starts when" is true.
- flai serve's launcher counts a ready story whose agent it has started as open for the rest of the look ("its agent started"), so one look never starts two overlapping stories before either agent moves its story to in progress.
- A held story that never had an agent appears in `agent.status` with a run naming only the story and the harness and model it asks for, because the current dashboard reads `run` unguarded; the dashboard story can use `hold` instead.
- `flai serve agent restart` of a held ready story queues it, as it does when the limit is full; the launcher starts it once clear. `flai serve agent start` goes past the hold with a warning, as ADR-0046 says.
