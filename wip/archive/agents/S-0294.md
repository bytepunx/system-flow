## Decisions

- The planner's four tasks stand as drafted. Layers: T-1124 and T-1125 together (disjoint paths: design docs and the config setting); T-1126 after both (it implements the ADR's decision and reads the setting); T-1127 after T-1126 (it documents what the code does and closes I-0084).
- "Asking nothing" is the run's outcome not being `asked` (its own question open), as the tasks and the planner's last TH-0208 entry say; an open thread by someone else does not stop the restart.
- A run that could not be started (`Error` set) is not restarted: it never ran.
- The count lives on the runs (`AgentRun`): an automatic restart carries the previous count plus one, and any other start begins at 0, which gives the reset on a manual restart and on re-entering ready without extra state.
- The restart happens at a look, after `resume`, so it covers runs the launcher awaited and orphaned ones alike.
- The ADR was numbered by hand. `flai adr new` gave 0106, which S-0286's branch held, so it became 0107. The trial merge then found S-0269 holding 0107 (TH-0238), so it became ADR-0108. I-0063 is bumped. On TH-0238 the remaining append-only collision with S-0269 (ADR index rows, I-0063 instances) is left to whichever rebases second.
- T-1125 also took the `settings.md` row and the regenerated reference from T-1127, because the settings-index test fails without the row. T-1126 wires the limit into `serve.AgentConfig`, since T-1125 could not do it before the field existed.
- The prompt of an automatically restarted agent has its own branch in `harness.go` (`Request.AutoRestart`, such as "1 of 2"), so it is not told "the operator restarted it". harness.go was added to T-1126's and the story's touches, and now overlaps S-0269's claim.
- With `agent.auto_restarts` 0, the first failure opens the thread (ADR-0108 point 4). If opening the thread fails, the launcher warns once, journals it, and tries again under a later flai serve.
