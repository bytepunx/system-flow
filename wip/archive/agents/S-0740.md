## Decisions

- Plan: layer 1 T-3168 (embed, flai/images/embed.go) and T-3287 (new: run.go, a docker step that streams, stops after the stall limit, and retries on the network); layer 2 T-3169 (pull) and T-3170 (build), both running their docker steps through T-3287's Runner, T-3170 also reading T-3168's embedded Dockerfiles; layer 3 T-3171 (ensure and build commands) choosing between them; layer 4 T-3172 (documents). The stall and retry moved out of T-3170 into T-3287 because the pull needs them too.
- T-3169 also touches flai/internal/agentimage/status.go: the Inspector's Info gains RepoDigests, which the pull checks against the list (List.Matches), and dashboard/cache.go, whose cache is reused per image under agent-image-digests/ (ADR-0295 §1).
- Only the harness image the agents run, claude-code, is pulled; bedrock is pulled by no one, since no agent runs it and the claude-code image carries its layers. The build builds bedrock, then claude-code over it.
- A pulled or built harness image is tagged with the name the start runs today, harness.DefaultImages (flai-agent-claude-code:local), and with flai-agent-<inner>:<version>; bedrock is tagged flai-agent-bedrock:<version>. S-0751 makes the start resolve the image.
- The pull falls back to the build when the release has no list (missing, no-release), the release or the registry cannot be reached, or the docker pull fails; it refuses, with no fallback, a list that does not verify (bad, unknown-key), is malformed, is for another version or repository, or a pulled image whose digest the list does not name, as a dashboard.Refusal.
- A development project flai (buildinfo.Development) is never pulled for: ensure and build build from the tree's flai/images Dockerfiles, bedrock's tree target with the root as context, when the project's root has them, and fail naming why otherwise.
- The build labels each image with dev.system-flow.recipe, and claude-code with dev.system-flow.base, bedrock's image ID. FLAI_COMMIT and FLAI_DATE are passed in a tree build but left out of the recipe, since ADR-0295 §3 does not compare the commit and the commit has its own label.
- agentimage.Check still judges a harness image on its flai label alone; comparing a harness image's recipe and base is left out of S-0740, which only writes the labels. flai-cli.md says so.
- T-3169 generalised the digest list code with dashboard.Product (flaiover's messages unchanged) and added the refusal kind unlisted for a pulled image whose RepoDigests the list does not name. T-3170 named the build's input BuildSource, since agentimage already has a Source type.
- Criteria ticked on test evidence over a fake docker and an httptest release; a real pull and build were not run here: no published release holds the agent image lists yet (S-0734 is accepted, not released), and a real build replaces the image the running agents use, which is the operator's to choose.
