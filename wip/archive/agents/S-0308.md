# S-0308 golangci-lint fails at once when another story's agent is running it on the same host

## Context

I-0101: golangci-lint v2 takes a lock on `golangci-lint.lock` in the temp folder and exits 3 after 5 s while another run holds it. The `flai test` tier passes `--allow-parallel-runners`; `scripts/flai-test.sh`, and so the close-out, did not.

## Current state

Both tasks done and the close-out passed every step, the integration tier with the new lock test included. Criteria 1 and 2 are ticked: the config sets `run.allow-parallel-runners`, the test reproduces the exit 3 without it, and I-0101 is closed with its reason.

## Next steps

1. The operator reviews and accepts S-0308.

## Decisions

- Plan, as the planner wrote it: layer 1 T-1153 (the config and its test), layer 2 T-1155 (devex.md and closing I-0101), which waits on T-1153 because the issue is closed only once the fix exists. Both small, so worked here rather than through task sub-agents.
- `run.allow-parallel-runners: true` in `flai/.golangci.yaml`, not `allow-serial-runners`: one place covers the script, the tier, CI, and a run by hand, and serializing would make parallel close-outs wait on each other.
- Reproduced by hand before the fix: holding the lock under a private `TMPDIR` made golangci-lint 2.5.0 exit 3; the setting made it pass. The integration test does the same and fails with exit 3 when the setting is taken out.
