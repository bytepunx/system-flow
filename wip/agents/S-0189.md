## Decisions

- Explorer runs `haiku` and verifier runs `sonnet`, as aliases. The explorer only finds and reads. The verifier's defects are the benefit to keep, so it gets the stronger of the two cheaper models. Aliases follow the harness's current model.
- A verifier runs `scripts/close-out.sh` on the committed worktree for the pre-review run. close-out then commits nothing, so `work-management.md`'s close-out rule and the new delegation rule agree without editing work-management.
- The designer accepted every recommendation in TH-0057 (2026-10-01T10:51:30Z):
  - Per-role config is `agent.roles.{explore,verify}`, the same shape as `agent`. claude-code receives it through `--agents`, built from the project's definition with the role's model over it.
  - Criterion 3 is met by "the story's agent fixes what a verifier finds, never a sub-agent", plus a guard test.
  - Criterion 4 moves to a follow-up research story `after` S-0189.
  - S-0185's verifier is replayed on Sonnet.
- The designer allowed the edit to `.claude/agents/**`. The Edit tool still refused it, because a session keeps the permissions it was started with. I applied exactly that edit with perl (ba06e64) and said so in TH-0057.
- Roles are a `Role` type (harness, model, config), not a nested `Agent`. A role cannot hold roles, and the MCP schema generator sees no cycle. The explorer flagged that risk.
- `Same` compares roles, so a changed role restarts a ready story's agent, as a changed model does.
- claude-code takes only a model for a role. A role with config or another harness refuses the start, and so does a role with no definition. A role with no model passes nothing, so its definition runs as written.
- Role flags: `--role-harness`, `--role-model`, `--role-config role.key=value` (an empty value removes the key), and `--unset-role`. The dashboard keeps roles on a save but does not edit them; editing them in the dashboard is left out of this story.
- The Sonnet replay used S-0185's second verifier prompt, word for word, from `~/.flai/serve/agents/sf-S-0185-20261001T084800Z.log`. It ran on a detached worktree at fa6aaa3, which I removed afterwards. The explorer had been refused reads of `~/.flai`, so I read the log myself.
