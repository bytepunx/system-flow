- Plan: the planner's four tasks, kept as drafted, one a layer. T-2478 waits for T-2477 because both write `flai/internal/kluster/deploy.go` and teardown, promote, and list reuse the deploy's steps, lock, logs, and record. T-2479 waits for T-2478 because the commands call all four. T-2480 waits for T-2479 because it documents the commands as built. Nothing runs together.
- One record file per namespace, `.flai-cache/kluster/deployments/<namespace>.json`, not one `deployments.json`: `design/system/kluster.md` and ADR-0254 §1 say one record per namespace, and a file each needs no merge between a story's write and a promotion's.

- The package keeps S-0577's `kluster.Exec` and its fakes-on-PATH tests rather than `execx.Runner`, widened to pass the environment and standard input the steps need; the code-quality addition names `execx.Runner` for git and docker, but S-0577's package already chose its own streaming `Exec`, and a second runner in one package would split the fakes.
- Promote builds in a detached worktree of main's head at `.flai-cache/kluster/main`, as ADR-0254 §5 says, made or moved there with git.

- The first close-out stopped at integration: `TestSettingsIndexIsComplete` wanted the `FLAI_KLUSTER_*` variables in `docs/operators/settings.md`, now added (0401e5860), and `TestHostRunsServeAndTheMCPServersAndTakesThemWithIt` timed out waiting for the MCP server's state, a host-process test this story does not touch.
- S-0580 noted on MS-0330 that its host API's `kluster.up` and `kluster.down` keep their own one-job state in flai serve and do not take this story's job lock (`.flai-cache/kluster/job.lock`); S-0579 or S-0581 may join the two.
