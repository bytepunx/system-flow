## Decisions

- Kept the planner's six tasks and their layers: T-1729; then T-1730, T-1732, T-1733 together (T-1730 changes `guard.go`, T-1732 `authors.go`, T-1733 the hooks and their tests, no path in common); then T-1731 after T-1730, since both change `guard.go`; then T-1734, which documents what all of them did.
- The role file decides; Go only explains. With `FLAI_ROLE` set, the guard decides a session's own call from its role file: reads pass, a listed call passes under its condition and, inside a permission, while the manifest's setting is on, and the rest is refused. The named conditions are implemented in the guard package, which parses the calls. A built-in role's refusal keeps its wording: when the file refuses, the guard asks the role's old Go rules for the reason, and uses the generic reason when they would have allowed the call. That keeps every guard test unchanged.
- flai embeds the baseline role files under `flai/internal/roles/baseline/`. A built-in role whose project has no file of its own (a project not yet upgraded, and the guard tests) is held by the baseline file. A test holds their front matter equal to the template's. S-0419 planned the same folder; it builds on this one.
- Fails closed: a defined role with no file, or a file of the role's name that does not parse, is refused every write, naming the file or the folder and `flai check`.
- The curator goes through the same path as the other three, so that one path decides for every role; its tests stay unchanged too.
- Without the command tree (the guard package's own tests), a command counts as having subcommands when `cliReads` or the role file names one of them, so that `flai queue` stays `flai queue` with no subcommand and `flai edit` takes any word. `flai guard` passes the real tree.
- The manifest gains `roles.<name>.permissions.<p>`, as ADR-0207 §5 says S-0416 does; a defined role's gated calls read it at each call. On MS-0207 S-0416 proposed to S-0502 that each keeps the other's lines in the manifest files and their docs.
