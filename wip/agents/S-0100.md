# S-0100 A work item being saved is never read half-written

## Context

The operator reported a CI failure on the flai workflow for the publish of flai 1.12.1: `TestWaitForEventsReportsAnEventWhileHeld` failed with `S-0001-story.md: no front matter`. The test saves an item from a goroutine while `wait_for_events` is held and reading the item files. `Repo.Save` wrote with `os.WriteFile`, which truncates the file first, so the read landed in between. This was not only a test flake: an agent's `inbox` or `wait_for_events` could fail the same way whenever the dashboard or the CLI saved an item at that moment.

## Current state

Done. `internal/atomicfile.WriteFile` writes a temporary file beside the target and renames it over it. Every writer of what is read while it changes uses it: `Repo.Save`, `flai edit`'s writes and its rollback, `itemnew`'s rollback, `board.md`, narratives and `index.md`, threads, and the thread block mirrored into a narrative. A race test (2,000 alternating saves under a reader that never stops) counted 4,243 torn reads with `os.WriteFile` and 0 with `WriteFile`. The CI test that failed passed 200 runs in a row, though it had not failed in 300 local runs before the fix either, which is why the race test exists. flai-test (lint 0 issues), the flaiover suite (413), lint-md, and `flai check --strict` are clean. Recorded as I-0036, closed as fixed here.
