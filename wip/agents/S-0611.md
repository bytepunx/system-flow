## Decisions

- The operator finalized S-0611 whole, so the split planner-E-0033 proposed on TH-0903 is not made (TH-0904).
- I keep the planner's five tasks and their layers:
  - Layer 1: T-2689 (send time in `request answered`), T-2690 (`agent.status` takes `finished`), and T-2692 (the dashboard asks `threads.list` for open threads). They wait for none and share no path, so they run together, each in a task sub-agent in the story's worktree.
  - Layer 2: T-2691 waits for T-2690, because it sends the `finished` parameter that T-2690 adds and defines.
  - Layer 3: T-2693 waits for all four, because it measures what they change.
- T-2689 and T-2690 both build Go under `flai/`, so a half-done edit in one can fail the other's `flai test` for a moment. Each sub-agent is told to wait and run again rather than fix a path it does not touch.
- `flai/internal/hostapi/people.go` stays in the story's touches until the close-out. If no task changes it, I narrow it then. Nothing changed it, so it was removed from the touches.
- The default `agent.status` keeps `last`, `orchestrator`, `analyzer`, and `curator` even when they name an ended run. Each is one run, and the board and activity page read them (T-2690).
- A done or cancelled story's agent panel shows the story's last run, which the default leaves out. T-2691's sub-agent found the gap. I made `StoryAgent.svelte` ask `/api/host-agent?finished=1` for such a story, and made the route pass that on. An archived story is always done or cancelled, so the panel needs no archived flag.
- `send_ms` was not measured through flai serve. Serve on this host runs the installed flai 1.86.4, which does not log it, and `server-performance.md` says so.
- Recorded I-0321: S-0615's `TestTCPAnswersAListenerAndNotAClosedOne` fails intermittently on this host, on main too. Bumped I-0319: the props-panel test timed out and stopped the first close-out. The third close-out passed.
