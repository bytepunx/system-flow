## Current state
Complete. `flai stream open` creates `story/S-nnnn` from the main checkout's branch in a worktree under `.flai-cache/worktrees/S-nnnn` (`--no-branch` opts out); a Repo opened inside a linked worktree resolves `wip/` and `.flai-cache` to the main checkout, so items, narratives, the board, and the token stay live. `flai stream sync` rebases with autostash and, on conflicts, stops inside the worktree and names the files. `flai accept` refuses a dirty worktree, rebases, fast-forwards the branch into main, removes worktree and branch, then proceeds as before; its dirty-tree check now ignores `wip/`. `touches` is front matter on stories and tasks (`--touches` on new, `flai touches`), `flai check` warns `wip.overlap` between in-progress items, the board prints it, and the dashboard's document explorer shows a "being worked on" notice with links. ## Decisions
- Worktree detection reads the `.git` file (`gitdir: <main>/.git/worktrees/<name>`) rather than shelling out, so every flai command, including reads without a runner, resolves the main checkout the same way.
- Conflicts leave the rebase in progress in the worktree rather than aborting: the agent resolves once instead of looping, and `git rebase --abort` remains available.
- The merge is fast-forward only, after a rebase; history on main stays linear and the story's diff against main is exactly its commits.
- Overlap is a warning, never an error: humans and agents coordinate; a lock nobody releases would block work.
- Overlap ignores a task and its own story, since a story usually declares the union of its tasks.
