## Decisions

- Kept the planner's five tasks and layers as TH-0999 sets them: the plan matches the story's goal, and no two tasks of a layer share a path.
  - Layer 1: T-2932, the ADR. It waits for nothing; the code tasks build what it decides.
  - Layer 2: T-2934 (MCP tool `accept` and its guard rule) and T-2935 (the shell's fail-closed refusal). Both wait for T-2932's decision; they share no path, so they run together.
  - Layer 2 runs in two worktrees: T-2934 in the story's, T-2935 in `.flai-cache/worktrees/T-2935` on `task/T-2935`. Both change and test package `flai/cmd`, so a half-done edit of one could fail the other's tests.
  - T-2932 found a gap the plan missed: the HTTP MCP server reads its caller's role from its own `FLAI_ROLE`, which is empty under `flai host`. ADR-0278 part 3 fixes it, so T-2934's touches gained `flai/cmd/mcp_http.go`, `flai/cmd/mcp.go`, `flai/internal/mcpserver/server.go`, `flai/internal/guard/guard_refusals.go`, `flai/internal/guard/call.go`, and `flai/internal/hostapi/writes_outcome.go`. The first three overlap S-0684, whose T-2904 moves the role into `mcpserver.Options.Role`. On MS-0454 S-0687 proposed adding the same `Options.Role` field and touching only the per-agent server callback and one option beside `Publish`.
  - Layer 3: T-2937 (role text and convention copies) waits for T-2934, whose tool name and inputs it writes down. T-2938 (design, user guide, issue close) waits for T-2934 and T-2935, which it describes. They share no path, so they run together.
