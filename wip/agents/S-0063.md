# S-0063 An acceptance that is not pushed stays visible on the board and in inbox, and flai push --pending pushes it

## Context

Today the dashboard says it once after the acceptance, and agents are told of the acceptance but not that it is unpushed. Work is in `.flai-cache/worktrees/S-0063` on `story/S-0063`.

## Current state
The work is done on `story/S-0063` in five commits (the last is d467281) and the story is held in in-progress, not moved to review, until S-0061 and S-0062 are accepted and this branch is synced onto them: it edits lines both of them edit (the MCP `InboxOut` struct and instructions string with S-0061; the operators' documentation, the long board paragraph in `docs/users/flaiover.md`, and the acceptance paragraph in `docs/users/flai.md` with S-0062). T-0228 stays in-progress for that reason.

flai: `internal/pending` asks git offline how the main checkout's branch stands against its remote-tracking branch (commits ahead, the items accepted among them by the subject `chore: [ID] accept and archive`, the tags reachable from the branch and not from the remote-tracking branch, commits behind), falling back to `origin/<branch>` when no upstream is configured, and says nothing when there is no git, no remote-tracking branch, or nothing ahead. `flai board` prints one line and `board --json` carries `unpushed` while an acceptance is pending. `flai push --pending [--dry-run]` pushes the branch and those tags with the host's credentials, says "nothing pending" otherwise, leaves ordinary commits to `git push`, refuses a diverged clone with what to do, and never forces. The MCP server is given a runner; `inbox` lists `unpushed` on every call while true and the `board` tool carries it; the instructions say what an agent does. Tests with real git and bare remotes for each case of the detection, the command end to end (an acceptance made with `--no-push`, dry run, push, second run, ordinary commits, divergence), and the MCP tools. `make flai-test` passes, 0 lint issues.

flaiover: `GET /api/unpushed` asks flai (`push --pending --dry-run`); `UnpushedNotice.svelte` on the board and on an accepted story's page, asking again on every board change, on window focus, and each minute while showing; no button. Component tests and a test through the real flai binary with a scratch remote. `make flaiover-test` (264 tests) and the build pass. Tried in a browser on the branch's dev server against a scratch project with a bare scratch remote: the notice showed on the board in both themes with the item, the commits ahead, the tag, and the command, stayed after a reload, showed on S-0001's page and not on another item's, had no button, and after `flai push --pending` on the host it cleared on the next focus event without a reload, on the board and the item page. Scratch project removed.
