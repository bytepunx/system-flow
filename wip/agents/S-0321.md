# S-0321 Publishing raises the manifest's flai minimum the moment it commits, before the release is built, so the host's flai drops the project until the binaries exist

## Context

Remediates I-0107: a publish commits a raised `flai.minimum` before the release's binaries exist, so the host's flai drops the project and kills the publish's own `publish.run`.

## Current state

Layer 1 in progress: T-1309 (release raises the minimum no higher than the publishing flai) and T-1310 (serve drains requests in flight when a project stops loading), each with a task sub-agent.

## Next steps

1. Review T-1309 and T-1310, close each with flai task done, and test.
2. T-1311 docs, then T-1312 close I-0107.
3. Close-out and review.

## Decisions

- The planner's tasks are kept as drafted: they follow the issue's first direction (raise the minimum only to a flai that can be installed) and add the drain so a dropped project no longer kills its own publish.
- Layer 1: T-1309 (release) and T-1310 (serve) run together; they share no path and neither builds what the other changes.
- Layer 2: T-1311 waits for both, since it documents what they built.
- Layer 3: T-1312 waits for T-1311, so I-0107 closes only once the fix is built and described.
