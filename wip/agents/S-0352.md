# S-0352 Each adapter states its capabilities and reads its harness's log into neutral usage events, and flai measures usage from those events

## Context

ADR-0130's adapter contracts, `Capabilities()` and `Reader()`, built inside the `claude-code` and `command` adapters, with `flai/internal/usage` measuring from neutral events and no recorded figure changing. S-0351's OpenRouter run (`design/system/agent-adapters.md` § Checked against OpenRouter) found message IDs are the upstream's and a message's stream `usage` is not final; `modelUsage` in `result` holds the totals.

## Decisions

- The planner's four tasks are kept as drafted: their touches name files and match the code, and `usage` imports nothing of `harness`, so `harness.Adapter` can return a `usage.Reader` without a cycle.
- Layers: 1, T-1387 (`usage` events and the Claude Code reader) and T-1388 (`harness` capabilities), together, since their touches share no path; 2, T-1389, which waits for T-1387's events and for T-1388's edits to the same `harness` files; 3, T-1390, which waits for T-1389 so the documents describe the events as built.
- Layer 1 runs its two tasks at once, one task sub-agent each; T-1387 is the longer and sets the pace.
- T-1389's touches gained `flai/internal/serve/activity.go`: it also calls `usage.Read`, for the strategic agents, and now reads their logs with the claude-code adapter's reader, the harness that runs them.
- A story's logs are read with the reader of the harness its newest run recorded, else of its agent's as `harness.For` resolves it. A log the `command` adapter wrote is read by a reader that yields nothing, as criterion 4 asks, even when it holds stream-json; until now such a log was measured. No story on this host is affected: every logged one has a claude-code run recorded. Three serve tests that fed stream-json through a story with no harness now name claude-code as its harness; no expected figure changed.
- The Claude Code reader joins a tool result's text blocks with a newline, and the empty-wake test reads the first JSON object in that text. Until now each block was tried on its own, so a non-JSON block before the JSON object would now give no empty wake. `wait_for_events` returns one block, so no figure changes.
- `ReadRates` skims through an optional `endSkimmer` so that it decodes only the lines that may hold a run's end, as before, rather than every line of every log on the host. It now returns an I/O error that stopped a log's read partway; before, it went on silently.
- S-0352 and S-0360 both change the one-line `flai serve agent` row of `design/system/flai-cli.md`, in different sentences. Proposed on MS-0097: whichever is accepted second takes the other's row from main and applies its own sentence edits to it.
- Tool names stay as each harness writes them (`mcp__flai__wait_for_events`, `Bash`, `Agent`): the measurement's rules name Claude Code's. A second harness's reader maps its names onto these, as ADR-0130's tool-name table per harness says.
