## Decisions

- The planner's five tasks are kept as drafted (TH-0996). The remedy is I-0234's first, as D-0443 names: the session moves into `mcpserver.Options` and `flai mcp` fills it from the environment. The code matches the plan: the session is read at `server.go:208-214`, `shared.go:180`, and `issues.go:196`, and `FLAI_RELEASES_API` at `versions.go:55`.
- Layers: 1 is T-2904. 2 is T-2905 and T-2906, which run together. 3 is T-2910. 4 is T-2915.
  - T-2905 waits for T-2904 because both change `Options` in `server.go`.
  - T-2906 waits for T-2904 because it passes the session fields T-2904 adds.
  - T-2905 and T-2906 share no path, so they run together in the story's worktree.
  - T-2910 waits for T-2905, whose fields it passes. It also waits for T-2906, which owns `server_test.go` and sets git's identity in `TestMain`.
  - T-2915 waits for T-2906 and T-2910, which leave no test setting the process.
- The `go test -race -count=1 ./internal/mcpserver` done-when items in T-2906 and T-2910 are met with `flai test` on the package instead. That runs the same tests under `-race -short`, and the convention keeps hand runs of `go test` out of a task. The `-short` tests are all but the two prime-on-this-repository tests, which this story does not change.
- T-2915's three timed `-race` runs are a measurement the story asks for, not test feedback. I run them myself, not through a sub-agent, and record each with its load.
