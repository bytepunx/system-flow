## Decisions

- ADR-0317 names the section the first criterion asks for: `timers`, holding only the workflow's own timers, every timer but lead, cycle, queue, and review, which ADR-0305 §6 already reports under their own fields. So the baseline's output and golden fixtures stay byte for byte (criterion 5).
- Plan, kept from the planner: layer 1 T-3243 (flai/internal/metrics); layer 2 T-3247 and T-3248 together. Both read the shape T-3243 builds, and they share no path. T-3247 also gets flai/internal/statsread/statsread.go: statsread.Read never set Options.Workflow, so flai stats and stats.get ran the baseline even when a project has a workflow file. Setting it to repo.Flow() is what lets a timer the operator adds reach both (criteria 3 and 4).
- T-3247 leaves the flai stats help text alone, so docs/users/flai-reference.md needs no regeneration and T-3248 does not wait on T-3247.
- Following D-0630: the metrics read timers through the workflow package (Timer, Measure, Kind), not a new workitem helper.
