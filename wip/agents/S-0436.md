## Decisions

- Kept the planner's four tasks and their plan of four layers, one task each: T-1849 (docedit's file rules), then T-1850 (the commands, which call T-1849's functions), then T-1851 (the host methods, whose save spec runs T-1850's command), then T-1852 (the docs, written once the code they describe is there). No two tasks run together: each layer builds on the one before.
- Size limit for `file show` and `file save`: 1 MiB (`docedit.MaxFileSize`), far above a token file or a stylesheet; it applies to the file read and to the content saved.
- A path or file out of reach exits 1, as `flai doc` does for a path out of reach. Content that is binary or over the limit, tokens that cannot be rendered, and a new check finding exit 4.
- `flai design init` writes the stylesheet with the token file through the same generator as `file save`, and still commits nothing, as its help has always said. Criterion 3's commit applies to `file save`.
- `file.get` and `file.save` are specs in `hostapi/writes.go` that run the commands, beside `doc.show` and `doc.save`, rather than a `files.go` that calls `FileShow` directly: criterion 4 says the methods run the two commands, and a spec brings the exit mapping, the request journal, and the story's worktree with it. `files.go` and `hostapi.go` came out of the touches. The end-to-end test that builds flai is in `files_test.go` and skips under `-short`, as the other tests that build flai do.
- Shared `flai/cmd/root.go` with S-0437 on MS-0128: S-0436 adds only its `file` command's `AddCommand` line, S-0437 only its own.
