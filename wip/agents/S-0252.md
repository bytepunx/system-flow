# S-0252 flai issue new numbers from the story's worktree only, so parallel story branches take the same issue number

## Context

I-0065: `issues.NextID` globs only the current checkout's `design/issues`, so two story worktrees number their issues alike. The planner's proposal stands: number past every issue in the main checkout, every story worktree, every local `story/*` branch, and main.

## Current state

Every task is done and committed on `story/S-0252`, synced with main. `storygit.FolderNames` (`flai/internal/storygit/folder.go`) lists a folder's files across the main checkout, every worktree, main, and every story branch; `issues.NextID` numbers past them; `TestIssueNewNumbersPastEveryStorysIssues` in `flai/cmd/issue_test.go` reproduces I-0065 and failed without the change. The designs and the user guide describe the numbering, and I-0065 is closed. Both criteria are checked.

## Next steps

1. A fresh verifier runs `scripts/close-out.sh S-0252` in the worktree and checks the diff against the criteria and conventions.
2. Fix what it finds, then move S-0252 to review.

## Decisions

- The planner's tasks T-0831, T-0832, and T-0833 are kept as drafted: they match the goal and the issue's instances.
- The plan is three layers of one task each. T-0832 waits for T-0831 because it calls the helper T-0831 adds. T-0833 waits for T-0832 because it describes what T-0832 built, and I-0065 closes only once the reproduction test passes. Nothing runs together.
- T-0831 and T-0832 went to task sub-agents; T-0833, three sentences and an issue close, was quicker done by hand.
- `FolderNames` skips any worktree, branch, or folder it cannot read and returns no error, so numbering never fails for want of git; `NextID` still reads its own checkout first for the same reason.
- `NextID` takes the runner as a parameter, and `NewOptions.Runner` passes it, nil meaning `execx.System`; the MCP server never calls `issues.New`, so it keeps the default.
- Close-out stopped at `flai check --strict` on main's S-0173 `story.unaccepted` and TH-0094 and TH-0111 `threads.archived` warnings, outside the story. As S-0248 did, under the operator's answer on TH-0056, it is recorded as an I-0057 occurrence rather than fixed here, and a second verifier runs the steps the script did not reach.
