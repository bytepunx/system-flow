# S-0311 The Orchestrator needs a role it can run tests in review under

## Context

The orchestrator runs `flai verify` on a story in review (S-0221) with `FLAI_ROLE=orchestrate` in its environment. Every test tier inherits it, so a Go test that runs a flai write in process meets flai's own orchestrator checks and fails (TH-0260).

## Current state

T-1161 done: runTier gives every tier FLAI_ROLE=verify; flai test flai/internal/verify passes. Layer 2 in progress: T-1162 (proof under orchestrate) and T-1163 (docs).

## Next steps

1. Review T-1162 and T-1163, close each with flai task done, and test their paths.
2. Close out with scripts/close-out.sh S-0311 and move to review.

## Decisions

- Kept the planner's three tasks as drafted (TH-0284): they cover the one criterion with the fix, its proof under the orchestrator's role, and its documentation.
- Layers: T-1161 alone, since both others depend on what it builds; then T-1162 and T-1163 together, as they share no path. T-1162 waits because its tests fail until tiers run under `verify`; T-1163 waits so it describes what was built.
- Tiers get `FLAI_ROLE=verify`, set after the inherited environment and `opts.Env` so it wins, rather than `FLAI_ROLE` removed: it names the run's role, and none of flai's role checks match it. Risk: a test that reads `FLAI_ROLE` without setting it (`mcpserver` `servedSession`, `endWhy`, `flai guard`) now sees `verify`; T-1162's `flai test flai/cmd flai/internal/mcpserver` shows whether any does.
