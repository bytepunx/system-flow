# S-0259 The Workflow menu has a Planner page showing its status, activity log, and runs

## Context

The planner (S-0208) logs its activities in `wip/agents/planner.md` (S-0206) and flai serve keeps each item's newest planner run in `agent.status`'s `plans`. The dashboard has a Plan action on item pages and card menus (S-0208, S-0263), but no page for the planner itself. Split from S-0228 on TH-0107.

## Decisions

- The flai channel has no read of an activity document and `agent.stream` reads only a story's agent, so T-0836 adds `activity.document {kind}` and `agent.stream {plan}`. The story's touches grow by `flai/internal/serve/stream.go`, `flai/cmd/serve_actions.go`, and the dashboard's `lib/planner.ts` and `lib/activity.ts`, which overlap no open story's.
- "Past runs" are each item's newest planner run, which is all flai serve records (`AgentState.Plans`); keeping every run is a change to serve's state beyond this page. A run's cost is the sum of the activity entries that ended while it ran, joined in the dashboard (`planner.ts`), since a run records no cost of its own.
- The enabling command is written in the page, `flai serve enable plan`, as the dashboard's other host-action notices write theirs.
- Plan, in three layers:
  - Layer 1: T-0836 (flai) and T-0837 (dashboard API and lib). They share no path, and T-0837 gives flai's answers in its tests in the shapes T-0836's `## Work` fixes, so they run at once.
  - Layer 2: T-0838, the page, waits for T-0837, whose routes and `planner.ts` it reads.
  - Layer 3: T-0839, the docs, waits for all three, to describe what was built.
- T-0836's sub-agent gave the planner's stream a hook of its own, `Host.PlanStream`, beside `AgentStream`, so no fake of the host changed; a planner's stream answers `item` and an empty `story`. It timed the document's read as a new phase; I renamed it to the existing `narratives.read`, since the document is read from `wip/agents` as the narratives are, rather than list a new phase in `docs/users/flai.md`, which S-0252 claims.
- `flaiover/src/lib/server/agent.ts` lists `activity.document` in `REQUIRED_METHODS`, which the hostapi contract test asks for; the story's and T-0836's touches name it.
- T-0837's `runCost` matches entries to a run by time alone: older entries name no items, so matching by item would cost them nothing.
- T-0838's sub-agent formatted durations with `$lib/age`'s `age`, which shows 45 s as `0m`; I exported `usage.ts`'s `duration` instead (hours and minutes, seconds under a minute), and the story's and T-0838's touches name `usage.ts`. It also had to add Planner's link to `SiteMenu.svelte`, which links every page by key, and `trigger` to `PlanRun`. The page reloads on a narrative change only when it is the planner's own document, so story agents' narrative edits do not ask for `/api/planner` again.
- T-0839 I wrote myself: two documents, with everything they describe already reviewed. `activity.document` is asked uncached (`repo().ask`), so the cache table by change kind in the design needs no row for it.
