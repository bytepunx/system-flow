# S-0367 Perform lint fix on every markdown file a story touches as part of validation

## Context

The markdown lint fix runs through flai, from an optional `fix_command` on a test tier of `system-flow.yaml`, so it is the project's command and not hard-wired to `scripts/lint-md.sh`.

## Decisions

- The fix is a tier's `fix_command` (`[scripts/lint-md.sh, --fix, "{files}"]` for the markdown tier), run by `verify.Fix`. A fix that fails never stops a commit, a sync, or an acceptance. Findings it leaves are reported by the lint tier, and since TH-0413 they block an acceptance (below).
- `storygit` takes the fix as a function in `SyncOptions`, because `verify` imports `storygit`; `taskdone`, `flai stream sync`, and `flai accept`'s rebase pass `verify.Fix`.
- Every clean sync fixes every file the branch changes against main, right after the rebase, and commits it (criteria 1 and 3). `flai task done` also fixes the paths it commits, before it commits them (criterion 1).
- Criterion 2 is read as the markdown `flai accept` commits from the main checkout; the operator confirmed it on TH-0413 (2026-10-12T16:58:39Z).
- Operator decision on TH-0413: markdown the fix cannot fix blocks the acceptance, naming the files, the lines, and the errors, so that the operator can correct them. `flai accept` refuses with those findings when the markdown tier still fails after the fix: on the main checkout's uncommitted markdown at preflight, before anything changes, and on the files the branch changes after its rebase and fix, before the merge. The markdown editor the operator asked for is the draft story S-0378, for the planner, not S-0367's.
- Revised plan: T-1470 (`verify` runs the check of the tiers that fix, over paths, and answers its findings) waits for T-1458. Both build `verify`, which `taskdone` imports. T-1459 (accept fixes and blocks) waits for T-1470. T-1471 (the docs and ADR-0139 describe the block) waits for T-1459. Every remaining layer holds one task.
- Plan, in layers:
  - Layer 1: T-1455 (`fix_command` and `verify.Fix`). Every other task uses it.
  - Layer 2: T-1456 (sync) and T-1457 (manifest, docs, ADR), together. They share no path, and T-1457 changes no Go file.
  - Layer 3: T-1458 (task done) waits for T-1456, whose `SyncOptions.Fix` its sync passes on.
  - Layer 4: T-1459 (accept) waits for T-1458. Both build the cmd package, which imports taskdone, so running them together could let a half-done edit fail the other's tests.
