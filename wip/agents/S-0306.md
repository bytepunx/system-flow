## Decisions

- The ADR index is merged row by row from a stopped rebase's three versions, not regenerated whole as I-0099 recommends. Regeneration from front matter would drop the hand-written status notes ("superseded in part by 0016") and needs the text above the table kept apart. A row merge keeps both and settles the case I-0099 counts, two branches each appending a row. It joins `Files.Merged`, so the trial merge leaves the index out of a pair's conflicts too.
- The merge lives in a new leaf package `internal/adrindex`: `issues` cannot import `adr`, which imports `check`, which imports `issues`.
- Plan, three layers. Layer 1: T-1583 (the `adrindex` merge) and T-1584 (ADR, design, user docs), which share no path and run together. Layer 2: T-1585 (wire it into `issues.SyncFiles`, help text, the reproducing sync test) waits for T-1583, whose package it calls.
