# S-0274 Opening a story is one call: flai story start moves it to in-progress, opens the stream, primes, and answers the first inbox together

## Context

`flai story start S-nnnn`, MCP `story_start`, and host-channel `story.start` replace the four start turns (move, stream open, prime, inbox) with one call. The planner's eight tasks (T-1091 to T-1118) are kept as written.

## Current state

S-0274 is closed out: all eight tasks done, each in its own commit on story/S-0274; the close-out passed every step (check, gofmt, vet, golangci-lint, go-test, vitest, markdown, template, flaiover, integration, smoke) and committed I-0108; the branch contains main. A verifier found all three criteria met and no convention break. All three criteria are ticked.

## Next steps

1. The operator reviews and accepts S-0274.
2. Two minor points the verifier raised, left as they are: the inbox step's Finish names the MCP tool inbox rather than a command, and story_start's header-only answer keeps the inbox whole, so in theory it could still pass 40,000 bytes with very many threads.

## Decisions

- The planner's tasks are kept as drafted: they cover the three criteria, and their touches and `after` already form the layers below.
- Layers: 1 = T-1091 (storygit open) and T-1099 (exported inbox), which wait for nothing and share no path; 2 = T-1103 (storystart), which calls T-1091's function; 3 = T-1109 (CLI) and T-1111 (MCP tool), which both call T-1099's and T-1103's functions; 4 = T-1115 (host channel, runs the CLI of T-1109), T-1117 (prompt and conventions) and T-1118 (docs), which name what layer 3 built.
- Within layer 1, T-1099 works in its own task worktree because `cmd` imports `mcpserver`, so a half-done inbox edit would break T-1091's `cmd` tests. Its files are disjoint from T-1091's, so they are copied back into the story worktree rather than merged.
- T-1099's exported inbox already exists: S-0269 moved it into package `flai/internal/inbox` (`inbox.Read`), which `flai task done` calls from the CLI and `(*server).inbox` wraps. T-1099 adds only the test that the CLI and the MCP tool share one cursor. Because `inbox` is not `mcpserver`, T-1103's `storystart` answers the inbox itself, so the three entry points need not each call it.
- T-1103: a start refuses a story not ready or held (overlap, `after`), as the criterion says; a full in-progress or review limit only warns, as `flai move` does, since `wait_for_work` already withholds a pull then.
- T-1109: `flai story start` exits 4 on a refusal (`exitDocRefused`, nothing changed) and 3 when a step after the move fails; `flai move` has no shared refusal sentence to reuse (it only warns on holds), so `move.go` is unchanged.
- T-1111: the answer is kept to ADR-0104's 40,000 bytes. Pack part 1 first, as `prime` cuts it, so `prime` parts 2.. follow; when the inbox makes it too big, its oldest changes are left out and counted in `changes_omitted`, as the inbox's own cap does; only when part 1 cannot fit even then is the pack its header alone. I added the trimming step to the sub-agent's header-only fallback, which in this repository would have answered no pack at all. Refusals and step failures are tool errors. `flai mcp` passes `worktrees.relative_paths` over stdio and HTTP.
- T-1115: `story.start` takes no agent parameter and runs as `flaiover`, like `task.done`; exit 3 is an internal error carrying the partial result. `flaiover/src/lib/server/agent.ts` names it in `REQUIRED_METHODS`, which the hostapi contract test demands; added to the touches.
- T-1117: an operator start past a hold, which `story_start` refuses, falls back in the prompt to `flai move` then `flai prime --story` and `flai stream open`; a story already in progress (reconcile, restart) keeps `flai stream open`.
- T-1118: `docs/users/conventions.md` and `design/system/agent-narrative.md` also described the two-step pull; fixed them and added them to the touches.
- `flai task done` commits everything uncommitted in the worktree, so closing one task of a layer swept its siblings' files into its commit twice (T-1109, T-1115). Both commits were mine and unpushed: reworded once with `--amend`, split once with `reset --soft`, so each task has its own commit. Recorded as an issue.
- The close-out is run by this agent, once, as `delegation.md` and `work-management.md` say (ADR-0110), not by a verifier as flai serve's start prompt (installed flai 1.34.0) says; a verifier reviews the diff against the criteria from `flai verify S-0274 --last`.
- Within layer 3, T-1111 gets its own task worktree for the same reason (`cmd` imports `mcpserver`); within layer 4 the tasks share the story worktree, as none builds what another changes.
