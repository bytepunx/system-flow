# S-0579 With the kluster host action on, flai serve deploys each story entering review into its namespace, runs the review checks against it, tears it down when the story leaves review, and promotes main on acceptance

## Context

## Current state

Tasks reviewed and planned in four layers (see Decisions). T-2481 is in progress: a task sub-agent writes the kluster pass in `flai/internal/serve/kluster.go`.

## Next steps

1. Review T-2481's work, close it with task_done, and run `flai test` on its paths.
2. T-2482: teardown and promotion in the pass.
3. T-2483: checks with the namespace's variables.

5. Commit, sync, ask flai serve for the close-out, and move S-0579 to review.

## Decisions

- The plan is four layers, one task each: T-2481 (deploys), then T-2482 (teardown and promotion), then T-2483 (checks), then T-2484 (documents). T-2482 extends T-2481's pass in `flai/internal/serve/kluster.go`. T-2483 starts the checks from that pass and reads its records, so it waits for T-2482, which shares the file. T-2484 documents what the three built. The planner had T-2482 and T-2483 in one layer. That no longer works once T-2483 touches `kluster.go`.
- T-2483's work is rewritten. flai serve starts no checks run on its own today. A run is started by `flai checks run` or the dashboard (`flai/cmd/checks.go`). So `RunChecks` gains an environment. A run for a story whose namespace passed at its head gets ADR-0254 §4's variables. With `checks` on, the pass starts a run after a passing deploy. `flai/cmd/checks.go` is added to the touches.
- Criterion 4 says a failed deploy "moves nothing". ADR-0254 §5a says it sends the story back to in-progress. It also gives `flai accept` a `kluster` blocker that no criterion names. The story is built to its criteria: the thread is opened, the story stays in review, and there is no blocker. `design/system/kluster.md` says what is built and what §5a leaves to a later story. See Open questions.
- A failed promotion opens its thread on `system-flow.yaml`, not on an epic, as ADR-0254 §5a says.

## Open questions

- ADR-0254 §5a has a failed deploy send the story back to in-progress, and `flai accept` refuse a story under the `kluster` blocker. S-0579's criteria build neither: a failed deploy opens one thread and moves nothing. Should a later story under E-0032 build the send-back and the blocker?
