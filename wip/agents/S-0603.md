## Decisions

- The planner's four tasks are kept as written: they match the three criteria and name the right functions in `flai/internal/serve/agents.go`.
- Layer 1: T-2621 and T-2629, run at once. They share no path: T-2621 changes `flai/internal/serve/agents.go` and its test; T-2629 changes `flai/internal/hostapi/` and `flai/cmd/serve_actions.go` and their tests.
- Layer 2: T-2623 waits for T-2621, since both change `flai/internal/serve/agents.go` and `agents_test.go`.
- Layer 3: T-2638 waits for all three: it measures what they change and reads T-2629's phases.
- T-2621: `AgentStates` returns the kept map itself, no copy. Every caller in `flai/internal/serve` and `flai/cmd` only reads it; each change goes through `AgentState.put` inside an `updateAgent` closure. `updateAgent` works on a deep copy (`cloneStates`, `AgentRun.clone`) and keeps a copy of what it wrote, since the launcher goes on changing runs it put in. `TestAgentRunCloneCoversEveryField` fails when `AgentRun` gains a pointing field `clone` misses.
- T-2621: the file counts as unchanged on the same inode (`os.SameFile`), size, and modification time. Every flai write renames a new file into place, so mtime granularity cannot hide one.
- T-2621: writers take `agentsWriteMu` and the file lock; `agentsMu` guards only the kept entry, so `agent.status` never queues behind a write.
- T-2629: the phases are `agent.states`, `agent.roles`, and `agent.activity` inside `agent.state`; reading the config has none.
