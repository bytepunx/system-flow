# S-0202 A card's right-click menu offers Finalize on a draft story and the card's other actions

## Context

The board's cards have no menu of their own: a right click on a card opens its lane's menu (S-0167), and a draft story has to be opened to be finalized (S-0201). This story gives each card a menu with Open, Finalize, the agent action, Block or Unblock, and Cancel, each through the write the item page uses.

## Current state

Tasks T-0764, T-0765, T-0766 written and planned. T-0764 is next.

2. Then T-0765, then T-0766, the same way.
3. Close out with `scripts/close-out.sh S-0202` through a verifier, and move S-0202 to review.

## Decisions

- Plan: three layers, one task each. T-0764 (the pure `cardMenu` and the shared `agentAction` rule) waits for nothing. T-0765 (the menu component and the board's wiring) waits for T-0764, whose function it renders. T-0766 (design and user guide) waits for T-0765, so the documents say what was built. Nothing runs together: each layer depends on the one before.
- The card menu replaces the lane menu on a card, and carries the lane's entries under a divider, so a right click on a card still reaches what S-0167 offered there, the card ticked first in a move.
- "The dashboard's user, not an agent view" is read as a writable dashboard: the dashboard writes as the designer (`item.finalize` runs `flai edit --no-draft --by=<owner>`, ADR-0077), and a read-only board offers no menu at all, as the lane menu does. There is no agent view in flaiover to tell apart.
- Start agent and Retry in the menu follow the same rule as the story page: the rule moves from `StoryAgent.svelte` to `agentAction` in `$lib/activity.ts`, so the two cannot drift.
