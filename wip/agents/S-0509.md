## Decisions

- Plan: the planner's four tasks stand, in four layers of one task each: T-2158 (ADR) → T-2163 (adapter, pilot) → T-2170 (serve's start paths) → T-2175 (proof, issues, docs). Each waits for the one before because it builds on its output: the ADR names the mounts, the adapter builds them, the start paths call the adapter, and the proof runs the whole.
- T-2170 also touches `flai/internal/serve/container.go` and its test, S-0508's readiness and stop code, which the planner did not know of; widened before the work.
- Already in place, read before planning: the four start paths call `harness.For` and `startOf`; `pilotRequest` keeps `Role`, `Item`, `Focus`, `Since`, and `AskedOn` in the JSON; pilot hands its whole request to the inner adapter, whose `Start` adds `--agent <role>` and `FLAI_ROLE`. What is missing: the adapter refuses a request with no story; the mounts; `Builtin`, the role file's prompt, is `json:"-"` and so lost; S-0508's readiness and stop name a story.
- The ADR chooses the main checkout read-write at its host path, as T-2158 recommends: the analyzer's report, the curator's `flai digest`, and the orchestrator's `--autocommit` commands write the checkout through the CLI, with no MCP route, and the guard already bounds those writes on the host. Read-only with writes over MCP would need new MCP tools first.
- TH-0815 asks how to make criterion 4's live run, since the host's flai 1.80.2 lacks this code and has no container harness set. Layers 1 to 3 do not wait on it.
