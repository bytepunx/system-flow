# S-0602 flai serve keeps threads, conversations, digest entries, issues, and activity documents parsed between requests, so a thread read takes about 5 ms, not 80 to 110 ms

## Context

Cause 13 of `design/system/server-performance.md` § A second pass at 596 stories (S-0596): threads, conversations, digest entries, issues, and activity documents are read and parsed again on every call. The fix keeps each kind parsed in flai serve's and flai mcp's process, as S-0156 keeps items.

## Current state

T-2660 is done: `flai/internal/workitem/keptfiles.go` keeps parsed files of any kind by path and stat (commit 38ea8723d). Layer 2 is starting: T-2667, T-2671, T-2673, T-2676, and T-2680, each in its own task worktree under `.flai-cache/worktrees/T-nnnn` on `task/T-nnnn`, because `messages` imports `threads` and every reader imports `workitem`, which T-2671 and T-2680 change.

## Decisions

- The planner's seven tasks are kept. Plan, three layers:
  - Layer 1: T-2660, the shared store. Every reader builds on it.
  - Layer 2: T-2667 (threads), T-2671 (conversations, in `messages` and `workitem/share.go`), T-2673 (digest), T-2676 (issues), T-2680 (activity documents). Each waits for T-2660 alone; no two share a path, so they run together.
  - Layer 3: T-2684, the measurement and the design. It waits for all five readers, since the after figures need every reader moved.
- The store goes in `flai/internal/workitem/keptfiles.go`, not `kept.go` as planned: S-0600 already made `kept.go` its kept items file. The type is `KeptFiles[T]`, so that it is not confused with `store.go`'s `kept`. T-2660's and the story's touches were changed to match, and the task bodies say so.
- `design/system/server-performance.md` is shared with S-0599 (MS-0366), S-0606 (MS-0375), and S-0604 (MS-0391): S-0602 adds and changes only its own cause 13 section and leaves the S-0596 tables alone, so T-2684 no longer marks the cause 13 row in the "Where the time goes" table, as the planner wrote. Whichever story lands second keeps every section in cause order.
- The store is process-wide, one package-level value per kind, keyed by absolute path, as `store.go`'s `parsed` is: the dashboard's methods open a `Repo` per request.
