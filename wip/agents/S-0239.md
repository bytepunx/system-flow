# S-0239 dashboard.allow_unsigned lets a development build connect, shown on every page and in every status

## Context

S-0237 built both gates already: `channel.Client.AllowUnsigned` and the dashboard's `allowUnsigned` option admit a missing stamp only. Nothing sets them yet. This story wires the setting to them, passes `FLAIOVER_ALLOW_UNSIGNED` to the container, and shows the allowance wherever the connection is shown. Started on shares: MS-0100 with S-0353 (`docs/operators/settings.md`) and MS-0101 with S-0356 (`docs/contributors/index.md`, `docs/operators/index.md`).

Layers 1 and 2 done and tested: T-1259, T-1260, T-1261 (30f509b), T-1262 (b7be776), T-1263 (889b7fa). Branch synced onto S-0353's acceptance, clean. Layer 3 (T-1264 banner, T-1265 statuses) starting.

## Decisions

- The planner's eight tasks are kept, in its four layers: T-1259 and T-1260 first, with no path in common; T-1261 and T-1262 after T-1259, whose setting they read, and T-1263 after T-1260, whose recorded side it lists; T-1265 after T-1261 and T-1262, since it shows the side T-1262 records and edits `flai/cmd/dashboard.go` after T-1261; T-1264 after T-1263, whose project list the banner reads; T-1266 last, so the docs use the words the code prints. Each layer runs its tasks at once, one task sub-agent each.
- The allowance admits a missing stamp only, never one that does not verify or names another component, as S-0237 built the gates and `design/system/release-signing.md` § The development case says ("accepts a peer with no stamp"). The tasks' drafts said "missing, unverifiable, or names another component"; the design and the built gates win, since a bad signature is not a development build.
- T-1261: the container record (`dashboard-container.json`) keeps `allow_unsigned`, so `flai host`'s restart, which has no manifest, repeats what the start worked out; `flai dashboard restart` and `upgrade` use the record or the settings now, so they can add the allowance but not remove it, as with the recorded image. `dashboard_watch.go` was widened into T-1261's touches for it.
- T-1262: `channel.Client.AllowUnsigned` became `func() bool`, asked at each attempt, and serve's `guard` sets it with the image gate, so a changed setting takes effect at the next dial without a data race. `Options.AllowUnsigned` reads the host configuration from `flai/cmd/serve.go`, and `candidates.go` gets the same guard; both were widened into T-1262's touches. The warn is the channel's, `connection allowed unsigned`, where the proof completes.
- T-1263: `unsignedLabel` lives in `$lib/project.svelte`, beside the client's `Project` type, for the switcher and the banner.
- MS-0104: shared `docs/operators/settings.md` with S-0354, S-0239 keeping its own rows and the generated table regenerated by the second to sync.
- The splits on MS-0100 and MS-0101 are kept: in the shared files this story changes only the `dashboard.allow_unsigned` rows, prose, and the dashboard image and host-connection sections.
