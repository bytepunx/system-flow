# S-0168 Several Charts Don't Use Window correctly

## Context

S-0168 asks that the cycle time and time in state charts load with the window chosen and follow it on the x axis. S-0166 (ADR-0054) made every time axis span the window.

Found on 2026-09-29, probing the running dashboard (flaiover 0.31.1, e60859b) and a dev server of this branch with headless Chromium against real `flai stats`:

- Cycle time draws the right axis for 30d, 7d, and 1d, opened directly or reached from another chart.
- The page keeps the window in component state only, so a remount (Board, then Charts) opens cycle time, the chart Charts lands on, at 30d.
- The page asks for stats only after the epic list answers; when that fails, the chart stays on Loading.
- Time in state has a category x axis of item IDs: no time range at all.

## Current state

T-0596 done (22528c1). T-0597 in progress: time in state as one stacked bar per day on a time axis spanning the window (TH-0039 answered: option 1).

## Next steps
1. T-0597: ADR refining ADR-0054; `timeInState` by day in `charts.ts`; metrics.md and docs; unit and page tests; browser check.
2. `scripts/flaiover-test.sh`, `flai check --strict`, commit, move S-0168 to review.

## Decisions

- Tasks are committed one by one, as the operator's start instruction says, not only when the story lands as `git.md` has it.
- Time in state needs a time axis to meet the criteria; its layout is the designer's choice (TH-0039), so it waits while T-0596 goes ahead.
- Time in state is one stacked bar per day of the window, the mean hours per state of the items completed that day (designer, TH-0039, 2026-09-30: option 1). Recorded in an ADR refining ADR-0054, since metrics.md defines the chart.
