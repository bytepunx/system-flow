## Decisions

- Plan: the planner's four tasks stand, one per layer, as drafted: T-2634 (the key), then T-2644 (`verify.Run` at once, reads the key), then T-2653 (smoke's skips, shares `run.go` and its tests with T-2644 and reads its ordering), then T-2661 (marks this repository's tiers and times the runs that the code tasks build). No two can run together, since each reads what the one before writes.
- The key is a flag, `parallel: true` on a tier, not `after: [<tier>]`. A tier marked `parallel` starts once every tier before it in the list that is not marked has ended, without waiting for the marked tiers before it; an unmarked tier waits for every tier before it, as now. With no tier marked the run is serial as before. The flag keeps "cheapest first, stop at the first failure" for free: the cheap per-path tiers stay unmarked, so the expensive ones start only when they pass. `after` would let a tier name exactly what it waits for, but needs a cycle check, a meaning for an `after` naming an unselected tier, and a way to tell an empty list from none; no tier here needs that precision. Recorded in the ADR T-2634 writes.
- A tier's `FLAI_VERIFY_PASSED` names the tiers it waited for that passed (and, in a close-out, the reused tiers and the check step), not whatever happened to end before it started, so what smoke skips does not depend on timing.
- In a close-out the `markdown` tier runs for the changed files, not whole, so smoke's `lint-md.sh` is skipped only when `markdown` ran whole (`all_command`), as the task says; in a close-out the saving comes from the check and the template test.
