# S-0236 flai dashboard resolves the image from the signed digest list and runs it by digest

## Context

S-0233 verifies flai releases before install; S-0234 publishes `flaiover_<version>.digests` and its signature on each `flaiover/vX.Y.Z` GitHub release. This story makes `flai dashboard`, `check`, `upgrade`, `status`, and `versions` choose and run the image by digest from that signed list (ADR-0070). Design: `design/system/release-signing.md` § The digest list.

## Current state

T-1239 to T-1242 are done.

- `selfupgrade.VerifySigned` is the one place a release's signed asset is verified.
- `dashboard.FetchList`, `Resolver.Resolve`, and `Cache` resolve and cache the verified list.
- `flai dashboard versions` marks unverifiable releases, and `--published` refuses them.

T-1243 (`flai dashboard` by digest, status, restart record) and T-1245 (Updates page) are in progress with task sub-agents in the story worktree.

## Next steps

1. Review T-1243 and T-1245, close each with `flai task done`, and run `flai test` on their paths.
2. Work T-1244 (`check` and `upgrade` by digest).
3. Work T-1246 (documentation, `make flai-reference`).
4. Run the close-out, review the diff against the criteria, tick them, and move to review.

## Decisions

- Plan, reviewing the planner's eight tasks, in six layers, worked one task at a time: they are moderate and mostly build on each other.
  1. T-1239: `selfupgrade` exports `Find`, `FetchAsset`, `FetchSigned`, `VerifyBlob`, and `TrustedKeys`. `List` already lists any prefix with assets, so the task is the signed fetch, not the listing.
  2. T-1240: digest list parser and cache in `flai/internal/dashboard`. It now waits for T-1239: no exported blob verifier existed (`signedByOneOf` is unexported), so the list's verification needs T-1239's, and the new package imports the one T-1239 edits.
  3. T-1241 (resolver) and T-1242 (`versions` mark), each after T-1239 and T-1240; no path in common.
  4. T-1243 (`flai dashboard`, `status`, the restart record) after T-1241; T-1245 (Updates page) after T-1242.
  5. T-1244 (`check`, `upgrade`) after T-1243: both change `dashboard.go` and `dashboard_test.go`.
  6. T-1246 (documentation) after T-1244 and T-1245, the last behaviour it describes.
- The unverifiable mark on dashboard releases reuses `listedFlai`'s fields, `unverifiable`, `signature`, `reason`, so the Updates page mirrors `HostProcesses.svelte`, rather than the planner's suggested `deployable`.
- `flai dashboard versions` keeps listing `flaiover/v*` tags and joins them with GitHub releases, so a version from before signing, a tag with no release, is listed and marked rather than dropped.
- A tag that is neither `latest` nor a version, on the signed repository, is refused by the resolver: it cannot be on a signed list. Allowing it is S-0239's `dashboard.allow_unsigned`.
