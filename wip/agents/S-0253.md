# S-0253 An acceptance merge committed conflict markers to a design document on main, and nothing caught it

## Context

I-0066: `design/system/work-hierarchy.md` reached main with conflict markers. They came in with 523b882, S-0201's rebase of f0f5443 during a sync: the conflict was `git add`ed with its markers and the rebase continued, and `flai accept` fast-forwarded main onto it. Nothing in flai looks for markers: Go and YAML fail to parse with one, markdown does not.

## Current state

Both tasks are done and committed. T-0858: `flai/internal/conflictmark` and `flai check`'s `markdown.conflict-marker` error. T-0859: `flai accept` refuses a branch any of whose added or changed files carries a marker (`refuseConflictMarkers` in `flai/cmd/branch.go`), tested by `TestAcceptRefusesABranchCarryingConflictMarkers`. I-0066 is closed. The close-out is next.

## Next steps

1. A verifier runs the close-out; fix what it finds, then move S-0253 to review.

## Decisions

- Proposed solution (the issue recommended none): catch the markers at two gates. `flai check` reports `markdown.conflict-marker`, an error, on each marker line in markdown under design, docs, wip, and the root, so a close-out and CI stop on one; and `flai accept` refuses a branch whose changed files carry one, so nothing reaches main with a marker even when the close-out was skipped. A shared pure scanner, `flai/internal/conflictmark`, finds them.
- Only `<<<<<<<`, `>>>>>>>`, and `|||||||` lines followed by a space or the end of the line are markers: `=======` is a valid setext underline in markdown, and every conflict has an opening and a closing marker anyway. For the same reason `git diff --check` is not used: it flags `=======` lines and whitespace too.
- Plan: layer 1 is T-0858; layer 2 is T-0859, which waits for T-0858 because it uses `conflictmark` and both edit `design/system/flai-cli.md` and `docs/users/flai.md`. Nothing runs together.
- The story's touches leave out `design/issues`: closing I-0066 writes there, and S-0260 claims the whole folder, so naming the issue file would hold both stories on a path every issue-closing story writes.

## Open questions

- `flai accept --dry-run`, the dashboard's preview, does not report conflict markers as a blocker; only the real acceptance refuses. Adding it means `flai/internal/preview`, outside this story: worth a story if the operator wants the preview to show it.
