# S-006 flai import for existing monorepos

## Context
flai new creates conforming repos; flai import converts existing ones (brief item 6). The design in flai-cli.md describes a six-step flow: scan, propose, ask folder names, create structure and render non-conflicting template files, ask per markdown file where it goes with git mv, write the manifest and check. Rendering reuses internal/template with Force off so nothing existing is overwritten; prompts reuse huh as in flai new; git goes through execx. The importer must be safe to run twice and honest in --dry-run.

## Current state
All three tasks done, story in review. internal/importer scans a tree (existing layout folders, candidate folders adr/adrs/architecture/doc/documentation, loose markdown outside code and candidates, sub-projects by go.mod, package.json with svelte.config for sveltekit, pyproject.toml, Cargo.toml; skips .git, node_modules, vendor, build output) and builds a plan (folders to create, whole-folder moves, markdown to decide, projects). cmd/import.go proposes, asks in a terminal (layout names, each folder move, each markdown destination), renders without overwriting, moves with git mv when tracked, writes projects into the manifest, runs check, and prints a summary; --dry-run, --yes, --layout, --var, --template, --force, --json. Tests: unit on a synthetic tree including a git mv and a no-overwrite conflict; in-process dry-run and apply. Lint and all tiers green. Committed at review and pushed.

## Decisions
- Candidate folders move whole (per file, skipping conflicts) rather than per file; loose markdown is per file and only in a terminal, otherwise left in place. An import is safe to run non-interactively and reversible with git.
- Detected sub-project directories are not descended into, so their docs are not treated as loose markdown.
- Rendering reuses template.Render with Force off; skipped files are counted as kept.
- The manifest's projects list is written by replacing the rendered `projects: []`, keeping the rest of the rendered file byte for byte.
- FLAI_CACHE_DIR overrides the default cache_dir at first run; test helpers and scripts/env.sh set it so nothing reaches the operator's home.
