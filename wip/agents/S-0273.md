# S-0273 flai test runs the project's test and lint tiers for a path or a package and answers pass or the first failures as findings

## Context

`flai test [path|package]...` runs the project's test and lint tiers for the paths given, cheapest first, and answers pass or the first failures as findings; `test` over MCP, `test.run` on the host channel. The planner drafted six tasks in four layers.

## Current state

Layer 1 in progress: T-1067 (manifest `tests` key) in the story worktree, T-1068 (`flai/internal/verify`) in its own worktree `.flai-cache/worktrees/T-1068` on `task/T-1068`.

2. Add the manifest-to-verify mapping glue, then run layer 2 (T-1069, T-1070).
3. T-1073, then T-1079, then close out.

## Decisions

- Kept the planner's four layers: (1) T-1067 and T-1068, no `after`, no shared path; (2) T-1069 and T-1070, after both of layer 1, which they join; (3) T-1073, after T-1069, whose `flai test --json` it runs; (4) T-1079, after all, which it describes, and sharing `template/CHANGELOG.md` with T-1067.
- T-1068 works in its own worktree: it may import `manifest` (for the `**` matcher in `shared.go`), which T-1067 edits at the same time. T-1070 will likewise get its own worktree in layer 2, since `cmd` builds `mcpserver`.
- Tier contract, shared by the manifest key and the verify package: `name`, `command` (argv with placeholders `{packages}` and `{files}`), `dir` (where it runs, relative to the checkout root; the placeholders are made relative to it), `paths` (`**` globs relative to the root, `!`-prefixed ones excluding), `format` (`go-test-json`, `vitest-json`, `golangci-json`, `gofmt-list`, `plain`), `all_only`, and `all_command` (argv used under `--all`; without it `{packages}` becomes `./...` and `{files}` `.`). `dir` and `all_command` were not in the planner's draft: Go tiers run in `flai/` and vitest in `flaiover/`, and vitest needs `related` for a path but `run` for everything.
- Findings are parsed only from a failing tier; a parse that finds nothing falls back to the `plain` tail. So a tier that skips itself (vitest without `node_modules`) passes.
- This repository's tier commands go through a new `scripts/with-env.sh`, which sources `env.sh` and runs its arguments, so `golangci-lint` and the npm cache resolve as the scripts resolve them; `scripts/flaiover-unit.sh` passes its arguments through to vitest. Both added to the story's and T-1069's touches.
- The manifest-to-verify mapping and one `verify` entry point that the CLI and MCP share are written by me between layers, so T-1069 and T-1070 never duplicate them.
