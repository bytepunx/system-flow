# S-0094 Tagging should occur before push

## Context

Since S-0087, `flai accept` computes no release, no tag, no push — that became a deliberate separate step, `flai release --pending`. But nothing else ever called it: `flai push --pending` only pushed tags that ALREADY existed from a prior, separate `flai release --pending` run. An operator who only ever clicked the dashboard's "Push now" (wired to `push.run` → `flai push --pending --publish`) got no release, no tag, ever — the GitHub release workflow (which fires on a pushed tag) never ran. Confirmed by reading the actual code, not assumed: `flai/cmd/push.go`'s `pending.Detect` only reads existing tags via `git tag --merged --no-merged`; nothing calls `release.Pending`/`TagPending` outside `flai release --pending`'s own command.

## Current state

Done. `flai push --pending` now tags everything `release.Pending` finds accumulated and unreleased since each component's last tag — applying the version bump, committing, and tagging on HEAD — before it decides what to push, via a new shared helper (`computeApplyAndTagPending`, extracted from `flai release --pending`'s own `publishPending`, which now calls the same helper). It then pushes the branch and every tag (the one just created, and any left over from an earlier partial run) together. `--dry-run` only previews the plan (read-only). `flai release --pending` itself is behaviourally unchanged, still available for seeing or forcing a release ahead of a push.

Verified live, twice, with a locally built `bin/flai` against real scratch repositories (the second with a real bare-repo remote, matching the operator's own setup): accept alone created no tag; a dry run created no tag; a real `flai push --pending --json` created `cli/v1.1.0` locally AND on the remote in the same command; a second run retagged nothing. No flaiover changes were needed at all — `UnpushedNotice.svelte`'s existing "Pushed with tags X" message already reads the same `unpushed.tags` field the backend now populates correctly, so the fix is entirely in `flai/`.

Found and fixed two stale docs while writing the accurate description, since they directly contradicted it and predate this story by a long way: `docs/users/flai.md` and `docs/operators/index.md` both still described the pre-S-0087 world (accept itself computing/tagging/pushing a release, and flags like `--no-push`/`--no-release` that no longer exist anywhere in the code).
