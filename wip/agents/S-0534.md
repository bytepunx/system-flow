# S-0534 A usage-limit refusal sets a budget state on the host that holds every start on that provider until the reset or a backoff, probes once, and reaches every inbox, the journal, the dashboard, and the ADR-0205 channel

## Context

ADR-0209 §5: a usage-limit refusal sets a budget state per provider on the host, in `budget.json` in the serve folder, that holds every start on that provider across every served project, probes once at the reset or after a backoff of 5m doubling to 1h, and reaches the journal, `inbox`, the dashboard, and the ADR-0205 channel. The usage-limit reader is S-0514's (`runLimit`, `limit.go`; D-0418: only a 429 or a rejecting `rate_limit_event` counts).

## Current state

T-2282 is done: `flai/internal/serve/budget.go` keeps the budget state per provider in `budget.json`, with the launcher's `budgetStart`, `budgetSpawned`, `budgetRelease`, `budgetEnded`, and `budgetChanged` (the one place a change is journaled). Layer 2 (T-2283, T-2286, T-2287, T-2288) is starting, one task sub-agent each, at once.

## Decisions

- The planner's nine tasks stand as drafted (TH-0711, approved by the orchestrator under `plan_backlog_stories`). Its two proposals, a hand clear command and holding the permission check, stay out, as the orchestrator's pending recommendation says; the criteria ask for neither.
- Layers, as planned: 1 is T-2282 (the state itself, which every other task reads). 2 is T-2283, T-2286, T-2287, T-2288, which wait for T-2282's API and share no path. 3 is T-2284 and T-2285, which wait for T-2283 because they change the same run files (`agents.go`, `plan.go`, `orchestrate.go`, `analyze.go`, `curate.go`), and T-2289, which waits for T-2287's `agent.status` field. 4 is T-2290, the docs, after all of them.
- The layers run one task sub-agent at a time in the shared worktree, except layer 2, whose four tasks run at once: they share no path and none builds what another changes.
- The state's key is the run's provider, or its harness when it names none (`claude-code` on its own login), as TH-0711's assumption 2 says. The probe is the first start that waits on the provider once `until` has passed (assumption 3); a probe that ends on anything but the limit clears the state (assumption 4).
- `mcpserver` does not import `serve`: the inbox's `budget` reaches the MCP server through an `Options` function `cmd` wires to the serve folder, as `AutoApprove` does (assumption 5).
- MS-0229: the hold on S-0536 stands, since both stories change the orchestrator's start path.
