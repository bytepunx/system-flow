## Decisions

- Remedy A, as the planner drafted it: a container story's close-out job runs `flai verify --record-issues` in the story's container, the commit and the sync run on the host through flai's own code with the main checkout's hooks, and the operator's checks for such a story run in the container. The operator finalized S-0628 with A's tasks, and ADR-0253 already says the close-out runs inside the container. TH-0949's recommendation on the cost of delay and the remedy still awaits the operator; nothing here waits on the cost of delay.
- ADR-0272 is taken (the checked-write lock). T-2772's ADR takes the next number `adr_new` gives, and T-2784 and T-2785 link that number.
- The symlink check in `flai/internal/docedit/file.go` stays out of scope, as the planner and the orchestrator recommended.
- Plan, reviewed and kept as the planner drafted it:
  - Layer 1: T-2772 (the ADR) and T-2775 (the container adapter's argv for one command). No after, no shared path: they run together.
  - Layer 2: T-2777 (the close-out job). It runs T-2775's argv.
  - Layer 3: T-2782 (the operator's checks). It runs T-2775's argv in the image T-2777 exposes.
  - Layer 4: T-2784 (the documents). It describes T-2772's decision and T-2777's and T-2782's behaviour.
  - Layer 5: T-2785 (close I-0295). Its reason names what every other task did.
- The adr_new number came out 0274, not 0273: another branch holds 0273. T-2784 and T-2785 link ADR-0274.
- T-2777 put the container close-out in a new file, `flai/internal/serve/verifyjob_container.go`, and moved `containerAllowed`'s decision into `containerImage`, so an agent's start and its close-out choose the same image. T-2782 changed its two callers, `flai/cmd/checks.go` and `flai/internal/serve/kluster.go`, to pass the story's container through the new `RunChecksIn`. `RunChecksWith` keeps its signature.
- The host's flai children (`--sync-only`, `stream sync`) get the hooks and fsmonitor overrides but not `GIT_DIR`, since they run git in more than one checkout. `gitPointers` refuses a redirected `.git` file or `commondir` before each host step.
- Left on the host, as ADR-0274 counts them among the runs by hand: the dashboard's `test.run` and `verify.run`. A kluster check of a container story gets `KUBECONFIG` by name, but the kubeconfig under the main checkout's `.flai-cache` is not mounted, so it cannot reach the cluster through it. Both are in the guides.
- While working T-2777, a sub-agent's scratch test printed the host's process environment, API keys among them, into this session's tool output. Nothing reached the repository. Later sub-agents were told never to print the environment. Reported to the operator.
