# S-0545 flai serve wakes a story's agent that is paused on a thread for every task-done message from another story, each needing only a settled reply

## Context

Remediates I-0232: `messaged` in `flai/internal/serve/agents.go` starts an agent paused on its own question for every task-done notice, each needing only a settled reply.

## Current state

S-0545 is in review. The close-out passed at 2a44f77 (verify S-0545 --last). Both criteria are ticked: the serve rule and its I-0232 reproduction test (criterion 1), and I-0232 closed (criterion 2). ADR-0252 records the decision.

## Decisions

- Kept the planner's five tasks and layers: T-2440 (ADR and design) first, since it decides the mark; T-2441 (the mark) and T-2442 (convention and docs) together, as they share no path; T-2443 (serve rule and test) after T-2441, as it reads the mark; T-2444 (close I-0232) last.
- Added `flai/cmd/message.go` to T-2441's touches: `flai message show` prints each entry's heading marks, and must print `(notice)` as it prints `(settled)`.
- ADR-0252, accepted, refining ADR-0154 and ADR-0205: only `flai task done`'s notice is marked `(notice)`; sync and merge-queue conflict messages, grown-claim messages, and the hold ask ask for agreement, so they stay unmarked and still wake. The rule applies only while the run's own thread question is unanswered; a run waiting only on another story's reply still wakes on a notice, as ADR-0154 rejected holding notices from an agent that may be building.
- Marked in the heading, as `(settled)` is, rather than judged by the notice's text, which is prose a later change may reword.
