## Context

ADR-0129 sets the shape: `agent.provider` beside `harness` and `model`; a host `agent.providers` map with `api`, `base_url`, `key_env`, and `models`; a manifest `providers` map that overrides `api`, `base_url`, and `models`, never `key_env`. Nothing starts an agent through a provider in this story.

## Decisions

- The planner's four tasks stand as drafted, one per layer: T-1371, then T-1372, then T-1373, then T-1374. T-1371 to T-1373 each add rows to `docs/operators/settings.md`, whose index test must pass at every close, so they cannot share a layer; T-1372 stores T-1371's `manifest.Provider`; T-1374 describes the commands T-1372 and T-1373 build. Each task is short, so one task sub-agent works each layer in the story's worktree.
- T-1371 also wires `ProviderErrors` into `flai check` (rule `manifest.providers`) and `flai manifest set`, and adds `provider` to `front-matter-fields.txt`: without them nothing refused a manifest `key_env`, and the fields test failed. Its sub-agent found both.
- T-1372 also changes `provider.go`: a `key_env` that is not a variable's name, or a `base_url` with a password, is refused without repeating the value, which may be a pasted key. Its sub-agent found it.
- T-1373 is widened to `flai story new` (`flai/cmd/items.go`), the host API's agent writes (`flai/internal/hostapi/writes.go`, `settings.go`), and `item_new`'s description (`flai/internal/mcpserver/folder.go`): `story new` shares the agent flags, and the host API would drop `provider` from any agent the dashboard writes. The dashboard's own fields stay S-0359's.
- `flai manifest set` writes `planning.agent` and `analysis.agent` whole as JSON, so `provider` goes in that JSON; no `*.agent.provider` keys are added. `agent.provider` stays `flai agent set`'s.
- Tests and task closes run through the tree's `scripts/flai.sh`: the installed MCP flai (1.40.1) refuses main's manifest since S-0364 (TH-0411).
