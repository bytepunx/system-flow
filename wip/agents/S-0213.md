## Context

Two values are new to the contract: the count of items without a value per column per day, and the projection. S-0212 (in review) adds a Planning group to the same chart page and builders; these charts join it once it lands.

## Decisions

- The planner's tasks are kept as drafted: their touches name files, and the order matches the dependencies in the code (`metrics.Options`, `planning.playOut`, `workitem.OrderByPolicy` all exist).
- Layers: (1) T-0953, the `metrics.md` contract and ADR every later task implements; (2) T-0955, which changes the cost of delay types in `costofdelay.go`; (3) T-0959, which changes the same types and needs T-0955's; (4) T-0965 and T-0967 together, the CLI print and the chart builders, both reading T-0959's output with no path in common; (5) T-0969 and T-0970 together, the page and the docs, both describing T-0967's kinds with no path in common.
- Layers 4 and 5 ran their two tasks at once, one sub-agent each in the shared worktree, since neither shares a path with the other. Each pair was committed by hand on its own paths before `flai task done`, which commits everything in the worktree (I-0104; not bumped: it is on S-0212's branch, not main).
- The projection follows `flai forecast`'s play-out exactly (busy factor, `after`, review holding no lane): `planning.PullTimes` exports the play-out rather than copying it, so the two cannot drift (ADR-0112).
- With no in-progress limit every pull is at now and every order costs nothing, as `flai forecast` pulls them; not a single lane, which would disagree with the forecast.
- CoD Outstanding and CoD Incurred offer the item type: the page keeps one report across charts, so a type chosen elsewhere would otherwise carry in with no way to change it, and `metrics.md` defines them over the report's type. CoD by Order offers only the window: the projection is always of the ready stories.
- The cod kinds are a list of their own, `COD_KINDS`, beside S-0212's `PLANNING_KINDS`, so the two merge by joining lists; both use a `planning` row on the page.
- `flai stats --help` and `docs/users/flai-reference.md` name the new keys (`make flai-reference`).
