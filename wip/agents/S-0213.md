Each pair was committed by hand on its own paths before `flai task done`, which commits everything in the worktree (I-0104; not bumped: it is on S-0212's branch, not main).
- The projection follows `flai forecast`'s play-out exactly (busy factor, `after`, review holding no lane): `planning.PullTimes` exports the play-out rather than copying it, so the two cannot drift (ADR-0112).
- With no in-progress limit every pull is at now and every order costs nothing, as `flai forecast` pulls them; not a single lane, which would disagree with the forecast.
- CoD Outstanding and CoD Incurred offer the item type: the page keeps one report across charts, so a type chosen elsewhere would otherwise carry in with no way to change it, and `metrics.md` defines them over the report's type. CoD by Order offers only the window: the projection is always of the ready stories.
- The cod kinds are a list of their own, `COD_KINDS`, beside S-0212's `PLANNING_KINDS`, so the two merge by joining lists; both use a `planning` row on the page.
- `flai stats --help` and `docs/users/flai-reference.md` name the new keys (`make flai-reference`).
