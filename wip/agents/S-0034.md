# S-0034 flai installer script and self-upgrade command

## Context

## Current state
Complete. `install.sh` at the repository root and `flai self-upgrade` both resolve the newest `flai/v*` release, download the platform archive and `checksums.txt` through the release asset API, verify the SHA-256, and install. Verified for real against the private repository: the script installed 1.0.3 into `.flai-cache/install-test`, and the source build pinned 1.0.2 then upgraded to 1.0.3 with `--dir`. Unit tests cover resolution, verification, extraction, replacement, and the command; `scripts/install-test.sh` runs both paths in the smoke tier and in CI. Story in review.

## Next steps
1. Operator review and `flai accept S-0034` (feature story: flai minor).

## Decisions
- The installer lives at the repository root as `install.sh`, not under `scripts/`, so the raw URL stays short and stable; `scripts/` remains for Makefile helpers. Modelled on bytepunx/kluster's installer.
- Assets are fetched through the GitHub release asset API with `Accept: application/octet-stream`, which works for the private repository with a token and for a public one without; `browser_download_url` would fail while private.
- Token sources, in order: `GITHUB_TOKEN`, `GH_TOKEN`, `gh auth token`. Both the script and the command use them; neither prompts.
- The command is `flai self-upgrade` because `flai upgrade` already means the template.
- Checksum verification is mandatory in both paths; a missing entry or tool aborts.
- The install test needs network and a token, so it fails loudly rather than skipping when neither is present; CI passes `GITHUB_TOKEN`.
