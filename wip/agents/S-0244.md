## Decisions

- Took the planner's four tasks as drafted. Layers: T-0867 and T-0868 first, together (no `after`, no file in common); T-0869 waits for both, since it describes T-0867's notice and may set the client limit T-0868 finds; T-0870 waits for all three, since it documents them and closes I-0059.
- T-0867 and T-0868 both edit files of the `mcpserver` package, so one's half-done edit could fail the other's build. T-0868 runs in its own worktree from the story branch, `task/T-0868`, and is merged back before T-0867 is committed on top. In the event the restarted agent carried T-0868's diff onto the story worktree as a patch (no file in common with T-0867) and committed the two separately, rather than merge by hand.
- T-0868, the client's tool-call limit (from the claude-code 2.1.280 binary): a hard wall-clock limit of `MCP_TOOL_TIMEOUT`, else 100,000,000 ms (about 27.8 hours), and an idle limit, `CLAUDE_CODE_MCP_TOOL_IDLE_TIMEOUT` or a per-server `timeout`, else 1,800,000 ms (30 minutes) over stdio and 300,000 ms (5 minutes) over HTTP. A progress notification starts the idle count again, and Claude Code passes a progress token on every tool call. A 1800 s wait over stdio would race the idle limit to the second, and any wait over HTTP was cut at 5 minutes. The cap is 30 minutes as planned, and a held wait sends a progress notification every minute to a call with a progress token. The harness does not need to raise a limit, so T-0869 sets no environment variable.
- T-0867 reports only a story in progress whose claim grows, and compares it only with other stories in progress: a story not yet started is held at pull time (ADR-0046). A new `wip.overlap` finding in `itemedit.Apply` is now a warning, not a refusal, so the write stands, as the task asks.
