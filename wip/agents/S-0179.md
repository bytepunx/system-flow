# S-0179 flai lints the markdown it writes in the main checkout, and a thread's entries in one second share a heading

## Context

wip/ is written in the main checkout (ADR-0019), so the markdown lint a story runs in its worktree never sees it (I-0027), and threads give a reply and a resolution in one second two identical headings (I-0043). Work is in `.flai-cache/worktrees/S-0179` on `story/S-0179`.

## Current state

Tasks T-0632 to T-0636 written. `scripts/lint-md.sh` passes on main at the start (0 errors over 1254 files): TH-0035 was fixed by hand. T-0632 done and committed (6b83098). T-0633 in progress: nothing written yet.

## Next steps
1. T-0633: `flai/internal/mdlint`, a subset of markdownlint configured by the project's file, checked against markdownlint-cli2 on fixtures and on this repository.
2. T-0634: `flai check` lints wip/ markdown as warnings.
3. T-0635: titles lose trailing punctuation; item creation, thread entries, and narrative log entries are linted before they are written.
4. T-0636: ADR, design, conventions (template first), user guide, close I-0027 and I-0043, run every tier.

## Decisions

- flai embeds a subset of markdownlint in Go (`flai/internal/mdlint`) rather than running markdownlint-cli2: `flai check`, item edits, and thread replies run it on every call, and a project made from the template may have no Node. The subset is the rules seen in I-0027 and I-0043 plus the ones agent-written bodies commonly break; the project's CI lint stays the authority. It is conservative: a case it cannot judge is not reported. ADR in T-0636.
- No lint runs when the project has no markdownlint configuration (the story's notes: a missing linter must not fail `flai check`).
- `flai check` lint findings are warnings, so `itemnew` and `itemedit`, which refuse any new check finding, refuse a body that brings one without code of their own.
