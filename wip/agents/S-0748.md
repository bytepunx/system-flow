# S-0748 A role file's to-review and to-backlog conditions become one condition that names any state the workflow has, and the baseline role files use it

## Context

## Current state

ADR-0304 recorded and committed: one condition `to`, written `when: {to: <state>}`, any state of the workflow on a moved trigger, only the workflow's initial state on an item_move or flai move call; `to-review` and `to-backlog` parse as aliases. T-3231 (the roles package) in progress.

## Next steps

1. Finish T-3231 and close it with task_done.
2. Run T-3238, T-3239, T-3240 as one layer.
3. Close out with verify, then review.

## Decisions

- ADR-0304 names the condition, since ADR-0301 §9 left it to S-0748 unnamed: `to`, as `when: {to: <state>}`. Old names stay as aliases resolved at parse (criterion 3's 'works as before'), so a project's own role files need no edit and the guard does not refuse them.
- On a call, `{to: <state>}` may name only the workflow's initial state, so it grants no more than `to-backlog`; any other state there is roles.grant.
- Plan: layer 1 T-3231 (the condition in the roles package); layer 2 T-3238 (guard, serve), T-3239 (role files, changelog), T-3240 (documents) together, each waiting on T-3231's condition and sharing no path. Layer 2 runs at once: three independent tasks.
- The builtin orchestrator triggers in serve name the baseline's review and backlog states, as the baseline role file does; reading a state by kind there is S-0742's.
