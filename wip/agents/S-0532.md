## Decisions

- Kept to MS-0219's split with S-0519: in `flai/internal/mcpserver/server.go` S-0532 changes only the `wait_for_events` and `inbox` descriptions and leaves `mcpserver.Options` and the permission hold alone; replied settled.
- The `agent` event goes in ADR-0211's event log, `.flai-cache/events.jsonl` (`inbox.LoggedEvent`, `AppendEvent`, `LoggedEvents`), not in a new `agent-events.jsonl` as the planner drafted: `CatchUp` already reads that log under the 50 cap, so a second log would duplicate the writer, the reader, and the merge. `why` and the other kind-specific values go in `Fields`. T-2271 gained `inbox/events.go` and its test in its touches; T-2277's body names the log.
- Event shape: kind `agent`; `to` one of `started`, `ended`, `failed`, `stopped`; `id`, `type`, `title` the item (the story, or the epic or story a planner planned), or the role's name with type `role` when a run has no item (orchestrator, analyzer, curator); `by` the agent's name, so that an agent is not told of its own runs; `fields.why` the journal's words, `fields.role` the run's kind.
- Plan, changed from the planner's: the serve tasks run one after another, not side by side, because they build and test one package, `flai/internal/serve`, and a half-done edit in one would fail the others' tests. Layers: 1 T-2271; 2 T-2274 (serve helper and limit), T-2275 (mcpserver, another package); 3 T-2272 (after T-2274); 4 T-2273 (after T-2272); 5 T-2276 (after T-2273); 6 T-2277 (after T-2276, so the docs describe what was built).
