# S-0322 flai task done commits every uncommitted file in the story worktree, so closing one task of a layer sweeps its siblings' work into its commit

## Context

Remediates I-0108 and I-0104 with the remedy the operator confirmed on TH-0337 (for S-0312, cancelled as a duplicate): `flai task done` commits the changed paths the closing task's touches cover, plus changed paths no other open task covers, leaves and lists the paths only another open task covers, and needs a message only when there is something to commit.

## Current state

All four tasks are done and committed on story/S-0322: ADR-0128 (T-1330), the commit step and its I-0104 and I-0108 tests (T-1328), the CLI, MCP, and host method (T-1331), and the docs with both issues closed (T-1329). `flai test` passes on every path changed. Criteria 2 and 3 are ticked. The trial merge conflicts with S-0339 only in `design/adrs/README.md` rows; agreed on MS-0017 that whichever is accepted second keeps both.

## Decisions

- The planner's four tasks are kept as drafted: they follow TH-0337's confirmed remedy and name every file the change reaches.
- Layers: 1. T-1330 (ADR and design), which settles what is committed; 2. T-1328 (commit step and the I-0104 and I-0108 reproduction tests), after T-1330; 3. T-1331 (CLI, MCP, host method) and T-1329 (docs, closing both issues), both after T-1328, sharing no path, so they run together.
- Layer 3's two tasks are closed with the worktree's own `scripts/flai.sh task done`, which carries T-1328's fix, rather than the installed flai behind MCP, which would sweep the sibling's files into the first close.
- T-1328: the sync refuses a worktree with uncommitted changes, so a close that leaves a sibling's paths would stop at the sync and never move the task. Its refusal no longer stops the run when the uncommitted paths are only the paths left; the close that leaves none syncs the branch. ADR-0128 says "a path left is not a failure: the run goes on", so this follows it; the sentence is added to ADR-0128 (written in this story, not yet on main) and to `design/system/flai-cli.md`.
- T-1328: paths are listed with `git diff --name-only -z HEAD` and `git ls-files --others --exclude-standard -z`; only untracked paths are staged, then `git commit -- <paths>`, since `git add -A -- <path>` fails on an already-staged deletion. Coverage reuses `workitem.NewHolds(...).Claim` and `workitem.PathsOverlap`. The JSON field for the paths left is `left`.
- T-1331: the text output prints `left for the other open tasks: <paths>`, and a sync refused only for those paths prints `sync: <branch> was not synced: <why>` rather than a stop report. The MCP tool's `message` is `omitempty`, so its schema requires only `task`; `task.done` drops a blank message rather than refusing it.
- T-1329: `template/CHANGELOG.md` gets a `1.0.81` heading, as S-0287 and S-0323 added theirs; the template's version is bumped at publish.
- Layer 3 was closed with the worktree's own flai: closing T-1331 committed only its seven files, listed T-1329's four as left, and did not sync; closing T-1329 then committed its files and the two issue closes, and synced. The fix holds on its own story.
