# S-0281 A story worktree has no flaiover/node_modules, so the close-out stops at the flaiover step until flaiover-install runs there

## Context

I-0080: `flai stream open` makes the worktree with `git worktree add`, which leaves out the git-ignored `flaiover/node_modules`, so close-out's `flaiover-test.sh` stops at `prettier: not found` and `flaiover-unit.sh` skips vitest without a word. The planner's fix, in the project's scripts rather than flai, stands.

## Current state

T-1088 in progress: `flaiover-install.sh --if-needed`, called by `flaiover-test.sh` always and by `flaiover-unit.sh` in a story worktree, is written; its reproduction is running in this worktree, which has no `flaiover/node_modules`.

## Next steps
1. Record T-1088's reproduction, commit, sync, move it to done.
2. T-1095: the scripts README, devex, and the operators' guide; close I-0080.
3. Close out through a verifier, then review.

## Decisions

- The plan is the planner's two tasks, kept as written: layer 1 is T-1088 (the scripts), layer 2 is T-1095 (the docs that describe them, and closing I-0080), which waits for T-1088 because it says in its words what T-1088 built. No two tasks run together.
- `--if-needed` compares `pnpm-lock.yaml` with `node_modules/.modules.yaml` by `find -newer`, as the scripts already compare `bin/flai` with the Go sources, and touches `.modules.yaml` after an install, since pnpm may leave it alone when nothing changed, so a second run does not install again.
- In that mode pnpm's output goes to stderr: `flai test`'s vitest tier reads `flaiover-unit.sh`'s stdout as the JSON reporter's.
- `flaiover-test.sh` installs wherever it runs, the main checkout too, since none of its steps runs without the dependencies; `flaiover-unit.sh` installs only where `CACHE_ROOT` differs from `ROOT`, and in the main checkout still skips while `node_modules` is missing, as T-1088 asks.
- The reproduction runs in this story's own worktree, which had no `flaiover/node_modules` when it opened, rather than a second scratch worktree: it is the case I-0080 describes.
