## Decisions

- The planner's tasks are kept as written: one chain in five layers, T-2449 → T-2450 → T-2451 → T-2452 → T-2453. Each waits on the one before because each run depends on what the one before set up or found: the stop and restart (T-2450) need T-2449's host and proof story; the first run's limitations (T-2451) are known before the Go run (T-2452); T-2453 sums both. No two tasks run together, so no task sub-agents: the work is watching runs and recording, which stays in this context.
- Proof stories S-0558 and S-0556, and option (a) for criterion 3 (close-out once by hand inside the layered image), as TH-0821 settled.
- Asked on TH-0836 for the host upgrade to 1.84.0 rather than running criteria 1 and 2 on 1.83.0: without S-0520's mounts (ADR-0253) a failure inside the container would not show which layer broke. Upgrading the host, rebuilding the images, setting `--login`, and moving the proof stories to ready are the operator's (ADR-0220).
- 2026-11-07, replan: S-0558 reached review six minutes after its start, before the operator's stop, and its agent asked nothing, so T-2450 could not run on it. T-2451 now waits on T-2449 alone and recorded S-0558's run. T-2450 waits on T-2451 and runs on S-0556's container, alongside T-2452. S-0556 also meets criterion 1's description, so criterion 2 is tried on it. - Criterion 1's card was verified through the state the card reads (`agent.status`, `~/.flai/serve/agents.json`, `agent.stream`), not by looking at the dashboard. Those records are the same shape for the container run as for a host run.
- `flai check` warned `issues.no-story` on I-0228 once this story bumped it, so I made its draft story S-0583 with `flai issue story`, under E-0029, as the conventions direct.
