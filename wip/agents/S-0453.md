- A thread not awaiting the agent reads `operator` whenever it awaits the operator, the agent's own threads included: an opener whose recommendation awaits confirmation (ADR-0090) reads `operator`, not `other`, which says more and still is not `you`.
- The operator is the manifest's `owner` or the thread's story's `owner` (ADR-0097's names), with `designer` when neither is named, as `inbox.designer` does.
- `.claude/agents/orchestrator.md` (T-1933) is written by this agent, not the sub-agent: Claude Code protects it.

The orchestrator keeps the set it took, named by `awaiting: "operator"`, less those it opened, answered last, with a pending recommendation, or last written by neither a story's agent nor a planner.
- `story_start` and `task_done` needed no code change: they already read the inbox with `Own` set to the story. Their help and `taskDoneDescription` still say the threads on other items are counted, which stays true of the ones awaiting the agent, so the reference is unchanged.
