## Decisions

- Plan: layer 1 is T-3437, the --at flag, which the other three describe or call. Layer 2 is T-3438 (template CI), T-3439 (this repository's CI and its design note), and T-3440 (user guide, CLI and workflow design). They share no path, so they run together. Each waits on T-3437 because it documents or calls the flag's behaviour.
- T-3437's touches: the verify_at lookup by point goes in flai/internal/workflow/suites.go, beside UsesSuiteKeys, rather than in workflow.go. A file with none of ADR-0312's keys reads as the baseline's (D-0669).
- flai test --at <point> refuses (exit 2) when the workflow names no suites for the point, as the baseline does for publish. A CI that calls it should fail loudly, not pass on nothing.
- flai test --at <point> --suite <s> runs suite s's tiers only when the point names s or all. That lets a CI job run one suite of the point, and refuses a suite the point does not name. --at with paths, --all, or a tier's name is refused.
- The MCP tool test gets no at field in this story. No criterion asks for it, and its file is outside the touches.
- T-3438: the template's CI installs flai with install.sh, the documented way, in place of go install. install.sh verifies the release's signature and checksum and needs no Go toolchain. The markdownlint action is dropped because the markdown tier runs the same lint. flai check --strict stays as a step of its own, since no tier runs it.
- T-3439: only system-flow-check.yml's smoke step switches, to flai test --at ci --suite smoke, because the smoke suite at ci is the smoke tier alone. flai.yml keeps its own commands: the race and macOS matrix, the golangci action, and the cross builds. flaiover.yml keeps its own: its flaiover tier is in the behavior suite, and no tier runs pnpm build. design/tech/ci.md records why for each job.
- T-3440's touches widened to docs/operators/runbooks/change-the-board.md, whose sentence saying nothing reads verify_at was no longer true.
