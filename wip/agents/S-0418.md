## Decisions

- **Re-scoped to ADR-0209 and ADR-0211 (TH-0749, option A).** The operator confirmed the orchestrator's recommendation at 2026-10-29T16:35:26Z. The `continuous` criterion is dropped, since ADR-0209 §1 rejects it. T-1741 is cancelled because S-0414 and S-0536 already read and check triggers. T-1746 is cancelled because no role is kept running. S-0418 gets `after: S-0536` and goes back to ready.
- **Plan, four layers (replanned 2026-10-29 against S-0536's and S-0417's code on main).** S-0417's role runs already record a trigger (`asked`) in `agents.json` and the activity log, so recording one is a small change to `role.go` that both starters need first.
  - Layer 1 holds T-1748: `RunRole` and the launcher's `role` take the trigger, and `startRole` is the start every trigger takes.
  - Layer 2 holds T-1743 (event triggers through S-0536's reason queue) and T-1744 (`roles.<name>.schedule` and its scheduler). Both wait for T-1748's `startRole`. They share no path, so they run together.
  - Layer 3 holds T-2340, which wires both into the serve loop in `serve.go`. It waits for both.
  - Layer 4 holds T-1751, the docs. It waits for T-2340 because it describes what T-2340 wires.
- **A role's event reasons coalesce over `orchestration.coalesce`.** ADR-0209 §2 gives the window only to the orchestrator, and a role file has no window of its own; adding a `roles.<name>.coalesce` key is scope the story does not name.
- **A role that takes items gets one run per item.** `RunRole` runs on one item at a time, so a batch of reasons is split by item; a role that takes none gets one run per batch.
- **Layer 2 ran in task worktrees.** T-1743 and T-1744 both compile in `flai/internal/serve`, so each sub-agent worked in its own worktree from `story/S-0418`, and their disjoint files were copied back before each close.
- **`flai manifest set` writes `roles.<name>.schedule`** (T-1744), beside `roles.<name>.agent`, so an operator sets it without a hand edit; T-1744's touches grew to `settings.go`, its test, and the settings index row a doc test requires.
- **A role's thread reasons are read per agent.** `inbox.CatchUp` reads as one agent, and a role that takes items writes as `<name>-<item>`, so `awaitingRole` judges each open thread for the role's agent on its item (T-1743's sub-agent).
- **A schedule runs a role on no item.** A role whose file takes items is logged as not started by a schedule rather than given a guessed item.
- **Docs beyond the criterion's list.** `flai role run`'s help, from which `flai-reference.md` is generated, `project-manifest.md`, and the backup runbook name the triggers, `roles.<name>.schedule`, and `role-reasons.json`. The changelog entry is under template 1.1.8, as 1.1.7 was published with S-0537 (D-0410).
- **T-2343 fixes I-0233's cause here.** The close-out's go-test tier failed the new loop test's cleanup: `Run` did not wait for a project's looks. The fix sits in `serve.go`, which this story owns, and its loop adds two looks; S-0543, I-0233's remediation story, may only need to confirm it.
- **Queued and scheduled starts are held, not dropped, by the budget.** D-0421: the hand start refuses a held budget, while the replanner and the schedules keep their due work. `startRole` leaves that refusal to `RunRole`.
- **Shared paths with S-0537 (MS-0232).** In `design/system/strategic-agents.md`, S-0418 keeps to the role-file sections. S-0537 changes `check.go`, `template/CHANGELOG.md`, `orchestrate_reasons.go`, and `docs/operators/settings.md` first, and S-0418 rebases onto them.
