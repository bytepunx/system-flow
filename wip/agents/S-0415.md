## Current state

## Next steps

1. T-1725: strategic pack reads topics and item kinds from role files, built-ins unchanged.
2. T-1726: check accepts defined roles.
3. T-1727: CLI and MCP prime dispatch to defined roles.
4. T-1728: design and docs.
5. Close-out, review.

## Decisions

- **Plan.** The planner's four tasks are kept, in four layers, not three: T-1725, then T-1726, then T-1727, then T-1728. T-1726 now waits for T-1725, because `internal/check` imports `internal/context`, so a half-done T-1725 would fail T-1726's tests. T-1727 waits for T-1725, whose pack and role list it dispatches to. T-1728 waits for both, since it describes what they built. Each task is short, so one runs at a time.
- **A built-in role with no file primes as before.** A project with no role file for `plan`, `orchestrate`, `analyze`, or `curate`, such as one made before ADR-0207 or a test fixture, keeps the Go topics and item kinds as its fallback. A file for the role, matched by its `role` verb, wins. S-0419's embedded baseline is where that fallback goes later. The unchanged tests in `strategic_test.go` use fixtures without role files and read `roleTopics`.
- **A role file that does not parse refuses `--role` for any role but `explore` and `verify`**, naming the file's finding, as criterion 3 says. The story's agent's own pack and the sub-agents' packs do not read role files.
- **`flai check` accepts the roles flai primes.** That is `story`, `explore`, `verify`, the four built-in verbs, and every verb a role file defines. Any other warns `conventions.roles`. The built-in verbs stay accepted without a file, so check and prime agree.
- **A defined role's agent is "the <name>"**, from its file's `name`. The built-in files give "the planner" and the rest, so the packs' text is unchanged.
