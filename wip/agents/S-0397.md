## Decisions

- **Contract.** `forge.Forge` gains `PullRequest(ctx, number)`, the pull request by number in any state: `FindPullRequest` sees open ones only, so "already merged" needs it. The merge stays `Merge` with the head the gate passed at.
- **Merged by someone else.** The kept status records the pull request's `State`. A story whose pull request is merged is not pushed again and gets no new pull request. The S-0395 gate passes over it.
- **Hand-off.** No CLI-to-serve channel exists. The request is a file under `.flai-cache/forge/merge/`, which a merge pass in flai serve polls every second. The pass renames it to taken, merges with its token behind the `forge` host action, and writes the answer. The CLI waits 30s for the take and 5m for the answer. No new listener and no new secret.
- **Remote branch.** It is deleted with `git push origin --delete` with the host's git credentials, as flai serve pushes it. A failed delete is reported but does not undo the merge.
- **Local main.** Fetch, then rebase any unpublished wip-only commits onto `origin`'s main in a temporary detached worktree, and move main there with `git reset --keep`. Uncommitted wip edits in the main checkout survive. `git rebase` there would refuse them, and `git stash` is shared by every worktree.
- **Local branch.** It is removed with `git branch -D`: a squash or rebase merge leaves it unmerged.
- **Plan layers.**
  - Layer 1: T-1633 (ADR) and T-1634 (contract, merge, hand-off in flai serve). No path in common.
  - Layer 2: T-1635 (accept path) and T-1636 (dashboard refusal). Both wait for T-1634's functions. They share no path. T-1636 needs only the refusal and the direct merge, which the child `flai accept` inherits from serve's environment, so it does not wait for T-1635. This changes the planner's plan.
  - Layer 3: T-1637 (docs). It waits for T-1633, T-1635, and T-1636, because it describes them.
