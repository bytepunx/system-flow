## Decisions

- Plan kept from the planner, three layers: [T-3403, T-3404], [T-3406 after T-3404, T-3408 after T-3403], [T-3411 after T-3406]. T-3406 waits for the behind check it calls. T-3408 documents what the ADR decides. T-3411 words the hold from the cause T-3406 records. No two tasks of one layer share a path.
- The ADR is ADR-0311, not 0309: S-0800 took 0309 and S-0798 took 0310. It refines ADR-0234 (the preflight) and ADR-0201 (flai.command checks with the tree's flai).
- Behind is judged by the running flai's build commit when the repository has it, else by its own release tag, else by the newest flai release tag merged in main: main is ahead when git rev-list counts commits reachable from main and not from that point under the manifest's flai sub-project path.
- The second check runs the manifest's flai.command in the main checkout, check --json unscoped, only when the in-process check found an error and the running flai is behind. Its answer counts only when its own version --json names a flai that is not behind main, so a flai.sh that fell back to the installed flai does not confirm the old finding.
- The Preflighter returns a report, the findings and the cause, so that PreflightHold records flai_behind; batch.go, land.go, and their test fakes change with it, so T-3406's touches widen to them. The flai check --json parser moves from taskdone into the check package so the preflight and task done share it.
- Not done here: holding an acceptance that changes a format the running flai reads (the issue's 'consider also'). The second check settles this repository's case, and a project without flai.command gets a hold that names the cause and the remedy. Recorded in ADR-0311's alternatives.
