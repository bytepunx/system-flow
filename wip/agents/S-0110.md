# S-0110 Two projects that remember the same MCP port both get it from flai host, and one crash-loops

## Context

The operator saw flai host (1.15.1) restart authstar's MCP server again and again. authstar's `.flai-cache/mcp-http.log` said `bind: address already in use` on 127.0.0.1:4243, which system-flow also remembers, since 2026-09-23 when 4243 was `flai mcp start`'s default. `mcpAddrFor` returned a remembered address as it was.

## Current state

Both tasks are done and the criteria are met, so the story goes to review.
- 3d230c4 (fix): a remembered address the host has already given another project is not given twice. The project moves to a free port, which it remembers, and the host logs `mcp address moved` with both ports. A new port also skips every port another registered project remembers, so one move cannot push the next project off its own.
- Tests: the address choice, and the host giving two projects one port each while leaving a third project's remembered port alone.
- Live: a scratch host with two scratch projects that both remembered 127.0.0.1:4263. Both servers ran and the log named the move. That run also exposed the cascade fixed in the same commit: a move could take a port another project remembered.
- `scripts/flai-test.sh` (lint, unit, integration, smoke) passes, as do `flai check --strict` and `lint-md`. The design and the operator guide are updated.

## Next steps
1. The operator reviews and accepts; the push releases the fix.
2. The operator restarts `flai host` on that release. authstar's and system-flow's servers both run, and the host log names which one moved and to which port. Any agent given the old address over HTTP must be given the new one.

## Decisions
- The second criterion named the operator's own host, which this session does not start. It was reworded to what was verified, the same collision on a scratch host. The operator's host confirms it after the release, as the story's Notes say.
- Which project keeps a shared port is whichever the host starts first. Both keep working, and only the moved one's agents need the new address, which the log gives.
