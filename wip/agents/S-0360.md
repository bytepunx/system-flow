# S-0360 flai serve checks each new claude version through the provider a project's agents name, so a host that reaches Claude only through a gateway is not reported failing

## Context

`flai serve`'s claude version check (`flai/internal/serve/claudecheck.go`, ADR-0106) always calls Anthropic. This story runs it through the provider the project's default agent names (ADR-0129, S-0350), and records the provider per version.

## Decisions

- The planner's two tasks stand: T-1426 (the check, `claudecheck.go` and its test) is layer 1, and T-1427 (`design/system/flai-cli.md`) is layer 2, after T-1426, because it describes what T-1426 settles. They share no path, but the document waits on the code's shape.
- The check keeps `harness.ClaudeCodeCheck`'s argv and takes its provider environment from the claude-code adapter's `Start` for a request naming the provider, with the key copied as `providerKeys` copies it. This keeps the change inside `flai/internal/serve`, and a story's start and the check share one source of the provider's variables.
- The provider is the project's default agent's (`agent.provider` in the manifest), resolved with `manifest.ResolveProvider` over the host's providers and the project's overrides, as `provide` resolves it for a start.
- T-1426 was worked by a task sub-agent. It reported no interference. As built: records are kept by version and then by provider, and an older single record per version reads as `anthropic`. The checker dedupes per claude and per provider. A skip for an unset key logs at warn and records nothing. A failure is told only to the projects whose default agent names that provider.
- T-1427 was widened, and I wrote it myself. Besides `design/system/flai-cli.md`, `docs/users/flai.md`, `docs/operators/index.md`, and `design/system/agent-adapters.md` describe the check too, and the failure thread's title now names the provider, so they would no longer be true otherwise. The planner's note that the thread's text was unchanged no longer holds. The widened claim overlaps S-0238 and S-0356 in other sections of those files; I said so on MS-0095 and MS-0096.
