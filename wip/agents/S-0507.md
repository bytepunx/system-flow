# S-0507 pilot, a Go binary in the bedrock image, is the container's entrypoint: it reads a start request, starts the inner harness through flai's adapters, relays its log, and resumes, as an ADR records beside the layered images

## Context

pilot is the container entrypoint for E-0029's agent images: it reads a start request on stdin, starts the inner harness through flai's adapter, relays its stdout, and resumes. S-0505 built the bedrock and claude-code images and `scripts/agent-container.sh`, which starts `claude` directly today.

## Current state

T-2153, T-2154, T-2161, and T-2168 are done. T-2174 is in progress: the bedrock image builds pilot and runs it as its entrypoint, and scripts/agent-container.sh feeds pilot a start request. Two trial runs of Claude Code (haiku, $0.02 cap) through pilot reached the HTTP MCP server and resumed the same session. That trial agent ran as agent-S-0507 and wrote this narrative's state once; this text replaces it.

## Decisions

- The planner's six tasks stand as drafted. Layers: 1 is T-2153 (ADR, docker.md) and T-2154 (harness fields), which share no path and run together; 2 is T-2161, which waits for T-2154's fields; 3 is T-2168, which waits for T-2161's request; 4 is T-2174, which waits for T-2168's binary; 5 is T-2178, which waits for T-2153's ADR and T-2174's images and edits docker.md after T-2153.
- The request's container fields are flat with JSON tags, as criterion 3 names them: `inner`, `mcp_url_env`, `mcp_token_env`, `cache`. One optional field is added, `mcp_host_env`, the variable holding the Host header the server listens on. The server's MCP SDK refuses a non-loopback Host, and a container dials `host.docker.internal` (S-0505's script sends the header for this reason).
- The claude-code adapter stays pure: with the container fields set, its `Start` names `<cache>/mcp.json` in `--mcp-config`, sets `CLAUDE_CONFIG_DIR` to `<cache>/claude`, and returns the file's content in a new `Start.Files`. pilot writes those files; `flai serve` gets none and is unchanged. The file names the token's variable as `${VAR}` rather than its value, so no token is written.
- `Request` gains `Resume`, set by pilot when its cache already records the session, so that a later start with the same session gets `--resume` as criterion 4 asks; the host's `resumes()` rule is otherwise unchanged.
- pilot records each session it started as an empty file `<cache>/pilot/sessions/<session>`, a harness-neutral mark, rather than reading Claude Code's own session files. A session that is not one file's name is refused.
- pilot's own diagnostics are plain `pilot:` lines on stderr, a start line and an end line, as criterion 5 and ADR-0212 ask, not slog events. They name neither the session nor argv, which carries the prompt.
- `scripts/agent-container.sh` takes the container's session from `FLAI_AGENT_SESSION`, not `FLAI_SESSION`: flai guard refuses a story's agent a command that sets `FLAI_SESSION` (ADR-0143), and the caller's own session is not the container's. The token reaches the container by `docker run -e NAME` from the script's environment, never in an argument or a file. Its prompt-file mode is gone: pilot builds the prompt from the request, as `flai serve` does.
- T-2174's by-hand check ran Claude Code twice on S-0507 through pilot, haiku with a $0.02 cap ($0.012 and $0.013): the `flai` server was `connected`, `${VAR}` in the MCP file expanded, and the second run resumed session 61625f83 with what the first knew. The trial agent ran as agent-S-0507 and wrote this narrative's state once, which was written again after it.
- pilot does not make `CLAUDE_CONFIG_DIR`: claude makes it when missing, and `scripts/agent-container.sh` links the login into it. Making it in pilot would put claude's layout in pilot.
