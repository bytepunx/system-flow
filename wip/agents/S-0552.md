## Decisions

- Plan: layer 1 is T-2370 (coalesce window), T-2371 (an operator's acceptance enqueues), and T-2372 (verifications per landed story), which share no file and run together, each in its own task worktree because they build the same packages. Layer 2 is T-2373 (the dashboard panel shows the window), which waits for T-2370's `Queue` field, and T-2374 (ADRs and docs), which waits for all three to describe what they did.
- `merge_queue.coalesce` defaults to 3m, which is "a few minutes" against a verification of about ten. The window runs from the earliest enqueue among the stories a batch would pick. `batch_max` pending stories start the batch at once. The 30-second queue tick is precise enough against a window of minutes, so flai serve is not changed.
- While the queue is held, or cannot batch, an operator's acceptance lands by hand as ADR-0221 says. Holding the queue is the operator's way to land outside it.
- S-0552 narrowed its touches to free the stories it held: no `flai/internal/serve`, no `system-flow.yaml` (the default suffices), and no `design/system/strategic-agents.md`. It shares `flai/cmd` with S-0546 and S-0547 (MS-0261, MS-0262) and `flai/internal/mergequeue` with S-0549 (MS-0263), and splits the manifest files and `docs/operators/index.md` with S-0548 by section (MS-0253).
- The dashboard's display of the window is in the goal but not the criteria. T-2373 does it because it is small.
