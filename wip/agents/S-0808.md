## Decisions

- Kept the planner's tasks and layers: (1) T-3433, the one answer to which suites the acceptance needs; (2) T-3434 (preview, cmd) and T-3435 (mergequeue), which both call T-3433's functions and share no file, run together, T-3435 in its own worktree task/T-3435 because preview imports mergequeue, so a half-done edit there could fail T-3434's builds; (3) T-3436, the documents, after both, since it describes their words.
- AcceptSuites(w, typ) returns *workflow.Suites: nil when the acceptance needs no suite (no accept transition or no verify), All for all, else the names. A workflow file with none of ADR-0312's keys reads as the baseline's, all (D-0669).
- The new refusal, code verify_suites, fires only for a suite the acceptance names in a list (never under all) that the last report's run did not select: its Suites is non-nil and lacks it, or there is no report. Under all it never fires, so the baseline's gates answer as before (criterion 4). A suite the run selected but has no entry for is one whose tiers the paths do not select, and passes, as S-0807's move rule reads it (design/system/workflow.md § What the move and the close-out read). The way out is the close-out job, which in review runs the suites the acceptance needs (NeededSuites).
- The merge queue judges a story's verify per suite from SuiteRuns when the acceptance names suites, counting a tier left to the queue as held, since the batch runs it (ADR-0174, D-0672).
