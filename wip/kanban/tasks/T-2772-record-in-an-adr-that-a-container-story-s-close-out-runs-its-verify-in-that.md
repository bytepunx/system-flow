# T-2772 Record in an ADR that a container story's close-out runs its verify in that container, and what still runs on the host

## Work

Write ADR-0272 with `flai adr new`, refining ADR-0229 and ADR-0253, on the remedy the plan's thread settles. Today `flai/internal/serve/verifyjob.go` (`command`, `runCloseOut`) runs `sh scripts/close-out.sh <story>` from the story's worktree with `exec.Command` on the host, whatever the story's harness, and `flai/internal/serve/checks.go` (`runOneCheck`) runs the operator's checks there too. ADR-0253 says the close-out runs inside the container, while `docs/users/flai.md` says it cannot (S-0520). The ADR settles that.

- **Decision.** For a story whose agent runs on the `container` harness, the close-out job runs `flai verify <story> --record-issues` in a container from the story's image, with the story's mounts. Those are the worktree, the two git mounts, `wip/` and `system-flow.yaml` read-only, and `.flai-cache/verify`. So the worktree's scripts and the test tiers they select run inside. The commit, `--sync-only`, and the sync rounds run on the host through flai's own code and git, never through a script from the worktree. They take the git dir from the main checkout, not from the worktree's `.git` file or its registration's `config.worktree`, which the container can write, and run only the main checkout's hooks. The operator's checks for such a story run in the same container. A story on any other harness keeps today's job.
- **What still runs on the host, by design.** The merge queue's batch tiers and an acceptance's `fix_command` run in the main checkout after an acceptance decision. `flai test` and `flai verify` run there when the operator runs them by hand. A story's agent on a host harness runs there anyway.

Needs no earlier task: it records the decision the code tasks build.

## Done when

- The ADR is accepted and listed in `design/adrs/README.md`, generated by flai.
- Its decision names the job's container command, what stays on the host, and why.
- Its Alternatives name the remedy the thread did not take: the boundary documented alone, or the whole close-out run inside.
- `flai check --strict` and the markdown lint pass on it.
