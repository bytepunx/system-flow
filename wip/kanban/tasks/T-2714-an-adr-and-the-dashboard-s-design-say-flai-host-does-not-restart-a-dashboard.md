# T-2714 An ADR and the dashboard's design say flai host does not restart a dashboard whose published port another process holds

## Work

Write the decision with `flai adr new`, refining ADR-0062 (`refines` in its front matter, and accepted with `flai adr accept`): flai host's watch has a fourth look, `port-held`, when docker runs the recorded container, `docker port <name> 3000/tcp` publishes nothing for it, and the host port the record's `publish` names answers all the same. The watch does not restart on it, since a restart cannot win the port back: it logs the state once each time it enters it, at error, with the holder; the status commands say what holds the port and how to free it; and the watch starts the dashboard on its own once the holder is gone and two looks find it gone or not answering. Name I-0243 as the context: a container Docker no longer lists, whose `docker-proxy` kept `0.0.0.0:4242`, made every new container's port map empty and drew 1,697 restarts in six days. Say why the holder is found by the `docker-proxy` command line (`/proc/<pid>/cmdline` is readable by any user, where `ss -p` and `/proc/<pid>/fd` need root for a root process), and what is said where it cannot be found.

Then change the watch bullet of `design/system/flaiover-dashboard.md` § Runtime ("flai host restarts a dashboard that is gone or not answering …") to name the fourth state and link the new ADR.

The ADR's file is new: `flai adr new` gives its number and name, and the story's `design/adrs` touch covers it. This task waits for nothing: it records the decision the code tasks build, and their `## Work` states it already.

## Done when

- A new accepted ADR refines ADR-0062 with the `port-held` look, the no-restart rule, how the holder is found, and I-0243 as its context; `design/adrs/README.md` is regenerated by flai.
- `design/system/flaiover-dashboard.md` § Runtime names the state and links the ADR, with its `updated` bumped.
