# components

Supporting files for the project's components, kept in the repository beside the design. Today that is one examples file per component: its examples, named sets of its props, which flaiover's Components page lists and loads into its props panel, so a component that renders only with data can be shown without typing its props each time. [ADR-0164](../adrs/0164-a-component-s-examples-are-named-sets-of-props-in-one-json-file-per-component.md) records the decision, and [component-library.md § Examples](../system/component-library.md#examples-s-0443) describes the format.

A component's examples file is `design/components/<sub-project>/<path>`: the sub-project's `name` in `system-flow.yaml`, then the component's path in the sub-project with `.svelte` replaced by `.examples.json`. `flaiover/src/lib/components/Card.svelte` has its examples in `design/components/flaiover/src/lib/components/Card.examples.json`. The file is JSON, one of the two exceptions to "Everything is markdown", and holds one key, `examples`, an array in the order the page lists them; each example has a `name`, its `props`, and optionally the `theme` (`light` or `dark`) and the `width` in CSS pixels the page shows it at.

The Components page writes a file when the operator saves an example, through flai's `file.save`, on the main branch or on the story the page shows, creating the file and its folders for a component's first example. A story's agent keeps the examples of the components it changes true: one that renames, moves, or removes a component, or changes its props, moves or edits its examples in the same story. `flai check` reports `components.examples` for a file that does not parse or fit the format, an example whose props do not fit its component, and a file whose component does not exist, and `flai check --strict` fails on it. Convention: [documentation.md](../conventions/documentation.md).
