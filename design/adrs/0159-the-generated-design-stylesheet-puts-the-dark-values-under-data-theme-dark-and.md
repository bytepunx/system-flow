# ADR-0159 The generated design stylesheet puts the dark values under [data-theme='dark'] and makes Tailwind's dark variant follow the same attribute, with a header naming flai design css --write and the token file

## Context

[ADR-0152](0152-agents-build-ui-from-a-tailwind-v4-stylesheet-flai-generates-from-the-tokens.md) has flai generate a Tailwind v4 `@theme` stylesheet from the design tokens, at the path the manifest's `design.stylesheet` names, and left to S-0385 how that stylesheet selects the dark values. The token file holds light values and the resolver's `theme` modifier with a `dark` context (ADR-0146). Tailwind v4's `@theme` holds one value per variable, and its utilities read the variables with `var()`, so overriding a variable under a selector changes every utility below it. Tailwind's own `dark:` variant follows `prefers-color-scheme` unless the stylesheet redefines it.

Three ways select the dark values: a media query on the system preference, a class such as `.dark`, or an attribute. The dashboard, the Design page's preview, and `flai design css` already use `[data-theme='dark']`.

## Decision

The generated design stylesheet puts the dark values under `[data-theme='dark']` and makes Tailwind's `dark:` variant follow the same attribute, with a header naming `flai design css --write` and the token file. The file is, in order:

1. A comment header saying the file is generated by `flai design css --write` from the token file it names, and not to edit it.
2. `@custom-variant dark (&:where([data-theme='dark'], [data-theme='dark'] *));`, so that a project's `dark:` utilities follow the same attribute as the tokens.
3. The `@theme` block of the light values.
4. A `[data-theme='dark']` rule overriding each variable whose dark value differs, left out when none does.

A project switches theme by setting `data-theme="dark"` on an element, usually `html`. Following the system preference is the project's script's to do, by setting the attribute from `matchMedia('(prefers-color-scheme: dark)')`.

`flai design css --tailwind` prints the same block without the header, so what it prints and what `--write` writes cannot differ.

## Consequences

- One selector everywhere: the dashboard, the preview, `flai design css`, and every project's generated stylesheet.
- `dark:` and the token values cannot disagree, since both follow the attribute.
- A project that wants the system preference with no script cannot have it from the generated file alone. If one asks, a manifest setting can choose the selector later.
- The UI's own stylesheet imports the generated file after `@import "tailwindcss";` and must not define its own `dark` variant.

## Alternatives considered

- **A media query.** Needs no script, but the operator cannot preview or force a theme, and it differs from the dashboard and the preview.
- **A `.dark` class.** Tailwind's documented example, but a second convention beside `data-theme` for no gain.
- **A selector chosen in the manifest.** Deferred until a project asks for it.
