# ADR-0202 flai gains a docker-agent harness adapter that runs a story's agent as a Docker Agent team mixing a Claude subscription, through its claude-code harness, with local models through Docker Model Runner or Ollama, under ADR-0130's contracts

## Context

The operator asked S-0496 whether flai could use Docker Agent to run a mixture of hosted and local models: Anthropic's Claude on a subscription beside models served on the operator's machine by Ollama or Docker Model Runner. Today a story's agent is one harness, `claude-code`, run headless by `flai serve` with the operator's own `claude` login or a provider the host names ([ADR-0129](0129-a-story-s-agent-names-a-provider-beside-its-harness-and-model-and-the-providers.md)); its sub-agents, the explorer, the verifier, and the task sub-agents, run inside Claude Code on the model each role names ([ADR-0065](0065-a-story-s-agent-carries-a-model-per-sub-agent-role-and-claude-code-runs-each.md)), and every model call goes to the same provider. A local model cannot stand in for one role today, because Claude Code speaks only Anthropic's API, and the provider is one per session.

Docker Agent, formerly cagent, is Docker's YAML-defined team of agents, a root and its `sub_agents`, each with its own model, instruction, and tools, run by one binary, `docker agent`, shipped with Docker Desktop 4.63 and later and installed on this host as v1.124.0. The survey in [agent-adapters.md](../system/agent-adapters.md#docker-agent), made on 2026-10-25, finds that it meets each of flai's concerns in a shape ADR-0130's contracts can take:

- It starts and resumes headless (`--exec`, `--json`, `--session <id>` where a new ID is created on first use, as Claude Code's `--session-id`), takes `flai mcp` as a stdio MCP toolset, and runs in a working directory or a worktree of flai's choosing.
- Its `pre_tool_use` hook sees every agent's tool calls with `agent_name`, so one `flai guard` can tell the root's calls from a sub-agent's, which Goose's cannot; its `permission_request` hook answers a prompt allow or deny within its timeout, the shape of `permission_prompt`'s hold-and-ask; both are set from the agent file or the command line, and global hooks cannot be suppressed by an agent file.
- A sub-agent names its own model on its own provider: `anthropic`, `openai`, `dmr` (Docker Model Runner, a llama.cpp endpoint), an `ollama` alias, or any OpenAI-compatible endpoint by `base_url`, `api_type`, and `token_key`, the same split as ADR-0129's `providers` entry. So one team can hold a Claude root and local sub-agents, or a local root and a Claude sub-agent.
- Its Anthropic provider is an API key or workload identity federation, never a subscription. The subscription reaches it only through its `claude-code` harness, an agent that delegates to the `claude` CLI on the operator's own `claude auth login --claudeai`, which Docker Agent never reads or stores, run with `--dangerously-skip-permissions`; a harness agent's own toolsets are ignored, and a harness agent can be a sub-agent of a model-backed root.
- Usage reaches a hook: `after_llm_call` carries `usage`, `cost`, `model_id`, and `agent_name`, sub-sessions included; sessions keep cumulative tokens and a cost priced from the models.dev catalogue, $0 for a model it lacks, with no usage command outside the TUI; a harness agent's tokens are what its CLI reports, which Claude Code does.

## Decision

flai gains a `docker-agent` harness adapter, under [ADR-0130](0130-every-harness-meets-flai-through-neutral-contracts-an-adapter-s-capabilities-a.md)'s contracts, that runs a story's agent as a Docker Agent team mixing a Claude subscription, through Docker Agent's `claude-code` harness, with local models through Docker Model Runner or Ollama.

- `harness: docker-agent` on a story's agent, the project's default, or a strategic agent names the adapter; the host sets its program and arguments with `flai serve agent harness docker-agent`, as for `claude-code` ([ADR-0038](0038-flai-serve-starts-a-story-s-own-agent-through-an-adapter-with-what-the-operator.md)).
- `Start` writes a team file per run under `.flai-cache` from the story's agent: the story's agent is the root; each role under `roles` (`explore`, `verify`, and the task sub-agent) is a `sub_agent` with that role's definition from `.claude/agents/` as its `instruction` and its model as `provider/model`, the role's `provider` an ADR-0129 entry mapped onto Docker Agent's `providers` (`base_url`, `api_type`, `token_key` the entry's `key_env`); `flai mcp --agent <name>` is an MCP toolset of every model-backed agent; `flai guard` is the `pre_tool_use` hook and `permission_prompt`'s hold-and-ask the `permission_request` hook, both passed on the command line so no agent file is trusted for them; the run is `--exec --json --session <flai's session ID> --working-dir <worktree> --safety restricted`, with the story's prompt on standard input, and `--session` resumes it after a thread is answered.
- A model named `claude-code` on the root or a role makes that agent a `harness: {type: claude-code}` agent with `effort` from the agent's `config`: Claude on the operator's subscription, with the CLI's own tools, `CLAUDE.md`, `.mcp.json`, and `.claude/settings.json` hooks; a model named `dmr/<model>`, `ollama/<model>`, or `<provider>/<model>` makes it a model-backed agent on that provider. The mixture the operator asked for is a `claude-code` root with `dmr` or `ollama` sub-agents, or a local root with a `claude-code` sub-agent for the work that needs it.
- `Capabilities` are `Resume`, `Guard`, `Ask`, `RoleModels`, and `StrategicAgents` true, and `Cost` true only for the model-backed agents, read by a `Reader` of the `--json` stream and the `after_llm_call` payloads the adapter's hook writes to the log, with `priced_by` naming the catalogue ([ADR-0132](0132-a-story-s-cost-comes-from-its-provider-s-spend-log-when-it-has-a-provider-from.md)); a `claude-code` harness agent's tokens are read as Claude Code reports them.
- The protected list ([ADR-0106](0106-a-story-whose-branch-changes-a-path-claude-code-protects-is-accepted-by-the.md)) gains Docker Agent's own files: the team file, `~/.config/cagent/`, `hooks.d/`, and any `.agents/` or agent YAML in the repository, since each changes what an agent may do.
- The first story is a spike with no adapter: a hand-written team file with a `claude-code` root, one `ollama` or `dmr` sub-agent, `flai mcp` as a toolset, and `flai guard` as `--hook-pre-tool-use`, run with `--exec --json` against this repository, which settles the facts below the survey leaves open before the adapter is built.

## Consequences

Trade-offs and caveats:

- Two agent loops, one inside the other, where there is one today. A `claude-code` harness agent is Claude Code run by Docker Agent: flai's guard runs twice on its calls, once as Claude Code's `PreToolUse` hook from `.claude/settings.json`, once as Docker Agent's `pre_tool_use`, but only the inner one sees Claude Code's tool names and `agent_id`, and the outer one sees a single `transfer_task` to the harness, so the guard's view of a Claude sub-agent's calls stays Claude Code's; flai's measurement of its turns ([ADR-0116](0116-when-flai-measures-a-story-s-usage-from-its-logs-it-classifies-each-turn-of-the.md)) depends on Claude Code's stream-json reaching the log through Docker Agent, which the survey leaves to check.
- The subscription reaches Claude only through the unmodified `claude` binary, which is what Anthropic's terms allow an end user to sign in to with their own plan; Docker Agent's own Anthropic provider needs an API key, billed per token, and since 2026-04-04 a subscription's OAuth token no longer works in a harness that calls the API itself. A team that puts Claude on a model-backed agent, to give it Docker Agent's tools and hooks, pays for the API; a team that keeps the subscription keeps Claude inside the `claude-code` harness, with Claude Code's tools and Claude Code's permission model, not Docker Agent's. Anthropic's advertised plan limits assume "ordinary, individual usage of Claude Code"; a team that fans out across local sub-agents and brings the results back to one Claude root is a lighter use of the plan than today's all-Claude session, not a heavier one.
- Cost figures lose one source of truth. Docker Agent prices model-backed calls from the models.dev catalogue, $0 for a local or unknown model, and a `claude-code` harness agent's cost is what Claude Code says; a local model's cost is the machine's, which no log carries. `flai stats` would read two `priced_by` sources per story and report local tokens as spend of zero.
- The adapter's value is in the roles, and a role on a local model is only as good as the local model's tool calling: the survey notes that not every local model supports function calling, that context windows are smaller, and that a 7B model wants 8 to 16 GB of RAM. The explorer, which reads and reports, is the role most likely to work on a local model; the verifier, which reads a diff against criteria, is the next; a task sub-agent that edits code is the last.
- `flai serve` gains a second harness to keep in step with its releases: Docker Agent's schema is at version 15 and migrates older files, its hook payloads and `--json` events are documented in part, and the `cagent` to `docker agent` rename is recent. The adapter is one more surface for `flai check` to probe, as `permission_prompt` is probed against each new Claude Code ([ADR-0106](0106-a-story-whose-branch-changes-a-path-claude-code-protects-is-accepted-by-the.md)).
- A project without Docker Desktop has `docker agent` only as a standalone binary and Docker Model Runner only as Docker Engine's plugin; Ollama needs neither, and is the local path the adapter should support first. On this host Docker Model Runner is not enabled and Ollama has no model pulled.

Limitations:

- A `claude-code` harness agent's `toolsets` are silently ignored, so it cannot be given `flai mcp` through Docker Agent; it reaches flai through `.mcp.json` as today, and its MCP server runs the installed `flai` from `PATH`, not the one `flai serve` chose. Whether a harness agent may have `sub_agents` of its own, so that Claude Code's own roles and Docker Agent's can nest, the documentation does not say.
- The `--json` event schema is undocumented beyond example event names, and whether it carries tokens and cost is unverified; `after_llm_call` hooks are the documented path, which puts usage in a hook's stdin rather than the harness's log, so the adapter writes its own log. There is no usage command (docker/docker-agent issue #3943, open).
- `--exec` answers every unmatched `ask` with no; a `permission_request` hook is the only approver, bounded by its `timeout`, and how it interacts with a `pre_tool_use` hook's `ask` headless is unverified. The four-minute bound of [ADR-0124](0124-permission-prompt-holds-a-write-at-most-four-minutes-then-refuses-it-and-leaves.md) becomes whatever timeout the adapter sets on the hook.
- Docker Agent's own permission rules match tool names and argument globs, not paths as Claude Code's protected list does; the protected paths are the guard's to deny, as [ADR-0131](0131-a-harness-without-a-guard-hook-runs-a-story-s-agent-but-none-of-its-roles.md) foresaw for a harness whose vocabulary flai cannot read.
- Docker Agent sessions live in `~/.cagent/session.db`, one store per OS user, outside the project; `flai serve` must name `--data-dir` under `.flai-cache` to keep a project's sessions with the project, as it keeps its worktrees.

Security concerns:

- The `claude-code` harness runs `claude` with `--dangerously-skip-permissions`: Claude Code's permission prompts, and with them `permission_prompt`'s hold-and-ask on a protected write, are off inside it, as Docker's own page warns. Only the hooks in `.claude/settings.json`, where `flai guard` runs, still stand in Claude Code, and Docker Agent's `pre_tool_use` hook does not see inside the harness. Until a spike shows that `flai guard` refuses a protected write from inside the harness, a `claude-code` harness agent must be treated as a harness that cannot ask, which ADR-0131 refuses to start unless `auto-approve` is on or the host's arguments deny the protected paths.
- Docker Agent's permissions and shell classifier are enforced client-side and are called defense in depth, not a boundary; its `--sandbox` runs the session in a VM through the `sbx` CLI with a default-deny network allowlist, but does not carry `claude` or its login into the sandbox, so the subscription path cannot be sandboxed by Docker Agent alone. Isolation is `--worktree` and flai's own worktree, as today.
- Telemetry is on by default and sends command names, tool names, agent names, model types, token counts, and estimated costs to Docker; `flai serve` must set `TELEMETRY_ENABLED=false` in every agent it starts, and say so in the operator documentation.
- `docker agent setup` writes provider keys to `~/.config/cagent/.env` in plain text, mode 0600; flai's host keeps only `key_env` names ([ADR-0129](0129-a-story-s-agent-names-a-provider-beside-its-harness-and-model-and-the-providers.md)) and must pass keys through the child's environment, never through that file or the team file, and the team file under `.flai-cache` must hold `token_key` names only.
- Global hooks in `~/.config/cagent/config.yaml` and `hooks.d/` run for every agent on the host and cannot be suppressed by an agent file: a hook planted there runs inside every story's agent. The adapter's protected list covers them, and `flai serve`'s start log should name the hooks in force.
- `model` hooks send tool arguments to an LLM judge, `redact_secrets` is best-effort, and a local model's prompts stay on the machine while a `dmr` or `ollama` endpoint on another host's `base_url` sends them there over plain HTTP by default.
- Author-declared defaults in a shared agent file can set `--safety autonomous`; flai writes the team file itself and passes `--safety` on the command line, and never runs an agent file pulled from a registry.

What becomes easier: a local model takes a role without a gateway, a story's roles may differ in provider, and an operator without an API key keeps the subscription for Claude and a free local model for the rest. What becomes harder: two loops to guard and measure, two sets of release surfaces to probe, and cost figures from two sources. What is given up until the spike reports: nothing is built by S-0496.

## Alternatives considered

- Claude Code alone over a gateway that fronts a local model (LiteLLM with an Ollama deployment, [ADR-0129](0129-a-story-s-agent-names-a-provider-beside-its-harness-and-model-and-the-providers.md)): one provider per session, so a local model replaces Claude for the whole story rather than taking a role, and Claude Code's Anthropic-shaped requests to a local model lose tool calling in translation; it does not mix.
- Codex CLI or OpenCode as the second harness, as the S-0339 finding recommends: each gives a local model a whole session on an OpenAI-compatible endpoint, with their own sub-agents on their own models, but neither mixes a Claude subscription in, since the subscription reaches Claude only through `claude`.
- A loop of flai's own: mixes anything, but rebuilds the tool loop, the sessions, the hooks, and the sub-agents Docker Agent already gives; kept as the later option ADR-0130 keeps it.
- Docker Agent as the only harness, Claude through its API-key provider: pays per token for what the subscription covers today and loses Claude Code's prompt caching and tools; refused for the Claude agent, kept for a project that has an API key and no subscription.
