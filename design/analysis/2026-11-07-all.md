`flai/internal/serve/verifyjob.go:290-291`: the close-out job's command is `sh scripts/close-out.sh <story>` from the story's worktree, run by `flai serve` on the host ([ADR-0229](../adrs/0229-the-close-out-runs-as-a-flai-serve-job-the-story-s-agent-asks-for-with-the.md): "The close-out runs as a job of flai serve in the story's worktree"). A story's agent writes its worktree, and a container harness ([ADR-0203](../adrs/0203-flai-may-run-a-story-s-agent-in-a-container-from-a-baseline-image-it-builds.md), [ADR-0253](../adrs/0253-a-container-that-runs-a-story-s-agent-mounts-the-main-checkout-s-wip-and-system.md)) mounts that worktree read-write by design, so what the container keeps off the host runs on it at the next close-out as the operator. [ADR-0247](../adrs/0247-a-strategic-agent-s-container-mounts-the-main-checkout-read-write-at-its-host.md) records the sibling path for strategic agents: "`.git/config` can name commands git runs on the host, such as `core.fsmonitor` or `core.sshCommand` ... a write through the shell is not seen", which I-0257 holds open. `.claude/settings.json`, which configures the guard hook, is in the same read-write mount (`flai/internal/harness/container.go:276-277`).

This is how the system is designed: the tests are the project's and must run somewhere. The risk is in what the container harness is taken to promise. `design/system/strategic-agents.md` § In a container (S-0509) and the ADRs above say what is mounted; none says that the host is protected from the worktree's scripts, and nothing in `docs/operators` warns that it is not. **Impact.** No instance observed. Estimated time lost per cycle: none; the cost is a boundary documented wider than it is.
