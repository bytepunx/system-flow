## Finding 1: the curator's unlinted digest entries in the main checkout refused every acceptance for three days

**Severity: high.** Issue: [I-0411](../issues/I-0411-the-acceptance-s-lint-fix-refuses-every-acceptance-while-the-curator-s.md).

The serve journal holds 20 orchestrator refusals between 2026-11-15T00:52:10Z and 2026-11-18T13:22:59Z that read `<S-nnnn> cannot be accepted: the main checkout's uncommitted files hold lint the fix of the markdown tier could not fix`, naming 16 stories (S-0738, S-0739, S-0742, S-0743, S-0744, S-0747, S-0789, S-0792, S-0807, S-0809, S-0810, S-0812, S-0817, S-0825, S-0839, S-0843). Each names digest entries the curator wrote in the main checkout and nobody committed: `design/digest/D-0671-…md:20 error MD028/no-blanks-blockquote` in six of them, and `D-0523`, `D-0635`, `D-0653`, `D-0662`, `D-0669` in others. On 2026-11-18 alone, five stories that had just passed their close-outs were refused this way within three hours (S-0812 09:17, S-0809 09:20, S-0839 10:03, S-0843 11:07, S-0810 11:24), and the orchestrator opened TH-1309, TH-1310, TH-1311, and TH-1314 asking the operator to "Fix line 20 of `design/digest/D-0671-…md` in the main checkout". `waiting.longest[]` shows what followed: S-0809 273,530 s (76 h), S-0810 280,637 s, S-0812 291,495 s, S-0811 291,953 s, and S-0834 296,845 s in review, each from 2026-11-18 to 2026-11-21, when the operator's session committed the file with S-0809's acceptance (`a68d900d1`). `waiting.weeks[]` W47: `review.total_seconds` 1,808,331 (502 h) over 50 stories, `mean_seconds` 36,167, against 9,496 in W46 and 2,098 in W45.

The design says the opposite of what happened. `design/system/workflow.md` § What waits on an acceptance: "Uncommitted files on main that the story does not change, a rebase it cannot settle, which goes back to the story's agent, and a thread of its own, which it resolves, no longer wait for the operator ([ADR-0189](../adrs/0189-the-orchestrator-s-acceptance-lands-on-a-dirty-main-as-the-merge-queue-s-does.md))", and `every acceptance commits the main checkout's uncommitted files under wip, design, and the shared paths` ([ADR-0248](../adrs/0248-every-acceptance-commits-the-main-checkout-s-uncommitted-files-under-wip-design.md)). [ADR-0140](../adrs/0140-flai-accept-refuses-an-acceptance-whose-files-a-tier-with-a-fix-command-still.md) is the rule that won: "At preflight, before anything changes. It fixes the main checkout's uncommitted files, then checks them. A failure refuses", and its Consequences say so: "Uncommitted files in the main checkout that fail the check block every acceptance until they are corrected or committed." The two rules together make the curator, which writes digest entries in the main checkout and commits nothing ([ADR-0191](../adrs/0191-the-digest-is-one-markdown-file-per-entry-under-the-design-folder-s-digest.md), [ADR-0196](../adrs/0196-the-curator-runs-behind-the-curate-host-action-and-takes-in-what-the-archive.md)), able to stop every acceptance with one blank line in a blockquote. [ADR-0318](../adrs/0318-flai-digest-new-and-edit-refuse-an-entry-whose-markdown-the-project-s-lint.md) (2026-11-17, S-0836) closes the source for new entries: `flai digest new` and `edit` now refuse an entry the lint rejects. It does not reach the entries already on disk, nor the ones the curator's `absorb` and `compact` rewrite: today `git status` lists 26 modified digest files uncommitted in the main checkout, and `markdownlint-cli2 0.20.0` over them, run as the acceptance's fix step runs it, gives `Summary: 1 error(s)`, `design/digest/D-0653-…md:20 error MD028/no-blanks-blockquote`. The next acceptance that is not the merge queue's landing is refused by it, as the five were on 2026-11-18.

**Impact.** Five stories held 273,530 s to 296,845 s in review, their epic's `after` chain behind them (S-0808 and S-0813 to S-0815 are E-0034's, S-0808 ready since 2026-11-17), and an in-progress lane idle: `concurrency.share[0]` 0.547. Estimated time lost per cycle: 76 h, the shortest of the five waits.

## Finding 2: an expired login restarted the orchestrator 666 times in fourteen hours, and nothing told the operator

**Severity: high.** Issue: [I-0412](../issues/I-0412-flai-serve-restarts-the-orchestrator-every-minute-while-the-harness-s-login-has.md).

The serve journal records 697 orchestrator runs in the window that `ended, failed: ended (exit 1)`, 666 of them between 2026-11-17T17:24:45Z and 2026-11-18T07:07:39Z, one every 73 seconds for 13.7 hours (49 an hour, every hour). Each run's log under `~/.flai/serve/agents/sf-orchestrator-20261117T17…` to `…20261118T07…` ends the same way: `"text":"Failed to authenticate: OAuth session expired and could not be refreshed"`, `"terminal_reason":"api_error"`, `"duration_ms":90`, `"total_cost_usd":0`. Each start was for the same reason, `planned S-0822, wrote T-3520, T-3521, T-3522`, which no run ever acted on, so `flai serve` started the next. The journal holds no hold, no thread, and no notice in those hours: the first entry that says anything else is the 07:33 push. The orchestrator's activity document counts 240 entries on 2026-11-17 and 54 on 2026-11-18 and shows none of this, since a run that fails before its first tool call logs nothing ([ADR-0079](../adrs/0079-the-planner-the-orchestrator-and-the-analyzer-each-log-their-activities-in-one.md)). The same login served the stories' agents: 3 `agent failed` entries fall in the span.

[ADR-0209](../adrs/0209-the-orchestrator-runs-for-a-reason-and-ends-started-by-flai-serve-on-the-events.md) decided the shape for one failure: "flai serve holds every strategic and story start while the host's budget is exhausted, circulating the exhaustion as an event instead of retrying each minute". [ADR-0214](../adrs/0214-a-curator-run-that-ends-on-the-harness-s-usage-limit-is-recorded-failed-with.md) holds the curator on the harness's usage limit and raises a retry that fails again "to the operator once on a thread". [ADR-0108](../adrs/0108-flai-serve-restarts-a-story-s-agent-that-ended-with-its-story-in-progress-up-to.md) restarts a story's agent "up to `agent.auto_restarts` times, then asks the operator on a thread". An authentication failure of the harness matches none of the three: it is not a budget, not a usage limit, and the orchestrator has no restart count, so a run that cannot start is started again on the next look, as a run that ended would be. The earlier loop of 2026-10-26T12Z to 2026-10-28T17Z, about 270 runs an hour for two days, is the same pattern before this window; the report of 2026-11-07 saw its wait on TH-0668 but not its cause.

**Impact.** The orchestrator accepted, ordered, and answered nothing for 13.7 h, and the operator learned of it from the journal alone. Money: none (`total_cost_usd` 0 each). Estimated time lost per cycle: 14 h, the length of the loop.
