This repository's is `flai/images/system-flow/Dockerfile`, tagged `flai-agent-sf-claude-code:local`, over `flai-agent-claude-code:local`: Go 1.26.0, `golang:<version>-alpine3.23`'s `/usr/local/go`, with `build-base` (gcc, musl-dev) for `go test -race`; golangci-lint v2.5.0 built with that Go; ShellCheck v0.10.0 from `koalaman/shellcheck-alpine`; pnpm 10.34.5 on the base's Node 24; for the smoke tier's install test (I-0281), Alpine's `curl` and `openssl`, which `install.sh` refuses to run without, `procps-ng`, whose `ps` takes the `-p` that `scripts/release-server.sh` uses and BusyBox's refuses, and GoReleaser v2.18.1, which `scripts/flai-snapshot.sh` runs, built in the Go stage with `GOTOOLCHAIN=auto` since its `go.mod` names Go 1.27.1, the toolchain fetched and checked against Go's checksum database as `scripts/install-tools.sh`'s `go install` does, and only the binary copied in; flai's modules downloaded into `GOMODCACHE=/opt/go/mod`, readable by any uid; `GOTOOLCHAIN=local`; and no `GOFLAGS`, so `go build` stamps VCS information as on the host. In a story's worktree Go passes over the worktree's `.git` file and runs git in the main checkout, whose folder Docker makes as root, so the stamp needs the `safe.directory` for it that the harness, `scripts/agent-container.sh`, and `scripts/agent-image.sh --check` give; `scripts/agent-vcs-test.sh`, in the smoke tier, builds stamped in the layer's image with those mounts and fails without it ([I-0255](../issues/I-0255-go-build-s-vcs-stamping-fails-with-git-exit-status-128-inside-the-agent.md), S-0686). It keeps pilot as the entrypoint and holds no login or key; about 1.75 GB. Its build passes `BASE`, the harness image, and the build arguments `system-flow.yaml` names under `agent.image.args`: `GO_VERSION`, `GOLANGCI_LINT_VERSION`, `SHELLCHECK_VERSION`, `PNPM_VERSION`, and `GORELEASER_VERSION`, the same pins as the Dockerfile's `ARG` defaults, written by hand since no flai command writes them (I-0364). `scripts/agent-image.sh --check [S-nnnn]` checks a build: it fails on an image that lacks a tool the test tiers run, then runs `scripts/smoke.sh` inside it with the close-out container's mounts (ADR-0274), scoped to the story and recording no issue (S-0672). Every base names an exact version, `GO_VERSION`, `GO_ALPINE_VERSION`, and `ALPINE_VERSION` by default; bedrock's golang and alpine bases also name their index digests, and claude-code's `FROM ${BASE}` gets the bedrock image by its index digest in a release; dependabot's `docker` entry watches `flai/images/bedrock` and `flai/images/system-flow` beside `flaiover`, so the pins move weekly (S-0630); `scripts/ci-pins.sh` fails a tag that is not exact, and a `FROM` with no `@sha256:` digest in the bedrock and claude-code Dockerfiles, a `:local` image exempt. Each `flai/v*` release publishes two of them to GHCR, built by `release-flai.yml` for linux/amd64 and linux/arm64: `ghcr.io/bytepunx/flai-agent-bedrock:<version>`, from the `prebuilt` target with the release's own flai and pilot for Linux, checked against its signed `checksums.txt`, and `ghcr.io/bytepunx/flai-agent-claude-code:<version>` over it, the version without its `v`. Each is signed with cosign and the release key by its index digest, attested when the repository is public, and listed in a signed digest list on the GitHub release `flai vX.Y.Z` ([release-signing.md](../system/release-signing.md#the-digest-list)). Where the images come from, in any project, since E-0036 ([ADR-0295](../adrs/0295-an-installed-flai-pulls-its-agent-images-by-the-digests-a-signed-list-on-its.md), [flai-cli.md](../system/flai-cli.md#where-the-agent-images-come-from-adr-0295)): a released flai pulls the published ones by the digests its release's signed lists name, or builds them on the host from the Dockerfiles it carries when the pull fails, and tags them with the name the container harness runs; a development flai is never pulled for, and builds from its tree. Over them flai builds the project's layer, with `BASE` set and the literal `agent.image.args`; a built image and the layer stay `:local`, unstamped and unsigned. Each build adds `dev.system-flow.recipe`, a hash of the Dockerfile, its target, and its build arguments, and above bedrock `dev.system-flow.base`, the ID of the image under it; an image whose `dev.system-flow.flai`, recipe, or base differs from what flai would build now is stale. `flai image status` judges them, and `flai image ensure`, `flai image build`, and `flai image build --layer` make them. `flai serve`'s image job renews a missing or stale image before a start that needs it and holds the start; `flai serve agent image auto off --project <root>` turns it off, and such a start refuses, naming `flai image ensure`. `flai serve agent image command --project <root> -- <program> [args...]` names the operator's own build command, run in the main checkout with no shell in place of the pull and the build, with nine `FLAI_IMAGE_*` variables, its images judged after; `flai serve agent harness container --image <inner>=<image>` names an image flai never pulls, builds, or judges. In this repository, whose flai is a development build, that command is `scripts/agent-image.sh`, which builds exactly the images `FLAI_IMAGE_STALE` names with the tags and labels flai gives; by hand, `make agent-images` runs it for flai `dev`, building `flai-agent-bedrock:dev` (also `:local`), `flai-agent-claude-code:local` (also `:dev`), and the layer, labelled as flai labels them; `--layer` builds the layer alone over the claude-code image already built. `scripts/agent-container.sh S-nnnn` runs a story's agent in the image `FLAI_AGENT_IMAGE` names, else the one `scripts/agent-image.sh --tag` prints, the image `flai serve`'s harness runs: the layer image when the manifest names one, else the claude-code image; it refuses an image not built (S-0670); `--probe S-nnnn` runs a trial of the image as `probe-S-nnnn`, which works no item (I-0224, S-0682). It runs it with the main checkout's `.git` read-only and the story's registration read-write, and its `wip/` and `system-flow.yaml` read-only and `.flai-cache/verify` read-write, mounted beside the worktree, as the harness mounts them ([ADR-0246](../adrs/0246-a-container-that-runs-a-story-s-agent-mounts-the-main-checkout-s-git-read-only.md)): it feeds pilot a start request and passes the MCP server's URL, token, and Host by `docker run -e NAME` from its own environment, never in an argument (S-0505, S-0507, E-0029, [agent-adapters.md](../system/agent-adapters.md#a-container-harness-of-flais-own)) |

## Why

The brief requires a published image the CLI can download and run. Docker avoids asking every user to install Node. The container holds the web server and nothing else: the board is operable from the browser because the server asks `flai serve` on the host for every read and write (ADR-0029), so no repository is mounted ([ADR-0031](../adrs/0031-the-dashboard-s-container-holds-nothing-of-the-project-a-port-and-two-secrets.md); until S-0077 it was, read-write, at its host path, ADR-0022). It runs as a non-root user with the host's UID passed via `--user`, because the two secret files it is handed are readable by that user alone.

Decision: [ADR 0007](../adrs/0007-sveltekit-spa-with-node-adapter-in-docker.md).
