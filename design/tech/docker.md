# Docker

| | |
|-|-|
| Host requirement | Docker Engine 24 or newer on `PATH` (dev host has 29) |
| Image | `ghcr.io/bytepunx/flaiover`, three-stage build from the repo root (`flaiover/Dockerfile`): `golang:1.26-alpine` builds flai, `node:24-alpine` builds flaiover and prunes to production deps, `node:24-alpine` runtime with `tini`, `git`, the OpenSSH client (about 0.7 MB, for pushing an acceptance with a key the operator gives the container, [ADR 0026](../adrs/0026-the-dashboard-may-push-with-a-key-the-operator-gives-it.md), S-0062), the flai binary, `USER 65532` by default and any `--user` supported; about 670 MB (S-0015). The repository's `LICENSE.md` is copied to `/app/LICENSE.md`, where the Host › License page reads it, and `org.opencontainers.image.licenses` is `LicenseRef-system-flow-Shield-1.0` (S-0231). A release image keeps its release stamp as `/app/release-stamp`, the statement `flaiover <version> <commit>` and its base64 signature by the release key, written from the build arguments `FLAIOVER_STAMP_STATEMENT` and `FLAIOVER_STAMP_SIGNATURE`, which only a `flaiover/v*` tag's `release-key` job signs; `latest` and `sha-*` from `main`, `flai dashboard --build`, and `make flaiover-image` carry none (S-0235, [release-signing.md](../system/release-signing.md#the-stamp-as-built-s-0235)) |
| Tags | `latest` on main, `<semver>` and `<major>` from `flaiover/v*` tags, `sha-<short>`; built by `release-flaiover.yml` with buildx and GHA cache. A `flaiover/v*` tag's build is also signed with cosign and the release key by its index digest, attested when the repository is public, and listed in a signed digest list on the GitHub release `flaiover vX.Y.Z`. `latest` and `sha-*` from main are unsigned and on no list ([release-signing.md](../system/release-signing.md#the-digest-list)) |
| Run | `flai dashboard` runs `docker run --detach --rm --name flaiover --publish <bind>:<port>:3000`, two read-only bind mounts under `/run/secrets` (the login token and the agent credential) with the variables that name them, `--user <uid>:<gid>`, the label `io.bytepunx.flai.ref` naming the reference, and `ghcr.io/bytepunx/flaiover@sha256:<digest>`: the image index's digest from the signed digest list of the flaiover release `dashboard.tag` names, `latest` for the newest, pulled by that digest ([flai-cli.md](../system/flai-cli.md#verifying-a-dashboard-release-before-it-is-run)). `--build` and an image of another repository run as `<image>:<tag>`, unsigned. No volume: nothing of the project is in the container ([ADR-0031](../adrs/0031-the-dashboard-s-container-holds-nothing-of-the-project-a-port-and-two-secrets.md)) |
| Agent images | Layered, one layer per Dockerfile under `flai/images/<layer>/` ([ADR-0212](../adrs/0212-the-agent-images-are-layered-a-bedrock-layer-and-one-layer-per-inner-harness.md)). `flai-agent-bedrock:local` (`flai/images/bedrock/Dockerfile`): `golang:1.26-alpine` builds flai and pilot from the tree; `alpine:3.24` runtime with `git`, `ca-certificates`, `tini`, flai, and pilot in `/usr/local/bin`; entrypoint `/sbin/tini -- /usr/local/bin/pilot`, which reads one start request on standard input and runs the inner harness through flai's adapter ([flai-cli.md](../system/flai-cli.md#pilot-the-agent-images-entrypoint-s-0507)); `USER 65532`, a home any `--user` can write; about 81 MB. `flai-agent-claude-code:local` on top of it (`flai/images/claude-code/Dockerfile`): Alpine's Node 24, `bash`, `ripgrep`, and Claude Code 2.1.312 from npm, its musl build; keeps bedrock's entrypoint; about 614 MB, most of it Claude Code's binary. A project's own layer builds over a harness layer (S-0510). Built locally with `scripts/agent-image.sh` (`make agent-images`), unstamped and unsigned, and built or published by no workflow; pilot ships in the image only, not in flai's GoReleaser release. `scripts/agent-container.sh S-nnnn` runs a story's agent in the second: it feeds pilot a start request and passes the MCP server's URL, token, and Host by `docker run -e NAME` from its own environment, never in an argument (S-0505, S-0507, E-0029, [agent-adapters.md](../system/agent-adapters.md#a-container-harness-of-flais-own)) |

## Why

The brief requires a published image the CLI can download and run. Docker avoids asking every user to install Node. The container holds the web server and nothing else: the board is operable from the browser because the server asks `flai serve` on the host for every read and write (ADR-0029), so no repository is mounted ([ADR-0031](../adrs/0031-the-dashboard-s-container-holds-nothing-of-the-project-a-port-and-two-secrets.md); until S-0077 it was, read-write, at its host path, ADR-0022). It runs as a non-root user with the host's UID passed via `--user`, because the two secret files it is handed are readable by that user alone.

Decision: [ADR 0007](../adrs/0007-sveltekit-spa-with-node-adapter-in-docker.md).
